## 1. 本篇目标

做完这一篇，你能：

### 4.1 `apps/web/app/login/page.tsx`（新增）

**完整文件路径：`apps/web/app/login/page.tsx`**

```tsx
'use client'

import { useState, type FormEvent } from 'react'
import { useRouter } from 'next/navigation'

const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? 'http://localhost:3001'

type TokenResponse = {
  accessToken: string
  tokenType: 'Bearer'
  expiresIn: number
  user: { id: string; email: string; role: string; createdAt: string }
}

/** 登录页：调用 POST /auth/login，把 accessToken 存到 localStorage。 */
export default function LoginPage() {
  const router = useRouter()
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)
  const [loading, setLoading] = useState(false)

  async function onSubmit(event: FormEvent<HTMLFormElement>): Promise<void> {
    event.preventDefault()
    setError(null)
    setLoading(true)
    try {
      const res = await fetch(`${API_BASE}/auth/login`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email, password }),
      })
      if (!res.ok) {
        const body = (await res.json().catch(() => null)) as { message?: string } | null
        throw new Error(body?.message ?? `HTTP ${res.status}`)
      }
      const data = (await res.json()) as TokenResponse
      localStorage.setItem('accessToken', data.accessToken)
      router.push('/apps')
    } catch (err: unknown) {
      setError(err instanceof Error ? err.message : String(err))
    } finally {
      setLoading(false)
    }
  }

  return (
    <main>
      <h1>登录</h1>
      <p>
        后端：<code>{API_BASE}</code>
      </p>
      <form onSubmit={onSubmit} style={{ display: 'grid', gap: 8, maxWidth: 320 }}>
        <label>
          邮箱
          <input
            type="email"
            value={email}
            onChange={(e) => setEmail(e.target.value)}
            required
            style={{ display: 'block', width: '100%' }}
          />
        </label>
        <label>
          密码
          <input
            type="password"
            value={password}
            onChange={(e) => setPassword(e.target.value)}
            required
            style={{ display: 'block', width: '100%' }}
          />
        </label>
        <button type="submit" disabled={loading}>
          {loading ? '登录中…' : '登录'}
        </button>
      </form>
      {error !== null && <p style={{ color: 'crimson' }}>登录失败：{error}</p>}
      <p>
        <a href="/apps">前往应用列表</a>
      </p>
    </main>
  )
}
```

**逐项解释**

- `'use client'` + `useState`：见阶段 0 · 07（用 Hook 就必须是客户端组件）。
- `import { useState, type FormEvent } from 'react'`：`type FormEvent` 是**类型导入**（编译后消失，只用于类型标注）——它表示「表单提交事件」的类型（见第 5.1 节）。
- `import { useRouter } from 'next/navigation'`：拿到「导航器」对象，用它在 JS 里跳路由（见第 5.5 节）。
- `API_BASE`：与阶段 0 · 07 同款，`??` 兜底默认打 3001（`NEXT_PUBLIC_*` 的原理见阶段 0 · 08）。
- 两个受控字段 `email` / `password`：`value={email}` + `onChange={(e) => setEmail(e.target.value)}`（见第 5.1 节）。
- `onSubmit(event)` 里**第一件事**是 `event.preventDefault()`：阻止表单默认提交（默认会刷新/跳转页面，见第 5.1 节）。
- `res.ok` 为假 → 读错误体、取 `message`（见第 5.2 节）；否则 `res.json()` 得到 `TokenResponse`。
- `localStorage.setItem('accessToken', data.accessToken)`：把 token 存进浏览器（见第 5.3 节）。
- `router.push('/apps')`：登录成功后跳转（见第 5.5 节）。
- `try/catch/finally`：`catch` 把错误写进 `error` 状态；`finally` 无论成败都关掉 loading。
- `<button type="submit" disabled={loading}>{loading ? '登录中…' : '登录'}</button>`：提交中禁用按钮，防重复点击。

### 4.2 `apps/web/app/apps/page.tsx`（新增）

**完整文件路径：`apps/web/app/apps/page.tsx`**

```tsx
'use client'

import { useCallback, useEffect, useState, type FormEvent } from 'react'
import { useRouter } from 'next/navigation'

const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? 'http://localhost:3001'

type AppMode = 'chatflow' | 'workflow'

type AppResponse = {
  id: string
  name: string
  description: string | null
  mode: AppMode
  ownerId: string
  createdAt: string
  updatedAt: string
}

type AppListResponse = { items: AppResponse[] }

/** 应用列表页：读 token → GET /apps；支持新建与删除；未登录引导去 /login。 */
export default function AppsPage() {
  const router = useRouter()
  const [apps, setApps] = useState<AppResponse[]>([])
  const [error, setError] = useState<string | null>(null)
  const [loading, setLoading] = useState(true)
  const [name, setName] = useState('')
  const [description, setDescription] = useState('')
  const [mode, setMode] = useState<AppMode>('chatflow')

  const loadApps = useCallback(async (): Promise<void> => {
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      router.replace('/login')
      return
    }
    const res = await fetch(`${API_BASE}/apps`, {
      headers: { Authorization: `Bearer ${token}` },
    })
    if (res.status === 401) {
      router.replace('/login')
      return
    }
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    const data = (await res.json()) as AppListResponse
    setApps(data.items)
  }, [router])

  useEffect(() => {
    let cancelled = false
    loadApps()
      .catch((err: unknown) => {
        if (!cancelled) setError(err instanceof Error ? err.message : String(err))
      })
      .finally(() => {
        if (!cancelled) setLoading(false)
      })
    return () => {
      cancelled = true
    }
  }, [loadApps])

  async function handleCreate(event: FormEvent<HTMLFormElement>): Promise<void> {
    event.preventDefault()
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      router.replace('/login')
      return
    }
    setError(null)
    const res = await fetch(`${API_BASE}/apps`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
      body: JSON.stringify({ name, description: description === '' ? undefined : description, mode }),
    })
    if (!res.ok) {
      const body = (await res.json().catch(() => null)) as { message?: string } | null
      setError(body?.message ?? `HTTP ${res.status}`)
      return
    }
    setName('')
    setDescription('')
    setMode('chatflow')
    await loadApps().catch((err: unknown) => setError(err instanceof Error ? err.message : String(err)))
  }

  async function handleDelete(id: string): Promise<void> {
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      router.replace('/login')
      return
    }
    setError(null)
    const res = await fetch(`${API_BASE}/apps/${id}`, {
      method: 'DELETE',
      headers: { Authorization: `Bearer ${token}` },
    })
    if (!res.ok) {
      const body = (await res.json().catch(() => null)) as { message?: string } | null
      setError(body?.message ?? `HTTP ${res.status}`)
      return
    }
    await loadApps().catch((err: unknown) => setError(err instanceof Error ? err.message : String(err)))
  }

  return (
    <main>
      <h1>应用列表</h1>
      <p>
        后端：<code>{API_BASE}</code>
      </p>
      <form onSubmit={handleCreate} style={{ display: 'grid', gap: 8, maxWidth: 320, marginBottom: 24 }}>
        <label>
          名称
          <input
            value={name}
            onChange={(e) => setName(e.target.value)}
            required
            maxLength={64}
            style={{ display: 'block', width: '100%' }}
          />
        </label>
        <label>
          描述（可选）
          <input
            value={description}
            onChange={(e) => setDescription(e.target.value)}
            maxLength={256}
            style={{ display: 'block', width: '100%' }}
          />
        </label>
        <label>
          模式
          <select value={mode} onChange={(e) => setMode(e.target.value as AppMode)} style={{ display: 'block' }}>
            <option value="chatflow">chatflow</option>
            <option value="workflow">workflow</option>
          </select>
        </label>
        <button type="submit">新建应用</button>
      </form>

      {error !== null && <p style={{ color: 'crimson' }}>操作失败：{error}</p>}
      {loading && <p>加载中…</p>}
      {!loading && apps.length === 0 && <p>暂无应用。</p>}
      <ul>
        {apps.map((app) => (
          <li key={app.id} style={{ marginBottom: 8 }}>
            <strong>{app.name}</strong> <code>{app.mode}</code>
            {app.description !== null && <span> — {app.description}</span>}{' '}
            <button onClick={() => void handleDelete(app.id)}>删除</button>
          </li>
        ))}
      </ul>
      <p>
        <a href="/">返回首页</a>
      </p>
    </main>
  )
}
```

**逐项解释**

- `AppResponse` / `AppListResponse`：契约 `AppResponse` / `AppListResponse` 的 TS 版（契约见 `packages/contract/openapi.yaml`）。注意 `description: string | null`（**可空**，不是可选），`mode` 是字面量联合类型（类型系统见阶段 0 · 04）。
- `loadApps` 用 `useCallback` 包裹：原因见第 5.5 节（稳定函数身份，才能安全放进 `useEffect` 依赖数组）。
- `const token = localStorage.getItem('accessToken')`：取 token（见第 5.3 节）。
- **无 token → `router.replace('/login')`**：直接引导去登录，而不是硬生生 401 报错（见第 5.5 节与第 7 节常见坑）。
- `fetch(..., { headers: { Authorization: \`Bearer ${token}\` } })`：带鉴权请求（见第 5.2 节）。
- `res.status === 401 → router.replace('/login')`：token 失效（过期/伪造）时同样回登录页。
- `<ul>{apps.map(...)}</ul>`：列表渲染（见第 5.4 节）。`key={app.id}` 用**稳定 id**。
- 三种状态：`loading`（加载中…）/ `error`（操作失败：…）/ 空（暂无应用。）——见第 5.5 节。
- `handleCreate` 里 `description: description === '' ? undefined : description`：**空串转 `undefined`**，`JSON.stringify` 会**丢弃** `undefined` 键 ⇒ 请求体里干脆没有 `description`，后端按「未提供」处理、落库为 `null`（比空串更干净）。
- `handleDelete`：`DELETE /apps/{id}` 成功后**不解析响应体**（后端返回 **204 无内容**，见第 5.2 节），而是重新 `loadApps()` 刷新列表。

### 5.1 受控表单：`value` + `onChange`、`onSubmit` 与 `e.preventDefault()`

**是什么**：**受控组件（controlled component）**指表单元素的值由 **React 状态**托管——元素的 `value` 来自 `useState`，用户的每次输入通过 `onChange` 写回状态。这样「谁是真值」只有一个来源：React 状态。

**基本语法**

```tsx
const [email, setEmail] = useState('')

<input value={email} onChange={(e) => setEmail(e.target.value)} />
```

| 要点 | 说明 |
| --- | --- |
| `value={email}` | 显示值 = 状态值。若不给 `onChange` 只给 `value`，输入框会**只读**（React 会警告） |
| `onChange` | 每次键入触发，`e.target.value` 是**最新**输入文本 |
| `setXxx(e.target.value)` | 写回状态 → 触发重渲染 → 输入框显示新值 |
| 对照：非受控 | 只给 `defaultValue`、让 DOM 自己管值——简单但 React 拿不到实时值 |
| 表单元素通用 | `<input>` / `<select>` / `<textarea>` 都用同一套：`select` 用 `value={mode}` + `onChange`（本页第三个字段就是 `<select>`） |

**`onSubmit` 与 `e.preventDefault()`**

```tsx
function onSubmit(event: FormEvent<HTMLFormElement>) {
  event.preventDefault()   // ← 关键
  // ...处理提交
}

<form onSubmit={onSubmit}>...</form>
```

- `<form>` 的**默认行为**是把表单数据按 `action`/`method` **提交并刷新页面**（默认 GET，会改地址栏甚至跳走）。在单页应用里我们想「自己用 fetch 提交、自己控制跳转」，所以要**阻止这个默认动作**——`event.preventDefault()` 就是干这个的。
- 忘了它：点「登录」会让浏览器刷新/跳转，`fetch` 还没跑完页面就没了（典型现象见第 7 节常见坑）。
- `FormEvent<HTMLFormElement>`：事件对象的类型，泛型参数写清是「哪个元素的表单事件」（阶段 0 · 04 的泛型）。
- **`'use client'` + Hook 判据**：本页用了 `useState` / `useRouter`，所以文件第一行必须 `'use client'`（见阶段 0 · 07）。
- 原生校验属性：`required`、`type="email"`、`maxLength={64}` 是**浏览器自带**的校验，拦在 `onSubmit` 之前；服务端仍会独立校验（前端校验只是体验优化，不能替代后端）。

### 5.2 带鉴权的 `fetch`：`Authorization: Bearer` / 读错误体 / 204

**是什么**：JWT 认证的通行做法——把 token 放进请求头 `Authorization: Bearer <token>`。后端（`JwtAuthGuard` / `get_current_user`）从该头取出并验证 token（见阶段 1 · 06）。

**基本语法**

```tsx
const res = await fetch(`${API_BASE}/apps`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`,
  },
  body: JSON.stringify({ name, mode }),
})
```

- `Authorization` 的值必须是 **`Bearer ` 前缀 + 空格 + token**（`Bearer` 后那个空格别漏，否则 401）。
- `Content-Type: application/json`：告诉后端请求体是 JSON，它才会按 JSON 解析。

**如何判断成败**：`res.ok` 在**状态码 200–299** 时为 `true`，否则 `false`。注意它**不抛异常**——HTTP 4xx/5xx 不算网络错误，`fetch` 仍会正常 resolve。

**非 2xx 时读错误体**（本页模式）：

```tsx
if (!res.ok) {
  const body = (await res.json().catch(() => null)) as { message?: string } | null
  throw new Error(body?.message ?? `HTTP ${res.status}`)
}
```

- 后端错误体是契约的 `ErrorResponse` = `{statusCode, message, error}`（见阶段 1 · 01 / 07）。
- `res.json().catch(() => null)`：**关键防守**——错误响应体**未必**是 JSON（可能是代理返回的 HTML、也可能是空体）。先 `.catch(()=>null)` 兜底，再用 `body?.message` 取消息；取不到就回退成 `HTTP ${res.status}`。若直接 `await res.json()` 而体不是 JSON，会再抛一个异常，把真正的错误盖掉。
- `body?.message`：可选链，`body` 为 `null` 时安全返回 `undefined`。

**204 无响应体**：`DELETE /apps/{id}` 成功返回 **204 No Content**——「成功了，但没有要返回的内容」。此时：

- `res.ok` **仍为 `true`**（204 ∈ 200–299），所以走成功分支；
- **不要**去 `await res.json()`（没有体，解析会抛错）。本页删除成功后**不读体**，直接重新拉列表。
- 这条对「契约一致」很重要：`DELETE` 的状态码（204）是契约的一部分，两套后端必须都返回 204（见本阶段验收篇）。

### 5.3 `localStorage` 存 token：为什么方便、风险在哪

**是什么**：`localStorage` 是浏览器提供的**键值存储**，跟随域名持久保存，**刷新、关标签页都不丢**。API 很简单：

```ts
localStorage.setItem('accessToken', token)   // 写
const token = localStorage.getItem('accessToken')  // 读；不存在返回 null
localStorage.removeItem('accessToken')       // 删（登出）
```

**为什么本项目这么用（取舍）**：这是**教学项目**，`localStorage` 最简单直观——存进去、刷新页面还在、跨页面（`/login` → `/apps`）可读，不用搭 Cookie / 会话服务。

**风险（务必理解，生产慎用）**

| 风险 | 说明 |
| --- | --- |
| **XSS 可读** | `localStorage` 对**同源下的任意 JS** 完全可见。只要页面被注入一段 `<script>`（XSS），攻击者一句 `localStorage.getItem('accessToken')` 就能**偷走 token**，再拿去冒充用户。 |
| **无自动过期/不可控发送时机** | token 不会自动失效（要自己判 `exp`），也不会「自动带上」——每次请求都得手动塞 `Authorization`（容易漏）。 |
| **同源多标签共享** | 同一浏览器多标签共享，一处泄露处处可用。 |

**生产更推荐的做法**

- **`httpOnly` Cookie**：把凭证放在 `Set-Cookie: HttpOnly; Secure; SameSite=Lax`。`HttpOnly` 让 **JS 读不到**——XSS 偷不走；浏览器的同源策略会**自动携带**该 Cookie，前端也不用手动塞头。
- **配合 CSRF 防护**：Cookie 会「被自动携带」，于是引入了 **CSRF（跨站请求伪造）** 风险——攻击者诱导你的浏览器带着 Cookie 去打后端。防御手段：`SameSite=Lax/Strict`（限制跨站携带）、CSRF token（双提交 Cookie）等。
- 或**内存存储 + 刷新令牌**：access token 只放内存（XSS 也难持久化偷取），另用 `httpOnly` Cookie 放长效 refresh token。

> 一句话：`localStorage` 换来的是**简单**，代价是**把 token 暴露给同源的一切脚本**。本项目为教学选简单方案，并**显式记录这个取舍**；真实产品应优先 `httpOnly` Cookie（+ CSRF 防护）。

### 5.4 列表渲染：`map` + `key`

**是什么**：React 把**数组**渲染成一组元素——用 `Array.prototype.map` 把数据数组变成 JSX 数组，React 会逐个渲染。

```tsx
<ul>
  {apps.map((app) => (
    <li key={app.id}>...</li>
  ))}
</ul>
```

**`key` 的作用（关键）**：`key` 是给 React 用来**在重渲染时识别「哪个元素还是原来那个」**的稳定标识。

- 有了稳定 `key`，React 才能正确**复用/移动/删除**元素（增删一项时不动其他项）。
- 本页用 `key={app.id}`（后端生成的 **uuid**）：天然唯一且稳定。
- **别用数组下标 `index` 当 key**：列表增删/重排时下标会错位，导致 React 复用错节点（出现「删除后串行」这类诡异 bug）。
- `key` **只被 React 使用，不会渲染进 DOM**。

**本页的渲染细节**：`{app.description !== null && <span> — {app.description}</span>}` 是**短路与条件渲染**（阶段 0 · 07 已讲）；`{' '}` 是插入一个空格，避免相邻元素粘在一起。

### 5.5 三态（loading / error / empty）与 `useEffect` 发起请求

**三态是什么**：一个「从后端取数据」的页面，至少要考虑三种非正常态，缺一种就会出现「闪一下空白」「永远转圈」「明明空却像坏了」的困惑：

| 态 | 状态变量 | 本页渲染 |
| --- | --- | --- |
| **加载中** | `loading = true`（初始即 `true`） | `{loading && <p>加载中…</p>}` |
| **出错** | `error !== null` | `{error !== null && <p style={{color:'crimson'}}>操作失败：{error}</p>}` |
| **空** | `apps.length === 0`（且 `!loading`） | `{!loading && apps.length === 0 && <p>暂无应用。</p>}` |

要点：

- `loading` **初值设 `true`**：一进页面就先显示「加载中…」，避免「先闪一个『暂无应用。』再变成列表」的假空。
- 判定空必须**同时满足 `!loading`**，否则加载中也会命中「暂无应用。」

**在 `useEffect` 里发起请求的正确写法**（本页模式）：

```tsx
const loadApps = useCallback(async (): Promise<void> => { /* ... fetch ... */ }, [router])

useEffect(() => {
  let cancelled = false
  loadApps()
    .catch((err: unknown) => { if (!cancelled) setError(...) })
    .finally(() => { if (!cancelled) setLoading(false) })
  return () => { cancelled = true }
}, [loadApps])
```

| 要点 | 说明 |
| --- | --- |
| **不能在 `useEffect` 里直接传 `async` 函数** | `useEffect(() => {...})` 的返回值要么 `undefined`要么清理函数；`async` 返回的是 Promise，React 会误当清理函数。所以要么**内部调用**一个 async 函数（本页做法），要么 `.then` 链 |
| **清理/竞态防护** | `cancelled` 标志 + `return () => { cancelled = true }`：组件卸载（或开发模式重挂载）后，异步回调不再 `setState`（阶段 0 · 07 讲过，此处复用） |
| **依赖数组 `[loadApps]`** | 「挂载时 + `loadApps` 变化时」执行。`loadApps` 用 `useCallback(fn, [router])` 包裹 ⇒ 它的**身份稳定**（`router` 不变就一直是同一个函数），不会每次都触发 effect 重跑 |
| **`useCallback` 是什么** | 缓存函数实例。JS 里每渲染一次函数体都会**新建**一个函数；不加 `useCallback`，`loadApps` 每次都是新对象 ⇒ 放进依赖数组会让 effect **无限重跑**。`useCallback(fn, deps)` 保证 `deps` 不变时返回**同一个**函数 |
| **`.finally`** | 无论成功失败都关 loading，避免出错后一直转圈 |

**`useRouter`：用 JS 跳路由**

```tsx
const router = useRouter()        // 'next/navigation'
router.push('/apps')              // 压入一条历史记录（可后退）
router.replace('/login')          // 替换当前记录（不可后退回本页）
```

- 本页无 token / 401 时用 **`replace`** 去 `/login`：登录前的受保护页本就不该留在历史里，用 `replace` 语义更对（`push` 会让用户点「后退」又回到 `/apps`）。
- 对照：`<a href="/">` 是普通链接（整页导航），`router.push` 是**客户端**导航。

## 7. 常见坑

| # | 坑 | 现象 | 原因 / 解决 |
| --- | --- | --- | --- |
| 1 | **忘了 `e.preventDefault()`** | 点「登录」后页面刷新/跳走，fetch 好像没生效 | `<form>` 默认提交会导航。`onSubmit` 第一行必须先 `event.preventDefault()`（第 5.1 节） |
| 2 | **只给 `value` 不给 `onChange`** | 输入框打不进字，控制台警告 `You provided a value prop ... without an onChange` | 受控组件必须 `value` + `onChange` 成对；不需要受控就用 `defaultValue` |
| 3 | **`Authorization` 少了 `Bearer ` 或空格** | 列表/新建全部 401 | 值必须是 `Bearer <token>`（注意空格）；后端只认这个格式 |
| 4 | **无 token 却直接请求** | 页面显示「操作失败：HTTP 401」，而不是去登录 | 先 `localStorage.getItem('accessToken')`，为 `null` 就 `router.replace('/login')`；401 时也回登录页（第 5.5 节） |
| 5 | **对 204 调 `res.json()`** | 删除「成功」却报解析错误 | 204 无响应体；成功后不要读体，直接重新拉列表（第 5.2 节） |
| 6 | **直接读错误体没兜底** | 真正的错误消息被「Unexpected token …」盖掉 | 用 `await res.json().catch(() => null)` 再取 `body?.message`（第 5.2 节） |
| 7 | **`useEffect` 里直接传 async** | 控制台警告 effect 返回了 Promise / 清理函数异常 | 在 effect 内部调用 async 函数或 `.then` 链，**不要** `useEffect(async () => {...})`（第 5.5 节） |
| 8 | **列表下标当 `key`** | 增删/重排后某行内容错乱 | 用稳定 id（本页 `app.id`）当 `key`，别用 `index`（第 5.4 节） |
| 9 | **首次进页面闪「暂无应用。」** | 明明有数据却先闪空态 | `loading` 初值要设 `true`，空态判定要 `!loading && apps.length === 0`（第 5.5 节） |
| 10 | **token 过期** | 过一会儿操作变 401、被踢回登录页 | `exp` 到期（当前 3600 秒）；这是预期行为，重新登录即可 |
| 11 | **删不掉 / 看不到自己的应用（404）** | 列表里自己的应用却提示 404 | 归属隔离：后端对「不存在**或**不属于当前用户」一律回 **404**（见本阶段验收篇）——确认用的是**同一个用户**的 token |

## 8. 本篇复盘与知识点

**一句话总结本篇**：前端把阶段 1 的「登录拿 token」与阶段 2 的「应用增删查」接起来——**登录页**存 token、**列表页**带 token 调 `/apps` 并渲染，全靠原生 `fetch` + `localStorage`，没有引入任何额外依赖。

**本篇学到的工程要点**

1. **受控表单**由 React 状态托管值；`onSubmit` 必须 `preventDefault()` 阻止默认提交。
2. **带鉴权的 `fetch`**：`Authorization: Bearer`；4xx/5xx 不抛异常，要看 `res.ok` 并**兜底读**错误体；**204 无响应体**别解析。
3. **`localStorage` 存 token 是「简单换安全」**：XSS 可读；生产更推荐 `httpOnly` Cookie（+ CSRF 防护）。
4. **列表渲染**用 `map` + 稳定 `key`（别用下标）。
5. **取数据页面要三态**（加载/错误/空）；`useEffect` 内用 async 函数 + 取消标志 + `useCallback` 稳定依赖。

**遗留/后续**

- 登出（清除 token）、token 过期前的自动刷新等，留待后续阶段。
- 把前端错误提示与契约 `ErrorResponse.message` 的联动做得更友好（如区分 400/401/404 文案），非本阶段重点。

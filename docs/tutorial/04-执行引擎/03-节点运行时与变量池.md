## 0. 阶段 4 的立论：图从「数据」变成「可执行」

阶段 3 把「图」钉成了一段可存取、可校验的 **JSON**（见 `03-画布/01-图JSON契约与校验.md`）。但 JSON 自己不会跑。阶段 4 要做的，就是给这份 JSON 装上**执行语义**：

```
阶段 3：Graph（JSON） ──存取/校验──▶ 数据库
阶段 4：Graph（JSON） ──编译/执行──▶ 逐节点跑起来 ──▶ SSE 流式输出
```

「图 = 数据」之后，**「图 = 可执行」**靠三样东西落地：

| 概念 | 一句话 |
| --- | --- |
| **变量池（`pool`）** | 节点之间**传值**的内存模型：初始放运行输入，每个节点跑完把自己的输出写回池子，下游按名字取 |
| **节点运行时** | 每种节点一个**纯函数**：`(节点配置, 变量池) → 输出`；不碰数据库、不碰框架 |
| **执行器（LangGraph）** | 按拓扑序把节点连起来跑，并**外发事件**（`node_started` / `token` / `node_finished` / …） |

本篇聚焦前两样（**节点运行时 + 变量池**），执行器见 `04-LangGraph与引擎-Python.md`（Python 侧）与 TS 引擎篇。

> 为什么要先把「节点」做成**纯函数**、把「传值」做成**变量池**？因为这两件事是引擎里**最容易两端跑偏**的部分——一旦它们被框架（LangGraph / NestJS / FastAPI）的细节污染，TS 与 Python 就再也对不齐了。把它们剥成纯逻辑，两端才能**逐字节对齐**。

## 1. 本篇目标

- 讲透**变量池 `pool`** 的初始形状、写入时机、下游取值方式——这是「节点间传值」的全部机制。
- 讲透**模板解析** `{{ a.b }}`：允许空格、按点路径取值、**取不到就抛错**而不是静默给空串。
- 讲透**「节点 = 纯函数」的落地**：节点函数是 `(node, pool) → output`；外层执行器把它包成 `(state) → Partial<State>`。
- 讲透 `llm` 桩：渲染 prompt、写 `{ text }`、**每 8 个 Unicode 码点**发一片 `token`——为的是**先把流式通道打通**，阶段 5 再换成真模型。
- 讲透**非字符串值渲染**：TS 用 `JSON.stringify`、Python 用 `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`——为什么必须**紧凑 + 不转义非 ASCII**，否则两端输出不一致。

**验收标准**

1. 同一张图（`start → llm → end`）在两端跑出的 `node_finished.output` 完全一致。
2. 模板 `Hello {{ inputs.topic }}` 在 `inputs.topic = "mini-dify"` 下渲染为 **`Hello mini-dify`**。
3. `llm` 节点对 `Hello mini-dify` 发出两片 `token`：**`"Hello mi"`** 与 **`"ni-dify"`**（每 8 个码点一片）。
4. 模板里引用不存在的路径时，流内出现 `run_failed`，`message` 为 `template variable not found: <path>`；`start` 缺必填输入时 `message` 为 `missing required input: <name>`。

## 3. 先看清要做什么

一个 `start → llm → end` 的图（`Graph` 形状见 `03-画布/01-图JSON契约与校验.md`），跑起来时数据这样流动：

```
RunRequest.inputs  = { topic: "mini-dify" }
            │
            ▼  执行器初始化
pool = { "inputs": { "topic": "mini-dify" } }        ← ① 变量池初值
            │
   ┌────────┴─────────────────────────────────────────────┐
   │  start 节点                                            │
   │    纯函数：校验 data.inputs 声明的必填项 → 输出 {inputs} │
   │    写回：pool["start-1"] = { "inputs": {...} }         │  ← ② 节点跑完写池
   └────────┬─────────────────────────────────────────────┘
            │
   ┌────────┴─────────────────────────────────────────────┐
   │  llm 节点                                             │
   │    纯函数：渲染 data.prompt                           │
   │       "Hello {{ inputs.topic }}" → "Hello mini-dify"  │  ← ③ 模板按名字取值
   │    输出 { "text": "Hello mini-dify" }                 │
   │    并发 2 片 token："Hello mi" / "ni-dify"             │  ← ④ 流式分片
   │    写回：pool["llm-1"] = { "text": "Hello mini-dify" } │
   └────────┬─────────────────────────────────────────────┘
            │
   ┌────────┴─────────────────────────────────────────────┐
   │  end 节点                                            │
   │    渲染 data.outputs[].value                          │
   │       "{{ llm-1.text }}" → "Hello mini-dify"          │  ← ⑤ 取下游输出
   │    输出 { "outputs": { "result": "Hello mini-dify" } } │
   └────────┬─────────────────────────────────────────────┘
            │
            ▼  run_finished.outputs
     { "result": "Hello mini-dify" }
```

三个关键动作，全在两个**纯函数**文件里：`template.*`（模板）与 `nodes/*.*`（三种节点）。执行器只做「编排 + 发事件」。

## 5. 【技术教学 · 首次】变量池（variable pool）模型

**是什么**：`pool` 是一个**普通的 JSON 对象**（TS 里是 `Record<string, unknown>`，Python 里是 `dict[str, Any]`）。它是执行期间**唯一在节点之间流动的共享内存**。

**基本语法（两端）**：

```ts
// TS：变量池类型
export type Pool = Record<string, unknown>
```

```python
# Python：变量池就是一个普通 dict，没有专门的类
# （函数签名里写 pool: dict[str, Any]）
```

**初值**：整图开始执行时，池子初始为**一个键**：

```jsonc
pool = { "inputs": <RunRequest.inputs> }   // 运行输入原样放进 "inputs"
```

**写入时机**：每个节点**执行完成后**，把自己的**输出**写到 `pool[<nodeId>]`。写回这一步由执行器负责（见 `04-LangGraph与引擎-Python.md` 的 `_merge_pool` reducer / TS 的 `RunState`），节点纯函数本身**只返回输出**：

```jsonc
// llm-1 节点跑完，执行器写回：
pool = {
  "inputs": { "topic": "mini-dify" },   // 一开始就在
  "llm-1":  { "text": "Hello mini-dify" } // 该节点刚写入
}
```

**下游取值**：下游节点要用上游的输出，就写 `{{ <nodeId>.<字段> }}`——**节点 id 就是池子里的键**：

```jsonc
"{{ llm-1.text }}"   // 取 pool["llm-1"]["text"] → "Hello mini-dify"
"{{ inputs.topic }}" // 取 pool["inputs"]["topic"] → "mini-dify"
```

**为什么这么设计（这就是 Dify 同类设计）**：

| 好处 | 说明 |
| --- | --- |
| **统一寻址** | 无论值来自「运行输入」还是「某节点输出」，都是一个 `<键>.<点路径>`——下游不用知道它是哪来的 |
| **无框架依赖** | 池子就是个 JSON 对象，纯函数读写它，天然两端一致 |
| **可调试** | 每个节点跑完往池里加一个键，出错时看池子就能定位是哪一步的值没进来 |

> 一句话：**节点间不直接互相调用，而是通过一个共享的「变量池」间接传值**——上游把结果放进 `pool[自己的 id]`，下游用 `{{ 上游id.字段 }}` 取。这就是「节点间传值」的全部机制。

## 6. 【技术教学 · 首次】模板解析 `{{ a.b }}` 与「取不到即报错」

**是什么**：节点配置里允许写**模板字符串**，形如 `Hello {{ inputs.topic }}`。执行时，模板片段会被**替换**成池子里对应的值。

**基本语法**：匹配 `{{ path }}` 的正则——花括号内**不含花括号**、**允许首尾空格**：

```ts
// TS
const TEMPLATE_PATTERN = /\{\{\s*([^{}]+?)\s*\}\}/g
```

```python
# Python
_TEMPLATE_PATTERN = re.compile(r"\{\{\s*([^{}]+?)\s*\}\}")
```

- `\{\{` / `\}\}`：字面量花括号（正则里要转义）。
- `\s* ... \s*`：允许 `{{a.b}}` 与 `{{ a.b }}` **两种写法等价**。
- `([^{}]+?)`：捕获「路径」，且路径里**不允许再出现花括号**（惰性匹配到第一个 `}}` 为止）。

**点路径取值**：把捕获到的路径按 `.` 切开，**一段一段**往池子深处走：

```
"inputs.topic".split(".")  →  ["inputs", "topic"]
pool["inputs"]["topic"]    →  "mini-dify"
```

**关键决定：任一段取不到就抛错，绝不静默给空串**：

```ts
// TS
throw new RunError(`template variable not found: ${path}`)
```

```python
# Python
raise RunError(f"template variable not found: {path}")
```

**为什么必须报错、而不是返回 `""` / `undefined`**：

| 静默给空串 | 报错（本项目做法） |
| --- | --- |
| 拼错的模板（如 `{{ inputs.topicx }}`）会渲染成 `Hello ` —— 表面上「跑通了」，实则数据错了 | 立刻中断，流内 `run_failed`，`message` 一眼看出是哪个路径找不到 |
| 调试时要在下游到处找「为什么值是空的」 | 错误直接指到**出错路径** |
| 契约里的行为无法钉死（空串有多种来源） | 契约可钉死为唯一文案 `template variable not found: {path}`（见 `packages/contract/error-messages.md` §4.2 与 `sse-events.md` §4） |

> 模板是「我**确定**上游这个字段存在」的声明。声明不成立时，正确的反馈是**报错**，不是把错误藏进空串。这也是两端能对齐的前提——**唯一且确定的失败文案**。

**「对象 / 数组」这种非字符串的值怎么办**：见 §9（涉及两端序列化口径，单独讲）。

## 7. 【技术教学 · 首次】「节点 = 纯函数」的落地：`(state, node) => Partial<State>`

**先回顾**：阶段 3 已经教过「业务规则用**纯函数**两端各实现」（见 `03-画布/01-图JSON契约与校验.md` —— `validateGraph` 不碰数据库、不依赖上下文，喂一份图进去、吐一份错误列表）。阶段 4 把同一条原则**用到节点执行**上。

**第一层：节点运行时本身是纯函数**，签名是「`节点配置 + 变量池` → `输出`」，不是「`state + node`」：

```ts
// TS：三种节点都是这个形状（入参：节点、池；出参：一个 JSON 对象）
function runStartNode(node: GraphNode, pool: Pool): Record<string, unknown>
function runEndNode(node: GraphNode, pool: Pool): Record<string, unknown>
```

```python
# Python：同一形状
def run_start_node(node: dict[str, Any], pool: dict[str, Any]) -> dict[str, Any]
def run_end_node(node: dict[str, Any], pool: dict[str, Any]) -> dict[str, Any]
```

特征与 `validateGraph` 完全一致：**不碰数据库、不碰框架、不依赖请求上下文**，只靠入参算输出。所以它能被单独喂数据测试、两端逐条对齐。

**第二层：执行器把节点函数「包」成 LangGraph 的节点动作**，这一层才有 `(state) → Partial<State>` 的形状（`llm` 还多一个发 `token` 的回调）：

```ts
// TS（在 EngineService.makeNodeAction 里）：包一层，负责发事件 + 写回池
return async (state: RunStateValue): Promise<Partial<RunStateValue>> => {
  context.queue.emit(nodeStarted(node.id, node.type))       // 副作用①：发 node_started
  const output = this.executeNode(node, state.pool, context.queue)  // 纯逻辑
  context.queue.emit(nodeFinished(node.id, node.type, output))      // 副作用②：发 node_finished
  return { pool: { [node.id]: output } }                     // 写回：只返回「增量」
}
```

```python
# Python（在 engine._make_node_action 里）：同一件事
async def action(state: RunState) -> dict[str, Any]:
    await queue.put(node_started(node["id"], node["type"]))
    output = await _execute_node(node, state["pool"], queue)
    await queue.put(node_finished(node["id"], node["type"], output))
    return {"pool": {node["id"]: output}}
```

**为什么把「纯逻辑」和「副作用」分成两层**：

| 层 | 职责 | 是否纯 |
| --- | --- | --- |
| 节点函数（`nodes/*`） | 算输出 `(node, pool) → output` | **纯**（好测、两端一致） |
| 节点动作（执行器里包的那层） | 发 `node_started` / `node_finished` 事件、写回池、记录出错节点 | **有副作用**（发事件、改队列） |

**返回「增量」而非「整份池」**：节点动作只返回 `{ pool: { [node.id]: output } }`（**只放自己这一键**），由 LangGraph 的 **合并 reducer** 把增量并进整池——这正是 §5「节点跑完写回 `pool[nodeId]`」的实现机制（reducer 细节见 `04-LangGraph与引擎-Python.md`）。**分工清晰**：节点只管算出「我这一个键的值」，池的累积交给执行器。

> 一致性小结：**阶段 3 说「校验是纯函数」，阶段 4 说「节点执行也是纯函数」。** 整个引擎里被两端反复对齐的，正是这些**没有副作用的确定性逻辑**；所有副作用（发事件、读写队列）都被收敛到执行器的固定几行里。

## 8. 【技术教学 · 首次】`llm` 桩与「每 8 个 Unicode 码点」分片

**本阶段的 `llm` 是桩**：它**不调用真模型**，只做两件事——把 `data.prompt` 用池渲染，再把结果**切成若干片**逐片外发。真模型要到阶段 5 才接上（`LlmNodeData.model` 本阶段不使用，见契约 `packages/contract/src/index.ts`）。

**节点逻辑（两端一致）**：

```
1. 取 data.prompt（契约里是字符串）
2. 用池渲染 → rendered          例："Hello mini-dify"
3. 把 rendered 每 8 个码点切一片，逐片 emitToken
4. 输出 { "text": rendered }     ← 写回 pool[<llmId>]
```

**分片大小是一个常量**：

```ts
// TS
const TOKEN_SIZE = 8
```

```python
# Python
TOKEN_SIZE = 8
```

**按「Unicode 码点」切，而不是按字节**：

```ts
// TS：Array.from 把字符串按码点拆成数组，再每 8 个 join 回去
function chunkByCodePoints(text: string, size: number): string[] {
  const codePoints = Array.from(text)          // ← 关键：按码点，不按 UTF-16 码元/字节
  const chunks: string[] = []
  for (let i = 0; i < codePoints.length; i += size) {
    chunks.push(codePoints.slice(i, i + size).join(''))
  }
  return chunks
}
```

```python
# Python：Python 字符串天然按码点索引，直接切片即等价
def _chunk_by_code_points(text: str, size: int) -> list[str]:
    return [text[i : i + size] for i in range(0, len(text), size)]
```

**为什么是「每 8 个码点」而不是「每 8 个字节」**：

| 按字节切 | 按码点切（本项目做法） |
| --- | --- |
| 中文 / emoji 是多字节（UTF-8 下一个汉字 3 字节、一个 emoji 常 4 字节） | 一个码点 = 一个「字符」（用户直觉的单位） |
| 第 8 个字节可能落在**某个字符的中间** → 切出**半个字符**（非法 UTF-8 / 乱码） | 永远不会把一个码点劈成两半 |
| 两端（JS 的 UTF-16 字符串 / Python 的 str）**字节级切片口径不同**，无法对齐 | 两端都按码点，**切片结果逐片相同** |

**实测**：`"Hello mini-dify"` 共 15 个码点 → **`8 + 7`** → 两片：**`"Hello mi"`** + **`"ni-dify"`**。之所以切 8 片、不一次发整串，是因为本阶段要**先把「流式通道」打通**：让 `token` 事件真的会**多次**出现在流里，前端也就能先按「逐片到达」渲染；阶段 5 把桩换成真模型时，**事件协议一个字都不用改**——只是「片」的来源从「本地切片」变成「模型吐字」。

> 补充：按「码点」切**不等于**按「字素簇（grapheme cluster）」切——带组合符的 emoji（如 `👨👩👧`）仍可能被拆开。但本项目要的是**两端逐片一致**，码点粒度已足够且最简单（`Array.from` 与 Python 切片天然对齐）。

## 9. 【技术教学 · 首次】非字符串值的模板替换：紧凑 JSON、不转义非 ASCII

**问题**：§6 说模板值会被替换，但**如果取到的值不是字符串呢**？例如某个节点输出的 `outputs` 是 `{ "a": 1 }`，模板 `{{ someNode.outputs }}` 该怎么渲染？

**规则**：**字符串原样替换；非字符串一律序列化成 JSON**（两端必须**逐字节相同**）。

```ts
// TS
function stringifyValue(value: unknown): string {
  return typeof value === 'string' ? value : JSON.stringify(value)
}
```

```python
# Python
def _stringify(value: Any) -> str:
    if isinstance(value, str):
        return value
    return json.dumps(value, ensure_ascii=False, separators=(",", ":"))
```

**为什么 Python 这两个参数不能省**（这是最容易踩、也最关键的坑）：

| 参数 | 默认行为 | 必须写成的值 | 不写会怎样 |
| --- | --- | --- | --- |
| `separators` | `json.dumps` 默认 `(", ", ": ")`（**带空格**） | `(",", ":")`（**紧凑**） | Python 输出 `{"a": 1}`，JS 输出 `{"a":1}` —— **多一个空格就不一致** |
| `ensure_ascii` | `json.dumps` 默认 `True`（**转义成 `\uXXXX`**） | `False`（**保留原字符**） | Python 输出 `{"name":"\u4e2d\u6587"}`，JS 输出 `{"name":"中文"}` —— **字节级不同** |

对照：**JS 的 `JSON.stringify` 默认就是「紧凑 + 不转义非 ASCII」**（JS 字符串是 UTF-16，正常输出非 ASCII 字符），所以 TS 侧**不需要**任何额外参数；Python 侧则必须**显式**补上这两个参数，才能与 JS 对齐。

**举例（两端都应输出同一串）**：

```
值 = { "a": 1, "name": "中文" }

TS  : JSON.stringify(v)                              → {"a":1,"name":"中文"}
Py  : json.dumps(v, ensure_ascii=False,
                 separators=(",", ":"))               → {"a":1,"name":"中文"}   ✅ 一致
Py  : json.dumps(v)                                   → {"a": 1, "name": "\u4e2d\u6587"}  ❌ 不一致
```

> 同一套「紧凑 + `ensure_ascii=False`」口径也用在 **SSE 帧的 payload 序列化**上（`events.ts` 的 `JSON.stringify` / `events.py` 的 `format_sse_frame`），见 `04-LangGraph与引擎-Python.md`。这是全项目统一的**「两端 JSON 序列化口径」**。

```ts
import { RunError } from './events'

/**
 * 模板解析（引擎语义，两端必须一致，见 sse-events.md §4）。
 *
 * 变量池 `pool` 初始为 `{ "inputs": <RunRequest.inputs> }`，每个节点执行完把自身输出
 * 写入 `pool[<nodeId>]`。字符串里的 `{{ a.b }}`（花括号内允许空格）按点路径取值并替换。
 */

/** 变量池：键为 `inputs` 或节点 id，值为该键下的 JSON 对象。 */
export type Pool = Record<string, unknown>

/** 匹配 `{{ path }}`：花括号内不含花括号，允许首尾空格。 */
const TEMPLATE_PATTERN = /\{\{\s*([^{}]+?)\s*\}\}/g

/** 把 `text` 中的模板片段按 `pool` 渲染（模板外的文本原样保留）。 */
export function renderTemplate(text: string, pool: Pool): string {
  return text.replace(TEMPLATE_PATTERN, (_match: string, rawPath: string) =>
    stringifyValue(resolvePath(rawPath.trim(), pool)),
  )
}

/** 按点路径从 `pool` 取值；任一段不存在即抛 `RunError`。 */
export function resolvePath(path: string, pool: Pool): unknown {
  let current: unknown = pool
  for (const segment of path.split('.')) {
    if (
      typeof current !== 'object' ||
      current === null ||
      Array.isArray(current) ||
      !(segment in current)
    ) {
      throw new RunError(`template variable not found: ${path}`)
    }
    current = (current as Record<string, unknown>)[segment]
  }
  return current
}

/** 渲染值转字符串：字符串原样，其余按紧凑 JSON 序列化（与 api-py 对齐）。 */
function stringifyValue(value: unknown): string {
  return typeof value === 'string' ? value : JSON.stringify(value)
}
```

**读法要点**：
- `TEMPLATE_PATTERN` 带 `g`（全局）标志，`String.replace` 会**替换所有**模板片段；`_match` 是整个 `{{...}}`，`rawPath` 是捕获组里的路径。
- `resolvePath` 的**防御条件**：当前层不是对象 / 是 `null` / 是数组 / 不含该段，**任一**成立即抛 —— 数组用 `.` 索引这种事被显式排除。
- `Array.isArray(current)` 排除数组：池子里的键都是**对象**（`inputs` 与各节点输出），数组不该被点路径穿透。
- `(segment in current)` 用 `in` 而非 `hasOwnProperty`：段不存在即报错。

**完整文件路径：`apps/api-ts/src/engine/nodes/start.node.ts`**

```ts
import type { GraphNode, StartNodeData } from '@mini-dify/contract'

import { RunError } from '../events'
import type { Pool } from '../template'

/**
 * `start` 节点：把 `RunRequest.inputs` 按 `data.inputs` 声明逐条校验（缺必填即失败），
 * 输出 `{ inputs: <运行输入> }`。失败文案见 error-messages.md §4.2。
 */
export function runStartNode(node: GraphNode, pool: Pool): Record<string, unknown> {
  const declared = (node.data as unknown as StartNodeData).inputs
  const provided = (pool.inputs ?? {}) as Record<string, unknown>
  for (const input of declared) {
    if (input.required === true && !(input.name in provided)) {
      throw new RunError(`missing required input: ${input.name}`)
    }
  }
  return { inputs: provided }
}
```

**读法要点**：
- `node.data` 在契约里是**自由结构**（`Record<string, unknown>`，见 `03-画布/01`），这里用 `as unknown as StartNodeData` **断言**成具体形状——**运行期形状校验**由执行器预检的 `validateNodeData` 负责（见 `04-LangGraph与引擎-Python.md` 与 TS 引擎篇），节点函数只信任它。
- `pool.inputs ?? {}`：初值就是 `{ inputs }`，这里再兜一层，避免 `pool.inputs` 为 `null`。
- 只校验 `required === true` 的项；非必填缺失**放行**。

**完整文件路径：`apps/api-ts/src/engine/nodes/llm.node.ts`**

```ts
import type { GraphNode, LlmNodeData } from '@mini-dify/contract'

import { renderTemplate, type Pool } from '../template'

/** 流式分片大小：每个 Unicode 码点 8 个字符一片（两端一致，见 sse-events.md §4）。 */
const TOKEN_SIZE = 8

/**
 * `llm` 节点（本阶段为**桩**）：把 `data.prompt` 用池渲染，输出 `{ text: <渲染后文本> }`，
 * 并把该文本按固定切片逐片交给 `emitToken`，以演示流式。
 */
export function runLlmNode(
  node: GraphNode,
  pool: Pool,
  emitToken: (text: string) => void,
): Record<string, unknown> {
  const prompt = String((node.data as unknown as LlmNodeData).prompt)
  const rendered = renderTemplate(prompt, pool)
  for (const chunk of chunkByCodePoints(rendered, TOKEN_SIZE)) {
    emitToken(chunk)
  }
  return { text: rendered }
}

/** 按 Unicode 码点切分（与 api-py 的按码点切片一致）。 */
function chunkByCodePoints(text: string, size: number): string[] {
  const codePoints = Array.from(text)
  const chunks: string[] = []
  for (let i = 0; i < codePoints.length; i += size) {
    chunks.push(codePoints.slice(i, i + size).join(''))
  }
  return chunks
}
```

**读法要点**：`emitToken` 是**回调**——TS 侧是同步回调（`(text) => queue.emit(token(node.id, text))`），Python 侧是**异步**的（`await emit(...)`）。差别来自两边的执行模型（TS 单线程事件循环 / Python `asyncio`），见 `04-LangGraph与引擎-Python.md`。

**完整文件路径：`apps/api-ts/src/engine/nodes/end.node.ts`**

```ts
import type { EndNodeData, GraphNode } from '@mini-dify/contract'

import { renderTemplate, type Pool } from '../template'

/**
 * `end` 节点：把 `data.outputs[].value` 逐条渲染，输出 `{ outputs: { name: 渲染值 } }`。
 * 该对象即 `run_finished` 的 `outputs`（多 `end` 时取拓扑序最后一个）。
 */
export function runEndNode(node: GraphNode, pool: Pool): Record<string, unknown> {
  const declared = (node.data as unknown as EndNodeData).outputs
  const outputs: Record<string, unknown> = {}
  for (const output of declared) {
    outputs[output.name] = renderTemplate(output.value, pool)
  }
  return { outputs }
}
```

**读法要点**：`outputs` 的**键**来自 `data.outputs[].name`（契约里是 `{ name, value }`），**值**是渲染后的 `value`。这个 `{ name: 渲染值 }` 就是 `run_finished.outputs`。

```python
"""模板解析（引擎语义，两端必须一致，见 sse-events.md §4）。

变量池 `pool` 初始为 `{"inputs": <RunRequest.inputs>}`，每个节点执行完把自身输出
写入 `pool[<nodeId>]`。字符串里的 `{{ a.b }}`（花括号内允许空格）按点路径取值并替换。
"""

import json
import re
from typing import Any

from app.engine.events import RunError

# 匹配 {{ path }}：花括号内不含花括号，允许首尾空格
_TEMPLATE_PATTERN = re.compile(r"\{\{\s*([^{}]+?)\s*\}\}")


def render_template(text: str, pool: dict[str, Any]) -> str:
    """把 `text` 中的模板片段按 `pool` 渲染（模板外文本原样保留）。"""
    return _TEMPLATE_PATTERN.sub(lambda match: _stringify(resolve_path(match.group(1).strip(), pool)), text)


def resolve_path(path: str, pool: dict[str, Any]) -> Any:
    """按点路径从 `pool` 取值；任一段不存在即抛 `RunError`。"""
    current: Any = pool
    for segment in path.split("."):
        if not isinstance(current, dict) or segment not in current:
            raise RunError(f"template variable not found: {path}")
        current = current[segment]
    return current


def _stringify(value: Any) -> str:
    """渲染值转字符串：字符串原样，其余按紧凑 JSON 序列化（与 api-ts 对齐）。"""
    if isinstance(value, str):
        return value
    return json.dumps(value, ensure_ascii=False, separators=(",", ":"))
```

**完整文件路径：`apps/api-py/app/engine/nodes/start.py`**

```python
"""`start` 节点：按 `data.inputs` 声明校验运行输入，输出 `{"inputs": <运行输入>}`。

失败文案见 `packages/contract/error-messages.md` §4.2。
"""

from typing import Any

from app.engine.events import RunError


def run_start_node(node: dict[str, Any], pool: dict[str, Any]) -> dict[str, Any]:
    declared: list[dict[str, Any]] = node["data"]["inputs"]
    provided: dict[str, Any] = pool.get("inputs") or {}
    for item in declared:
        if item.get("required") is True and item["name"] not in provided:
            raise RunError(f"missing required input: {item['name']}")
    return {"inputs": provided}
```

**完整文件路径：`apps/api-py/app/engine/nodes/llm.py`**

```python
"""`llm` 节点（本阶段为**桩**）：渲染 `data.prompt`，输出 `{"text": <渲染后文本>}`。

并把该文本按固定切片逐片交给 `emit`，以演示流式（切片口径与 api-ts 一致）。
"""

from collections.abc import Awaitable, Callable
from typing import Any

from app.engine.template import render_template

# 流式分片大小：每个 Unicode 码点 8 个字符一片（两端一致，见 sse-events.md §4）
TOKEN_SIZE = 8

EmitToken = Callable[[str], Awaitable[None]]


async def run_llm_node(
    node: dict[str, Any], pool: dict[str, Any], emit: EmitToken
) -> dict[str, Any]:
    prompt = str(node["data"]["prompt"])
    rendered = render_template(prompt, pool)
    for chunk in _chunk_by_code_points(rendered, TOKEN_SIZE):
        await emit(chunk)
    return {"text": rendered}


def _chunk_by_code_points(text: str, size: int) -> list[str]:
    # Python 字符串按码点索引，天然与 api-ts 的 Array.from 切片一致
    return [text[i : i + size] for i in range(0, len(text), size)]
```

该对象即 `run_finished` 的 `outputs`（多 `end` 时取拓扑序最后一个）。
"""

from typing import Any

from app.engine.template import render_template


def run_end_node(node: dict[str, Any], pool: dict[str, Any]) -> dict[str, Any]:

## 12. 两端对照表

| 关注点 | TS（`apps/api-ts/src/engine`） | Python（`apps/api-py/app/engine`） | 是否逐字节一致 |
| --- | --- | --- | --- |
| 变量池类型 | `type Pool = Record<string, unknown>` | 普通 `dict[str, Any]`（无专门类） | 语义一致 |
| 池初值 | `{ pool: { inputs } }`，reducer 默认 `{}` | `{"pool": {"inputs": inputs}}` | 一致 |
| 写回方式 | 动作返回 `{ pool: { [node.id]: output } }`，由 `Annotation` 的 reducer 合并 | 动作返回 `{"pool": {node["id"]: output}}`，由 `Annotated[dict, _merge_pool]` 合并 | 一致（见 `04-LangGraph与引擎-Python.md`） |
| 模板正则 | `/\{\{\s*([^{}]+?)\s*\}\}/g` | `re.compile(r"\{\{\s*([^{}]+?)\s*\}\}")` | 等价 |
| 路径取值失败 | `throw new RunError(\`template variable not found: ${path}\`)` | `raise RunError(f"template variable not found: {path}")` | **文案逐字节一致** |
| 非字符串渲染 | `JSON.stringify(value)`（默认紧凑、不转义） | `json.dumps(value, ensure_ascii=False, separators=(",", ":"))` | **输出逐字节一致**（靠显式两参数） |
| `start` 必填校验 | `input.required === true && !(input.name in provided)` | `item.get("required") is True and item["name"] not in provided` | 一致；文案 `missing required input: {name}` |
| `start` 输出 | `{ inputs: provided }` | `{"inputs": provided}` | 一致 |
| `llm` 渲染 | `renderTemplate(prompt, pool)` → 输出 `{ text: rendered }` | `render_template(prompt, pool)` → 输出 `{"text": rendered}` | 一致 |
| `llm` 分片 | `Array.from(text)` 每 8 个码点一片，`emitToken` 同步回调 | `text[i:i+8]` 每 8 个码点一片，`await emit(...)` 异步回调 | 切片结果一致（回调同步/异步之别见 04 篇） |
| `end` 输出 | `{ outputs: { [name]: rendered } }` | `{"outputs": {name: rendered}}` | 一致 |
| JSON 键顺序 | 契约层不要求（`sse-events.md` §1 以「解析后 JSON 相等」为准） | 同 | 无需一致 |

> 小结：**同一套语义、两种语法**。凡是「会被写进 SSE 帧 / 出错文案」的部分（模板失败文案、必填文案、各节点 output 形状、token 切片），两端都必须**逐字节一致**；而「语法层面的差异」（回调同步 vs 异步、`Record` vs `dict`）发生在语言内部，不影响对外输出。

| 两端一致 | 除 `runId` / `elapsedMs` 外，**逐字节相同** |
| 模板取不到 | 把 `end` 的 value 改成 `{{ llm-1.nope }}` → 流内出现 `run_failed`，`message` = `template variable not found: llm-1.nope` |
| 缺必填输入 | `-d '{"inputs":{}}'`（`topic` 必填却缺失）→ 流内 `run_failed`，`message` = `missing required input: topic` |

---

## 14. 常见坑

| 坑 | 现象 | 原因 / 解决 |
| --- | --- | --- |
| 模板取不到时静默返回空串 | 「跑通了」但输出少了一块，难定位 | 必须**抛错**走 `run_failed`，文案固定 `template variable not found: {path}`（§6） |
| 模板正则不允许空格 | `{{ inputs.topic }}` 匹配不上 | 正则要写 `\s*([^{}]+?)\s*`，两种空格写法都得认（§6） |
| 点路径穿透数组 | 引用数组元素时行为不可预期 | `resolvePath` 显式排除 `Array`：池里的值都是对象（§10） |
| Python 用默认 `json.dumps` 渲染对象 | 输出带空格 / 中文被转义成 `\uXXXX`，与 TS 不一致 | 必须 `ensure_ascii=False, separators=(",", ":")`（§9） |
| 按字节切 `token` | 中文/emoji 被切成半个字符（乱码） | 按**码点**切：TS 用 `Array.from`，Python 直接切片；每片 8 个码点（§8） |
| 节点函数里直接发事件 | 纯函数被副作用污染、两端难对齐 | 纯逻辑放 `nodes/*`；发事件收进执行器的「节点动作」层（§7） |
| 节点返回整份池而非增量 | 多节点并发/顺序下互相覆盖 | 只返回 `{ pool: { [节点id]: output } }`，累积交给合并 reducer（§7、§12） |
| `node.data` 直接当具体类型用 | 数据形状不合法时抛 `TypeError` 而非契约文案 | 运行期形状校验由预检 `validateNodeData` 负责；节点内只做断言（§10、`error-messages.md` §4.1） |
| `llm` 桩误以为在调真模型 | 改了 `model` 字段却没效果 | 本阶段 `llm` 是**桩**，`model` 不使用，为阶段 5 预留（§8） |
| TS 侧给 `JSON.stringify` 加「缩进」参数 | 与 Python 紧凑输出不一致 | 保持默认（紧凑）；两端口径见 §9、§12 |

## 15. 本篇技术点登记（同步到 `docs/tutorial/INDEX.md`）

| 技术点 | 说明 |
| --- | --- |
| **变量池（variable pool）模型** | `pool` 初值 `{ "inputs": <运行输入> }`；节点跑完把输出写入 `pool[<nodeId>]`；下游用 `{{ nodeId.field }}` 取值。节点间传值的统一机制（Dify 同类设计） | **首次教学于本篇** |
| **模板解析** `{{ a.b }}` | 花括号内允许空格；按点路径取值；**取不到即抛 `RunError`**（`template variable not found: {path}`），不静默给空串 | **首次教学于本篇** |
| **「节点 = 纯函数」的落地** | 节点函数 `(node, pool) → output` 为纯逻辑；执行器包成 `(state) → Partial<State>` 的节点动作（发事件、写回池）。与阶段 3「校验也是纯函数」一脉相承 | **首次教学于本篇** |
| **`llm` 桩与「每 8 个 Unicode 码点」分片** | 本阶段 `llm` 不调真模型：渲染 prompt → 输出 `{ text }` → 每 8 个**码点**发一片 `token`，先打通流式通道（阶段 5 换真模型，协议不变）；按码点而非字节，避免多字节字符被切碎 | **首次教学于本篇** |
| **非字符串值的模板替换口径** | TS `JSON.stringify`（默认紧凑、不转义非 ASCII）vs Python `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`；必须显式对齐，否则两端输出不一致 | **首次教学于本篇** |

# 05 · 验收（发布与 API）

> 阶段 10 · 收尾
>
> 验收目标：**发布是快照，不是引用**——改草稿不影响线上，再发布才生效；**key 只存哈希**——库里搜不到明文，撤销后立即失效；**对外接口只多一把 key**——同一张图、同一套事件、同一套文案，两端逐字节一致。
>
> **本篇面试考点**：怎么证明「发布是复制而不是引用」 · 为什么验收要先测「未发布」 · 为什么「改草稿不发布」必须和「再发布」成对验 · 明文不落库怎么查 · SHA-256 和 bcrypt 在验收上的区别 · 为什么 key 跨应用调用是 401 而不是 403 · 为什么「应用不存在」要单独测 · 4xx 为什么必须是 JSON 而不是 SSE · 流内失败为什么 HTTP 还是 200 · 撤销为什么要验「同名可重建」 · 事件级 diff 为什么要折叠 token 帧 · 已知差异 `{"name": null}` 为什么不纳入判定 · 阶段 10 的回归重点是什么。

| 本阶段验收 | 不在本阶段 |
| --- | --- |
| 发布 = 草稿复制到 `published_graph_json` | 发布版本历史 / 回滚 / 灰度 |

五个验收辅助函数（只在当前 PowerShell 会话里生效）：

```powershell
# 写 JSON 文件：Windows PowerShell 5 的 -Encoding utf8 会带 BOM，
# 服务端/curl 可能把 BOM 当成请求体的第一个字符，所以统一用无 BOM 的 UTF-8。
function Write-Json($path, $text) {
  [System.IO.File]::WriteAllText((Join-Path $PWD $path), $text,
    (New-Object System.Text.UTF8Encoding($false)))
}

# 统一发请求：返回「状态码」，响应体写到文件（SSE 文本帧与 JSON 错误共用）。
# -BodyFile 用 @file 交给 curl.exe，避免 PowerShell 对中文和引号做二次转义。
function Send-Api {
  param(
    [string]$Method = 'POST',                 # HTTP 方法
    [string]$Url,                             # 完整地址（协议 + 端口 + 路径）
    [hashtable]$Headers = @{},                # 认证头 / API Key 头
    [string]$BodyFile,                        # 请求体文件（可空）
    [string]$OutFile                          # 响应体落盘路径
  )
  $curlArgs = @('-sS', '-o', $OutFile, '-w', '%{http_code}', '-X', $Method, $Url)
  foreach ($name in $Headers.Keys) { $curlArgs += @('-H', "${name}: $($Headers[$name])") }
  if ($BodyFile) {
    $curlArgs += @('-H', 'Content-Type: application/json', '--data-binary', "@$BodyFile")
  }
  return (& curl.exe @curlArgs)
}

# 读错误体：两端都是契约里的 ErrorResponse（{statusCode, message, error}）。
function Show-ErrorBody($file) {
  $body = Get-Content $file -Raw | ConvertFrom-Json
  "$($body.statusCode) $($body.error): $($body.message)"
}

# 读 `run_finished` 的 outputs（SSE 帧固定是「event 行 + data 行」）。
function Get-RunOutputs($file) {
  $lines = Get-Content $file
  for ($i = 0; $i -lt $lines.Count - 1; $i++) {
    if ($lines[$i] -eq 'event: run_finished') {
      return ($lines[$i + 1].Substring(6) | ConvertFrom-Json).outputs
    }
  }
  return $null
}

# 读终态事件名（run_finished / run_failed）。终态唯一，读到即返回。
function Get-TerminalEvent($file) {
  foreach ($line in Get-Content $file) {
    if ($line -eq 'event: run_finished') { return 'run_finished' }
    if ($line -eq 'event: run_failed') { return 'run_failed' }
  }
  return $null
}
```

## 4. 用例矩阵

### 4.1 发布语义与快照隔离

> 顺序不能乱：P1/P2 必须在**第一次发布之前**测，否则「未发布」这个前置就不成立。

| # | 操作 | 期望 |
| --- | --- | --- |
| P1 | 未发布时 `GET /apps/{id}/graph/published` | `404 Graph not published` |
| P2 | 未发布时 `POST /public/apps/{id}/run` | `400 App is not published`，`Content-Type: application/json` |
| P3 | `POST /apps/{id}/graph/publish` | `200`，`{publishedAt, graph}`；`publishedAt` 形如 `...Z` |
| P4 | 用刚创建的 key 公开运行（`topic=alpha`） | `200` SSE；`run_finished.outputs.answer = "echo: alpha"` |
| P5 | 只 `PUT /graph` 保存 G1-draft2，**不发布**，再公开运行 | 回答仍是 `"echo: alpha"`（旧快照），不含「草稿：」 |
| P6 | 再 `POST /graph/publish`，再公开运行 | 回答变成 `"echo: 草稿：alpha"` |
| P7 | 发布后 `GET /apps/{id}/graph` | 仍返回草稿（`草稿：...`），发布**不改**草稿 |
| P8 | 连续发布两次后查 `published_at` | 同一行被覆盖（只有一个时间列，无版本表） |

#### P1 / P2：未发布

```powershell
# P1：读取已发布图 —— 快照资源不存在
$code = Send-Api -Method GET -Url "http://localhost:3001/apps/$appId/graph/published" -Headers $TH -OutFile "_p1.json"
"P1 => $code"; Show-ErrorBody "_p1.json"

# P2：公开调用还没发布的应用（此时还没有 key，先建一把）
$created = Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/api-keys" -Headers $TH `
  -ContentType "application/json" -Body (@{ name = "accept10" } | ConvertTo-Json)
$key = $created.key

Write-Json "_pub_alpha.json" '{"inputs":{"topic":"alpha"}}'
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -Headers @{ 'X-API-Key' = $key } -BodyFile "_pub_alpha.json" -OutFile "_p2.json"
"P2 => $code"; Show-ErrorBody "_p2.json"
```

预期：

```text
P1 => 404
404 Not Found: Graph not published
P2 => 400
400 Bad Request: App is not published
```

#### P3 ~ P6：发布 → 改草稿 → 再发布

```powershell
# P3：发布当前草稿
$published = Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/graph/publish" -Headers $TH
"P3 publishedAt = $($published.publishedAt)"   # 2026-...Z

# P4：公开运行（只传 inputs）
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -Headers @{ 'X-API-Key' = $key } -BodyFile "_pub_alpha.json" -OutFile "_p4.txt"
"P4 => $code"
(Get-RunOutputs "_p4.txt").answer              # echo: alpha

# P5：只改草稿，不发布
Invoke-RestMethod -Method Put "http://localhost:3001/apps/$appId/graph" -Headers $TH `
  -ContentType "application/json" -InFile "_g1_draft2.json" | Out-Null
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -Headers @{ 'X-API-Key' = $key } -BodyFile "_pub_alpha.json" -OutFile "_p5.txt"
"P5 => $code"
(Get-RunOutputs "_p5.txt").answer              # 仍是 echo: alpha

# P6：再发布，线上才切到新版本
Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/graph/publish" -Headers $TH | Out-Null
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -Headers @{ 'X-API-Key' = $key } -BodyFile "_pub_alpha.json" -OutFile "_p6.txt"
"P6 => $code"
(Get-RunOutputs "_p6.txt").answer              # echo: 草稿：alpha
```

预期：

```text
P4 => 200
echo: alpha
P5 => 200
echo: alpha
P6 => 200
echo: 草稿：alpha
```

P5 是本阶段的核心断言：**发布是复制，不是引用**。如果实现把 `publishedGraphJson` 写成 `graphJson` 的引用（或运行前重新读草稿），P5 会直接变成 `echo: 草稿：alpha`。

#### P7 / P8：草稿与快照互不影响

```powershell
# P7：发布不改草稿
$draft = Invoke-RestMethod -Method Get "http://localhost:3001/apps/$appId/graph" -Headers $TH
$draft.nodes[1].data.prompt                    # 草稿：{{ inputs.topic }}

# P8：快照只有一份，发布是覆盖
$again = Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/graph/publish" -Headers $TH
($again.publishedAt -ne $published.publishedAt)  # True：时间被刷新
```

### 4.2 API Key 生命周期

| # | 操作 | 期望 |
| --- | --- | --- |
| K1 | `POST /apps/{id}/api-keys`（TS） | `201`；`key` 长 35、以 `sk-` 开头；`prefix` 长 11 且等于 `key` 前 11 位 |
| K2 | `GET /apps/{id}/api-keys` | `200`；`items` 里**没有** `key` / `keyHash` 字段；`revokedAt=null` |
| K3 | 再建同名（未撤销） | `400 API key name already exists` |
| K4 | 建 61 个字符的名称 | `400 API key name is too long` |
| K5 | 建空名 `""` | `400 name must be at least 1 characters` |
| K6 | 建名缺失 `{}` | `400 name is required`（两端一致） |
| K7 | `DELETE /api-keys/{id}` | `204`，无响应体 |
| K8 | 撤销后列表 | 该行仍在，`revokedAt` 非空 |
| K9 | 撤销后再用该 key 调用 | `401 Invalid API key` |
| K10 | 撤销后用同名重建 | `201`（重名只算未撤销的） |
| K11 | 用**另一个用户**的 token 列 key | `404 App not found`（不泄露存在性） |
| K12 | 撤销不存在的 id | `404 API key not found` |

```powershell
# K1：创建（用独立的名称，避免和 P2 的 accept10 重名）
$lifecycle = Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/api-keys" -Headers $TH `
  -ContentType "application/json" -Body (@{ name = "lifecycle" } | ConvertTo-Json)
$lifecycleKey = $lifecycle.key
$lifecycleKey.Length                          # 35
$lifecycleKey.Substring(0, 3)                 # sk-
$lifecycle.prefix.Length                      # 11
$lifecycle.prefix -eq $lifecycleKey.Substring(0, 11)   # True

# K2：列表（按 createdAt 倒序，items[0] 是最新创建的一把）
$list = Invoke-RestMethod -Method Get "http://localhost:3001/apps/$appId/api-keys" -Headers $TH
$list.items[0].PSObject.Properties.Name -join ','   # 没有 key / keyHash

# K3 / K4 / K5 / K6：四类非法名称
foreach ($name in @("lifecycle", ("x" * 61), "")) {
  Write-Json "_key_body.json" (@{ name = $name } | ConvertTo-Json)
  $code = Send-Api -Url "http://localhost:3001/apps/$appId/api-keys" -Headers $TH `
    -BodyFile "_key_body.json" -OutFile "_key_err.json"
  "$code => $(Show-ErrorBody '_key_err.json')"
}
Write-Json "_key_body.json" '{}'
$code = Send-Api -Url "http://localhost:3001/apps/$appId/api-keys" -Headers $TH `
  -BodyFile "_key_body.json" -OutFile "_key_err.json"
"$code => $(Show-ErrorBody '_key_err.json')"
```

预期：

```text
400 => 400 Bad Request: API key name already exists
400 => 400 Bad Request: API key name is too long
400 => 400 Bad Request: name must be at least 1 characters
400 => 400 Bad Request: name is required
```

```powershell
# K7 / K8：撤销后列表仍保留该行
$code = Send-Api -Method DELETE -Url "http://localhost:3001/api-keys/$($lifecycle.id)" -Headers $TH -OutFile "_revoke.json"
"K7 => $code"                                  # 204
(Invoke-RestMethod -Method Get "http://localhost:3001/apps/$appId/api-keys" -Headers $TH).items |
  Where-Object { $_.id -eq $lifecycle.id } |
  Select-Object name, prefix, revokedAt        # revokedAt 非空

# K9：撤销后立即失效
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -Headers @{ 'X-API-Key' = $lifecycleKey } -BodyFile "_pub_alpha.json" -OutFile "_k9.json"
"K9 => $code"; Show-ErrorBody "_k9.json"       # 401 Invalid API key

# K10：同名重建（撤销的不算冲突）
$rebuild = Invoke-RestMethod -Method Post "http://localhost:3001/apps/$appId/api-keys" -Headers $TH `
  -ContentType "application/json" -Body (@{ name = "lifecycle" } | ConvertTo-Json)
$rebuild.id -ne $lifecycle.id                  # True：新的一行
```

K11 需要一个「另一个用户」：

### 4.3 对外调用协议

| # | 请求 | 期望 |
| --- | --- | --- |
| U1 | 不带任何 key 头 | `401 Missing API key`，JSON |
| U2 | `X-API-Key: "   "`（纯空白） | `401 Missing API key` |
| U3 | `Authorization: Bearer <key>` | `200 text/event-stream`（两种传法等价） |
| U4 | 错误 key | `401 Invalid API key` |
| U5 | app2 的 key 调 app1（app1 存在） | `401 Invalid API key` |
| U6 | 任意 key 调一个不存在的 appId | `404 App not found` |
| U7 | body 带 `conversationId` | `400 conversationId should not exist` |
| U8 | 缺 `inputs` | `400 inputs is required` |
| U9 | 公开运行 `useHistory` 的已发布图 | `400 llm node l1 useHistory requires a conversation`，JSON |
| U10 | 公开运行必失败图（G3） | **`200`** SSE，终态 `run_failed`，`llm request unauthorized` |
| U11 | U1~U10 的响应头 | 4xx 是 `application/json`；只有 U10 是 `text/event-stream` |

```powershell
# U1：完全没有 key
$code = Send-Api -Url "http://localhost:3001/public/apps/$appId/run" `
  -BodyFile "_pub_alpha.json" -OutFile "_u1.json"
```

### 5.2 公开 SSE 事件级 diff

比较**事件名序列**与**每帧 payload 的键集合**，忽略具体值。

```powershell
# 只比形状：连续 token 折叠成一个（帧数由 provider 分片与调度决定，不属于契约）。
function Get-EventShape($file) {
  $lines = Get-Content $file
  $shape = @()
  for ($i = 0; $i -lt $lines.Count; $i++) {
    if ($lines[$i] -notlike 'event: *') { continue }
    $name = $lines[$i].Substring(7)
    $keys = ''
    if ($i + 1 -lt $lines.Count -and $lines[$i + 1] -like 'data: *') {
      $obj = $lines[$i + 1].Substring(6) | ConvertFrom-Json
      $keys = (($obj.PSObject.Properties.Name | Sort-Object) -join ',')
    }
    if ($name -eq 'token') {
      if ($shape.Count -gt 0 -and $shape[-1] -eq 'token|nodeId,text') { continue }
      $shape += 'token|nodeId,text'
      continue
    }
    $shape += "$name|$keys"
  }
  return $shape
}
```

### 5.3 错误体逐字节对比

两端已经共用同一套 `ErrorResponse` 归一化（TS 的 `HttpErrorFilter`、Python 的 `errors.py`），所以同一条错误应该**逐字节相同**。

## 10. 面试考点汇总

| 问题 | 一句话答案 |
| --- | --- |
| 怎么证明发布是复制而不是引用？ | 发布后只改草稿不发布，公开调用仍返回旧文本；再发布才变 |
| 为什么验收要先测「未发布」？ | 未发布是唯一能证明「公开接口不读草稿」的前置状态 |
| 为什么 P5/P6 必须成对？ | 只测 P5 可能实现永远读旧图；只测 P6 可能实现直接读草稿 |
| 明文不落库怎么查？ | 拿明文当 `key_hash` 查，必然 0 行；再独立算一次 SHA-256 与库中值比对 |
| SHA-256 vs bcrypt 在验收上差在哪？ | 无盐高熵 key 可直接走唯一索引；bcrypt 每次盐不同，无法按哈希查询 |
| 为什么撤销后同名可重建？ | 重名检查只算 `revoked_at is null`，便于轮换 |
| 为什么跨应用 key 是 401 而不是 403？ | 对外只暴露「这把 key 无效」，不确认调用者对内资源的权限模型 |
| 为什么「应用不存在」要单独测？ | 先认证后查应用：app 不存在给 404，存在但不匹配给 401 |
| 4xx 为什么必须是 JSON？ | 响应头在预检阶段写出；SSE 一旦开流就只能用 `run_failed` 表达失败 |
| 流内失败为什么 HTTP 还是 200？ | 状态行在开流时已发送，之后只能用事件表达终态 |
| 事件 diff 为什么折叠 token？ | 帧数由 provider 分片与调度决定，契约只保证事件名与 payload 形状 |
| `run_started` 为什么没有 `conversationId`？ | 对外不支持会话，字段是**省略**而不是 `null` |
| 为什么要验 `Authorization: Bearer` 传法？ | 契约声明两种传法等价，`X-API-Key` 优先；空白值都算「未提供」 |
| 已知差异 `{"name": null}` 为什么接受？ | Python 的可选字段无法区分缺失与 null；状态码一致，文案差异已知 |
| 阶段 10 的回归重点？ | 草稿运行、会话运行、工具/RAG/分支，以及「发布不改草稿」 |

## 11. 阶段收尾

阶段 10 交付的完整链路：

```text
契约（0.10.0）
  └── 4 个接口 + ApiKeyResponse / CreateApiKeyResponse / PublicRunRequest + apiKeyAuth
        │
Prisma 迁移（DDL 唯一所有者）
  └── api_keys（key_hash 唯一、key_prefix、owner_id、软删除 revoked_at）
        │
api-ts
  └── ApiKeysModule（随机生成 / SHA-256 / 重名 / 撤销）
      PublicController（五步校验 + 只读 runPublished）
        │
api-py
  └── 同一 service 语义 + 同一五步顺序 + 同一 ErrorResponse
        │
web
  └── Zod 校验 + 发布面板 + 一次性明文 + curl 示例
```

阶段 10 刻意留下的边界（写进 README 而不是待办）：

- **对外不支持会话**：`PublicRunRequest` 只有 `inputs`；`useHistory` 的图发布后公开调用是 400；
- **只保留一份快照**：没有版本历史与回滚，再发布即覆盖；
- **撤销不物理删除**：列表继续展示历史，便于审计；
- **无限流**：按 key / 应用维度的限流留给生产化阶段。

## 3. 对比脚本

把“跑一次 + 提取可比字段”固化成脚本，避免每次都手工看输出。

**完整文件路径：`scripts/p6-compare.ps1`**（仓库脚本，可复用）

```powershell
# 阶段 6 验收：对同一个应用、同一份输入，分别请求两套后端，
# 提取「事件名 + 关键字段」，忽略随机值后逐行对比。
param(
  [Parameter(Mandatory = $true)][string]$AppId,
  [Parameter(Mandatory = $true)][string]$InputsJson,   # 如 '{"expr":"2+3*4"}'
  [string]$TsBase = 'http://localhost:3001',
  [string]$PyBase = 'http://localhost:8000'
)

function Get-Token([string]$Base) {
  $body = '{"email":"alice@example.com","password":"password123"}'
  $resp = curl.exe -s -X POST "$Base/auth/login" -H "Content-Type: application/json" -d $body | ConvertFrom-Json
  return $resp.accessToken
}

# 只保留「可比」字段：事件类型、节点、工具名、参数、结果、轮次、文本
function Get-ComparableFrames([string]$Base, [string]$Token) {
  $raw = curl.exe -s -N -X POST "$Base/apps/$AppId/run" `
    -H "Authorization: Bearer $Token" -H "Content-Type: application/json" -d $InputsJson
  $lines = $raw -split "`n"
  $event = ''
  $frames = @()
  foreach ($line in $lines) {
    $trimmed = $line.Trim()
    if ($trimmed.StartsWith('event:')) {
      $event = $trimmed.Substring(6).Trim()
      continue
    }
    if (-not $trimmed.StartsWith('data:')) { continue }
    $jsonText = $trimmed.Substring(5).Trim()
    if ($event -eq 'run_started') { continue }          # 只含 runId/时间
    if ($jsonText -eq '') { continue }
    $obj = $jsonText | ConvertFrom-Json
    switch ($event) {
      'tool_call'   { $frames += "tool_call|$($obj.nodeId)|$($obj.toolName)|$($obj.args | ConvertTo-Json -Compress)|$($obj.round)" }
      'tool_result' { $frames += "tool_result|$($obj.nodeId)|$($obj.toolName)|$($obj.result)|$($obj.round)" }  # 忽略 elapsedMs
      'token'       { $frames += "token|$($obj.nodeId)|$($obj.text)" }
      'node_started'   { $frames += "node_started|$($obj.nodeId)|$($obj.nodeType)" }
      'node_finished'  { $frames += "node_finished|$($obj.nodeId)|$((($obj.output | ConvertTo-Json -Compress) -replace '\s+',''))" }
      'run_finished'   { $frames += "run_finished|$((($obj.outputs | ConvertTo-Json -Compress) -replace '\s+',''))" }
      'run_failed'     { $frames += "run_failed|$($obj.nodeId)|$($obj.message)" }
      default          { $frames += "$event" }
    }
  }
  return $frames
}

$tsToken = Get-Token $TsBase
$pyToken = Get-Token $PyBase
$tsFrames = Get-ComparableFrames $TsBase $tsToken
$pyFrames = Get-ComparableFrames $PyBase $pyToken

Write-Host "==== api-ts ====" -ForegroundColor Cyan
$tsFrames | ForEach-Object { Write-Host $_ }
Write-Host "==== api-py ====" -ForegroundColor Cyan
$pyFrames | ForEach-Object { Write-Host $_ }

$diff = Compare-Object $tsFrames $pyFrames
if ($null -eq $diff) {
  Write-Host "`nPASS: 两端事件序列完全一致" -ForegroundColor Green
  exit 0
}
Write-Host "`nFAIL: 两端存在差异" -ForegroundColor Red
$diff | Format-Table -AutoSize
exit 1
```

用法：

```powershell
pwsh scripts/p6-compare.ps1 -AppId '<APP_ID>' -InputsJson '{"expr":"2+3*4"}'
```

> **面试考点 · 为什么对比要忽略 `elapsedMs`？**
> 因为它衡量的是“这台机器这一次执行了多久”，本身就不可比：
>
> - 两端在不同进程、不同 GC/事件循环状态下运行；
> - 同一个后端连续跑两次，数值也不同。
>
> 如果把它纳入对比，测试会随机失败（flaky），然后大家开始“重跑一次就好了”——**测试一旦不可信，就没人看它了。**
> 正确做法：把字段分成“协议字段（必须一致）”和“观测字段（允许不同）”，在契约里就标注清楚。

> **面试考点 · 为什么脚本要进仓库，而不是放在本地笔记里？**
> - 换机器/换人，验收流程不丢；
> - 脚本就是**可执行的验收文档**，比“我记得要点三下”可靠；
> - 后续阶段可以扩写成 CI 的一步。
>
> 代价是要维护脚本，但相比“每次验收靠记忆”，成本低得多。

### T11 协议 / 体积 / 超时

```text
[[call:http_get:{"url":"file:///etc/passwd"}]]        → tool http_get failed: not allowed
[[call:http_get:{"url":"http://"}]]                    → invalid arguments
[[call:http_get:{"url":"http://127.0.0.1:9/"}]]        → error
```

体积超限用一个本地大文件：

```powershell
# 生成 100KB 文件并用静态服务器暴露
$file = Join-Path $env:TEMP 'p6-big.txt'
'x' * 102400 | Set-Content $file -NoNewline
uv run python -m http.server 18080 --directory $env:TEMP
# 另开终端
```

```text
[[call:http_get:{"url":"http://127.0.0.1:18080/p6-big.txt"}]]   → too large
```

> `http_get` 的超时是**工具内部固定的 5s**（不是 `LLM_TIMEOUT_MS`）。要验证 `timeout`，用 mock 的延迟端点无法覆盖（mock 只有 POST），需要一个会挂起的 HTTP 服务；本项目的自动化测试用单元测试覆盖，手工验收可以先跳过。

## 6. 回归（阶段 1~5）

工具改动碰了引擎，必须回归前几个阶段的核心路径。

| 阶段 | 回归项 | 期望 |
| --- | --- | --- |
| 1 | 注册 / 登录 / `/auth/me` | 201 / 200 / 200 |
| 2 | 应用 CRUD、越权 404 | 与阶段 2 一致 |
| 3 | 画布保存 / 读取 / 发布 | 图结构不变 |
| 4 | 无工具的 start→llm→end | 事件序列与阶段 4 相同 |
| 5 | LLM 错误映射（401/429/500/超时） | 文案不变 |

```powershell
# 最小回归（无工具路径）
pwsh scripts/p6-compare.ps1 -AppId '<APP_ID>' -InputsJson '{"expr":"hello"}'
```

T2 用例本身就是最重要的回归：**未启用工具时，行为必须与阶段 5 完全一致。**

> **面试考点 · 为什么“没启用工具”的路径这么重要？**
> 因为它占绝大多数流量。ReAct 改造最容易出的问题不是“工具调用错了”，而是**不影响任何已有功能**这条底线被破坏：
>
> - 条件边误加，导致普通 llm 节点也走 `__tools`；
> - 预检把 `tools: undefined` 当成非法；
> - 事件从“每轮一次”变成“整段一次”。
>
> 新功能的验收看“新路径对不对”，**回归看“老路径有没有被弄坏”**。两者缺一不可。

## 7. 常见故障

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 运行无 `tool_call`，直接回显 | `data.tools` 为空 / 未保存 | 查 `graph_json` 的 `data->'tools'` |
| 400 `references unknown tool` | 工具名拼错 / 后端未重启 | 对比 `/tools` 返回的名字 |
| `tool_call` 后立即 `run_failed` | 模型给的参数非法 | 看 `args` 是否 `{}` |
| 两端 `token` 分片不同 | 用了真实 provider | 用 mock 验收，真实 provider 只比最终文本 |
| `tool_result` 后没有下一轮 | 轮次上限 / 条件边写错 | 查 `MAX_TOOL_ROUNDS`、日志里有无 `__tools` 节点 |
| `Recursion limit ... reached` | `recursionLimit` 未抬高 | 检查阶段 6 `02` 篇的公式 |
| Python 侧 `Field required: type` | `AIMessage.tool_calls` 缺 `type` | 见阶段 6 `03` 篇 7.1 |
| 前端工具清单为空 | `/tools` 401/500 | Network 面板看状态码 |

## 9. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 为什么矩阵化验收 | 场景可枚举、结果可复现；避免“点一遍就算过” |
| 固定测试图 | 控制变量，区分代码回归与配置变化 |
| 忽略 `elapsedMs` | 观测值不可比；纳入会导致 flaky |
| 时间类工具 | 结果天然不同，只比结构不比值 |
| 对比脚本进仓库 | 可执行的文档，可演进为 CI |
| 为什么要回归 | 新路径正确 ≠ 老路径没坏 |
| 无工具路径 | 占绝大多数流量，是最重要的回归项 |
| mock + 真实 provider | mock 验协议，真实验兼容 |
| 脚本断言粒度 | 协议字段严格、观测字段宽松、随机值排除 |

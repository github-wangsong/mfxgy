# 04 · 前端工具选择面板（工具调用）

> 阶段 6 · 第 4 步
>
> 做完：进入画布时拉取 `GET /tools`；选中 `llm` 节点后可以勾选/取消工具，选择结果写入 `node.data.tools`；全部取消时**删除该键**；工具名与描述完全来自后端，前端不硬编码。
>
> **本篇面试考点**：工具清单为什么静默降级 · 为什么不能在 `useEffect` 里 `await` 后直接 `setTools` · `data.tools` 的脏数据容错 · 为什么“全不选”要删键而不是存 `[]` · 勾选顺序是否需要保留 · 工具描述为什么来自后端 · 前端要不要校验工具名 · token 过期时面板为空却不跳转的取舍。

---

## 1. 数据流

```text
进入画布
  → GET /tools（Bearer）→ tools: ToolDefinition[]
  → 选中 llm 节点
  → selectedTools = parseArrayOrEmpty(node.data.tools)
  → 勾选 → toggleLlmTool → setNodes（本地）
  → 保存草稿 → data.tools 进入 graph_json
  → 运行 → 预检（未知工具 400）→ bindTools → ReAct
```

工具**定义**（名字、描述、参数）只有一个真源：后端注册表。前端只负责“展示 + 写入选择”，不参与定义。

> **面试考点 · 为什么工具描述不写在前端？**
> 如果前端硬编码一份工具列表：
>
> - 后端新增工具，前端要发版才能看到；
> - 后端改了描述（比如说明限制），前端显示过期信息；
> - 两套后端的工具集合如果有差异，前端无法同时正确显示。
>
> 前端只存**选择**（`data.tools: string[]`），定义永远从 `GET /tools` 拿。**能由服务端决定的，不要在前端复制一份。**

## 2. Schema

**完整文件路径：`apps/web/lib/schemas.ts`**（工具节选）

```ts
/** 内置工具定义（`GET /tools`）。`parameters` 是 JSON Schema，前端只展示不解释。 */
export const toolDefinitionSchema = z.strictObject({
  name: z.string().min(1),
  description: z.string(),
  parameters: jsonObjectSchema,
})

/** GET /tools 的响应体。 */
export const toolListResponseSchema = z.strictObject({
  items: z.array(toolDefinitionSchema),
})

/** 工具定义（由 schema 推导，与契约 `ToolDefinition` 对齐）。 */
export type ToolDefinition = z.infer<typeof toolDefinitionSchema>
```

`parameters` 用 `jsonObjectSchema`（`z.record(z.string(), z.unknown())`）而不是具体结构：

- 前端不用它渲染表单（工具参数由**模型**生成，不是用户填写）；
- 但如果将来要做“调试面板”，也可以按 JSON Schema 渲染；
- 用 `strictObject` 保证后端多加字段时前端**立刻发现**（契约演进需要同步）。

> **面试考点 · 既然前端不用 `parameters`，为什么还要校验它？**
> 因为它是响应体的一部分，而我们的约定是**所有响应都过 Zod**。
> 少校验一个字段的代价是：后端把 `parameters` 从对象改成字符串（或拼错成 `parameter`），前端毫无察觉，直到某天做调试面板时才发现“字段一直不对”。
> **校验的成本是一次 `safeParse`，收益是契约漂移被立刻发现。**

## 3. 拉取清单

**完整文件路径：`apps/web/app/apps/[id]/page.tsx`**

```tsx
  // 工具清单（GET /tools）；拉取失败时静默降级为空列表，不阻塞画布。
  const [tools, setTools] = useState<ToolDefinition[]>([])
```

```tsx
  // 进入画布时拉取工具清单（需 Bearer）；失败静默降级，不阻塞画布编辑。
  useEffect(() => {
    const token = localStorage.getItem('accessToken')
    if (token === null) return
    let cancelled = false
    fetch(`${API_BASE}/tools`, { headers: { Authorization: `Bearer ${token}` } })
      .then((res) => {
        if (!res.ok) return null
        return parseResponse(res, toolListResponseSchema, 'GET /tools')
      })
      .then((body) => {
        if (cancelled || body === null) return
        setTools(body.items)
      })
      .catch(() => {
        // 静默降级：工具清单不可用时只是不显示勾选项。
      })
    return () => {
      cancelled = true
    }
  }, [])
```

三个细节：

1. **`cancelled` 标记**：组件卸载（或 StrictMode 双挂载）后不再 `setState`；
2. **`.catch` 吞掉错误**：工具清单是“增强能力”，拿不到不该让整个画布不可用；
3. **`res.ok` 为假时返回 `null`**，而不是抛错——同样是静默降级的一部分。

> **面试考点 · 为什么这里静默降级，而应用列表页的 401 要跳登录？**
> 两个接口的**必要性不同**：
>
> | 接口 | 失败后果 | 策略 |
> | --- | --- | --- |
> | `GET /apps`（列表页） | 页面没有内容，无法工作 | 401 → 跳登录 |
> | `GET /tools`（画布内） | 少了勾选项，仍可编辑/保存/运行 | 静默降级 |
>
> 更细的取舍：token 过期时用户在画布里编辑了半天，如果因为“工具清单 401”被强制跳登录，编辑内容会丢。
> 所以这里连 401 都不跳转，只是不显示工具——**降级的粒度应该匹配“这个功能有多重要”。**

> **面试考点 · 这里为什么不用 `async/await`？**
> `useEffect` 的回调不能是 `async`（返回 Promise 会让 React 误以为是清理函数）。两种写法：
>
> ```tsx
> // A：then 链（本项目）
> fetch(...).then(...).then(...).catch(...)
>
> // B：内部 async IIFE
> void (async () => { ... })()
> ```
>
> A 的好处是**每一段的错误都能被 `.catch` 收住**；B 里如果 `await` 后的代码抛错，需要自己 `try/catch`。
> 两种都可以，关键是**不要在 `useEffect` 里留下未处理的 Promise 拒绝**。

## 4. 派生当前选择

```tsx
  /** 当前 llm 节点已启用的工具名（`data.tools` 缺失或非数组时视为未启用）。 */
  const selectedTools = useMemo<string[]>(() => {
    const raw = selectedNode?.data.tools
    return parseArrayOrEmpty(raw, z.string())
  }, [selectedNode])
```

`node.data` 的类型是 `Record<string, unknown>`（画布节点的自由结构），所以 `tools` 可能是：

- 不存在（阶段 5 保存的节点）；
- `string[]`（正常）；
- 脏数据（手工改过 JSON、旧版本 bug 留下的 `null` / 数字）。

`parseArrayOrEmpty(raw, z.string())` 的策略是：**能解析就用，不能就当成空数组**。

> **面试考点 · 为什么不在读的时候直接 `throw`，而是容错？**
> 这是**读路径**。画布是编辑器，读到一个坏字段就白屏，用户会丢失整张图。
> 正确策略是：
>
> - **读**：宽容（坏值 → 默认值），保证能打开；
> - **写**：严格（只写合法值），保证不产生新的坏数据；
> - **运行**：严格（预检报错），保证不会带着坏配置跑。
>
> 三个阶段用不同严格度，是编辑器类产品的通用原则——**不能因为一个字段坏了，就让用户打不开自己的作品。**

## 5. 勾选与取消

```tsx
  /**
   * 勾选 / 取消勾选 llm 节点的工具：写入 `data.tools` 数组；
   * 全部取消时**删除该键**（空数组等于启用但无工具，语义不同）。
   */
  function toggleLlmTool(id: string, toolName: string): void {
    setNodes((nds) =>
      nds.map((node) => {
        if (node.id !== id) return node
        const current = parseArrayOrEmpty(node.data.tools, z.string())
        const next = current.includes(toolName)
          ? current.filter((name) => name !== toolName)
          : [...current, toolName]
        const nextData = { ...node.data }
        if (next.length === 0) {
          delete nextData.tools
        } else {
          nextData.tools = next
        }
        return { ...node, data: nextData }
      }),
    )
  }
```

### 5.1 为什么全不选要删键

后端判断“是否启用工具”的依据：

```ts
// engine.service.ts
const toolNames = toolNamesOf(node)   // 读 data.tools
const toolEnabled = toolNames.length > 0
```

`[]` 与 `undefined` 在后端**结果一样**（都不启用），那为什么还要删？

1. **图 JSON 干净**：没启用的节点不该带一个空数组字段；
2. **语义准确**：`[]` 表示“我明确选择了零个工具”，`undefined` 表示“我没配置工具”——当前业务下前者没有意义；
3. **与阶段 5 的约定一致**：可选字段留空 = 删键（见 `05-LLM节点/04-节点参数面板.md`）；
4. **对比稳定**：图保存前后形状一致，方便 diff。

> **面试考点 · 那如果是“过滤器”这类字段，`[]` 和“不设置”语义不同吗？**
> 是的，而且经常相反：
>
> - 过滤器 `tags: []` 常表示“不筛任何标签（返回空）”；
> - `tags` 未设置常表示“不启用筛选（返回全部）”。
>
> 所以**不能机械地规定“空数组一律删键”**，而是要看业务语义：
> 这个字段的“默认行为”是“没有”还是“全部”？**先定义语义，再决定空值怎么写。**

### 5.2 顺序保留

`[...current, toolName]` 保留勾选顺序，取消时用 `filter` 保持其余元素顺序。

顺序要不要保留？

- **对后端无影响**：`bindTools` 接受数组，顺序只影响模型看到的工具顺序，不影响正确性；
- **对日志/对比有影响**：两端读同一张图，工具顺序相同，模型的行为更容易复现；
- **对用户可预期**：勾选顺序稳定，保存前后一致。

> **面试考点 · 用 `Set` 不是更合适吗？**
> 运行时用 `Set` 查重是 O(1)，但：
>
> - `data` 要序列化成 JSON，`Set` 不能直接序列化；
> - 工具数量是个位数，`includes` 的成本可忽略；
> - 数组能保留顺序。
>
> **数据结构跟着“要存什么”走，而不是跟着“理论上更快的查询”走。**

## 6. 面板 JSX

```tsx
<div className="stack stack--sm">
  <div className="label">工具</div>
  <div className="faint">勾选后由后端 ReAct 循环执行工具调用（可多轮）；全不选则不启用。</div>
  {tools.length === 0 && <div className="faint">（工具清单不可用）</div>}
  {tools.map((tool) => (
    <label key={tool.name} className="checkbox-row">
      <input
        type="checkbox"
        checked={selectedTools.includes(tool.name)}
        onChange={() => toggleLlmTool(selectedNode.id, tool.name)}
      />
      <div>
        <code>{tool.name}</code>
        <div className="faint">{tool.description}</div>
      </div>
    </label>
  ))}
</div>
```

- `key={tool.name}`：工具名唯一且稳定（不要用数组下标，工具顺序变化时会导致勾选状态错位）；
- `checked={selectedTools.includes(tool.name)}`：受控复选框，状态来自 `node.data`，而不是组件内部 state；
- `onChange` 只调用 `toggleLlmTool`，不在这里做任何校验。

> **面试考点 · 为什么不用组件内部 `useState` 存勾选状态？**
> 因为勾选状态**属于节点数据**，不是面板的临时 UI 状态：
>
> - 切换选中节点时，面板要显示**那个节点**的选择；
> - 保存时要从 `node.data` 读；
> - 撤销/重做（将来）要基于节点数据恢复。
>
> 如果存在面板 state 里，切换节点就得手动同步，且容易与 `nodes` 不一致。**能派生自源数据的，就不要另存一份。**

## 7. 选择如何生效

```text
勾选 → node.data.tools = ["calculator"]
     → 保存草稿 → graph_json.nodes[].data.tools
     → 运行 → 预检：calculator 已注册 ✅
     → 该 llm 节点走「条件边 + 环」
     → bindTools([calculator]) → 模型可发起调用
```

对照阶段 6 `02` 篇的图构建：

```ts
const toolNodes = graph.nodes.filter((node) => node.type === 'llm' && toolNamesOf(node).length > 0)
```

**只要 `data.tools` 非空，这个节点就从“普通节点”变成“ReAct 节点”。** 前端不需要额外开关。

> **面试考点 · 为什么把“启用工具”做成隐式的（有工具就启用），而不是加一个 `useTools: boolean`？**
> 两个字段会产生**非法组合**：
>
> ```text
> useTools: true,  tools: []      → 启用但没有工具，行为是什么？
> useTools: false, tools: ["x"]   → 配了工具但禁用，保存它有意义吗？
> ```
>
> 用“`tools` 非空即启用”只需维护一个真源，非法状态从结构上就不存在。
> **能用一个字段表达的，不要用两个字段 + 一致性约束。**

### 8.4 实际调用

勾选 `calculator`，prompt 写：

```text
请计算 {{ inputs.expr }}，标记：[[call:calculator:{"expression":"2+3*4"}]]
```

运行 → 预期流式面板出现：

```text
tool_call   calculator  {"expression":"2+3*4"}  round 1
```

取消勾选后再运行 → 预期**没有** `tool_call`，模型直接回显（mock 的 `echo: ...`）。

> 这一步是阶段 6 最关键的验收：**面板的勾选真的改变了执行路径。**

### 8.5 未知工具（手工构造）

在数据库里把 `tools` 改成 `["nope"]`：

```powershell
docker compose exec postgres psql -U minidify -d minidify -c `
  "update apps set graph_json = jsonb_set(graph_json, '{nodes,0,data,tools}', '[\"nope\"]') where id = '<APP_ID>';"
```

> 注意：真实场景不会这么改数据，这里只是验证“后端预检不信任前端”。`nodes,0` 假设第一个节点就是 `llm`，按你图里的实际下标调整。

运行 → 预期 `HTTP 400`（普通 JSON，不是 SSE）：

```json
{"statusCode":400,"message":"llm node llm1 references unknown tool: nope","error":"Bad Request"}
```

刷新画布 → 面板里 `nope` **不会**显示为勾选项（因为它不在 `tools` 清单里），但数据里仍在；保存一次后仍会保留。

> 这正是“前端不校验工具名”的直接后果：前端的职责是展示已知工具，**合法性由后端预检保证**。
> 如果希望前端也拦截，应该在保存前对照 `tools` 清单检查——但那只是体验优化，不是安全边界。

`.env.local` 切到 `8000` 并重启前端，重复 8.1~8.4。

## 9. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 工具清单静默降级 | 增强能力，失败不影响编辑；与列表页 401 跳转区分 |
| `useEffect` 里不用 `async` | 回调返回 Promise 会被当成清理函数；用 then 链或 IIFE |
| `cancelled` 标记 | 卸载/StrictMode 双挂载后不 setState |
| 脏数据容错 | 读宽容、写严格、运行严格 |
| 全不选删键 | 与“未配置”统一；避免空数组带来歧义 |
| 空数组语义 | 依业务而定：过滤器的 `[]` 与“未设置”可能相反 |
| 顺序保留 | 对模型可见顺序稳定，便于复现与 diff |
| `key={tool.name}` | 名字稳定唯一；下标会在顺序变化时错位 |
| 受控复选框 | 状态来自节点数据，不另存面板 state |
| 隐式启用 | `tools` 非空即启用，避免两个字段的非法组合 |
| 前端不校验工具名 | 展示已知工具即可；合法性由后端预检 |
| 描述来自后端 | 单一真源，避免前端信息过期 |

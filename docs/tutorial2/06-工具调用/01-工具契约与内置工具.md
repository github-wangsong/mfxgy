## 1. 工具清单与边界

阶段 6 只做三个**只读**工具：

| 工具 | 参数 | 返回 | 用途 |
| --- | --- | --- | --- |
| `calculator` | `{ expression: string }` | 数字字符串 | 让模型做精确算术 |
| `get_current_time` | 无 | ISO-8601 UTC 时间 | 让模型知道“现在” |
| `http_get` | `{ url: string }` | 响应体文本（≤64KB） | 读取公开网页/API |

设计约束：

1. **无副作用**：不写库、不发消息、不改文件——只读工具可以放心让模型自己决定调用；
2. **返回字符串**：`tool_result.result` 是字符串，模型的消息格式也只接受文本结果；
3. **参数用 JSON Schema 描述**：直接作为 OpenAI function calling 的 `parameters`，模型据此生成参数；
4. **工具名稳定**：一旦发布就不能改名（图里存的是字符串名字）；
5. **默认不启用**：`llm.data.tools` 为空表示不启用工具，模型行为与阶段 5 完全一致。

> **面试考点 · 为什么工具不做写操作？**
> 写工具的权限模型复杂一个数量级：
>
> - 谁授权？应用作者还是运行者？
> - 写失败了怎么回滚？
> - 模型被提示注入诱导写坏数据怎么办？
>
> 只读工具的最坏情况是“读到了不该读的数据”（仍需 SSRF/权限防护），但不会造成状态破坏。
> **工具系统应该从只读开始，写操作需要独立的授权、审计与幂等设计。** 这不是“以后再说”，而是“没有这些就别开放写”。

> **面试考点 · `parameters` 为什么用 `Record<string, unknown>`，而不是定义成强类型？**
> 因为它是**给模型看的 JSON Schema**，形状由 OpenAI 的 function calling 规范决定，而不是由我们的业务类型决定。
> 强类型化会带来两个问题：
>
> - 每个工具的参数结构不同，联合类型会迅速膨胀；
> - JSON Schema 的字段（`type` / `properties` / `required` / `additionalProperties`）是协议层，不是业务层。
>
> 契约里保留 `object`，把“具体形状”交给各工具的注册表项。**协议层用宽类型，业务层用窄类型**——边界要分清。

> **面试考点 · `GET /tools` 为什么要鉴权？**
> 工具列表本身不敏感，但它暴露了**系统能力边界**：
>
> - 攻击者可以据此判断有没有可被提示注入利用的工具；
> - 工具描述里可能包含内部信息（接口名、限制值）；
> - 与运行接口保持一致的鉴权，避免“未登录也能探测”。
>
> 另一个实际原因：前端工具面板需要带 token 请求，鉴权让前后端在开发期就对齐“所有业务接口都要 token”。

## 3. 工具错误类型

**完整文件路径：`apps/api-ts/src/tools/tool-error.ts`**

```ts
/**
 * 工具执行失败（见 error-messages.md §6.2）。
 *
 * `reason` 只能取契约规定的固定值；引擎据此拼出
 * `tool {name} failed: {reason}`，两端逐字节一致。
 */
export type ToolFailureReason =
  | 'invalid arguments'
  | 'timeout'
  | 'not allowed'
  | 'too large'
  | 'error'

export class ToolError extends Error {
  constructor(readonly reason: ToolFailureReason) {
    super(reason)
  }
}
```

为什么要专门定义一个错误类：

- 工具内部可能抛各种异常（`TypeError`、`AbortError`、HTTP 错误）；
- 引擎只认识**五种 reason**，其余一律归 `error`；
- 用类型把“可预期的失败”和“程序 bug”分开：`ToolError` 是可预期的，其它异常说明工具有 bug（但仍要归一成 `error`，不能让进程崩）。

> **面试考点 · 为什么 `reason` 是联合类型而不是任意字符串？**
> 它要出现在 `run_failed.message` 里，两端必须逐字节一致。
> 如果允许任意字符串，TS 侧可能写 `"Invalid Arguments"`、Python 侧写 `"invalid args"`，前端/契约测试就崩了。
> 联合类型让**非法值在编译期就报错**（Python 侧用 `Literal` 达到同样效果，见 `03` 篇）。
> **凡是会跨进程/跨语言传输的枚举，都要在类型层锁死。**

## 4. 注册表

**完整文件路径：`apps/api-ts/src/tools/registry.ts`**

```ts
import type { ToolDefinition } from '@mini-dify/contract'

import { runCalculator } from './calculator.tool'
import { runGetCurrentTime } from './current-time.tool'
import { runHttpGet } from './http-get.tool'

/**
 * 内置工具注册表（唯一真源，见 packages/contract/openapi.yaml 的 `ToolDefinition`）。
 *
 * `TOOL_DEFINITIONS[].parameters` 是 JSON Schema 形状，可直接作为 OpenAI
 * function calling 的 `parameters` 交给模型；`executeTool` 按名字分派执行。
 * 返回值一律为**字符串**（与 `tool_result.result` 的契约一致）。
 */
export const TOOL_DEFINITIONS: ToolDefinition[] = [
  {
    name: 'calculator',
    description: '安全地计算一个四则运算表达式，支持 + - * /、括号、小数与一元负号。',
    parameters: {
      type: 'object',
      properties: {
        expression: {
          type: 'string',
          description: '要计算的表达式，例如 "2+3*4"',
        },
      },
      required: ['expression'],
      additionalProperties: false,
    },
  },
  {
    name: 'get_current_time',
    description: '返回当前 UTC 时间（ISO-8601、毫秒精度、以 Z 结尾）。无参数。',
    parameters: {
      type: 'object',
      properties: {},
      additionalProperties: false,
    },
  },
  {
    name: 'http_get',
    description: '对给定 URL 发起 HTTP GET，返回响应体文本。仅允许 http/https。',
    parameters: {
      type: 'object',
      properties: {
        url: {
          type: 'string',
          description: '要请求的 http:// 或 https:// URL',
        },
      },
      required: ['url'],
      additionalProperties: false,
    },
  },
]

/** 工具名是否已注册。 */
export function hasTool(name: string): boolean {
  return TOOL_DEFINITIONS.some((definition) => definition.name === name)
}

/** 按名字取工具定义（未注册时返回 undefined）。 */
export function getToolDefinition(name: string): ToolDefinition | undefined {
  return TOOL_DEFINITIONS.find((definition) => definition.name === name)
}

/**
 * 执行一个工具，返回**字符串**结果。
 *
 * 未注册的工具名由引擎在预检阶段拦截；此处再抛普通 Error 作为兜底。
 * 工具内部失败一律抛 `ToolError`（带固定 `reason`），由引擎拼成规范文案。
 */
export async function executeTool(name: string, args: Record<string, unknown>): Promise<string> {
  switch (name) {
    case 'calculator':
      return runCalculator(args)
    case 'get_current_time':
      return runGetCurrentTime()
    case 'http_get':
      return runHttpGet(args)
    default:
      throw new Error(`unknown tool: ${name}`)
  }
}
```

要点：

1. **定义与执行放在一起**：`TOOL_DEFINITIONS` 给模型看，`executeTool` 给引擎用；新增工具必须两处都加，否则会出现“模型能调但执行报错”或“执行存在但模型不知道”；
2. `hasTool` 用于**预检**（未知工具必须 400，见 `02` 篇）；
3. `default` 分支抛普通 `Error` 而不是 `ToolError`——这属于**调用方传了未注册的名字**，是程序错误，不是工具执行失败。

> **面试考点 · 为什么注册表用 `switch`，而不是 `{ [name]: fn }` 映射？**
> 映射写法更简洁，但 `switch` 有两个好处：
>
> - 类型收窄：`name` 在每个 `case` 里是字面量，参数类型可以逐个精确；
> - 显式：新增工具时 `switch` 会漏（没有 `default` 就返回 `undefined`），逼迫你补全。
>
> 如果工具上百个，映射 + 显式注册表更合适。**三个工具用 switch，是“够用且清楚”。**

## 5. `calculator`：不用 `eval`

**完整文件路径：`apps/api-ts/src/tools/calculator.tool.ts`**

```ts
import { ToolError } from './tool-error'

/**
 * `calculator`：对 `{ expression: string }` 做**安全**四则运算求值。
 *
 * 不使用 `eval` / `Function`，而是手写一个最小递归下降解析器：
 * 支持 `+ - * /`、括号、小数与一元正负号。语法或数值非法（如 `2+`、除零）
 * 一律抛 `ToolError('invalid arguments')`。
 */
export function runCalculator(args: Record<string, unknown>): string {
  const expression = args.expression
  if (typeof expression !== 'string' || expression.trim() === '') {
    throw new ToolError('invalid arguments')
  }
  const value = new ExpressionParser(expression).parse()
  if (!Number.isFinite(value)) {
    throw new ToolError('invalid arguments')
  }
  return formatNumber(value)
}

/** 数值字符串化：消除浮点噪声（如 0.1+0.2 → "0.3"），并把 -0 归一为 "0"。 */
function formatNumber(value: number): string {
  if (value === 0) {
    return '0'
  }
  const normalized = Number(value.toPrecision(12))
  return String(normalized)
}

/** 最小表达式解析器（递归下降）：expression := term (('+'|'-') term)*。 */
class ExpressionParser {
  private position = 0

  constructor(private readonly input: string) {}

  parse(): number {
    const value = this.parseExpression()
    this.skipSpaces()
    if (this.position < this.input.length) {
      throw new ToolError('invalid arguments')
    }
    return value
  }

  private parseExpression(): number {
    let value = this.parseTerm()
    for (;;) {
      this.skipSpaces()
      const char = this.input[this.position]
      if (char === '+') {
        this.position += 1
        value += this.parseTerm()
      } else if (char === '-') {
        this.position += 1
        value -= this.parseTerm()
      } else {
        return value
      }
    }
  }

  private parseTerm(): number {
    let value = this.parseUnary()
    for (;;) {
      this.skipSpaces()
      const char = this.input[this.position]
      if (char === '*') {
        this.position += 1
        value *= this.parseUnary()
      } else if (char === '/') {
        this.position += 1
        const divisor = this.parseUnary()
        if (divisor === 0) {
          throw new ToolError('invalid arguments')
        }
        value /= divisor
      } else {
        return value
      }
    }
  }

  private parseUnary(): number {
    this.skipSpaces()
    const char = this.input[this.position]
    if (char === '+') {
      this.position += 1
      return this.parseUnary()
    }
    if (char === '-') {
      this.position += 1
      return -this.parseUnary()
    }
    return this.parsePrimary()
  }

  private parsePrimary(): number {
    this.skipSpaces()
    if (this.input[this.position] === '(') {
      this.position += 1
      const value = this.parseExpression()
      this.skipSpaces()
      if (this.input[this.position] !== ')') {
        throw new ToolError('invalid arguments')
      }
      this.position += 1
      return value
    }
    return this.parseNumber()
  }

  private parseNumber(): number {
    const start = this.position
    let seenDot = false
    while (this.position < this.input.length) {
      const char = this.input[this.position]
      if (char >= '0' && char <= '9') {
        this.position += 1
      } else if (char === '.' && !seenDot) {
        seenDot = true
        this.position += 1
      } else {
        break
      }
    }
    const text = this.input.slice(start, this.position)
    if (text === '' || text === '.') {
      throw new ToolError('invalid arguments')
    }
    const value = Number(text)
    if (!Number.isFinite(value)) {
      throw new ToolError('invalid arguments')
    }
    return value
  }

  private skipSpaces(): void {
    while (this.position < this.input.length && /\s/.test(this.input[this.position])) {
      this.position += 1
    }
  }
}
```

语法层级（递归下降的核心）：

```text
expression := term (('+'|'-') term)*
term       := unary (('*'|'/') unary)*
unary      := ('+'|'-') unary | primary
primary    := '(' expression ')' | number
```

优先级由**层级**保证：`parseExpression` 里调 `parseTerm`，所以 `*` `/` 天然比 `+` `-` 先算；括号通过 `parsePrimary` 递归回 `parseExpression`。

> **面试考点 · 为什么绝对不能用 `eval` / `new Function`？**
> 工具的参数来自**模型生成的文本**，而模型可能被提示注入控制。等价于把用户输入直接当代码执行：
>
> ```js
> // 模型返回 expression:
> "process.exit(1)"
> "require('child_process').exec('rm -rf /')"
> ```
>
> `eval` 在 Node 里能访问全局对象、`require`（取决于上下文）、文件系统。这是**远程代码执行漏洞**，不是“风格问题”。
> 即使换成 `mathjs` 这类库，也要确认它没有暴露 `import`/函数定义等能力，并限制表达式长度（防 ReDoS）。
> **任何“表达式求值”需求，第一反应必须是解析器或白名单，而不是 eval。**

> **面试考点 · 为什么除零要手动判断？**
> JS 的 `1 / 0` 是 `Infinity`，不抛错；`0 / 0` 是 `NaN`。
> 如果直接返回，模型会收到 `"Infinity"`，接下来可能把它当数字继续算，产生无意义结果。
> 这里显式抛 `invalid arguments`，让模型知道“这个表达式算不了”。
> 注意 `runCalculator` 末尾还有一层 `Number.isFinite` 兜底——**多层防御，因为浮点溢出（如 `1e308 * 10`）也走不到除零分支。**

> **面试考点 · `formatNumber` 为什么要 `toPrecision(12)`？**
> ```js
> 0.1 + 0.2           // 0.30000000000000004
> Number((0.1+0.2).toPrecision(12))   // 0.3
> ```
> IEEE 754 双精度无法精确表示 `0.1`，直接 `String` 会输出一长串噪声。`toPrecision(12)` 保留 12 位有效数字，再转回数字去掉尾随零。
> 12 位是经验值：足够覆盖常见业务计算，又不会把真正的精度差异抹掉。
> 这不是“修好浮点”，而是**在展示层做一次合理的舍入**——真要精确金额，应该用整数分或 `decimal.js`。

## 7. `http_get`：最危险的只读工具

**完整文件路径：`apps/api-ts/src/tools/http-get.tool.ts`**

```ts
import { ToolError } from './tool-error'

/** 响应体上限：64KB（见契约 §6.2 的 `too large`）。 */
const MAX_BODY_BYTES = 64 * 1024

/** 超时：5 秒（见契约 §6.2 的 `timeout`）。 */
const TIMEOUT_MS = 5000

/**
 * `http_get`：对 `{ url: string }` 发起 GET，返回响应体文本。
 *
 * 安全约束：
 * - 仅允许 `http:` / `https:` 协议，否则 `not allowed`；
 * - 5s 超时 → `timeout`；
 * - 响应体超过 64KB → `too large`（读取过程中即中止，不把大响应读进内存）；
 * - 其它异常 → `error`。
 */
export async function runHttpGet(args: Record<string, unknown>): Promise<string> {
  const url = args.url
  if (typeof url !== 'string' || url === '') {
    throw new ToolError('invalid arguments')
  }
  let target: URL
  try {
    target = new URL(url)
  } catch {
    throw new ToolError('invalid arguments')
  }
  if (target.protocol !== 'http:' && target.protocol !== 'https:') {
    throw new ToolError('not allowed')
  }

  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), TIMEOUT_MS)
  try {
    const response = await fetch(target, { signal: controller.signal })
    if (response.body === null) {
      return ''
    }
    const reader = response.body.getReader()
    const chunks: Uint8Array[] = []
    let total = 0
    for (;;) {
      const { done, value } = await reader.read()
      if (done) {
        break
      }
      total += value.byteLength
      if (total > MAX_BODY_BYTES) {
        await reader.cancel()
        throw new ToolError('too large')
      }
      chunks.push(value)
    }
    return new TextDecoder().decode(concatBytes(chunks, total))
  } catch (error) {
    if (error instanceof ToolError) {
      throw error
    }
    if (isAbortError(error)) {
      throw new ToolError('timeout')
    }
    throw new ToolError('error')
  } finally {
    clearTimeout(timer)
  }
}

function concatBytes(chunks: Uint8Array[], total: number): Uint8Array {
  const merged = new Uint8Array(total)
  let offset = 0
  for (const chunk of chunks) {
    merged.set(chunk, offset)
    offset += chunk.byteLength
  }
  return merged
}

function isAbortError(error: unknown): boolean {
  return typeof error === 'object' && error !== null && (error as { name?: unknown }).name === 'AbortError'
}
```

> **面试考点 · 只允许 `http/https` 就安全了吗？**
> **远远不够。** 这是 SSRF（Server-Side Request Forgery）的经典入口。当前实现能被诱导访问：
>
> - `http://169.254.169.254/`（云厂商元数据服务，可能拿到临时凭证）；
> - `http://127.0.0.1:3001/...`（内网服务）；
> - `http://10.0.0.5/admin`（内网管理后台）。
>
> 生产环境必须补充：
>
> 1. **IP 黑名单**：解析 DNS 后检查目标 IP 是否属于私有网段/回环/链路本地；
> 2. **重定向限制**：`fetch` 默认跟随重定向，可能从公网跳到内网；应禁用或逐跳校验；
> 3. **域名白名单**：最稳，但限制业务能力；
> 4. **出站代理**：所有请求走一个受控代理，由代理做策略。
>
> 本项目是教学实现，只做了协议校验——**要知道它不安全，而不是以为它安全。**

> **面试考点 · 为什么“边读边计数”而不是先 `Content-Length` 再读？**
> `Content-Length` 不可信：
>
> - 服务端可以不返回；
> - 可以撒谎（声明 1KB，实际发 1GB）；
> - chunked 编码没有长度。
>
> 正确做法是**读一块、加一次、超限立即 `reader.cancel()`**。这样内存占用有上界（略超 64KB），而不是把 1GB 读进来再判断。
> 注意 `cancel()` 是必须的：只抛错不取消，底层连接会继续下载。

> **面试考点 · 为什么 `AbortController` + `setTimeout` 就能实现超时？**
> `fetch` 原生支持 `signal`。`controller.abort()` 会让正在进行的请求和**正在读取的 body** 都抛出 `AbortError`。
> 只在 `fetch` 外面套 `Promise.race` 是不够的：请求会被“放弃等待”，但底层连接仍在传输、body 仍在内存里。
> `finally { clearTimeout(timer) }` 同样重要——请求提前完成时不清定时器，会导致进程在超时点做一次无意义的 abort。

```ts
import { Controller, Get, UseGuards } from '@nestjs/common'
import type { ToolListResponse } from '@mini-dify/contract'

/** 契约见 packages/contract/openapi.yaml 的 `/tools`。 */
@Controller('tools')
@UseGuards(JwtAuthGuard)

  @Get()
  list(): ToolListResponse {

  }

```

**完整文件路径：`apps/api-ts/src/tools/tools.module.ts`**

```ts
import { Module } from '@nestjs/common'

import { AuthModule } from '../auth/auth.module'
import { ToolsController } from './tools.controller'

/** 内置工具模块（阶段 6）：仅提供 `GET /tools`。`JwtAuthGuard` 由 `AuthModule` 导出。 */
@Module({
  imports: [AuthModule],
  controllers: [ToolsController],
})

```

`app.module.ts` 增加一行：

```ts
imports: [PrismaModule, AuthModule, AppsModule, GraphModule, EngineModule, ToolsModule],
```

> **面试考点 · 为什么 `ToolsModule` 不导出任何 provider？**
> `TOOL_DEFINITIONS` 是纯常量，`executeTool` 是纯函数，没有状态、没有依赖注入需求。
> 引擎需要执行工具时，直接 `import { executeTool } from '../tools/registry'` 即可——**不需要经过 Nest 的 DI**。
> 这不是“绕过框架”，而是**只在需要生命周期管理（数据库连接、配置、缓存）时才用 DI**。纯函数用模块导入更简单、更好测试。

## 10. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 不用 `eval` | 参数来自模型，等于执行不可信代码；用解析器 |
| 递归下降 | 层级决定优先级；括号递归回表达式层 |
| 除零 | JS 返回 Infinity/NaN，不抛错；必须显式判断 + `isFinite` 兜底 |
| 浮点展示 | `toPrecision(12)` 去噪声；精确金额用整数/decimal |
| JSON Schema 给模型 | function calling 的参数描述；业务层不强行强类型 |
| 工具结果字符串 | 契约与模型消息都只接受文本；结构用 JSON 字符串 |
| `ToolError.reason` | 固定五值，跨语言逐字节一致；编译期锁死 |
| `http_get` 风险 | SSRF、元数据服务、内网；需 IP 黑名单/重定向限制/白名单 |
| 边读边限流 | `Content-Length` 不可信；超限 `cancel()` |
| `AbortController` | fetch 层中断，连 body 读取一起停；`finally` 清定时器 |
| `/tools` 鉴权 | 暴露能力边界；与业务接口统一 |
| 注册表单一真源 | 定义与执行同处；`hasTool` 供预检 |

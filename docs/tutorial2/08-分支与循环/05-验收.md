# 05 · 验收（分支与循环）

> 阶段 8 · 收尾
>
> 验收目标：**同一张图、同一份输入，两端的 `branch_taken` 分支、聚合结果、迭代输出逐字节一致**；非法图在保存时被拒绝；超限在跑第一项之前就失败。
>
> **本篇面试考点**：分支验收为什么要“改数组顺序”用例 · 为什么事件级的 diff 比最终输出更早发现分叉 · 空数组算不算失败 · 为什么 `NaN` 用例只能做单元级验证 · 迭代超限为什么要求“零条 `iteration_item`” · 阶段 8 的回归重点是哪些旧图 · 验收脚本为何只提取“可比字段”。

---

## 1. 验收边界

| 本阶段验收 | 不在本阶段 |
| --- | --- |
| `condition` 分支选择与事件 | 多条件组合（AND/OR） |
| `aggregator` 取值顺序 | 并行分支（同时执行） |
| `iteration` 逐项渲染 | 嵌套迭代 |
| 图校验规则 8/9/10 | 分支内子图 |
| 跨语言数值序列化 | 对象键序完全对齐 |
| 前端多出口与面板 | 分支拖拽排序（UI 调整顺序） |

## 4. 用例矩阵

### 4.1 分支（G1）

| # | 输入 | 期望 |
| --- | --- | --- |
| B1 | `level=vip, amount=500` | `branch_taken` 恰好 1 次，`caseId="vip"`，`label="VIP 用户"` |
| B2 | `level=normal, amount=2000` | `caseId="high"`（先判 vip 失败，再判 high 成功） |
| B3 | `level=normal, amount=1500` | `caseId="high"` |
| B4 | `level=normal, amount=500` | `caseId="else"`，`label="else"` |
| B5 | `level=vip, amount=2000` | `caseId="vip"`（**第一个匹配**，不继续判 high） |
| B6 | 不传 `level`（`{}`） | `caseId="else"`（缺失变量按空串） |
| B7 | `amount="abc"` | `caseId="else"`（`Number("abc")` = NaN → 比较 false） |
| B8 | `amount=""` | 先判 vip 失败；`gt` 比较 `Number("")=0 > 1000` → false → `else` |
| B8' | 把 high 的 operator 换成 `lte`、value `"0"`，`amount` 缺失 | `caseId="high"`（`Number("") === 0`，已知坑，见 02 §3.2） |
| B9 | 把 `conditions` 顺序改成 `[high, vip]`，输入 `vip/2000` | `caseId="high"`（**顺序决定结果**） |
| B10 | 分支全不匹配且删掉 `else` 边后保存 | 400 `condition node c1 else branch has no outgoing edge` |
| B11 | 给 `vip` 连两条边 | 400 `condition node c1 has duplicate edge for case vip` |
| B12 | 某条边 `sourceHandle` 改成 `"nope"` | 400 `edge X from condition node c1 has invalid sourceHandle: nope` |

**B5 是核心用例**：它区分“第一个匹配”与“所有匹配”两种实现。

### 4.2 聚合（G2）

| # | 输入 | 期望 `g1.answer` |
| --- | --- | --- |
| A1 | `level=vip` | `echo: A`（`la` 执行，`lb` 不存在 → 空串跳过） |
| A2 | `level=normal` | `echo: B` |
| A3 | `level=vip`，并把 `values` 改成 `["{{ lb.text }}", "{{ la.text }}"]` | `echo: A`（第二个非空） |
| A4 | `values: ["{{ la.text }}"]`，`level=normal` | `""`（唯一候选不存在） |

A1/A2 验证“未执行分支不报错”——这是 `tryRenderTemplate` 的核心收益。

### 4.3 迭代（G3）

| # | `inputs.items` | 期望 |
| --- | --- | --- |
| I1 | `["退款","发票"]` | `results=["[1/2] 退款","[2/2] 发票"]`，`count=2`，`joined` 用 `\n` |
| I2 | `[1.0,2.5,3.0]` | `results=["[1/3] 1","[2/3] 2.5","[3/3] 3"]`（**跨语言关键**） |
| I3 | `[]` | `results=[]`、`count=0`、`joined=""`，**无** `iteration_item` |
| I4 | 4 项（超过 `maxIterations:3`） | `run_failed`，且**没有任何** `iteration_item` |
| I5 | `"not json"` | `run_failed iteration node i1 inputArray must be an array` |
| I6 | `{"a":1}` | 同上（非数组） |
| I7 | `[{"b":1,"2":2}]` | **不纳入对比**（键序未对齐，见 03 §3.5） |
| I8 | `["中文", "emoji 😀"]` | 中文与 emoji 原样（`ensure_ascii=False`） |

### 4.4 图校验（保存时）

| # | 图 | 期望文案（节选） |
| --- | --- | --- |
| V1 | `conditions: []` | `condition node c1 must have at least one condition` |
| V2 | case id 都是 `vip` | `... has duplicate case id: vip` |
| V3 | case id 是 `else` | `... case id "else" is reserved` |
| V4 | `operator: "between"` | `... has invalid operator: between` |
| V5 | `variable: ""` | `... case vip variable is required` |
| V6 | 某分支没有边 | `... case vip has no outgoing edge` |
| V7 | `aggregator.outputs: []` | `aggregator node g1 must have at least one output` |
| V8 | `values: []` | `aggregator node g1 output answer must have at least one value` |
| V9 | `inputArray: "   "` | `iteration node i1 inputArray is required` |
| V10 | `maxIterations: 0 / 101 / 1.5` | `iteration node i1 maxIterations must be between 1 and 100` |

V1~V10 必须**两端文案逐字节一致**（含标点与 `null` 的写法）。

## 5. 对比脚本

**完整文件路径：`scripts/p8-compare.ps1`**

```powershell
# 阶段 8 验收：分支 / 聚合 / 迭代的跨端对比
# 用法：pwsh scripts/p8-compare.ps1 -TsApp <id> -PyApp <id> -TsToken <t> -PyToken <t>
param(
  [Parameter(Mandatory = $true)] [string] $TsApp,
  [Parameter(Mandatory = $true)] [string] $PyApp,
  [Parameter(Mandatory = $true)] [string] $TsToken,
  [Parameter(Mandatory = $true)] [string] $PyToken
)

$ErrorActionPreference = "Stop"

function Invoke-Run([string] $base, [string] $app, [string] $token, [string] $inputsJson) {
  # `curl -N` 拿原始 SSE 文本；不解析 JSON，只按行提取
  $body = "{`"inputs`":$inputsJson}"
  $raw = curl.exe -s -N -X POST "$base/apps/$app/run" `
    -H "Authorization: Bearer $token" -H "Content-Type: application/json" -d $body
  return $raw
}

function Get-DataLines([string[]] $lines, [string] $needle) {
  # 只保留 `data: {...}` 中同时包含 needle 的行（SSE 的 event 行与 data 行成对出现）
  return @($lines | Where-Object { $_ -like "data: *" -and $_ -like "*$needle*" })
}

$cases = @(
  @{ name = "vip";          inputs = '{"level":"vip","amount":"500"}' },
  @{ name = "high";         inputs = '{"level":"normal","amount":"2000"}' },
  @{ name = "else";         inputs = '{"level":"normal","amount":"500"}' },
  @{ name = "first-match";  inputs = '{"level":"vip","amount":"2000"}' },
  @{ name = "missing";      inputs = '{}' }
)

$failed = $false

foreach ($case in $cases) {
  $ts = (Invoke-Run "http://localhost:3001" $TsApp $TsToken $case.inputs) -split "`n"
  $py = (Invoke-Run "http://localhost:8000" $PyApp $PyToken $case.inputs) -split "`n"

  # branch_taken：提取 caseId 与 label（紧凑 JSON 的键序固定）
  $tsBranch = (Get-DataLines $ts '"nodeId":"c1","caseId"') -join "|"
  $pyBranch = (Get-DataLines $py '"nodeId":"c1","caseId"') -join "|"

  if ($tsBranch -ne $pyBranch) {
    Write-Host "[$($case.name)] branch mismatch" -ForegroundColor Red
    Write-Host "  TS: $tsBranch"
    Write-Host "  PY: $pyBranch"
    $failed = $true
  } else {
    Write-Host "[$($case.name)] branch OK" -ForegroundColor Green
  }
}

# 迭代：joined 的 JSON 转义串必须一致（数组以 JSON 字符串形式作为 inputs.items）
$iterInputs = '{"items":"[\"退款\",\"发票\"]"}'
$ts = (Invoke-Run "http://localhost:3001" $TsApp $TsToken $iterInputs) -split "`n"
$py = (Invoke-Run "http://localhost:8000" $PyApp $PyToken $iterInputs) -split "`n"

$tsJoined = (Get-DataLines $ts '"joined"') -join "|"
$pyJoined = (Get-DataLines $py '"joined"') -join "|"
if ($tsJoined -ne $pyJoined) {
  Write-Host "[iteration] joined mismatch" -ForegroundColor Red
  Write-Host "  TS: $tsJoined"
  Write-Host "  PY: $pyJoined"
  $failed = $true
} else {
  Write-Host "[iteration] joined OK" -ForegroundColor Green
}

if ($failed) { throw "p8 compare failed" }
"PASS"
```

说明：

1. **只提取可比字段**：`branch_taken` 的 `nodeId/caseId/label`、迭代 `joined`；
2. **不比较** `runId`、`elapsedMs`、`token` 文本（模型层可能分帧不同）；
3. 依赖 SSE 帧的 `data:` 行是**紧凑 JSON**（阶段 4 的格式约定），所以字符串包含判断稳定；
4. 脚本进仓库、可进 CI。

> **面试考点 · 为什么要比事件，而不只比最终 `outputs`？**
> 因为分叉可能发生在**中间**：
>
> ```text
> 分支选错 → 但两个分支的 prompt 恰好都回 "echo: A" → 最终 outputs 相同
> ```
>
> 只看最终输出会漏掉“路由错误”。
> 事件是**过程契约**：`branch_taken` 记录“选了哪条”，`iteration_item` 记录“处理到第几项”。
> 验收要覆盖**过程 + 结果**，否则回归测试会给出虚假的绿色。

## 6. 专项验证

### 6.1 分支顺序（B9）

把 G1 的 `conditions` 从 `[vip, high]` 改成 `[high, vip]`，保存并重新发布，再跑：

```powershell
curl.exe -s -N -X POST http://localhost:3001/apps/<APP>/run `
  -H "Authorization: Bearer $tsToken" -H "Content-Type: application/json" `
  -d '{"inputs":{"level":"vip","amount":"2000"}}'
```

- 改序前：`caseId=vip`
- 改序后：`caseId=high`

**同一张图，只改数组顺序，结果不同**——这条能证明实现是“按顺序第一个匹配”，不是“按某种优先级”。

### 6.2 未连线分支（V6）

1. 画布删除 `else` 的边；
2. 面板显示「缺少出边：否则」；
3. 点保存 → 400，`message` 与 V6 文案一致；
4. 前端日志/提示展示后端原文（没有前端自己编的文案）。

### 6.3 聚合未执行分支（A4）

`values` 只留 `["{{ la.text }}"]`，输入走 `else`：

- `la` 未执行 → `pool.la` 不存在；
- `tryRenderTemplate` 返回 `""`；
- 结果 `""`，**不报错**。

如果把该节点换成 `end` 的 `outputs` 引用 `{{ la.text }}`：

- `renderTemplate` 严格 → `run_failed template variable not found: la.text`。

**同一个变量、两种引用位置，两种结果**——验证“分支安全 vs 主干严格”的边界。

### 6.4 迭代超限（I4）

```powershell
curl.exe -s -N -X POST http://localhost:3001/apps/<APP>/run `
  -H "Authorization: Bearer $tsToken" -H "Content-Type: application/json" `
  -d '{"inputs":{"items":"[\"a\",\"b\",\"c\",\"d\"]"}}'
```

期望事件序：

```text
run_started
node_started i1
run_failed  iteration node i1 exceeded max iterations: 3
```

**断言**：`Subscribe-Object` / `Select-String` 结果中 `iteration_item` 计数为 **0**。
如果出现 3 条 `iteration_item`，说明超限检查在循环里（错误）。

### 6.5 `1.0` 跨端（I2）

```powershell
$tsBody = '{"inputs":{"items":"[1.0,2.5,3.0]"}}'
curl.exe -s -N -X POST http://localhost:3001/apps/<TS_APP>/run `
  -H "Authorization: Bearer $tsToken" -H "Content-Type: application/json" -d $tsBody
curl.exe -s -N -X POST http://localhost:8000/apps/<PY_APP>/run `
  -H "Authorization: Bearer $pyToken" -H "Content-Type: application/json" -d $tsBody
```

比较两条 `node_finished(i1)` 的 `output`：

- 两端都应为 `["[1/3] 1","[2/3] 2.5","[3/3] 3"]`；
- Python 若出现 `"1.0"`、`"3.0"`，说明 `js_json_dumps` 没生效（或被 `json.dumps` 覆盖）。

### 6.6 `NaN` / `Infinity`（单元级）

JSON 请求体里无法表达 `NaN`，所以这条只能做单元级验证：

```powershell
# cwd = apps/api-py
uv run python -c "from app.engine.template import js_json_dumps; print(js_json_dumps(float('nan')), js_json_dumps(float('inf')), js_json_dumps(-0.0))"
# 期望：null null 0
```

TS 对照：

```powershell
# cwd = apps/api-ts
node -e "console.log(JSON.stringify(NaN), JSON.stringify(Infinity), JSON.stringify(-0))"
# null null 0
```

> **面试考点 · 为什么 API 级测不出 `NaN`？**
> 因为 HTTP 请求体是 JSON 文本，而 JSON 标准**没有** `NaN`/`Infinity`：
>
> ```json
> { "items": "[NaN]" }   ← 这是字符串 "NaN"，不是数字
> ```
>
> `NaN` 只可能来自**语言内部计算**（如工具返回值）。所以：
>
> - 序列化函数做**单元测试**；
> - API 做**集成测试**；
> - 两者不能互相替代。

### 6.7 迭代空数组（I3）

```powershell
-d '{"inputs":{"items":"[]"}}'
```

期望：

```text
node_finished i1  { results: [], count: 0, joined: "" }
```

`count` 是数字 `0`（不是字符串），`joined` 是空串。
**不报错**：空数组是合法输入，`0 <= maxIterations`。

## 7. 回归

| 阶段 | 回归点 | 为什么 |
| --- | --- | --- |
| 1 | 注册/登录 | 所有请求都带 token |
| 2 | 应用 CRUD | 图的宿主是 app |
| 3 | 画布保存/发布 | 阶段 8 的新节点要能存回 JSONB |
| 4 | SSE 事件序 | 新事件插入不能打乱旧事件 |
| 5 | LLM 流式 | 聚合里的 `llm.text` 依赖它 |
| 6 | ReAct + 工具 | **条件边被两处使用**（工具回环 vs 分支），必须互不干扰 |
| 7 | 知识库检索 | `retrieval` 事件与分支事件共存 |

**阶段 8 最危险的回归**：条件边实现扩展后，阶段 6 的 ReAct 回环失效。

验证方式：

1. 用阶段 6 的“勾选 calculator”图跑一次；
2. 期望仍出现 `tool_call` → `tool_result` → 第二轮 → `node_finished`；
3. `recursionLimit` 没有被分支逻辑改坏（轮次上限仍为 `MAX_TOOL_ROUNDS + 2` 之类）。

另一条：**旧图（阶段 3~7）没有 `condition` 节点**，运行时不能因为新增的节点类型遍历而报错。

## 8. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 保存 400 `else branch has no outgoing edge` | 没连「否则」 | 从 else handle 拖一条边 |
| 保存 400 `invalid sourceHandle: null` | 边从节点主体拖出（旧图/手工改库） | 删边重连；或补 `sourceHandle` |
| 保存 400 `has duplicate edge for case vip` | 同一分支两条边 | 删掉多余的一条 |

## 10. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 为什么要“改数组顺序”用例 | 能区分“第一个匹配”与“全部匹配/优先级”实现 |
| 为什么 diff 事件而非只 diff 输出 | 路由错误可能被相同文案掩盖 |
| 空数组算失败吗 | 不算；`0 <= maxIterations`，输出空结果 |
| `NaN` 为什么只能单测 | JSON 规范没有 `NaN`；请求体传不进来 |
| 超限为什么要求零条 `iteration_item` | 检查在循环前；有进度就说明实现错了 |
| 聚合未执行分支 | `tryRenderTemplate` 返回空串；`end` 里同引用会 `run_failed` |
| 阶段 8 最危险回归 | 条件边与 ReAct 条件边冲突 |
| 验收脚本只取可比字段 | `runId/elapsedMs` 天然不同；token 分帧可变 |
| 文案逐字节比对 | 规则顺序也是契约 |
| 旧图回归 | 新增节点类型不能让无分支的图报错 |

## 11. 阶段 8 小结

```text
契约（三种节点 data + type 枚举）
  → 图校验（规则 8/9/10：分支边、聚合非空、迭代范围）
  → 条件边（节点写 branches，router 读 branches）
  → 聚合（第一个非空，扁平输出）
  → 迭代（节点内循环 + 安全解析 inputArray + 严格渲染 outputTemplate）
  → 数值对齐（js_json_dumps）
  → 前端（多 handle + 级联删边 + 文本态数值）
  → 事件级对比（branch_taken / iteration_item / joined）
```

阶段 8 的核心不是“多了三个节点”，而是：

1. **图能表达分支，但选择权仍在引擎**（节点不决定下一跳）；
2. **分支的安全解析与主干严格解析是两套语义**，不能混用；
3. **跨语言差异要逐项列举**（`1.0`、`NaN`、键序），能对齐的对齐，不能对齐的写进限制；
4. **验收要比过程**（事件），否则会得到虚假的绿色。

# 03 · 迭代节点与跨语言数值对齐（分支与循环）

> 阶段 8 · 第 3 步
>
> 做完：`iteration` 节点把模板解析出的 JSON 数组逐项渲染，发 `iteration_item` 进度事件，输出 `{ results, count, joined }`；TS 与 Python 对 `1.0`、`NaN`、`Infinity` 的序列化结果**逐字节一致**。
>
> **本篇面试考点**：节点内循环 ≠ 图循环（为什么不涨 `recursionLimit`）· `JSON.parse` 失败与非数组为什么同一文案 · `maxIterations` 是“报错”还是“截断” · 逐项环境为什么用展开覆盖 · `itemIndex` 为什么从 1 开始 · `JSON.stringify(1.0) === "1"` 而 `json.dumps(1.0) === "1.0"` · `NaN`/`Infinity` 在两种语言里的非法 JSON 问题 · JS 对象键序与 Python 插入序 · 图校验拦住浮点 `maxIterations` 后，运行时兜底为何仍不一致。

## 1. 迭代不是图循环

```text
iteration 节点
┌──────────────────────────────────────────┐
│  items = JSON.parse(render(inputArray))  │
│  for item of items:                       │
│    emit iteration_item(index, total)     │
│    results.push(render(outputTemplate))  │
└──────────────────────────────────────────┘
          ↓
   { results, count, joined }
```

对比两种“循环”：

| | 图循环（阶段 6 ReAct） | 节点内循环（本篇） |
| --- | --- | --- |
| 谁在循环 | LangGraph 的 superstep | 节点函数里的 `for` |
| 图上可见 | 可见（回边） | 不可见（一个节点） |
| 消耗递归预算 | 是（`recursionLimit`） | 否 |
| 能否中途暂停 | 是（每个节点边界） | 否（一次执行到底） |
| 适用 | 轮次不确定（工具调用） | 次数确定（数组长度） |

> **面试考点 · 为什么迭代不做成图循环？**
> 如果每个数组元素都展开成图上的“一次迭代”，需要：
>
> - 动态生成 N 个节点（图在运行前就要编译，做不到）；
> - 或者用“回边 + 索引状态”，把简单 map 变成状态机。
>
> 而数组长度在运行时才知道，图是**静态编译**的。所以：
>
> **次数在运行前不确定 → 图循环；次数由数据决定且一次性完成 → 节点内循环。**
> 这也是为什么 `iteration` 不需要改 `recursionLimit`——它只占一个 superstep。

## 2. `iteration.node.ts`

**完整文件路径：`apps/api-ts/src/engine/nodes/iteration.node.ts`**

```ts
import type { GraphNode, IterationNodeData } from '@mini-dify/contract'

import { RunError } from '../events'
import { renderTemplate, tryRenderTemplate, type Pool } from '../template'

/** `iteration.maxIterations` 的默认值（与契约 `default: 20` 一致）。 */
export const DEFAULT_MAX_ITERATIONS = 20

/**
 * `iteration` 节点（阶段 8）：`inputArray` 安全解析后 `JSON.parse`，必须是数组；
 * 逐项先发 `iteration_item`（`index` 从 1 开始），再以
 * `{ ...pool, <itemName>: <item>, itemIndex, itemCount }` 渲染 `outputTemplate`。
 *
 * 输出 `{ results, count, joined }`，`joined = results.join("\n")`。
 * 数组长度超过 `maxIterations` 或解析结果不是数组时抛 `RunError`（见 error-messages.md §8.2）。
 */
export function runIterationNode(
  node: GraphNode,
  pool: Pool,
  emitItem: (index: number, total: number) => void,
): Record<string, unknown> {
  const data = node.data as unknown as IterationNodeData
  const maxIterations =
    typeof data.maxIterations === 'number' ? data.maxIterations : DEFAULT_MAX_ITERATIONS
  const itemName =
    typeof data.itemName === 'string' && data.itemName !== '' ? data.itemName : 'item'

  const rendered = tryRenderTemplate(data.inputArray, pool)
  let items: unknown
  try {
    items = JSON.parse(rendered)
  } catch {
    throw new RunError(`iteration node ${node.id} inputArray must be an array`)
  }
  if (!Array.isArray(items)) {
    throw new RunError(`iteration node ${node.id} inputArray must be an array`)
  }
  if (items.length > maxIterations) {
    throw new RunError(`iteration node ${node.id} exceeded max iterations: ${maxIterations}`)
  }

  const total = items.length
  const results = items.map((item, index) => {
    emitItem(index + 1, total)
    return renderTemplate(data.outputTemplate, {
      ...pool,
      [itemName]: stringifyItem(item),
      itemIndex: index + 1,
      itemCount: total,
    })
  })

  return { results, count: results.length, joined: results.join('\n') }
}

/** 当前项字符串化：字符串原样，其余按紧凑 JSON（两端一致）。 */
function stringifyItem(item: unknown): string {
  return typeof item === 'string' ? item : JSON.stringify(item)
}
```

### 2.1 `inputArray` 为什么用安全解析

```ts
const rendered = tryRenderTemplate(data.inputArray, pool)
```

`inputArray` 的典型写法：

```text
{{ inputs.topics }}
```

如果 `inputs.topics` 不存在：

- `renderTemplate` → 抛 `template variable not found: inputs.topics`；
- `tryRenderTemplate` → `""` → `JSON.parse("")` 抛错 → 统一成 `inputArray must be an array`。

两种路径最终都是 `run_failed`，但**文案不同**：

| 方式 | 报错 |
| --- | --- |
| 严格渲染 | `template variable not found: inputs.topics` |
| 安全渲染 | `iteration node i1 inputArray must be an array` |

选安全渲染，是因为迭代的语义是“数组可以合法地为空/缺失”吗？**不是**——这里选它只是为了与 Python 侧实现一致（Python 统一用 `try_render_template`），并且错误文案更贴近“节点配置问题”。

> **注意**：`""` 不是合法 JSON 数组，所以“缺失”最终仍是失败。
> 如果希望“缺失 = 空数组”，应该显式写 `JSON.parse(tryRender(..) || "[]")`——但这会掩盖配置错误，当前不做。

### 2.2 三种失败

| 条件 | 文案 |
| --- | --- |
| `JSON.parse` 失败 | `iteration node i1 inputArray must be an array` |
| 解析结果不是数组（`{}` / `"x"` / `1`） | 同上 |
| `items.length > maxIterations` | `iteration node i1 exceeded max iterations: 2` |

前两条**故意共用同一文案**：

- 对用户来说，“渲染出来不是数组”是同一类问题；
- 区分 `SyntaxError` 与“不是数组”没有行动价值（都是改 `inputArray`）。

> **面试考点 · 这是不是“丢失信息”？**
> 是，但这是**有意的信息压缩**：
>
> - 用户需要知道的是“这里要一个数组”；
> - 具体是 JSON 语法错还是类型错，可以看节点配置自查；
> - 两端实现不同（JS `JSON.parse` vs Python `json.loads`）时，统一文案能避免“同一输入两种错误”。
>
> **错误信息的价值在于“能指导修复”，而不是“尽可能详细”。**

### 2.3 超限是报错，不是截断

```ts
if (items.length > maxIterations) {
  throw new RunError(`... exceeded max iterations: ${maxIterations}`)
}
```

对比两种策略：

| 策略 | 行为 | 风险 |
| --- | --- | --- |
| 报错（本项目） | 运行失败，用户改配置 | 用户必须调大上限 |
| 截断 | 只处理前 N 项 | **静默丢数据**，用户不知道结果不全 |
| 拒绝保存 | 保存时检查数组长度 | 数组来自运行时输入，保存时不知道长度 |

因为数组长度是**运行时数据**，保存时无法校验；运行时报错是唯一能“让用户知道”的方式。
代价是“输入太长就失败”，收益是**不会悄悄只处理一部分**。

### 2.4 逐项环境

```ts
return renderTemplate(data.outputTemplate, {
  ...pool,
  [itemName]: stringifyItem(item),
  itemIndex: index + 1,
  itemCount: total,
})
```

`{ ...pool, ... }` 的含义：

- 保留上游所有变量（`inputs`、`llm1`、`knowledge1`…）；
- **覆盖**三个名字：`itemName`、`itemIndex`、`itemCount`。

覆盖的风险：

```text
itemName = "inputs"     → 覆盖 pool.inputs（灾难）
itemName = "itemIndex"  → 被后面的 itemIndex 覆盖（用户的 itemName 失效）
```

当前没有校验 `itemName` 是否为保留字。

> **面试考点 · 为什么不做保留字校验？**
> 可以做，而且应该做（比如禁止 `inputs` / `itemIndex` / `itemCount`）。
> 当前未做的原因：`itemName` 是阶段 8 新增字段，前端默认值 `item`，用户很少改。
> 这是一个**已知缺口**：如果面试官问“你的迭代节点有什么边界问题”，这里就是答案之一。
> **知道自己系统的缺口，比声称“没有问题”更专业。**

### 2.5 `itemIndex` 从 1 开始

```ts
emitItem(index + 1, total)
itemIndex: index + 1
```

面向用户的索引从 1 开始：

- 与“第 1 项、第 2 项”的自然语言一致；
- `iteration_item` 事件的 `index` 与模板里的 `itemIndex` **同一个值**，不会一个 0-based 一个 1-based。

内部 `items.map((item, index) => ...)` 仍然是 0-based（JS 数组语义）。

> **面试考点 · 为什么不用 0-based 保持“代码一致”？**
> 事件与模板是**面向用户**的，不是面向程序员的。
> 一个系统里同时存在两种索引约定是正常的：
>
> - 内部数组：0-based（语言习惯）；
> - 用户可见：1-based（自然语言）。
>
> 关键是**在边界处只转换一次**，并且文档写清楚。本项目在 `emitItem` 与 `itemIndex` 两处都转，且用同一表达式 `index + 1`。

### 2.6 输出

```ts
return { results, count: results.length, joined: results.join('\n') }
```

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `results` | `string[]` | 逐项结果，前端可列表展示 |
| `count` | `number` | 便于模板直接用 `{{ iter1.count }}` |
| `joined` | `string` | 一次性拼进 prompt（`\n` 连接） |

为什么同时给 `count`：`{{ iter1.results.length }}` 在模板里**不支持**（模板只做点路径取值，没有 `.length` 访问）。
所以需要 `count` 这个“预计算字段”。

> **面试考点 · `joined` 为什么用 `"\n"` 而不是 `", "`？**
> `\n` 是“多行文本”的通用分隔，适合直接塞进 prompt：
>
> ```text
> 以下是候选答案：
> {{ iter1.joined }}
> ```
>
> 如果用 `", "`，长文本会变成一行，模型难以区分条目边界。
> 分隔符也是契约（两端必须相同），改它要同步改 Python 的 `"\n".join(results)`。

## 3. 跨语言数值对齐

这是本篇最重要的一节。

### 3.1 问题：`1.0` 到底输出什么

同一个数组：

```json
{ "inputs": { "nums": [1.0, 2.5] } }
```

`iteration.outputTemplate = "{{ item }}"`。

**JS**：

```js
JSON.stringify(1.0)   // "1"
JSON.stringify(2.5)   // "2.5"
```

**Python**：

```python
json.dumps(1.0)       # "1.0"
json.dumps(2.5)       # "2.5"
```

结果：

```text
TS:     results = ["1", "2.5"]      joined = "1\n2.5"
Python: results = ["1.0", "2.5"]    joined = "1.0\n2.5"
```

**同一个图、同一份输入，两端输出不同。**

### 3.2 根因

| 语言 | 数字模型 | `1.0` 的表示 |
| --- | --- | --- |
| JavaScript | 只有 `number`（IEEE-754 double） | `1` 与 `1.0` 是同一个值，序列化统一为 `1` |
| Python | `int` 与 `float` 分开 | `1.0` 是 `float`，`json.dumps` 保留 `.0` |

JS **没有整型/浮点型的区分**，所有数字都是 double；`JSON.stringify` 对整数结果省略 `.0`。
Python 的 `float` 是独立类型，`json.dumps` 忠实输出 `.0`。

### 3.3 解决：`js_json_dumps`

**完整文件路径：`apps/api-py/app/engine/template.py`**（数值规范化）

```python
def js_json_dumps(value: Any) -> str:
    """按 **JavaScript `JSON.stringify` 的口径**做紧凑 JSON 序列化。

    为什么不能直接用 `json.dumps`：两种语言对浮点的输出不同 ——
    `JSON.stringify(1.0)` 得到 `"1"`，而 Python `json.dumps(1.0)` 得到 `"1.0"`。
    迭代节点对「数字数组」逐项渲染时，这个差异会让两端输出分叉。
    另外 JS 对 `NaN`/`Infinity` 输出 `null`，Python 默认输出 `NaN`/`Infinity`（非法 JSON）。

    规则：
    - 整数值的 `float` → 整数（`1.0` → `1`）
    - `NaN` / `±Infinity` → `None`（序列化为 `null`）
    - 递归处理 list / dict
    """
    return json.dumps(
        _js_normalize(value), ensure_ascii=False, separators=(",", ":")
    )


def _js_normalize(value: Any) -> Any:
    """递归把 Python 数值/容器规范成 JS `JSON.stringify` 的等价形式。"""
    if isinstance(value, bool):
        # bool 是 int 的子类，必须排在 float/int 判断之前
        return value
    if isinstance(value, float):
        if value != value or value in (float("inf"), float("-inf")):  # NaN / ±Inf
            return None
        return int(value) if value.is_integer() else value
    if isinstance(value, list):
        return [_js_normalize(item) for item in value]
    if isinstance(value, dict):
        return {key: _js_normalize(item) for key, item in value.items()}
    return value
```

三个规则：

1. **整数值的 `float` → `int`**：`1.0` → `1`；
2. **`NaN` / `±Infinity` → `null`**：JS 的 `JSON.stringify(NaN)` 就是 `"null"`；
3. **`bool` 先于 `int` 判断**：Python 里 `True` 是 `int` 子类，`isinstance(True, int) == True`，不先排除会把 `True` 当数字处理。

### 3.4 对齐验证表

| 输入 | JS `JSON.stringify` | Python `json.dumps` | `js_json_dumps` |
| --- | --- | --- | --- |
| `1.0` | `"1"` | `"1.0"` | `"1"` ✅ |
| `1.5` | `"1.5"` | `"1.5"` | `"1.5"` ✅ |
| `-0.0` | `"0"` | `"-0.0"` | `"0"` ✅（`int(-0.0) = 0`） |
| `NaN` | `"null"` | `"NaN"`（非法 JSON） | `"null"` ✅ |
| `Infinity` | `"null"` | `"Infinity"`（非法 JSON） | `"null"` ✅ |
| `True` | `"true"` | `"true"` | `"true"` ✅ |
| `None` | `"null"` | `"null"` | `"null"` ✅ |
| `"中文"` | `"\"中文\""` | `"\"\\u4e2d\\u6587\""` | `"\"中文\""` ✅（`ensure_ascii=False`） |
| `{"a":1.0}` | `"{\"a\":1}"` | `"{\"a\":1.0}"` | `"{\"a\":1}"` ✅ |

### 3.5 还有一处没对齐：对象键序

JS 的对象属性顺序规则：

```js
JSON.stringify({ b: 1, "2": 2, "1": 3 })
// '{"1":3,"2":2,"b":1}'
```

**整数样式的键会被排到前面，并按数值升序**（这是 ES2015 起的规范行为）。

Python 的 `dict` 保持**插入顺序**：

```python
json.dumps({"b": 1, "2": 2, "1": 3})
# '{"b": 1, "2": 2, "1": 3}'
```

所以，如果迭代项是**对象**：

```json
{ "b": 1, "2": 2 }
```

- TS：`{"2":2,"b":1}`
- Python：`{"2": 2, "b": 1}`（紧凑后键序仍不同）

> **面试考点 · 怎么彻底解决键序？**
> 三种做法：
>
> 1. **按 JS 规则重排**：Python 侧把所有“整数样式键”提前并升序，其余保持插入序——完整复刻 ES 规范，代码不复杂但容易漏边界（`"-1"` 不算整数样式键、`"01"` 不算）；
> 2. **统一按键名字典序输出**：两端都排序，简单，但**改变了 JS 的原生行为**（TS 侧也要额外处理）；
> 3. **不处理，文档声明限制**：迭代项建议用字符串或数字，避免对象。
>
> 本项目选 3（当前实现），因为迭代的典型输入是字符串数组（主题、关键词）。
> **“知道哪里没对齐”比“假装全对齐”重要**——面试时能说出 1、2 两种方案的取舍，说明你真的想过。

### 3.6 `maxIterations` 的运行时兜底也不一致

TS：

```ts
const maxIterations = typeof data.maxIterations === 'number' ? data.maxIterations : DEFAULT
```

Python：

```python
max_iterations = (
    int(raw_max)
    if isinstance(raw_max, (int, float)) and not isinstance(raw_max, bool)
    else DEFAULT_MAX_ITERATIONS
)
```

差异：

| `data.maxIterations` | TS | Python |
| --- | --- | --- |
| `20` | 20 | 20 |
| `20.5` | 20.5（比较 `len > 20.5`） | 20（`int()` 截断） |
| `true` | 走 `typeof === 'number'`？`typeof true` 是 `"boolean"` → 默认 20 | `isinstance(True, (int,float))` 为真，但被 `not isinstance(bool)` 排除 → 20 |
| `"20"` | 默认 20 | 默认 20 |
| `-1` | -1 → 任何非空数组都超限 | -1 → 同样超限 |

`20.5` 这一行不一致。**但图校验规则 10 已经禁止非整数**：

```ts
!(Number.isInteger(maxIterations) && maxIterations >= 1 && maxIterations <= 100)
```

所以正常路径不会出现 `20.5`。只有“绕过图校验直接改库”才会触发。

> **面试考点 · 既然校验拦住了，为什么运行时还要兜底？**
> 因为运行时不信任 `graph_json`（历史数据、手工修改）。
> 兜底不需要“与 TS 完全一致”，只需要“不会崩溃”；**一致性由入口校验保证，鲁棒性由运行时兜底保证**。
> 但如果要追求“任何输入都两端一致”，运行时也必须用同一套规则（TS 也应 `Math.trunc`）。
> 当前选择是“校验严格 + 兜底简单”，这是一个明确的工程取舍。

## 4. Python 实现

**完整文件路径：`apps/api-py/app/engine/nodes/iteration.py`**

```python
"""`iteration` 节点（阶段 8）。

与 api-ts 的 `apps/api-ts/src/engine/nodes/iteration.node.ts` 对齐：
`inputArray` 安全解析后 `JSON.parse`，必须是数组；逐项先发 `iteration_item`
（`index` 从 1 开始），再以 `{...pool, <itemName>: <item>, itemIndex, itemCount}`
渲染 `outputTemplate`。

输出 `{ "results": string[], "count": number, "joined": string }`，
`joined = "\\n".join(results)`。数组长度超过 `maxIterations` 或解析结果不是数组时抛
`RunError`（见 error-messages.md §8.2）。
"""

import json
from collections.abc import Awaitable, Callable
from typing import Any

from app.engine.events import RunError
from app.engine.template import js_json_dumps, render_template, try_render_template

# `iteration.maxIterations` 的默认值（与契约 `default: 20` 一致）
DEFAULT_MAX_ITERATIONS = 20

EmitItem = Callable[[int, int], Awaitable[None]]


async def run_iteration_node(
    node: dict[str, Any],
    pool: dict[str, Any],
    emit_item: EmitItem,
) -> dict[str, Any]:
    """执行 `iteration` 节点：逐项发 `iteration_item` 并渲染 `outputTemplate`。"""
    data: dict[str, Any] = node["data"]
    raw_max = data.get("maxIterations")
    max_iterations = (
        int(raw_max)
        if isinstance(raw_max, (int, float)) and not isinstance(raw_max, bool)
        else DEFAULT_MAX_ITERATIONS
    )
    raw_item_name = data.get("itemName")
    item_name = raw_item_name if isinstance(raw_item_name, str) and raw_item_name != "" else "item"

    rendered = try_render_template(data["inputArray"], pool)
    try:
        items = json.loads(rendered)
    except ValueError:
        raise RunError(f"iteration node {node['id']} inputArray must be an array") from None
    if not isinstance(items, list):
        raise RunError(f"iteration node {node['id']} inputArray must be an array")
    if len(items) > max_iterations:
        raise RunError(
            f"iteration node {node['id']} exceeded max iterations: {max_iterations}"
        )

    total = len(items)
    results: list[str] = []
    for index, item in enumerate(items):
        await emit_item(index + 1, total)
        results.append(
            render_template(
                data["outputTemplate"],
                {
                    **pool,
                    item_name: _stringify_item(item),
                    "itemIndex": index + 1,
                    "itemCount": total,
                },
            )
        )

    return {"results": results, "count": len(results), "joined": "\n".join(results)}


def _stringify_item(item: Any) -> str:
    """当前项字符串化：字符串原样，其余按紧凑 JSON（两端一致）。

    用 `js_json_dumps` 而不是 `json.dumps`：整数值浮点在 JS 里序列化为 `1`、
    在 Python 里是 `1.0`，迭代数字数组时会导致两端输出分叉。
    """
    if isinstance(item, str):
        return item
    return js_json_dumps(item)
```

细节：

1. **`from None`**：抑制 `JSONDecodeError` 的 `__context__`，日志里只有规范文案，不出现 Python 的原始异常链；
2. **`await emit_item(...)`**：Python 版事件发送是异步的（`asyncio.Queue.put`），TS 版是同步 `queue.emit`；
3. **`render_template` 严格**：`outputTemplate` 里引用不存在的变量 → `RunError`（与主干节点一致），只有 `inputArray` 是安全的。

引擎挂载：

```python
    if node["type"] == "iteration":
        async def emit_item(index: int, total: int) -> None:
            await queue.put(iteration_item(node["id"], index, total))

        return await run_iteration_node(node, pool, emit_item)
```

事件（阶段 4 定义）：

```python
def iteration_item(node_id: str, index: int, total: int) -> dict[str, Any]:
    """`iteration_item`：迭代进度（每项一次，`index` 从 1 开始）。"""
    return {"event": "iteration_item", "data": {"nodeId": node_id, "index": index, "total": total}}
```

事件序：

```text
node_started    i1
iteration_item  i1 1/3
iteration_item  i1 2/3
iteration_item  i1 3/3
node_finished   i1  { results: [...], count: 3, joined: "..." }
```

## 5. 验证

### 5.1 字符串数组

图：`start → iter1 → end1`

```json
{
  "iter1": {
    "title": "逐项生成",
    "inputArray": "{{ inputs.topics }}",
    "itemName": "topic",
    "outputTemplate": "第 {{ iter1.itemIndex }}/{{ iter1.itemCount }} 项：{{ topic }}"
  },
  "end1": {
    "outputs": [{ "name": "joined", "value": "{{ iter1.joined }}" }]
  }
}
```

输入：

```json
{ "topics": ["退款", "发票", "物流"] }
```

预期：

```text
iteration_item 1/3, 2/3, 3/3
node_finished(iter1).output = {
  results: ["第 1/3 项：退款", "第 2/3 项：发票", "第 3/3 项：物流"],
  count: 3,
  joined: "第 1/3 项：退款\n第 2/3 项：发票\n第 3/3 项：物流"
}
```

> **注意**：`outputTemplate` 里必须写 `{{ itemIndex }}` / `{{ itemCount }}`（**不带节点前缀**），因为逐项环境是把它们平铺进 `pool` 的。
> 下游节点只能引用 `{{ iter1.results }}` / `{{ iter1.count }}` / `{{ iter1.joined }}`；`iter1.itemIndex` **不存在**（它只在单次迭代的临时环境里）。

### 5.2 数字数组（跨语言关键用例）

```json
{ "nums": [1.0, 2.5, 3.0] }
```

`outputTemplate: "{{ item }}"`：

```text
TS:     ["1", "2.5", "3"]
Python: ["1", "2.5", "3"]      ← js_json_dumps 生效
```

如果 Python 侧误用 `json.dumps`：

```text
Python: ["1.0", "2.5", "3.0"]  ← 分叉
```

验证命令：

```powershell
# 两端各跑一次，比较 joined
curl.exe -s -N -X POST http://localhost:3001/apps/<ID>/run -H "Authorization: Bearer $t1" `
  -H "Content-Type: application/json" -d '{"inputs":{"nums":[1.0,2.5,3.0]}}'
curl.exe -s -N -X POST http://localhost:8000/apps/<ID>/run -H "Authorization: Bearer $t2" `
  -H "Content-Type: application/json" -d '{"inputs":{"nums":[1.0,2.5,3.0]}}'
```

### 5.3 对象数组（已知键序限制）

```json
{ "rows": [{ "name": "A", "score": 1.0 }] }
```

- TS：`{"name":"A","score":1}`
- Python：`{"name":"A","score":1}` ✅

（键序碰巧相同，因为都是字母键。）

再试带“整数样式键”的对象：

```json
{ "rows": [{ "b": 1, "2": 2 }] }
```

```text
TS:     {"2":2,"b":1}      ← JS 把 "2" 提到前面
Python: {"b":1,"2":2}      ← 保持插入序
```

**这就是 3.5 说的未对齐点**。验收时不要用这种输入。

### 5.4 超限

`maxIterations: 2`，输入 3 项：

```text
event: run_started
event: node_started iter1
event: run_failed  iteration node i1 exceeded max iterations: 2
```

**超限检查在循环之前**，所以不会先出现 `iteration_item`。
如果看到 `iteration_item 1/3`、`2/3` 之后才 `run_failed`，说明检查被放进了循环里（错误实现）。

### 5.5 非数组

```json
{ "inputArray": "{{ inputs.obj }}", "inputs": { "obj": { "a": 1 } } }
```

→ `iteration node i1 inputArray must be an array`

非法 JSON：

```json
{ "inputArray": "not json" }
```

→ 同一文案。

### 5.6 模板缺变量

`outputTemplate: "{{ missing }}"`：

→ `template variable not found: missing`（严格渲染，不是安全渲染）。

## 6. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 节点内循环 vs 图循环 | 次数由数据决定 → 节点内；不占递归预算 |
| 为什么不用图循环 | 图静态编译，运行时才知道长度 |
| `JSON.parse` 失败与非数组同文案 | 对用户是同一类修复动作；跨语言易统一 |
| 超限报错不截断 | 静默丢数据比失败更糟 |
| 检查在循环前 | 否则会先发几条 `iteration_item` 才失败 |
| `{...pool, item}` 覆盖 | 上游变量可用；`itemName` 无保留字校验（缺口） |
| `itemIndex` 1-based | 面向用户；内部 0-based，边界只转一次 |
| 为什么有 `count` | 模板不支持 `.length` |
| `joined` 用 `\n` | prompt 多行；分隔符是契约 |
| `1.0` 分叉 | JS 只有 double；Python float 保留 `.0` |
| `js_json_dumps` | 整数值 float → int；NaN/Inf → null；递归 |
| `bool` 先判断 | Python `True` 是 `int` 子类 |
| `ensure_ascii=False` | 中文不转 `\uXXXX` |
| 键序未对齐 | JS 整数样式键前置；Python 插入序；三种解法 |
| `20.5` 兜底不一致 | 图校验禁止非整数；运行时不信任历史数据 |

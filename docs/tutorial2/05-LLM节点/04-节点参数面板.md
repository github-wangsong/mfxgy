# 04 · 节点参数面板（LLM 节点）

> 阶段 5 · 第 4 步
>
> 做完：选中 `llm` 节点后，右侧检查器能编辑 `model` / `prompt` / `system` / `temperature` / `maxTokens`；改动只进本地 `nodes` 状态，点「保存草稿」才写库；留空的数字字段会**从 `data` 中删掉该键**，而不是存成 `undefined` 或 `0`。
>
> 本篇只做阶段 5 的五个字段；`tools`（阶段 6）、`useHistory`（阶段 9）后续追加到同一个面板。
>
> **本篇面试考点**：受控数字输入为什么要用文本态 · `Number('') === 0` 与 `NaN` 陷阱 · 可选字段“删键”而不是 `undefined` · `JSON.stringify` 对 `undefined` 的处理 · `useEffect` 依赖故意省略的代价 · 每次输入都 `setNodes` 全量 map 的成本 · 保存时机（编辑态 vs 提交态）· 前端做不做数值范围校验 · 为什么 `title` 不参与运行。

## 1. 数据流

```text
点击节点
  → setSelectedNodeId(node.id)
  → selectedNode = nodes.find(...)
  → 面板读 selectedNode.data.*
  → onChange: updateNodeData(id, patch) → setNodes(全量 map)
  → 只改本地状态（不请求后端）
  → 点「保存草稿」→ buildGraph(nodes, edges) → PUT /apps/{id}/graph
```

要点：**编辑与保存分离**。

- 每敲一个字符不发请求：避免请求风暴，也避免“半截 prompt”被存进库；
- 保存是一次性动作，用户有明确的“我改完了”的意图；
- 发布是另一个动作（阶段 3：先保存再 publish）。

> **面试考点 · 为什么不做“自动保存”？**
> 自动保存适合**结构化、低风险**的字段（如开关、下拉），不适合**大段文本**：
>
> - prompt 编辑中途保存，会写入不完整内容；
> - 网络抖动时无法告知“这次改动没保存”；
> - 与发布语义冲突（自动保存后，用户分不清“已发布”和“草稿”）。
>
> 本项目的选择：显式保存 + 明确的状态提示。`Notion`/`Figma` 这类自动保存产品，背后有冲突合并（CRDT/OT）与版本历史，复杂度不在一个量级。

## 2. 选中与更新

**完整文件路径：`apps/web/app/apps/[id]/page.tsx`**（阶段 5 相关部分）

```tsx
  // 当前选中的节点 id（null 表示未选中）
  const [selectedNodeId, setSelectedNodeId] = useState<string | null>(null)
```

```tsx
  /** 选中的节点对象（由 id 派生，避免把整个节点再存一份 state）。 */
  const selectedNode = useMemo(
    () => nodes.find((node) => node.id === selectedNodeId) ?? null,
    [nodes, selectedNodeId],
  )
```

点击画布节点时：

```tsx
<ReactFlow
  // ...
  onNodeClick={(_event, node) => setSelectedNodeId(node.id)}
  onPaneClick={() => setSelectedNodeId(null)}
>
```

更新节点 `data` 的唯一入口：

```tsx
  /**
   * 浅合并更新节点 `data`。
   *
   * 只做一层合并：`data` 内部的嵌套结构（如 inputs 数组）由调用方构造完整新值，
   * 不做深合并——深合并会让“删除数组元素”这类操作无法表达。
   */
  function updateNodeData(id: string, patch: Record<string, unknown>): void {
    setNodes((nds) =>
      nds.map((node) => (node.id === id ? { ...node, data: { ...node.data, ...patch } } : node)),
    )
  }
```

> **面试考点 · 为什么用“浅合并 + 调用方给完整新数组”，而不是深合并？**
> 深合并的语义是“只覆盖给出的叶子”，它**无法表达删除**：
>
> ```text
> 当前 inputs: [A, B]
> 想删掉 B
> 深合并无法表达“把数组变成 [A]”——不传就是保持原样
> ```
>
> 所以数组字段一律由调用方算好新数组再整体替换：

```tsx
updateNodeData(selectedNode.id, {
  inputs: selectedInputs.filter((_cur, i) => i !== index),   // 整体替换
})
```

> 这和 PATCH 的 `exclude_unset` 是同一类问题：**“没给”和“给了空”必须能区分**。

## 3. 数字字段：文本态

`temperature` / `maxTokens` 是可空数字。直接绑 `number` 会有两个问题：

```tsx
// 反面写法
<input
  type="number"
  value={selectedNode.data.temperature ?? ''}          // number | ''
  onChange={(e) => updateNodeData(id, { temperature: Number(e.target.value) })}
/>
```

1. 输入 `1.` 时，`Number('1.')` 是 `1`，受控值立刻变回 `1`，**小数点被吃掉**，无法继续输入 `1.5`；
2. 清空输入框时 `Number('')` 是 `0`，于是“留空”变成“temperature = 0”，语义完全变了。

正确做法：**输入框用字符串 state 承载，提交时才解析成数字。**

```tsx
  // temperature / maxTokens 在编辑期用原始文本承载，避免小数（如 "1.5"）被数值回写打断
  const [temperatureText, setTemperatureText] = useState('')
  const [maxTokensText, setMaxTokensText] = useState('')
```

**切换选中节点时**，把文本态同步成该节点的当前值：

```tsx
  // 切换选中节点时，把数字字段的编辑文本同步为该节点当前值（空则留空）
  useEffect(() => {
    const t = selectedNode?.data.temperature
    setTemperatureText(typeof t === 'number' ? String(t) : '')
    const m = selectedNode?.data.maxTokens
    setMaxTokensText(typeof m === 'number' ? String(m) : '')
    // 仅在选中项变化时同步；编辑过程中不回写，避免打断输入
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [selectedNodeId])
```

注意依赖数组是 `[selectedNodeId]`，**故意不包含 `selectedNode`**：

- 包含 `selectedNode`：每次输入导致 `nodes` 变化 → `selectedNode` 变化 → effect 重跑 → 文本被“当前值”覆盖（比如刚输入 `1.`，被覆盖成 `1`）；
- 不包含：只在切换节点时同步——**这正是我们想要的**。

代价：如果外部代码修改了选中节点的数值（如“重置表单”），文本态不会自动更新。当前没有这种操作，所以可接受。

> **面试考点 · 为什么这里可以关掉 `exhaustive-deps`？**
> lint 规则是**默认正确**，不是**永远正确**。关掉时必须回答两个问题：
>
> 1. 漏掉的依赖变化时，不重跑会怎样？—— 编辑过程中文本被覆盖（正是要避免的）；
> 2. 需要的场景怎么覆盖？—— 切换节点时 `selectedNodeId` 变化，会重跑。
>
> 如果答不上来，就不该关。**每一条 `eslint-disable` 都应该是一句可解释的设计决策，而不是“报错就关”。**

### 3.1 解析与删键

```tsx
  /**
   * 编辑 llm 数字字段（temperature / maxTokens）。
   *
   * - 文本先写进 state（保证输入过程不被数值化打断）；
   * - 非空且可解析为数字 → 写入 `data[field]`（number）；
   * - 留空或非法 → **删除该键**（不留字段 = 不发送）。
   */
  function changeLlmNumber(
    id: string,
    field: 'temperature' | 'maxTokens',
    raw: string,
    setText: (value: string) => void,
  ): void {
    setText(raw)
    const trimmed = raw.trim()
    if (trimmed === '' || Number.isNaN(Number(trimmed))) {
      setNodes((nds) =>
        nds.map((node) => {
          if (node.id !== id) return node
          const nextData = { ...node.data }
          delete nextData[field]
          return { ...node, data: nextData }
        }),
      )
      return
    }
    updateNodeData(id, { [field]: Number(trimmed) })
  }
```

为什么“删键”而不是赋 `undefined`：

```ts
const data = { temperature: undefined }
JSON.stringify({ data })      // → {"data":{}}   键消失了，效果一样
```

看起来等价，但：

- `{ temperature: undefined }` 在 TypeScript 里仍然**声明了该键**，`'temperature' in data` 为 `true`，`Object.keys` 也会包含它（值 undefined 的键存在于对象中）；
- 后续如果有 `Object.entries(data)` 做序列化/校验，会碰到 `undefined`；
- 保存到 JSONB 前如果走 `JSON.parse(JSON.stringify())`，键又消失——**行为依赖中间经过了什么**。

删键让状态**从一开始就是干净的**，不依赖序列化器的细节。

> **面试考点 · `Number('')` 是多少？`Number.isNaN('abc')` 呢？**
> ```js
> Number('')        // 0
> Number('  ')      // 0
> Number('abc')     // NaN
> Number('1.5')     // 1.5
> Number('1e3')     // 1000
> Number('0x10')    // 16
> ```
> 所以“空串”必须**在转数字之前**用 `trimmed === ''` 单独判断，否则空输入会变成 0。
> 另一个坑：`Number.isNaN` 是判断值是否为 `NaN`；`isNaN('abc')` 会先做类型转换，语义不同。校验代码一律用 `Number.isNaN(Number(x))`。

> **面试考点 · 前端要不要拦 `temperature = 999`？**
> 可以给**软提示**（比如输入框 `max` 提示），但不要硬拦：
>
> - 不同 provider 支持范围不同（0~1 / 0~2）；
> - 范围会随模型变化；
> - 真正的判定只有 provider 能做。
>
> 前端硬拦的风险：provider 支持 1.8，前端拦在 1.0，用户永远用不了。
> **前端校验的是“格式与明显错误”，取值范围交给最终执行方。**

## 4. 面板 JSX

```tsx
{selectedNode.type === 'llm' && (
  <>
    <div className="field">
      <label className="label">模型（留空则用环境变量 LLM_MODEL）</label>
      <input
        className="input"
        value={String(selectedNode.data.model ?? '')}
        onChange={(e) => updateNodeData(selectedNode.id, { model: e.target.value })}
      />
    </div>

    <div className="field">
      <label className="label">提示词（Prompt）</label>
      <textarea
        className="textarea textarea-mono"
        placeholder="支持 {{ inputs.xxx }} / {{ 节点id.字段 }} 模板"
        value={String(selectedNode.data.prompt ?? '')}
        onChange={(e) => updateNodeData(selectedNode.id, { prompt: e.target.value })}
        rows={6}
      />
    </div>

    <div className="field">
      <label className="label">系统消息（system，可空）</label>
      <textarea
        className="textarea textarea-mono"
        placeholder="可空；非空时作为 system 消息发送"
        value={String(selectedNode.data.system ?? '')}
        onChange={(e) => updateNodeData(selectedNode.id, { system: e.target.value })}
        rows={3}
      />
    </div>

    <div className="field">
      <label className="label">temperature（可空）</label>
      <input
        className="input"
        type="number"
        step="0.1"
        placeholder="留空则不发送"
        value={temperatureText}
        onChange={(e) =>
          changeLlmNumber(selectedNode.id, 'temperature', e.target.value, setTemperatureText)
        }
      />
    </div>

    <div className="field">
      <label className="label">maxTokens（可空）</label>
      <input
        className="input"
        type="number"
        min="1"
        placeholder="留空则不发送"
        value={maxTokensText}
        onChange={(e) =>
          changeLlmNumber(selectedNode.id, 'maxTokens', e.target.value, setMaxTokensText)
        }
      />
    </div>
  </>
)}
```

`String(... ?? '')` 的必要性：`data.model` 在类型上是 `unknown`，可能是 `undefined`。React 的受控输入不接受 `undefined`，会从“非受控”切到“受控”并报警告。

> **面试考点 · 为什么每次输入都 `setNodes(全量 map)`，性能没问题吗？**
> 节点数量是几十的量级，一次 `map` 是 O(n)，成本可忽略。
> 真正的成本在**重渲染**：`nodes` 变化会让 `<ReactFlow>` 重新计算受影响的节点。React Flow 内部做了 memo（按节点对象引用），只有被修改的节点会重渲染，其余节点对象引用不变。
> 所以这段代码的性能模型是：
>
> - `setNodes` 创建新数组 + 复制 n 个节点对象（浅）；
> - 只有目标节点是新对象，只有它重渲染。
>
> 如果节点上千，才需要把编辑态与画布态分离、或引入局部状态管理。**先让代码正确，再谈优化；但要能说出优化点在哪。**

> **面试考点 · `String(selectedNode.data.title ?? '')` 每次渲染都调用，浪费吗？**
> 不浪费——字符串拼接级别的开销，远小于 React 的 diff。
> 更值得关注的是**不要在渲染体里做重计算**（filter/map 大数组、解析大 JSON）。本项目把这些放进 `useMemo`（如 `selectedInputs`）。
> 判断标准：这段计算的复杂度是否随数据量增长到肉眼可见。**不是所有计算都值得 memo。**

## 5. 配置如何进入运行

面板改的是 `node.data`；保存时 `buildGraph(nodes, edges)` 会把 `data` **原样**写进图：

```ts
// 阶段 3 的 buildGraph（节选）
nodes: nodes.map((node) => ({
  id: node.id,
  type: node.type,
  position: { x: node.position.x, y: node.position.y },
  data: node.data,          // ← 面板改的字段在这里进入契约
})),
```

运行时 `runLlmNode` 读 `node.data`：

```ts
const data = node.data as unknown as LlmNodeData
const model = data.model ? data.model : (process.env.LLM_MODEL ?? '')
```

所以整条链路是：

```text
面板 → node.data → PUT /graph → apps.graph_json (JSONB)
     → 运行读 graphJson → llm 节点读 data.model/prompt/temperature
```

**没有任何“把参数再传给后端”的接口**——节点参数就是图的一部分。这也是为什么阶段 3 强调“图 JSON 是唯一真源”。

> **面试考点 · `title` 会传给模型吗？**
> 不会。`title` 只在画布/检查器里展示，`runLlmNode` 只读 `model` / `prompt` / `system` / `temperature` / `maxTokens`。
> 但 `title` 会存进 `graph_json` 并出现在发布快照里——**它属于业务数据，不属于 prompt**。
> 如果希望标题影响模型，必须显式写进 prompt 模板。**字段存在 ≠ 字段被使用，读代码时要看清消费点。**

## 7. 面试考点汇总

| 问题 | 答案要点 |
| --- | --- |
| 数字输入为什么要文本态 | `1.` 会被 `Number` 吞掉小数点；空串会变成 0 |
| 可选字段删键 | `undefined` 的键仍存在；序列化后才消失，行为依赖中间层 |
| `useEffect` 依赖省略 | 只在切换节点时同步文本；包含 `selectedNode` 会打断输入 |
| `exhaustive-deps` | 关掉必须能解释“漏了会怎样、场景怎么覆盖” |
| 每次输入全量 `setNodes` | 节点数十级别可接受；React Flow 按引用 memo，只重渲染目标节点 |
| 保存时机 | 编辑态 ≠ 提交态；显式保存避免半截 prompt 入库 |
| 前端数值范围 | 只做格式/明显错误；范围由 provider 决定 |
| 浅合并 vs 深合并 | 深合并无法表达删除数组元素 |
| `title` 是否参与运行 | 不参与；只用于展示，但会进图 JSON |
| 参数如何到后端 | 随 `graph_json` 保存；运行读图，无独立参数接口 |

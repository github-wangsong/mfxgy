## 3. 根 package.json

**完整文件路径：`package.json`（仓库根）**

> `jsonc` 里的 `//` 只为讲解；真实 JSON 文件不能带注释，复制时删掉。

```jsonc
{
  // 仓库名：所有 workspace 包都归这个根管理
  "name": "mini-dify",
  // 根包不发布，版本仅占位
  "version": "0.0.0",
  // private=true：防止误把根包发布到 npm
  "private": true,
  // 钉死本仓库使用的 pnpm 版本；Corepack 会读这个字段，环境版本由文件决定
  "packageManager": "pnpm@12.10.1",
  "scripts": {
    // 编译契约包：先产出 dist/index.js + index.d.ts，api-ts 才能 import 到类型
    "build:contract": "pnpm --filter @mini-dify/contract build",
    // 启动 NestJS：先编译契约，再进 api-ts 跑 nest start --watch
    "dev:api-ts": "pnpm run build:contract && pnpm --filter @mini-dify/api-ts start:dev",
    // 启动 FastAPI：--directory 先把工作目录切到 apps/api-py，再执行模块入口
    "dev:api-py": "uv run --directory apps/api-py python -m app.main",
    // 启动 Next.js：端口固定写在 apps/web/package.json（3000）
    "dev:web": "pnpm --filter @mini-dify/web dev"
  }
}
```

## 4. pnpm-workspace.yaml

**完整文件路径：`pnpm-workspace.yaml`**

```yaml
# pnpm 的 workspace 清单：告诉 pnpm「哪些目录是子包」
packages:
  # 所有应用：api-ts / api-py（不参与 pnpm 依赖，只占目录）/ web
  - apps/*
  # 所有共享包：contract
  - packages/*
```

> `apps/api-py` 是 Python 项目，pnpm 不会装它的依赖，只是把它当成目录；Python 依赖由 uv 管。

> **面试考点 · pnpm 为什么比 npm 快、省磁盘、更严格？**
>
> - **全局 store + 内容寻址**：pnpm 把包按内容哈希解压到全局 store；项目 `node_modules` 里是指向 store 的**硬链接**（同盘）或符号链接。同一版本在 10 个项目里只存一份，npm 则每个项目各存一份。
> - **严格依赖树**：npm 会把依赖**扁平化提升**到顶层 `node_modules`，于是你能 import 到没写进 `package.json` 的包（幽灵依赖）；pnpm 的顶层只暴露你**声明过**的依赖，没声明就报错。
> - **monorepo 一等公民**：`pnpm-workspace.yaml` 声明包范围，`workspace:*` 建立本地软链，`pnpm --filter <包名>` 精确执行某个子包脚本。`--filter` 是 CI 里做增量构建的基础。
> - **版本钉死**：根 `packageManager: "pnpm@12.10.1"` 让 Corepack 自动选择这个 pnpm 版本，避免「同事用 pnpm 8、你用 pnpm 10」导致锁文件格式不一致。
>
> **追问：为什么 `node_modules/.pnpm` 里有真实目录，顶层却是链接？**
> `.pnpm` 是虚拟 store（每个包版本一个目录），顶层是符号链接，用来实现「严格可见性」；硬链接指向全局 store，所以文件内容不重复。
>
> **追问：monorepo 的代价？**
> 依赖版本容易漂移、CI 需要缓存与增量、权限边界变弱；所以本项目只把「跨包共享」的契约放进 `packages/`，应用之间不互相 import。

## 5. Docker 只跑数据库

**完整文件路径：`docker-compose.yml`**

```yaml
# 本地开发中间件：只跑 PostgreSQL；三个应用全部在宿主机本地运行
services:
  db:
    # 官方 pgvector 镜像：PostgreSQL 16 + vector 扩展，免去手工编译
    image: pgvector/pgvector:pg16
    # 固定容器名，方便 docker exec / 日志排查
    container_name: mini-dify-db
    # 除非手动 stop，否则异常退出自动重启
    restart: unless-stopped
    environment:
      # 数据库用户名；${VAR:-默认值} = 读 .env，没有就用默认值
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      # 数据库密码
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-difyai123456}
      # 首次启动时自动创建的库名
      POSTGRES_DB: ${POSTGRES_DB:-minidify}
    ports:
      # 宿主机端口:容器端口；宿主机端口可由 .env 覆盖，避免和本机已有 PG 冲突
      - "${POSTGRES_PORT:-5432}:5432"
    volumes:
      # 命名卷：容器删了数据还在（卷由 Docker 管理，不落在仓库目录）
      - db_data:/var/lib/postgresql/data
    healthcheck:
      # 健康检查命令：pg_isready 返回 0 表示数据库可接受连接
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-minidify}"]
      # 每 5 秒检查一次
      interval: 5s
      # 单次检查超时 3 秒
      timeout: 3s
      # 连续失败 12 次才标记 unhealthy
      retries: 12

volumes:
  # 声明命名卷；compose 会自动创建
  db_data:
```
**完整文件路径：`.env.example`（仓库根）**

```bash
# 中间件变量：只给 docker-compose.yml 做变量替换
# 使用：Copy-Item .env.example .env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=difyai123456
POSTGRES_DB=minidify
POSTGRES_PORT=5432
```

> 应用自己的连接串不放根 `.env`：Prisma 与 SQLAlchemy 的连接串格式不同，必须各自放在 `apps/api-ts/.env` 与 `apps/api-py/.env`。

## 6. 各应用的 env 样例

**完整文件路径：`apps/api-ts/.env.example`**

```bash
# NestJS 监听端口
PORT=3001
# 数据库连接串（阶段 1 接入 Prisma 后才使用；Prisma 的格式不带 +driver）
DATABASE_URL="postgresql://postgres:difyai123456@localhost:5432/minidify"
```

**完整文件路径：`apps/api-py/.env.example`**

```bash
# FastAPI 监听端口
PORT=8000
# 数据库连接串（阶段 1 接入 SQLAlchemy 后才使用；SQLAlchemy 必须显式写驱动 +psycopg）
DATABASE_URL=postgresql+psycopg://postgres:difyai123456@localhost:5432/minidify
```

**完整文件路径：`apps/web/.env.example`**

```bash
# 前端请求的后端地址；切换后端只改这一行，页面代码不动
NEXT_PUBLIC_API_BASE=http://localhost:3001
# 切到 Python 后端时改成：
# NEXT_PUBLIC_API_BASE=http://localhost:8000
```

## 7. 启动数据库并安装依赖

```powershell
# 1) 生成根 .env（docker compose 会读它）
Copy-Item .env.example .env

# 2) 启动 PostgreSQL + pgvector；-d = 后台
docker compose up -d db

# 3) 看状态：STATUS 列应出现 (healthy)
docker compose ps

# 4) 验证 vector 扩展可用
docker exec mini-dify-db psql -U postgres -d minidify -c "CREATE EXTENSION IF NOT EXISTS vector;"
docker exec mini-dify-db psql -U postgres -d minidify -c "\dx"
```

`\dx` 的输出里应有一行 `vector`。

```powershell
# 安装所有 workspace 的 JS 依赖（在仓库根执行，会读取 apps/* 与 packages/*）
pnpm install
```

> 阶段 0 还没有 Prisma，所以不需要 `allowBuilds`；阶段 1 加 Prisma 时再补。

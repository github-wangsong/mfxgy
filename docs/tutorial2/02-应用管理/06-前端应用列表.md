# 06 · 前端应用列表（应用管理）

> 阶段 2 · 第 6 步
>
> 做完：`/apps` 能列出当前用户的应用、新建、删除；列表与创建响应都过 Zod；未登录或 401 自动回 `/login`；切换后端后只能看到各自账号名下的数据。
>
> **本篇面试考点**：`useCallback` + `useEffect` 的依赖稳定性 · 请求竞态与 `cancelled` 标志 · 为什么先判 401 再解析 body · 204 不能 `res.json()` · 时间格式化的水合陷阱 · 写操作后为什么重新拉列表 · 空串 vs `undefined` 的语义。

---

## 1. 页面职责

| 动作 | 请求 | 处理后 |
| --- | --- | --- |
| 进入页面 | `GET /apps` | Zod 校验 → 渲染卡片 |
| 新建 | `POST /apps` | 清空表单 → 重新拉列表 |
| 删除 | `DELETE /apps/{id}` | 重新拉列表 |
| 未登录 / 401 | — | `router.replace('/login')` |

页面是**客户端组件**：token 在 `localStorage`，只有浏览器能读。

## 2. 用到的 schema

**完整文件路径：`apps/web/lib/schemas.ts`**（应用相关节选）

```ts
// ---------------------------------------------------------------------------
// 应用
// ---------------------------------------------------------------------------

/** 应用模式。 */
export const appModeSchema = z.enum(['chatflow', 'workflow'])

/** 应用对外视图。 */
export const appResponseSchema = z.strictObject({
  id: z.string(),
  name: z.string(),
  /** 契约里 description 不在 required 中：允许省略，也允许显式 null。 */
  description: z.string().nullable().optional(),
  mode: appModeSchema,
  ownerId: z.string(),
  createdAt: utcTimestampSchema,
  updatedAt: utcTimestampSchema,
})

/** GET /apps 的响应体。 */
export const appListResponseSchema = z.strictObject({
  items: z.array(appResponseSchema),
})

export type AppMode = z.infer<typeof appModeSchema>
export type AppResponse = z.infer<typeof appResponseSchema>
export type AppListResponse = z.infer<typeof appListResponseSchema>
```

> `description` 写成 `.nullable().optional()`：契约的 `required` 里没有它，理论上键可以缺失；但两套后端实际都会返回（空值为 `null`）。**按契约字面放宽，按实现行为使用。**

## 3. 页面完整代码

**完整文件路径：`apps/web/app/apps/page.tsx`**

```tsx
'use client'

import { useCallback, useEffect, useRef, useState, type FormEvent } from 'react'
import { useRouter } from 'next/navigation'

import { parseResponse, readApiErrorMessage } from '@/lib/api'
import {
  appListResponseSchema,
  appModeSchema,
  type AppMode,
  type AppResponse,
} from '@/lib/schemas'

const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? 'http://localhost:3001'

/** 把 ISO 时间切成可读的「YYYY-MM-DD HH:mm:ss」，避免服务端/客户端时区差异导致的水合不一致。 */
function formatTime(value: string): string {
  // 不用 new Date().toLocaleString()：服务端与浏览器时区不同会让 SSR 与 hydration 结果不一致
  return value.slice(0, 19).replace('T', ' ')
}

/** 应用列表页：读 token → GET /apps；支持新建与删除；未登录引导去 /login。 */
export default function AppsPage() {
  const router = useRouter()

  // 列表数据；类型来自 Zod 推导，不是手写 interface
  const [apps, setApps] = useState<AppResponse[]>([])
  // 统一的错误提示（加载 / 创建 / 删除共用）
  const [error, setError] = useState<string | null>(null)
  // 初次加载中：用于显示骨架/占位，避免闪一下“暂无应用”
  const [loading, setLoading] = useState(true)

  // 新建表单的三个字段
  const [name, setName] = useState('')
  const [description, setDescription] = useState('')
  const [mode, setMode] = useState<AppMode>('chatflow')
  // 表单展开状态
  const [showForm, setShowForm] = useState(false)
  // 展开后自动聚焦名称输入框
  const nameInputRef = useRef<HTMLInputElement>(null)

  const loadApps = useCallback(async (): Promise<void> => {
    // 每次请求都重新读，避免组件挂载时 token 还没写入
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      // replace：不把受保护页留在历史栈里，避免后退来回跳
      router.replace('/login')
      return
    }
    const res = await fetch(`${API_BASE}/apps`, {
      headers: { Authorization: `Bearer ${token}` },
    })
    // 先判 401：此时响应体是错误体，交给 parseResponse 只会得到“契约不符”的次生错误
    if (res.status === 401) {
      router.replace('/login')
      return
    }
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    // 200 也要校验：HTTP 成功不代表 body 符合契约
    const data = await parseResponse(res, appListResponseSchema, 'GET /apps')
    setApps(data.items)
  }, [router])

  useEffect(() => {
    // cancelled 解决两件事：组件卸载后不再 setState；StrictMode 下第一次请求的结果被丢弃
    let cancelled = false
    loadApps()
      .catch((err: unknown) => {
        if (!cancelled) setError(err instanceof Error ? err.message : String(err))
      })
      .finally(() => {
        if (!cancelled) setLoading(false)
      })
    return () => {
      cancelled = true
    }
  }, [loadApps])

  useEffect(() => {
    // showForm 从 false → true 时，DOM 已挂载，可以安全聚焦
    if (showForm) nameInputRef.current?.focus()
  }, [showForm])

  async function handleCreate(event: FormEvent<HTMLFormElement>): Promise<void> {
    // 阻止表单默认提交（整页刷新）
    event.preventDefault()
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      router.replace('/login')
      return
    }
    setError(null)
    const res = await fetch(`${API_BASE}/apps`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
      // 空描述发 undefined：JSON.stringify 会丢掉这个键，
      // 后端就不会把空串写进库（库里用 NULL 表示“没填”）
      body: JSON.stringify({ name, description: description === '' ? undefined : description, mode }),
    })
    if (!res.ok) {
      // 400/401/500 都读契约错误体的 message
      setError(await readApiErrorMessage(res))
      return
    }
    // 成功：清空表单
    setName('')
    setDescription('')
    setMode('chatflow')
    // 重新拉列表，而不是本地 push：排序、时间戳、服务端默认值都以服务端为准
    await loadApps().catch((err: unknown) => setError(err instanceof Error ? err.message : String(err)))
  }

  async function handleDelete(id: string): Promise<void> {
    const token = localStorage.getItem('accessToken')
    if (token === null) {
      router.replace('/login')
      return
    }
    setError(null)
    const res = await fetch(`${API_BASE}/apps/${id}`, {
      method: 'DELETE',
      headers: { Authorization: `Bearer ${token}` },
    })
    if (!res.ok) {
      setError(await readApiErrorMessage(res))
      return
    }
    // 204 没有响应体：这里绝不能 res.json()，否则会抛 Unexpected end of JSON input
    await loadApps().catch((err: unknown) => setError(err instanceof Error ? err.message : String(err)))
  }

  return (
    <main className="app-main">
      <div className="page-head">
        <div>
          <h1 className="page-title">应用</h1>
          <p className="page-sub">
            {loading ? '正在加载应用…' : `共 ${apps.length} 个应用，可进入画布编排流程。`}
          </p>
        </div>
        <button
          type="button"
          className="btn btn-primary"
          onClick={() => setShowForm((open) => !open)}
        >
          新建应用
        </button>
      </div>

      <div className="stack">
        {error !== null && <div className="alert alert-error">操作失败：{error}</div>}

        {showForm && (
          <section className="card">
            <div className="card-head">
              <h2 className="section-title">新建应用</h2>
            </div>
            <form onSubmit={handleCreate} className="card-body stack stack--sm">
              <div className="row">
                <div className="field grow">
                  <label className="label" htmlFor="app-name">
                    名称
                  </label>
                  <input
                    id="app-name"
                    ref={nameInputRef}
                    className="input"
                    value={name}
                    onChange={(e) => setName(e.target.value)}
                    required
                    // 与后端 DTO 的 @Length(1, 64) 对齐：前端先挡一层，后端仍然会校验
                    maxLength={64}
                  />
                </div>
                <div className="field grow">
                  <label className="label" htmlFor="app-description">
                    描述（可选）
                  </label>
                  <input
                    id="app-description"
                    className="input"
                    value={description}
                    onChange={(e) => setDescription(e.target.value)}
                    maxLength={256}
                  />
                </div>
                <div className="field grow">
                  <label className="label" htmlFor="app-mode">
                    模式
                  </label>
                  <select
                    id="app-mode"
                    className="select"
                    value={mode}
                    onChange={(e) => {
                      // 下拉值来自 DOM，是字符串；用契约枚举校验后再写入状态。
                      const parsed = appModeSchema.safeParse(e.target.value)
                      if (parsed.success) setMode(parsed.data)
                    }}
                  >
                    <option value="chatflow">chatflow</option>
                    <option value="workflow">workflow</option>
                  </select>
                </div>
              </div>
              <div className="row">
                <button type="submit" className="btn btn-primary">
                  创建应用
                </button>
              </div>
            </form>
          </section>
        )}

        {loading && <div className="empty">加载中…</div>}

        {!loading && apps.length === 0 && (
          <div className="card">
            <div className="empty">暂无应用，点击右上角「新建应用」开始。</div>
          </div>
        )}

        {!loading && apps.length > 0 && (
          <div className="grid-cards">
            {apps.map((app) => (
              // key 用稳定主键，不用数组下标：删除后下标会错位，React 会复用错组件状态
              <article key={app.id} className="card card--interactive">
                <div className="card-head">
                  <h2 className="section-title truncate">{app.name}</h2>
                  <span className="badge badge-brand mono">{app.mode}</span>
                </div>
                <div className="card-body stack stack--sm">
                  {app.description != null && app.description !== '' ? (
                    <p className="muted">{app.description}</p>
                  ) : (
                    <p className="faint">无描述</p>
                  )}
                  <p className="faint mono">创建于 {formatTime(app.createdAt)}</p>
                </div>
                <div className="card-foot row row--between">
                  <a className="btn btn-sm" href={`/apps/${app.id}`}>
                    打开画布
                  </a>
                  <button
                    type="button"
                    className="btn btn-sm btn-danger"
                    // void：把 Promise 明确标记为“不等待”，避免 lint 的 floating promise 警告
                    onClick={() => void handleDelete(app.id)}
                  >
                    删除
                  </button>
                </div>
              </article>
            ))}
          </div>
        )}
      </div>
    </main>
  )
}
```

## 4. 关键点

> **面试考点 · `loadApps` 为什么要 `useCallback`？**
> 它被 `useEffect` 当依赖。如果每次渲染都创建新函数，`useEffect` 会认为依赖变了 → 重新执行 → `setState` → 再渲染 → 再创建新函数，形成**无限请求循环**。
> `useCallback(..., [router])` 让函数在 `router` 不变时保持同一引用。`router` 来自 `useRouter()`，在 App Router 里是稳定对象。
>
> **追问：那直接把请求写在 `useEffect` 里不行吗？**
> 行，但 `handleCreate` / `handleDelete` 成功后也要重新拉列表，抽成 `loadApps` 才能复用。**复用的代价是依赖必须稳定，这就是 `useCallback` 的来源。**

> **面试考点 · `cancelled` 标志解决了什么？**
> 两个问题：
>
> 1. **卸载后 `setState`**：用户在请求返回前离开页面，React 会警告“在未挂载组件上更新状态”（旧版本报错，18+ 虽不报但仍是无意义更新）。
> 2. **竞态**：快速切换筛选/重复请求时，先发出的请求可能后返回，把新数据覆盖成旧数据。
>
> 模式固定为：`let cancelled = false` → 异步回调里判断 → cleanup 里置 `true`。
> React 18 的 StrictMode 在开发环境会**故意挂载 → 卸载 → 再挂载**，用来暴露缺少清理的副作用。没有 `cancelled` 的代码在这里会暴露问题。
>
> **追问：`AbortController` 呢？**
> 更彻底：直接取消请求，省掉网络与解析开销。`cancelled` 只是“忽略结果”。两者常一起用，本项目为了简洁只用标志位。

> **面试考点 · 为什么先判断 `res.status === 401`，再 `parseResponse`？**
> 401 的响应体是错误体（`{statusCode, message, error}`），不是 `AppListResponse`。如果先 `parseResponse`，会得到一个“响应不符合契约”的错误，把真正的“登录过期”信息盖掉。
> 顺序应该是：**先按状态码分流（401 跳登录、其它非 2xx 抛错），2xx 再做契约校验。**

> **面试考点 · 删除返回 204，为什么不能 `res.json()`？**
> 204 表示“成功且无响应体”。`res.json()` 会尝试解析空字符串，抛 `Unexpected end of JSON input`。正确做法是只看 `res.ok`，然后重新拉列表。
> 这一点也说明：**HTTP 客户端不能假设“成功就一定有 JSON”。**

> **面试考点 · 创建成功后为什么重新请求列表，而不是 `setApps([...apps, data])`？**
> 本地追加看起来更快，但会和服务器产生分歧：
>
> - 列表排序由服务端决定（`createdAt desc`），本地追加的位置可能不对；
> - `createdAt` / `updatedAt` / `description` 的最终值由服务端生成，本地拼的可能是旧值；
> - 多标签页、其他客户端同时操作时，本地状态已经过期。
>
> 重新拉一次是“**以服务端为唯一真源**”的简单做法。数据量大时再考虑乐观更新 + 版本号/ETag。

> **面试考点 · 时间为什么用 `slice(0, 19)` 而不是 `new Date(...).toLocaleString()`？**
> `toLocaleString()` 依赖**运行环境的时区与 locale**：服务端渲染时是 UTC（或服务器时区），浏览器 hydration 时是用户本地时区，两边 HTML 不一致 → React hydration mismatch。
> `slice(0, 19)` 是对字符串做确定性截断，服务端与客户端结果必然相同。代价是**显示的是 UTC 时间**，不是用户本地时间。
> 如果必须显示本地时间，正确姿势是：先渲染 UTC/占位，在 `useEffect` 里再转本地时间（此时只在客户端执行），或给元素加 `suppressHydrationWarning`。
>
> **追问：`slice(0, 19)` 拿到的是什么？**
> `2026-10-18T03:20:11.482Z` 的前 19 个字符是 `2026-10-18T03:20:11`，再把 `T` 换成空格。毫秒和 `Z` 被丢掉——展示够用，但**不要用它回传服务端**，精度和时区信息都丢了。

> **面试考点 · `description === '' ? undefined : description` 的意义？**
> `JSON.stringify({ description: undefined })` 会把键**整个丢掉**，请求体里就没有 `description`，后端不会写入空串。
> 如果直接发 `""`：数据库会存一个空字符串，`description` 就有 `null` 和 `""` 两种“空”，前端判断要写两遍（本项目已经写了两遍：`!= null && !== ''`）。
> **空值只保留一种表示**（这里是 `null`），是数据建模的基本纪律；前端在边界处做归一化，后端就不必猜。

> **面试考点 · 为什么 `select` 的 `onChange` 还要 `safeParse`？**
> `e.target.value` 的类型是 `string`，不是 `AppMode`。直接 `setMode(e.target.value as AppMode)` 是编译期撒谎：如果有人改了 `<option>` 的值，运行期就会出现非法状态。
> `appModeSchema.safeParse` 在运行期确认它是两个合法值之一，失败就忽略。**凡是来自 DOM / 网络 / localStorage 的值，都当不可信输入。**

> **面试考点 · 创建/删除遇到 401 会怎样？**
> 当前实现里，`handleCreate` / `handleDelete` 只把 401 的文案显示出来，没有跳登录页（只有 `loadApps` 会跳）。这是阶段 2 的简化。
> 生产里应该把 `fetch` 封装成统一客户端：自动带 token、统一处理 401、统一解析错误体。**重复的请求样板是 bug 的温床**——三处各写一遍，就有一处会漏。

## 5. 验证

```powershell
# 两个后端任选其一；先用 3001
pnpm --filter @mini-dify/web dev
```

浏览器：

```text
1. 未登录直接访问 http://localhost:3000/apps → 自动跳 /login
2. 用 alice@example.com / password123 登录 → 进入 /apps
3. 右上角「新建应用」→ 名称填 support-bot，模式选 chatflow → 创建
   - Network 里 POST /apps 返回 201
   - 列表出现新卡片，描述显示「无描述」，创建时间是 UTC
4. 再建一个，模式选 workflow → 新卡片排在最前（createdAt desc）
5. 点「删除」→ Network 里 DELETE /apps/{id} 返回 204
   - 卡片消失；如果删光，显示「暂无应用」
6. 把名称留空提交 → 浏览器 required 拦住（不会发请求）
7. DevTools → Application → Local Storage 删除 accessToken → 刷新 /apps
   → 自动跳 /login
```

### 5.1 验证归属隔离与双后端

```powershell
# 1. 停掉 dev server，把 apps/web/.env.local 改成 8000
NEXT_PUBLIC_API_BASE=http://localhost:8000

# 2. 重启（NEXT_PUBLIC_* 是构建期内联）
pnpm --filter @mini-dify/web dev
```

```text
3. 用 bob 登录 → /apps 只显示 bob 的应用，看不到 alice 的
4. 用 bob 新建一个应用 → 成功
5. 把 .env.local 改回 3001、重启、用 bob 登录
   → 刚才在 api-py 建的应用仍然在（同一张表）
```

这个来回切换说明：**前端只依赖契约，不依赖具体后端；数据归属由 token 决定，不由前端决定。**

## 6. 阶段 2 验收清单

| 检查项 | 期望 |
| --- | --- |
| `POST /apps`（两端） | 201，`mode` 默认 `chatflow` |
| `GET /apps`（两端） | 只返回自己的，`createdAt` 倒序 |
| `GET /apps/{id}` 越权 | 404 `App not found` |
| `PATCH /apps/{id}` | 只改传入字段；显式 `null` 可清空描述 |
| `DELETE /apps/{id}` | 204，无 body |
| 无 token / 伪 token | 401 |
| 多传 `ownerId` | 400 `ownerId should not exist` |
| 跨后端 | 同一 `id` 可在两套后端读写 |
| 前端 | 未登录回跳、创建、删除、空状态、错误可读 |

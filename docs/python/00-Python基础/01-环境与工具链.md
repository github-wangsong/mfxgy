## 3. Python 是什么

### 3.1 一句话定位

> Python 是一门**解释型、动态类型、自带电池**的通用编程语言。

拆开看这三个词：

| 特性 | 含义 | 对照 TypeScript |
| --- | --- | --- |
| 解释型 | 代码不先整体编译成机器码，而是由解释器逐行读取、编译成字节码后执行 | TS 要先 `tsc` 编译成 JS 再跑 |
| 动态类型 | 变量不需要声明类型，运行时才确定对象类型 | TS 是静态类型（编译期检查） |
| 自带电池 | 标准库覆盖文件、网络、JSON、并发、测试等，开箱即用 | Node 需要大量 npm 包 |

### 3.2 CPython：你装的「Python」到底是什么

Python 是一门**语言规范**，具体实现有多种。你从官网下载的是 **CPython**——用 C 写的官方参考实现，也是绝大多数生产环境的默认选择。

```
你写的 .py 源码
      │  ① 词法/语法分析
      ▼
    AST（抽象语法树）
      │  ② 编译
      ▼
  字节码 .pyc（平台无关）
      │  ③ CPython 虚拟机逐条执行
      ▼
   运行结果
```

关键点：**字节码不是机器码**，它仍需 CPython 虚拟机解释执行。这也是 Python 比 C 慢、但开发效率高的根本原因。

> 对照：Node 的 V8 会把 JS 热点代码 JIT 编译成机器码，所以纯计算场景 JS 通常快于 Python；但 Python 的计算密集场景通常交给 NumPy/Polars 等 C 扩展，而不是纯 Python 循环。

### 3.3 版本选择：为什么要 3.12+

本项目 `apps/api-py/pyproject.toml` 明确要求：

```toml
requires-python = ">=3.12"
```

原因：

- 3.11+ 的 `asyncio.TaskGroup`、异常组 `except*` 是异步代码的重要工具；
- 3.12 的 f-string 语法增强、类型参数语法（`class Foo[T]`）更现代；
- 生态（FastAPI / SQLAlchemy 2.0 / LangGraph）对新版本支持良好；
- 低版本会遇到 `requires-python` 不满足、包解析直接失败。

**结论**：装 **3.12**（或更高稳定版），不要用 3.8/3.9 学本系列。

## 4. 安装 Python（Windows）

### 4.1 方式一：官网安装器（推荐给新手）

1. 打开 https://www.python.org/downloads/windows/ ，下载 **Python 3.12.x** 的 64-bit installer。
2. 运行安装器，**务必勾选** `Add python.exe to PATH`。
3. 选择 `Install Now`（默认会装 pip、venv、IDLE）。
4. 装完重开一个终端。

### 4.2 方式二：winget（命令行）

```powershell
winget install --id Python.Python.3.12 -e
```

### 4.3 验证

```powershell
python --version
```

预期输出（版本号可能略高）：

```
Python 3.12.11
```

再看解释器实际路径，**这一步很重要**——后面排查「装了但用不上」全靠它：

```powershell
where.exe python
```

预期输出类似：

```
C:\Users\<你>\AppData\Local\Programs\Python\Python312\python.exe
C:\Users\<你>\AppData\Local\Microsoft\WindowsApps\python.exe
```

> 如果出现多行，`where.exe` 的**第一行**就是实际生效的那个。第二行的 `WindowsApps\python.exe` 是微软商店的占位程序，常导致「输入 python 却弹出应用商店」。

顺便确认包管理器可用：

```powershell
python -m pip --version
```

预期：

```
pip 24.x from ... (python 3.12)
```

> 为什么用 `python -m pip` 而不是直接 `pip`？
> `pip` 是独立可执行文件，可能属于**另一个** Python 安装；`python -m pip` 强制「用当前这个解释器自带的 pip」，永远对得上。这是本系列的统一写法。

## 5. 虚拟环境 venv（首次教学）

### 5.1 为什么必须要虚拟环境

Python 的依赖**默认装在解释器全局目录**（`site-packages`）。两个项目都要 `fastapi`，但一个要 0.110、一个要 0.115，就会互相覆盖——这就是「依赖地狱」。

`venv` 的做法：**给每个项目复制一份独立的解释器目录**，项目内的包只装进这份副本。

| 概念 | 对照 Node.js |
| --- | --- |
| 全局 `site-packages` | 全局 `npm i -g` 的包 |
| `venv` 虚拟环境 | 项目内的 `node_modules` |
| `venv` 被 Git 忽略 | `node_modules` 被 Git 忽略 |

### 5.2 创建与使用

在你自己的练习目录（不要用项目目录）执行：

```powershell
mkdir D:\practice\py-demo
python -m venv D:\practice\py-demo\.venv
```

命令拆解：

| 部分 | 含义 |
| --- | --- |
| `python -m venv` | 用当前解释器运行标准库 `venv` 模块 |
| `D:\practice\py-demo\.venv` | 目标目录，惯例命名为 `.venv`（点开头，隐藏且易识别） |

创建后目录长这样：

```
py-demo\
└── .venv\
    ├── Scripts\
    │   ├── python.exe        ← 这份环境自己的解释器
    │   ├── pip.exe
    │   └── Activate.ps1      ← 激活脚本
    ├── Lib\site-packages\    ← 这份环境自己的第三方包
    └── pyvenv.cfg            ← 环境元信息（指向基础解释器）
```

### 5.3 激活

```powershell
& D:\practice\py-demo\.venv\Scripts\Activate.ps1
```

激活成功后，提示符前会出现 `(.venv)`：

```
(.venv) PS D:\practice\py-demo>
```

退出：

```powershell
deactivate
```

> **Windows 执行策略坑**：如果报 `无法加载文件 Activate.ps1，因为在此系统上禁止运行脚本`，这是 PowerShell 的执行策略限制，**不是 Python 问题**。
> 推荐做法：**不改系统策略**，直接不激活——用 `uv run`（§6）或显式调用 `.\.venv\Scripts\python.exe`。若确实要激活，可只对当前窗口放行：
> ```powershell
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
> ```
> `-Scope Process` 只影响当前终端窗口，关闭即失效，风险最小。**不要**改成 `LocalMachine` 全局放行。

### 5.4 验证隔离生效

```powershell
(.venv) PS D:\practice\py-demo> python -m pip install requests
(.venv) PS D:\practice\py-demo> python -c "import requests; print(requests.__file__)"
```

预期：路径包含 `py-demo\.venv\Lib\site-packages\...`——证明包装进了**这个**环境。

再看全局是否被污染（新开一个**没激活**的终端）：

```powershell
python -c "import requests"
```

预期：`ModuleNotFoundError: No module named 'requests'`——说明隔离成功。

## 6. 依赖管理：pip 与 uv

### 6.1 pip + requirements.txt（传统方式）

```powershell
python -m pip install fastapi
python -m pip freeze > requirements.txt
python -m pip install -r requirements.txt
```

局限：

- **没有锁定文件语义**：`freeze` 记录的是当前装了什么，不含「为什么装」的依赖树；
- **慢**：逐包下载、解析、安装，没有并行；
- **不区分运行时/开发依赖**（要靠 `requirements-dev.txt` 人工约定）。

### 6.2 uv（现代方式，本项目采用）

`uv` 是 Rust 写的包管理器，速度比 pip 快一个数量级，并且原生支持锁文件与依赖分组。本项目 `apps/api-py` 目录里就有：

```
apps/api-py/
├── pyproject.toml     ← 依赖声明（人写）
├── uv.lock            ← 锁文件（工具写，精确到每个包的哈希）
├── .venv/             ← 虚拟环境（uv 自动创建，不入库）
└── app/               ← 源码
```

**常用命令**

| 命令 | 作用 | 对照 npm |
| --- | --- | --- |
| `uv init` | 初始化新项目（生成 `pyproject.toml`） | `npm init` |
| `uv add fastapi` | 加依赖并写入 `pyproject.toml`、更新 `uv.lock` | `npm install fastapi` |
| `uv add --dev pytest` | 加开发依赖（进 `[dependency-groups].dev`） | `npm i -D` |
| `uv sync` | 按 `uv.lock` 把环境装到与锁文件完全一致 | `npm ci` |
| `uv run python main.py` | 在项目环境里执行命令（自动确保环境同步） | `npx` / `npm run` |
| `uv lock` | 重新解析并生成锁文件 | `npm install`（更新 lock） |

### 6.3 用 uv 复现项目环境

```powershell
cd apps/api-py
uv sync
```

`uv sync` 会读 `pyproject.toml` + `uv.lock`，创建/更新 `.venv` 到**完全一致**的版本。预期最后几行类似：

```
Resolved 68 packages in 3ms
Installed 68 packages in 1.24s
 + fastapi==0.115.x
 + uvicorn==0.30.x
 ...
```

> **`uv sync` 与 `npm ci` 的心智一致**：锁文件说了算，不重新解析版本。团队协作、CI 都应该用 `sync` 而不是「随手 install」。

### 6.4 运行项目

```powershell
uv run python -c "import fastapi; print(fastapi.__version__)"
```

预期：打印出 FastAPI 版本号，且**不需要手动激活 venv**——`uv run` 自动使用项目环境。

## 7. 读懂 pyproject.toml（首次教学）

完整文件路径：`apps/api-py/pyproject.toml`

```toml
[project]
name = "mini-dify-api-py"
version = "0.1.0"
description = "mini-dify Python 后端（FastAPI + SQLAlchemy 2.0），与 api-ts 实现同一份契约。"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.115.0",
    "uvicorn[standard]>=0.30.0",
    "pydantic>=2.9.0",
    "pydantic-settings>=2.5.0",
    "email-validator>=2.2.0",
    "sqlalchemy>=2.0.30",
    "psycopg[binary]>=3.2.0",
    "pyjwt>=2.9.0",
    "bcrypt>=4.2.0",
    "langgraph>=1.2.16",
    "langchain-openai>=1.0.0",
    "httpx>=0.28.1",
    "pgvector>=0.5.1",
    "python-multipart>=0.0.32",
    "langchain-text-splitters>=1.1.3",
]

[dependency-groups]
dev = [
    "pytest>=8.3.0",
    "ruff>=0.6.0",
]
```

逐段解释：

| 段 | 含义 | 对照 `package.json` |
| --- | --- | --- |
| `[project]` | 元信息 + 运行时依赖，标准来自 **PEP 621** | 顶层 `name`/`version` |
| `name` / `version` | 包名与版本（不是 PyPI 发布也能填） | 同名字段 |
| `requires-python` | 允许的解释器版本范围 | `engines.node` |
| `dependencies` | 运行时依赖，`包名>=版本` | `dependencies` |
| `[dependency-groups] dev` | 开发依赖分组（PEP 735） | `devDependencies` |

两个语法细节：

1. **`uvicorn[standard]` 的方括号是「extras」**：装 `uvicorn` 的同时装它推荐的可选依赖（`uvloop`、`httptools` 等，用于性能）。对照 npm 就是 `npm i uvicorn` 再加一组可选包，只是 Python 用方括号声明。
2. **`>=0.115.0` 是下限而非精确版本**：精确版本由 `uv.lock` 锁定。这正好对应 `package.json` 写范围、`package-lock.json` 写精确版本的分工。

> 阶段 3/01 会详细讲 `pyproject.toml` 的其余字段（`[build-system]`、`[tool.ruff]`、可选依赖、workspace），这里只需先建立「声明 vs 锁定」的分层认知。

## 8. 四种运行方式

| 方式 | 命令 | 用途 |
| --- | --- | --- |
| 运行文件 | `python main.py` | 最常用 |
| 运行模块 | `python -m app.main` | 让包内相对导入正常工作 |
| 运行片段 | `python -c "print(1+1)"` | 快速验证一行 |
| 交互式 REPL | `python` | 试语法、查对象 |

### 8.1 `python -m` 与直接运行文件的关键差异（首次教学）

```powershell
python app/main.py          # 直接运行文件
python -m app.main           # 以模块方式运行（从仓库根执行）
```

差异在于 **`sys.path[0]`**：

- 直接运行文件时，`sys.path[0]` 是该文件所在目录，**包的父目录不在路径里**，`from app.core import x` 会失败；
- `-m` 方式运行时，`sys.path[0]` 是当前工作目录，包能正常被发现。

结论：**只要代码里有包内绝对导入，就用 `-m`**。本项目的启动命令将来也是模块方式。

> 验证一下 `sys.path`：

```powershell
uv run python -c "import sys; print(sys.path[0])"
```

预期：输出空字符串 `''`（表示当前工作目录）。

### 8.2 `__pycache__` 与 `.pyc`

第一次 `import` 某个模块后，Python 会在同目录生成 `__pycache__/模块名.cpython-312.pyc`。

| 项 | 说明 |
| --- | --- |
| 是什么 | 编译后的字节码缓存，加速下次导入 |
| 要提交吗 | **不要**，加入 `.gitignore` |
| 能删吗 | 能，删了会自动重建 |
| 和源码不同步怎么办 | Python 用源码 mtime + 大小判断，改了源码会自动重编译 |

## 9. 与 Node.js / TypeScript 概念对照表

| Python | Node/TS | 说明 |
| --- | --- | --- |
| `python.exe` | `node.exe` | 运行时 |
| `venv`（`.venv/`） | `node_modules/` | 项目级依赖隔离 |
| `pyproject.toml` | `package.json` | 依赖与元信息声明 |
| `uv.lock` | `package-lock.json` | 精确锁定版本 |
| `uv add` / `uv sync` | `npm install` / `npm ci` | 安装 |
| `uv run xxx` | `npx xxx` | 项目环境内执行 |
| `__init__.py` | `index.ts` | 包的入口标识 |
| `python -m pkg.mod` | `node -r` / `tsx` | 以模块方式运行 |
| `__pycache__/` | `dist/`（部分） | 生成物，不入库 |

> 最大心智差异：Python **没有编译步骤**（字节码缓存是隐式的），所以「改完直接跑」；但也没有 TS 的编译期类型检查，需要靠 mypy/ruff（阶段 3/04）。

## 12. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `python : 无法将“python”项识别为...` | 安装时没勾 `Add to PATH` | 重装勾选 PATH，或手动添加 `...\Python312\` 与 `...\Scripts\` |
| 输入 `python` 弹出微软商店 | `WindowsApps` 下的占位 exe 排在 PATH 前面 | 关掉「应用执行别名」中的 python，或调整 PATH 顺序 |
| `Activate.ps1 因为在此系统上禁止运行脚本` | PowerShell 执行策略限制 | 优先用 `uv run` / 直接调 `.venv\Scripts\python.exe`；确需激活则 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| 装完包却 `ModuleNotFoundError` | 装到了另一个解释器（全局/别的 venv） | 用 `python -m pip` 而非 `pip`；`where.exe python` 确认；`python -c "import sys; print(sys.prefix)"` |
| `uv sync` 报 `requires-python` 不满足 | 本机 Python < 3.12 | 升级到 3.12；或 `uv python install 3.12` 让 uv 自管解释器 |
| 中文输出乱码 | 终端编码非 UTF-8 | `chcp 65001`；或设环境变量 `PYTHONUTF8=1` |
| `.venv` 提交进了 Git | 没写 `.gitignore` | 加入 `.venv/`、`__pycache__/`、`*.pyc`；`git rm -r --cached .venv` |
| 同时用 pip 和 uv 装包，锁文件对不上 | 两套工具写不同的记录 | 项目内**统一用 uv**；pip 只用于无项目的一次性试验 |
| `python -m app.main` 报 `ModuleNotFoundError: No module named 'app'` | 不在仓库根执行，或用了 `python app/main.py` | 在 `apps/api-py` 目录下用 `-m`；确认有 `app/__init__.py` |

---

## 13. 本篇小结

- **CPython** 是官方解释器：源码 → 字节码（`.pyc`）→ 虚拟机执行；`__pycache__` 是字节码缓存，不入库。
- **版本**：本系列与项目统一 **Python 3.12+**（`requires-python = ">=3.12"`）。
- **虚拟环境**：`venv` 给每个项目一份独立解释器与 `site-packages`，等价于 Node 的 `node_modules`；`.venv/` 必须加入 `.gitignore`。
- **依赖管理**：`pip` 传统但无锁文件语义；`uv` 提供 `pyproject.toml`（声明）+ `uv.lock`（锁定）+ `uv sync`（复现），本项目采用 uv。
- **运行方式**：有包内导入就用 `python -m 包.模块`；`python -m pip` 永远比裸 `pip` 可靠。
- **下一步**：进入语法最小集——变量、缩进、内置类型、容器与切片。

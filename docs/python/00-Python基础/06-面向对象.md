## 3. 类与实例

### 3.1 最小类

```python
class App:
    """一个应用。"""

    def __init__(self, name: str, public: bool = False):
        self.name = name
        self.public = public

    def describe(self) -> str:
        return f"{self.name}（{'公开' if self.public else '私有'}）"


blog = App("blog")
print(blog.describe())        # blog（私有）
print(blog.name)              # blog
```

### 3.2 创建过程与 `self` 的本质

```python
blog = App("blog", public=True)
```

发生了什么：

```
① 调用类 App(...) → 触发 __new__（极少需要重写，默认创建实例）
② 得到实例对象后，调用 __init__(实例, "blog", public=True)
③ __init__ 把属性挂到该实例的 __dict__ 上，返回 None
④ 表达式返回这个实例
```

`self` 的真相：

| 问题 | 答案 |
| --- | --- |
| `self` 是关键字吗？ | **不是**，只是约定名（换成 `this` 语法也合法，但别这么干） |
| 它是什么？ | 调用时**自动传入的实例引用**，等价于 JS 的 `this` |
| 为什么必须写？ | Python 不会隐式注入，必须显式声明为第一个参数 |

```python
print(App.describe(blog))     # blog（私有）—— 未绑定调用，手动传实例
print(blog.describe())        # 等价写法，实例调用自动绑定
```

### 3.3 `__init__` 不是构造函数

严格说，`__new__` 负责**创建**，`__init__` 负责**初始化**。

```python
class Weird:
    def __new__(cls, *args, **kwargs):
        print("__new__ 创建实例")
        return super().__new__(cls)

    def __init__(self):
        print("__init__ 初始化实例")

Weird()
```

输出：

```
__new__ 创建实例
__init__ 初始化实例
```

> 日常开发只写 `__init__`；`__new__` 仅在单例、不可变类型子类化等场景才需要。

### 3.4 实例属性 vs 类属性（重点）

```python
class App:
    kind = "flow"                 # 类属性：所有实例共享

    def __init__(self, name):
        self.name = name          # 实例属性：每个实例独立


a1 = App("blog")
a2 = App("chat")

print(a1.kind, a2.kind)           # flow flow（都在类上找到）
a1.name = "new-blog"
print(a2.name)                    # chat（实例属性互不影响）
```

查找顺序：**实例 `__dict__` → 类 `__dict__` → 父类**（接近 LEGB 里的「就近原则」）。

```python
print(a1.__dict__)                # {'name': 'new-blog'}
print(App.__dict__.keys())        # dict_keys([..., 'kind', ...])
```

### 3.5 共享可变类属性的陷阱

```python
class Bad:
    items = []                    # ❌ 所有实例共享同一个 list

    def add(self, x):
        self.items.append(x)


b1, b2 = Bad(), Bad()
b1.add(1)
print(b2.items)                   # [1]  ← 期望 []
```

原因：`self.items.append(x)` **没有给 `self.items` 赋值**，只是原地修改了类属性指向的那个 list。

正确写法：

```python
class Good:
    def __init__(self):
        self.items = []           # ✅ 每个实例一份

    def add(self, x):
        self.items.append(x)
```

> 与 [03 篇](../00-Python基础/03-函数与作用域.md) 的可变默认参数陷阱是同一类问题：**可变对象别放在共享位置**。

## 4. 三种方法（首次教学）

```python
class App:
    engine = "python"

    def __init__(self, name):
        self.name = name

    # ① 实例方法：第一个参数是 self，能访问实例与类
    def describe(self):
        return f"{self.name} on {self.engine}"

    # ② 类方法：第一个参数是 cls，常用于工厂方法
    @classmethod
    def from_dict(cls, data: dict):
        return cls(data["name"])

    # ③ 静态方法：无 self/cls，纯工具函数，逻辑上归属该类
    @staticmethod
    def is_valid_name(name: str) -> bool:
        return bool(name) and len(name) <= 32
```

调用：

```python
app = App.from_dict({"name": "blog"})     # 类方法：不需要先有实例
print(app.describe())                      # blog on python
print(App.is_valid_name("blog"))           # True
```

### 4.1 三者对比

| 类型 | 装饰器 | 首参 | 能访问实例 | 能访问类 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| 实例方法 | 无 | `self` | ✅ | ✅（通过 `self`） | 绝大多数业务方法 |
| 类方法 | `@classmethod` | `cls` | ❌ | ✅ | 工厂方法、替代构造器 |
| 静态方法 | `@staticmethod` | 无 | ❌ | ❌ | 与该类相关但不依赖状态的小工具 |

> **什么时候用类方法**：需要「另一种构造方式」时，如 `Settings.from_env()`、`App.from_dict()`。比在外部写 `App(...)` 更能表达意图，也便于子类继承时返回正确的类（`cls` 而非硬编码类名）。

### 4.2 装饰器是什么（先建立直觉）

`@classmethod` 这类语法叫**装饰器**：它把下面的函数**替换**成另一个对象。

```python
@staticmethod
def f(): ...

# 等价于
def f(): ...
f = staticmethod(f)
```

> 装饰器的完整机制（闭包、带参装饰器、`functools.wraps`）在 `01-Python进阶/03` 讲，本篇只需会用这三个内置装饰器。

## 5. 封装：命名约定与 `@property`

### 5.1 Python 没有真正的 private

| 写法 | 含义 |
| --- | --- |
| `name` | 公开 |
| `_name` | 约定私有：外部别用，但**仍可访问** |
| `__name` | 触发 name mangling：实际存为 `_类名__name` |

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance        # 变成 _Account__balance


acc = Account(100)
print(acc.__balance)          # ❌ AttributeError
print(acc._Account__balance)  # 100 ← 仍能绕过，所以只是「防误用」
```

> 结论：Python 靠**约定**而非强制。真实项目中用单下划线表达「内部使用」即可，双下划线只在需要避免子类同名冲突时用。

### 5.2 `@property`：受控属性（首次教学）

```python
class Account:
    def __init__(self, balance: int = 0):
        self._balance = balance

    @property
    def balance(self) -> int:
        """只读访问。"""
        return self._balance

    @balance.setter
    def balance(self, value: int) -> None:
        if value < 0:
            raise ValueError("余额不能为负")
        self._balance = value


acc = Account(100)
print(acc.balance)      # 100   ← 像属性一样访问，实际调用方法
acc.balance = 50        # 走 setter
print(acc.balance)      # 50
acc.balance = -1        # ValueError: 余额不能为负
```

要点：

- 外部**看起来是属性**（`acc.balance`），内部是方法调用；
- 可以在 setter 里做校验，避免「构造完再被改成非法值」；
- 只定义 `@property` 不给 setter → **只读属性**；
- 命名上用 `_balance` 存真实值，`balance` 作为门面。

> 项目里 `Settings` 的字段由 Pydantic 在**赋值/构造时**校验，原理相同：不让非法值进入对象。

### 5.3 计算属性

```python
class Rectangle:
    def __init__(self, w, h):
        self.w, self.h = w, h

    @property
    def area(self) -> float:
        return self.w * self.h
```

`area` 永远随 `w`/`h` 变化，不需要手动同步——这是「派生数据用属性而不是字段」的典型。

## 6. 继承

### 6.1 基本写法与 `super()`

```python
class Node:
    def __init__(self, node_id: str):
        self.node_id = node_id

    def label(self) -> str:
        return self.node_id


class LlmNode(Node):
    def __init__(self, node_id: str, model: str):
        super().__init__(node_id)      # 调用父类初始化
        self.model = model

    def label(self) -> str:            # 方法重写
        return f"{self.node_id}:{self.model}"


node = LlmNode("n1", "gpt-4o-mini")
print(node.label())      # n1:gpt-4o-mini
print(isinstance(node, Node))       # True
```

### 6.2 为什么必须 `super().__init__(...)`

子类 `__init__` **覆盖**父类的，不调用父类初始化，父类属性就不会存在：

```python
class BadNode(Node):
    def __init__(self, node_id):
        self.node_id = node_id          # 手动重复父类逻辑（不推荐）
```

`super()` 的好处：父类改动时子类自动跟随；多继承时按 MRO 正确调用。

### 6.3 MRO：方法解析顺序

```python
class A:
    def who(self): return "A"

class B(A):
    def who(self): return "B"

class C(A):
    def who(self): return "C"

class D(B, C):
    pass

print(D().who())        # B
print([c.__name__ for c in D.__mro__])    # ['D', 'B', 'C', 'A', 'object']
```

规则：**从左到右、深度优先、但保证子类先于父类**（C3 线性化）。`super()` 不是「父类」，而是「MRO 中的下一个」。

> 日常开发**优先单继承 + 组合**；多继承只用于「混入（Mixin）」场景，且保持无状态。

### 6.4 抽象基类（了解）

```python
from abc import ABC, abstractmethod


class BaseNode(ABC):
    @abstractmethod
    def run(self, inputs: dict) -> dict:
        """子类必须实现。"""


class StartNode(BaseNode):
    def run(self, inputs: dict) -> dict:
        return inputs
```

未实现抽象方法的子类**实例化时报错**，这让「接口契约」在运行期就有了约束。

> 项目的节点体系（阶段 12）就是这种「基类定义协议 + 各节点实现」的结构。

## 7. 多态与鸭子类型

### 7.1 鸭子类型（Python 的核心风格）

> 「如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。」

```python
def run_all(nodes):
    return [node.run({}) for node in nodes]
```

`run_all` **不检查类型**，只要求对象有 `run` 方法。`StartNode`、`LlmNode`、`EndNode` 都能传进来——无需共同父类。

| 方式 | 类型检查时机 |
| --- | --- |
| 静态类型语言 | 编译期（`implements Node`） |
| Python 鸭子类型 | 运行期（调用 `node.run` 才报错） |
| Python + `Protocol` | 静态检查器（mypy/pyright）帮你检查，运行期仍是鸭子 |

### 7.2 用 `Protocol` 声明「长得像什么」（预告）

```python
from typing import Protocol


class Runnable(Protocol):
    def run(self, inputs: dict) -> dict: ...
```

`Protocol` 只影响类型检查，不产生继承关系。阶段 1/01 详讲。

### 7.3 组合优于继承

```python
# ❌ 继承：只为复用行为
class LoggingApp(App): ...

# ✅ 组合：把能力作为依赖注入
class AppService:
    def __init__(self, app: App, logger):
        self.app = app
        self.logger = logger
```

原则：**「是一个」（is-a）用继承，「有一个」（has-a）用组合**。绝大多数业务代码应该用组合。

## 8. 常用魔术方法

### 8.1 `__str__` 与 `__repr__`

```python
class App:
    def __init__(self, name, public=False):
        self.name = name
        self.public = public

    def __str__(self) -> str:              # print() / f"{obj}" 用
        return f"{self.name}"

    def __repr__(self) -> str:             # 调试、容器显示用
        return f"App(name={self.name!r}, public={self.public!r})"


app = App("blog")
print(app)              # blog
print([app])            # [App(name='blog', public=False)]
```

| 方法 | 面向 | 要求 |
| --- | --- | --- |
| `__str__` | 用户 | 可读 |
| `__repr__` | 开发者 | **尽量能重建对象**（`eval` 友好） |

> 只实现 `__repr__` 也可以：`print` 时 Python 会退而使用它。

### 8.2 `__eq__` 与 `__hash__`

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other) -> bool:
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self) -> int:
        return hash((self.x, self.y))


print(Point(1, 2) == Point(1, 2))          # True
print(len({Point(1, 2), Point(1, 2)}))     # 1
```

两个要点：

- 重写 `__eq__` 后必须重写 `__hash__`，否则对象**不可哈希**（不能进 `set`/不能当 `dict` 键）；
- `__eq__` 里对不认识的对象返回 `NotImplemented`（不是 `False`），让 Python 尝试反向比较。

### 8.3 其他常用

| 魔术方法 | 触发方式 | 用途 |
| --- | --- | --- |
| `__len__` | `len(obj)` | 容器长度 |
| `__getitem__` | `obj[key]` | 索引访问（也支持切片） |
| `__iter__` / `__next__` | `for x in obj` | 可迭代（阶段 1/02） |
| `__call__` | `obj()` | 让实例像函数一样调用 |
| `__enter__` / `__exit__` | `with obj` | 上下文管理（阶段 1/04） |
| `__bool__` | `if obj` | 真值判断 |
| `__contains__` | `x in obj` | 成员判断 |

> 原则：魔术方法只在你**确实要模拟内建语义**时实现。为了「炫技」重载运算符会让代码难懂。

## 9. 项目实战：读懂 Settings 与异常类

### 9.1 `Settings(BaseSettings)`：类属性即字段声明

完整文件路径：`apps/api-py/app/config.py`（节选）

```python
from pathlib import Path
from pydantic import Field
from pydantic_settings import BaseSettings, SettingsConfigDict

_PROJECT_DIR = Path(__file__).resolve().parent.parent


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=_PROJECT_DIR / ".env", extra="ignore")

    service_name: str = "api-py"
    version: str = "0.1.0"
    database_url: str = "postgresql+psycopg://postgres:difyai123456@localhost:5432/minidify"
    access_token_expires_in: int = Field(default=3600, validation_alias="JWT_EXPIRES_IN")
    port: int = 8000


settings = Settings()
```

本篇知识点逐条对应：

| 代码 | 知识点 |
| --- | --- |
| `class Settings(BaseSettings)` | 继承：复用父类的配置加载、校验、`__init__` 逻辑 |
| `service_name: str = "api-py"` | **类属性 + 类型注解**：这里被 Pydantic 用作「字段声明」，由元类收集 |
| `model_config = SettingsConfigDict(...)` | 类属性承载配置（不是实例属性），因为「怎么读配置」对所有实例都一样 |
| `extra="ignore"` | 行为开关：忽略 `.env` 里多余的键 |
| `settings = Settings()` | 模块级实例：配合 [04 篇](./04-模块、包与导入.md) 的模块缓存 → 全项目单例 |
| 不用手写 `__init__` | 父类 `BaseSettings` 已实现「从环境变量/文件读取并校验」 |

> 这是「**声明式类**」的典型：类体只写「有什么字段、什么类型、什么默认值」，行为由基类提供。SQLAlchemy 模型（阶段 6）也是同一套路——类属性声明列，元类负责映射。

### 9.2 `AppError(Exception)`：继承内建异常

`apps/api-py/app/errors.py` 的写法（同类结构）：

```python
class AppError(Exception):
    """本项目业务异常基类。"""
```

要点：

- 继承 `Exception` → 能被 `except AppError` 或 `except Exception` 捕获；
- 类体可以完全为空（`pass` 或只写 docstring），继承本身就表达了「这是一种业务错误」；
- 上层可以按类型分层处理：`except NotFoundError` 映射 404，`except AppError` 映射 400。

> 结合 [05 篇](./05-异常与文件IO.md) 的异常链：`raise AppError("...") from e` 既保留业务语义，又不丢根因。

## 10. 与 TypeScript 对照

| Python | TypeScript | 差异 |
| --- | --- | --- |
| `class App:` | `class App {}` | 语法接近 |
| `def __init__(self, x)` | `constructor(x)` | Python 显式写 `self` |
| `self.x = x`（必须显式） | 构造参数属性简写 `constructor(private x: number)` | TS 更省代码 |
| `_x`（约定） | `private x` / `#x`（真私有） | Python 私有只是约定 |
| `@property` | `get x()` / `set x(v)` | 都是方法伪装成属性 |
| `@classmethod` | `static create()` | 语义接近（`cls` vs 类名） |
| `@staticmethod` | `static util()` | 一致 |
| `class B(A)` | `class B extends A` | 一致 |
| `super().__init__()` | `super()` | 一致 |
| 多继承 + MRO | 单继承 + `implements` | Python 支持多继承 |
| 鸭子类型 | 结构化类型（interface） | TS 编译期检查，Python 运行期 |
| `__repr__` | `toString()` | 用途接近 |
| `__eq__` | 需手写 `equals()` | 都需显式实现 |

### 11.2 找错

```python
class Cart:
    items = []

    def add(self, item):
        self.items.append(item)
```

问题：`items` 是可变类属性，所有购物车共享。修复：

```python
class Cart:
    def __init__(self):
        self.items = []

    def add(self, item):
        self.items.append(item)
```

### 11.3 动手题

实现 `User` 类：

- 构造参数 `email`、`age`；
- `email` 必须是只读属性；
- `age` 用 `@property` 校验（0 < age <= 150）；
- `__repr__` 输出 `User(email='a@b.com', age=18)`。

参考实现：

```python
class User:
    def __init__(self, email: str, age: int):
        self._email = email
        self.age = age          # 走 setter 校验

    @property
    def email(self) -> str:
        return self._email

    @property
    def age(self) -> int:
        return self._age

    @age.setter
    def age(self, value: int) -> None:
        if not (0 < value <= 150):
            raise ValueError("age 必须在 1~150 之间")
        self._age = value

    def __repr__(self) -> str:
        return f"User(email={self._email!r}, age={self._age!r})"
```

> 注意 `self.age = age` 会触发 setter（因为 `age` 是 property），而 `self._email` 直接写字段。

## 12. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 所有实例数据串在一起 | 可变类属性（`items = []`） | 在 `__init__` 里创建实例属性 |
| `TypeError: __init__() takes 1 positional argument but 2 were given` | 定义方法时忘了 `self` | 实例方法首参写 `self` |
| `AttributeError: 'X' object has no attribute 'y'` | 没调用 `super().__init__()` | 子类初始化里加 `super().__init__(...)` |
| 对象打印成 `<__main__.App object at 0x...>` | 没实现 `__repr__` | 加 `__repr__`（调试必备） |
| 放进 `set` 报 `unhashable type` | 实现了 `__eq__` 未实现 `__hash__` | 一并实现，或用 `@dataclass(frozen=True)` |
| `@property` 同名冲突 | getter 与字段同名 | 内部字段用 `_name`，属性名用 `name` |
| 子类属性被父类覆盖 | 多继承 MRO 顺序与预期不同 | 打印 `类.__mro__` 确认；优先单继承 |
| 外部直接改了内部状态 | 用了公开字段 | 改 `@property` + 私有字段 |
| 在类体里调用实例方法 | 类体执行时还没有实例 | 放到 `__init__` 或实例方法里 |

## 13. 本篇小结

- **类 = 模板，实例 = 具体对象**；`App(...)` 先 `__new__` 创建、再 `__init__` 初始化。
- **`self` 不是关键字**，只是自动传入的实例引用；实例方法首参必须显式写。
- **实例属性在 `__init__` 里创建**；类属性被所有实例共享，**可变类属性是高危坑**。
- **三种方法**：实例方法（`self`）、类方法（`cls`，工厂）、静态方法（无状态工具）；`@` 是装饰器语法。
- **封装靠约定**：`_x` 内部用、`__x` 触发名称改写；对外暴露用 `@property` 做校验与派生。
- **继承用 `super().__init__()`** 串起父类初始化；多继承按 MRO，日常优先单继承 + 组合。
- **鸭子类型**是 Python 风格：只看有没有方法，不看继承关系；需要静态约束时用 `Protocol`（阶段 1/01）。
- **魔术方法**让对象融入语言语义：`__repr__` 调试、`__eq__`+`__hash__` 进容器、`__len__`/`__getitem__`/`__call__` 模拟内建行为。
- **项目范式**：`Settings(BaseSettings)` 用类属性声明字段（声明式类），`AppError(Exception)` 用继承表达错误分类。

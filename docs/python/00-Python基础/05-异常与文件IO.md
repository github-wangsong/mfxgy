## 3. 异常是什么

### 3.1 一次完整的异常现场

```python
def divide(a, b):
    return a / b

print(divide(10, 2))     # 5.0
print(divide(10, 0))
```

输出：

```
5.0
Traceback (most recent call last):
  File "demo.py", line 5, in <module>
    print(divide(10, 0))
  File "demo.py", line 2, in divide
    return a / b
ZeroDivisionError: division by zero
```

Traceback 的读法：**从下往上看**——最后一行是异常类型与消息，上面是调用栈（越往下越接近出错点）。

### 3.2 异常继承体系（节选）

```
BaseException
├── SystemExit                 ← sys.exit() 抛出
├── KeyboardInterrupt          ← Ctrl+C
├── GeneratorExit
└── Exception                  ← 业务代码应捕获的根
    ├── ArithmeticError
    │   └── ZeroDivisionError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── ValueError
    ├── TypeError
    ├── AttributeError
    ├── NameError
    ├── OSError                  ← IO 类错误根
    │   ├── FileNotFoundError
    │   ├── PermissionError
    │   └── TimeoutError
    ├── RuntimeError
    ├── ImportError
    └── StopIteration
```

关键结论：

- **业务代码只捕获 `Exception` 及其子类**，不要捕获 `BaseException`（否则会吞掉 Ctrl+C 和 `sys.exit`）。
- 捕获父类会连带捕获所有子类：`except OSError` 能接住 `FileNotFoundError`。

### 3.3 常见内建异常速查

| 异常 | 触发场景 |
| --- | --- |
| `ZeroDivisionError` | 除以 0 |
| `IndexError` | 序列索引越界 |
| `KeyError` | 字典键不存在 |
| `ValueError` | 类型对但值不合法（`int("abc")`） |
| `TypeError` | 类型不匹配（`"1" + 1`） |
| `AttributeError` | 对象没有该属性（常见于 `None.xxx`） |
| `NameError` | 名字未定义 |
| `FileNotFoundError` | 文件不存在 |
| `PermissionError` | 无权限 |
| `UnicodeDecodeError` | 用错编码解码 |
| `json.JSONDecodeError` | 非法 JSON 文本 |
| `StopIteration` | 迭代器耗尽（`next()` 越界） |

## 4. `try/except/else/finally`（首次教学）

### 4.1 四段的执行时机

```python
def read_port(text):
    try:
        port = int(text)              # ① 可能出错的代码
    except ValueError:
        print("解析失败")             # ② 出 ValueError 时执行
        return 8000
    else:
        print("解析成功")             # ③ 没出异常才执行
        return port
    finally:
        print("无论如何都执行")        # ④ 一定会执行
```

```python
print(read_port("9000"))
```

输出：

```
解析成功
无论如何都执行
9000
```

```python
print(read_port("abc"))
```

输出：

```
解析失败
无论如何都执行
8000
```

| 段 | 何时执行 | 典型用途 |
| --- | --- | --- |
| `try` | 总是 | 放可能抛异常的语句 |
| `except` | 抛出匹配异常时 | 处理/兜底 |
| `else` | `try` 全部成功时 | 放「不需要保护」的后续逻辑 |
| `finally` | **总是**（含 `return`/异常） | 释放资源、清理 |

> `else` 的价值：把「可能出错的」与「后续正常逻辑」分开，避免后续逻辑被同一个 `except` 误伤。

### 4.2 `finally` 与 `return` 的优先级

```python
def f():
    try:
        return "try"
    finally:
        print("finally 执行")

print(f())
```

输出：

```
finally 执行
try
```

规则：`finally` 一定执行；若 `finally` 里也有 `return`，会**覆盖** `try` 的返回值（这是坏实践，别写）。

### 4.3 捕获多种异常

```python
try:
    value = int(text)
except (ValueError, TypeError) as e:      # 元组：任一匹配
    print(f"输入非法: {e}")
```

### 4.4 多个 `except` 从上到下匹配

```python
try:
    ...
except FileNotFoundError:
    ...          # 具体异常放前面
except OSError:
    ...          # 父类放后面
```

顺序错了会让具体分支永远进不去（因为父类先匹配）。

> 匹配是**类型匹配**，不是值匹配；第一个匹配的 `except` 胜出。

## 5. 正确使用 `except`（重点）

### 5.1 禁止裸 `except:`

```python
try:
    do_something()
except:              # ❌ 捕获 BaseException：Ctrl+C、SystemExit 全被吞
    pass             # ❌ 还什么都不做
```

后果：

- 用户按 Ctrl+C 无法中断；
- 真实 bug 被静默吞掉，排查时毫无线索。

### 5.2 `except Exception` 只用于最外层兜底

```python
def main():
    try:
        run()
    except Exception as e:
        logger.exception("未预期错误")     # 记录完整堆栈
        raise                              # 或者返回统一错误
```

> 原则：**能精确捕获就精确捕获**；最外层兜底才用 `Exception`，并且**必须记录**。

### 5.3 `except ... as e` 的变量作用域

```python
try:
    int("abc")
except ValueError as e:
    print(e)

print(e)     # ❌ NameError: name 'e' is not defined
```

Python 3 在 `except` 块结束时会**删除** `e`（避免异常对象与堆栈形成引用环）。需要留信息就先赋给别的变量：

```python
error_message = None
try:
    int("abc")
except ValueError as e:
    error_message = str(e)
```

## 6. `raise` 与异常链（首次教学）

### 6.1 主动抛出

```python
def set_age(age: int) -> None:
    if age < 0:
        raise ValueError(f"age 不能为负: {age}")
```

`raise` 的参数必须是异常**实例**（或类，Python 会自动实例化）。

### 6.2 重新抛出

```python
try:
    risky()
except OSError:
    logger.exception("磁盘操作失败")
    raise            # 不带参数：原样重抛，保留 traceback
```

> `raise` 与 `raise e` 的区别：`raise` 保留原始 traceback；`raise e` 会重置部分栈信息。**重抛一律用裸 `raise`**。

### 6.3 异常链 `raise ... from ...`

```python
class ConfigError(Exception):
    """配置错误。"""


def load_config(path):
    try:
        with open(path, encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError as e:
        raise ConfigError(f"配置文件不存在: {path}") from e
```

输出的 traceback 会显示：

```
FileNotFoundError: [Errno 2] No such file or directory: 'x.env'

The above exception was the direct cause of the following exception:

ConfigError: 配置文件不存在: x.env
```

`from e` 的意义：**对上层暴露业务异常，同时保留根因**。

`from None` 则显式切断链条（不推荐，除非确实想隐藏底层细节）。

### 6.4 自定义异常类

```python
class AppError(Exception):
    """本项目业务异常基类。"""


class NotFoundError(AppError):
    def __init__(self, resource: str, ident: str):
        super().__init__(f"{resource} 不存在: {ident}")
        self.resource = resource
        self.ident = ident
```

好处：

- 上层可用 `except AppError` 统一处理业务错误；
- 可携带结构化字段（`resource`/`ident`），便于映射成 HTTP 状态码。

> 阶段 5/03 会把这类异常映射成统一的 `{statusCode, message, error}` 响应体——项目 `app/errors.py` 就是终点。

## 7. EAFP vs LBYL

| 风格 | 全称 | 写法 |
| --- | --- | --- |
| **EAFP** | Easier to Ask Forgiveness than Permission | 先做，出错再处理 |
| **LBYL** | Look Before You Leap | 先检查条件，再执行 |

```python
# LBYL
if "port" in config:
    port = config["port"]
else:
    port = 8000

# EAFP（Python 风格）
try:
    port = config["port"]
except KeyError:
    port = 8000

# 但最简洁的是：
port = config.get("port", 8000)
```

什么时候用哪种：

- **并发/文件/网络**：优先 EAFP（检查与执行之间有竞态窗口）；
- **简单容器访问**：用 `get`/`in`；
- **不要为了「避免异常」写一堆预检查**，Python 的异常成本很低。

## 8. `assert` 不是业务校验

```python
def withdraw(balance, amount):
    assert amount > 0, "金额必须为正"     # ❌ 业务校验不要用 assert
    return balance - amount
```

原因：`python -O` 会**移除所有 assert**，校验直接消失。

正确用法：`assert` 只用于「不可能发生」的内部不变量（开发期自检）。

## 9. 文件 IO

### 9.1 `open` 的模式

| 模式 | 含义 | 文件不存在 | 文件存在 |
| --- | --- | --- | --- |
| `"r"` | 只读（默认） | `FileNotFoundError` | 从头读 |
| `"w"` | 只写 | 创建 | **清空** |
| `"a"` | 追加 | 创建 | 末尾追加 |
| `"x"` | 独占创建 | 创建 | `FileExistsError` |
| `"r+"` | 读写 | `FileNotFoundError` | 从头读写 |
| `"b"` | 二进制（与上面组合，如 `"rb"`） | — | — |

> **`"w"` 会清空文件**，这是最危险的一个模式。想保留内容用 `"a"`。

### 9.2 永远用 `with`（首次教学）

```python
# ❌ 手动关闭：中间抛异常就泄漏
f = open("data.txt", "r", encoding="utf-8")
content = f.read()
f.close()

# ✅ with：退出块时自动 close，即使抛异常
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

`with` 的背后是**上下文管理协议**：

```
进入 with 块 → 调用 f.__enter__()，返回值绑定给 as 后的变量
退出 with 块 → 调用 f.__exit__(exc_type, exc, tb)
              → 无论正常结束还是异常，都会调用
```

> 自己写 `__enter__/__exit__` 或 `@contextmanager` 见 `01-Python进阶/04`。本篇只需记住：**凡是「打开-使用-释放」的资源，一律 `with`**。

### 9.3 编码必须显式声明

```python
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()
```

不写 `encoding` 时用的是**平台默认编码**：

| 平台 | 默认编码 |
| --- | --- |
| Windows 中文环境 | 常见 `cp936`（GBK） |
| Linux / macOS | `UTF-8` |

后果：同一份 UTF-8 文件在 Windows 上读可能抛：

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0x80 in position 12
```

**规则：读写文本文件一律显式 `encoding="utf-8"`。**

### 9.4 逐行读取（大文件正确姿势）

```python
# ❌ 一次性读入内存，1GB 文件就占 1GB+
with open("big.log", encoding="utf-8") as f:
    lines = f.readlines()

# ✅ 流式迭代：一次只有一行在内存
with open("big.log", encoding="utf-8") as f:
    for line in f:
        line = line.rstrip("\n")
        if "ERROR" in line:
            print(line)
```

> 文件对象本身是**迭代器**，`for line in f` 就是惰性读取。这是阶段 1/02「生成器」的天然案例（项目 `rag/splitter.py` 切分文档同思路）。

### 9.5 写文件

```python
with open("out.txt", "w", encoding="utf-8", newline="") as f:
    f.write("第一行\n")
    f.write("第二行\n")
```

要点：

- `"w"` 会清空；
- `newline=""` 避免 Windows 把 `\n` 转成 `\r\n`（跨平台文本一致性）；
- 写多行也可以 `f.writelines(["a\n", "b\n"])`。

### 9.6 `pathlib`：路径用对象，不要拼字符串（首次教学）

```python
from pathlib import Path

base = Path("D:/practice/py-demo")
data_dir = base / "data"                 # 用 / 拼接，自动处理分隔符
data_dir.mkdir(parents=True, exist_ok=True)

file = data_dir / "notes.txt"
file.write_text("hello", encoding="utf-8")
print(file.read_text(encoding="utf-8"))  # hello

print(file.exists())                     # True
print(file.suffix)                       # .txt
print(file.stem)                         # notes
print(file.name)                         # notes.txt
print(file.parent)                       # D:\practice\py-demo\data
```

对比字符串拼接：

| 需求 | 字符串 | `pathlib` |
| --- | --- | --- |
| 拼接 | `os.path.join(a, b)` | `a / b` |
| 取目录 | `os.path.dirname(p)` | `p.parent` |
| 取扩展名 | `os.path.splitext(p)[1]` | `p.suffix` |
| 递归查找 | `glob.glob("**/*.py")` | `p.rglob("*.py")` |
| 读文本 | `open(p).read()` | `p.read_text(encoding="utf-8")` |

> 项目 `config.py` 用 `Path(__file__).resolve().parent.parent` 得到**绝对路径**，从而做到「无论 cwd 在哪都读同一份 `.env`」。

### 9.7 JSON 读写

```python
import json

data = {"name": "api-py", "port": 8000}

# 写
Path("cfg.json").write_text(
    json.dumps(data, ensure_ascii=False, indent=2),
    encoding="utf-8",
)

# 读
loaded = json.loads(Path("cfg.json").read_text(encoding="utf-8"))
print(loaded["name"])       # api-py
```

两个易错点：

- `ensure_ascii=False` 才能输出中文（否则变成 `\u4e2d\u6587`）；
- `json.loads` 遇到非法文本抛 `json.JSONDecodeError`（它是 `ValueError` 的子类）。

## 10. 项目实战：读懂 errors.py 的异常处理

完整文件路径：`apps/api-py/app/errors.py`（节选）

```python
def register_error_handlers(app: FastAPI) -> None:
    """注册异常处理器（须在创建 app 之后、提供服务之前调用）。"""

    @app.exception_handler(StarletteHTTPException)
    async def _http_exception_handler(_request: Request, exc: StarletteHTTPException) -> JSONResponse:
        message = exc.detail if isinstance(exc.detail, str) else str(exc.detail)
        return _envelope(exc.status_code, message)

    @app.exception_handler(RequestValidationError)
    async def _validation_exception_handler(_request: Request, exc: RequestValidationError) -> JSONResponse:
        return _envelope(status.HTTP_400_BAD_REQUEST, _build_message(exc.errors()))
```

用本篇知识拆解：

| 代码 | 知识点 |
| --- | --- |
| `@app.exception_handler(X)` | 注册「异常类型 → 处理函数」，本质是**集中式 except** |
| 两个 handler 分开注册 | **精确捕获**：HTTP 异常与校验异常分别处理，不写万能 `except` |
| `exc.detail if isinstance(exc.detail, str) else str(exc.detail)` | 类型判断 + 兜底转换，防止 `detail` 不是字符串 |
| `exc.errors()` | Pydantic 收集到的错误列表（结构化数据） |
| `_envelope(...)` | 把异常转成**统一错误体** `{statusCode, message, error}` |
| 没有 `print(e)`/`pass` | 错误被转换成契约要求的响应，而不是被吞掉 |

再看 `security.py` 中一个「静默兜底」的合理案例：

```python
def verify_password(password: str, password_hash: str) -> bool:
    try:
        return bcrypt.checkpw(...)
    except ValueError:
        return False
```

这里捕获 `ValueError` 是**有意为之**：哈希串格式非法时，应当返回「密码错误」，而不是让接口 500。**关键在于「精确类型 + 明确语义」**，而不是随手 `except Exception`。

> 考试点：同样是 `try/except`，`errors.py` 是「转换后继续抛给客户端」，`security.py` 是「转成布尔值」——两者的共同点是**都清楚自己想处理什么**。

## 11. 与 TypeScript 对照

| Python | TypeScript | 说明 |
| --- | --- | --- |
| `try/except/else/finally` | `try/catch/finally` | Python 多一个 `else` |
| `except ValueError as e` | `catch (e)` + `instanceof` | TS 需手动判断类型 |
| `raise ValueError("x")` | `throw new Error("x")` | 都是抛对象 |
| `raise X from e` | `{ cause: e }`（ES2022） | 保留根因 |
| `class MyError(Exception)` | `class MyError extends Error` | 自定义异常 |
| `with open(...)` | `using`（新特性）/ `try/finally` | Python `with` 更普及 |
| `pathlib.Path` | `node:path` | Python 是对象式 API |
| `json.loads/dumps` | `JSON.parse/stringify` | 名称相反，注意别记混 |
| `encoding="utf-8"` | 默认 UTF-8 | Python 有平台默认编码坑 |

### 12.2 找错

```python
def load(path):
    try:
        f = open(path)
        return f.read()
    except:
        return ""
```

三处问题：

1. 裸 `except` 会吞掉 `KeyboardInterrupt`/`SystemExit`；
2. 没有 `encoding="utf-8"`，Windows 可能乱码或抛 `UnicodeDecodeError`；
3. 没有关闭文件（应 `with`）。

修复：

```python
def load(path):
    try:
        with open(path, encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        return ""
```

### 12.3 动手题

写一个函数 `count_errors(log_path)`：

- 流式读取大文件（不 `readlines`）；
- 统计包含 `"ERROR"` 的行数；
- 文件不存在时返回 `0`（不抛异常）。

参考实现：

```python
def count_errors(log_path):
    count = 0
    try:
        with open(log_path, encoding="utf-8") as f:
            for line in f:
                if "ERROR" in line:
                    count += 1
    except FileNotFoundError:
        return 0
    return count
```

## 13. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 程序「静默失败」 | 裸 `except: pass` | 精确捕获 + 记录日志 |
| `NameError: name 'e' is not defined` | `except` 块结束后 `e` 被删除 | 提前把需要的信息赋给普通变量 |
| Traceback 只剩底层错误，看不出业务含义 | 直接 `raise e` 或没包异常 | `raise BusinessError(...) from e` |
| `UnicodeDecodeError: 'gbk' codec...` | 未指定 `encoding`，用了平台默认 | 显式 `encoding="utf-8"` |
| 文件被清空 | 用了 `"w"` 模式 | 追加用 `"a"` |
| `ValueError: I/O operation on closed file` | `close()` 后又读写 | 用 `with` 管理生命周期 |
| 大文件 OOM | `read()`/`readlines()` 全量加载 | `for line in f` 流式处理 |
| `json.decoder.JSONDecodeError` | 文本不是合法 JSON（BOM/尾逗号） | 校验来源；`utf-8-sig` 处理 BOM |
| `PermissionError` | 文件被占用/无权限 | 关闭占用进程；检查权限 |
| 校验在 `python -O` 后失效 | 用 `assert` 做业务校验 | 改 `if ... raise ValueError` |
| 捕获顺序错，具体分支不生效 | 父类 `except` 写在前面 | 具体异常在前，父类在后 |

## 14. 本篇小结

- **异常是对象**，继承自 `Exception`；业务代码只捕获 `Exception` 子类，绝不裸 `except`。
- **`try/except/else/finally`**：`else` 放「成功后逻辑」，`finally` 一定执行（含 `return`），但别在 `finally` 里 `return`。
- **精确捕获**：能写 `ValueError` 就不写 `Exception`；最外层兜底必须记录堆栈。
- **异常链**：`raise NewError(...) from e` 同时保留业务语义与根因；重抛用裸 `raise`。
- **EAFP** 是 Python 风格：先做再处理；但简单容器访问优先 `get`/`in`。
- **文件 IO 三件套**：`with` + 显式 `encoding="utf-8"` + 流式迭代（大文件不 `readlines`）。
- **`pathlib` 优于字符串拼路径**：`/` 拼接、`parent`/`suffix`/`stem`、`read_text`/`write_text`。
- **项目范式**：`errors.py` 把异常**转换**成契约错误体（不是吞掉），`security.py` 把 `ValueError` **转成** `False`——都清楚「处理什么、为什么」。
- **下一步**：面向对象——`class`、`__init__`、继承、`@property`、魔术方法。

## 3. 闭包

### 3.1 从工厂函数说起

```python
def make_multiplier(factor: int):
    def multiply(x: int) -> int:
        return x * factor          # 用到了外部变量 factor
    return multiply


double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))      # 20
print(triple(10))      # 30
```

疑问：`make_multiplier` 已经返回了，`factor` 为什么还活着？

答：`multiply` **闭包**了 `factor`——它把外部函数的变量「随身带走」了。

### 3.2 闭包的定义（首次教学）

闭包 = **内层函数** + **它引用的外层函数变量（自由变量）**，且外层函数已返回。

三个条件：

1. 有嵌套函数；
2. 内层函数引用了外层函数的变量；
3. 外层函数把内层函数返回出去（或内层函数活得比外层久）。

### 3.3 证据：`__closure__` 与 cell

```python
def make_adder(n):
    def add(x):
        return x + n
    return add


add5 = make_adder(5)
print(add5.__closure__)              # (<cell at 0x...: int object at 0x...>,)
print(add5.__closure__[0].cell_contents)   # 5
print(add5.__code__.co_freevars)           # ('n',)
```

| 属性 | 含义 |
| --- | --- |
| `__closure__` | 元组，每项是一个 `cell` |
| `cell_contents` | cell 里存的实际值 |
| `co_freevars` | 自由变量名列表 |

这就是「变量被子带到未来」的物理证据：**值存在 cell 里，随函数对象一起存活**。

### 3.4 闭包写状态（不用类）

```python
def make_counter():
    count = 0

    def incr() -> int:
        nonlocal count          # 要修改外层变量必须声明 nonlocal
        count += 1
        return count

    return incr


c = make_counter()
print(c(), c(), c())      # 1 2 3

c2 = make_counter()
print(c2())               # 1 ← 各自独立的 cell
```

对比类实现：闭包更轻，适合「只有一个行为 + 一点私有状态」；需要多个方法/继承时用类。

> `nonlocal` 在 [00-Python基础/03](../00-Python基础/03-函数与作用域.md) 已讲。这里只需记住：**读**外层变量不用声明，**改**才要 `nonlocal`。

### 3.5 闭包陷阱（复习）

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])      # [2, 2, 2] ← 不是 [0, 1, 2]
```

原因：闭包捕获的是**变量**而不是**当时的值**，循环结束后 `i` 已是 2。修复：默认参数 `lambda i=i: i`（详细分析见 [00-Python基础/03](../00-Python基础/03-函数与作用域.md) §8）。

> 这个坑在装饰器里会再次出现（多个装饰器共享循环变量），务必记牢。

## 4. 装饰器本质（首次教学）

### 4.1 一句话定义

> **装饰器 = 接收函数、返回函数（或可调用对象）的可调用对象。**

```python
def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs).upper()
    return wrapper


@shout
def greet(name: str) -> str:
    return f"hello {name}"


print(greet("world"))        # HELLO WORLD
```

`@shout` 的作用**完全等价于**：

```python
def greet(name): ...
greet = shout(greet)         # 名字被重新绑定成 wrapper
```

所以「装饰器」既不神秘也不特殊：**它就是一次函数调用 + 重新赋值**，发生在**模块导入/类定义时**（不是每次调用时）。

### 4.2 执行时机

```python
def deco(func):
    print("① 装饰阶段：定义时执行一次")
    def wrapper(*a, **k):
        print("③ 调用阶段：每次调用都执行")
        return func(*a, **k)
    return wrapper


@deco
def work():
    print("② 原函数体")

print("--- 准备调用 ---")
work()
work()
```

输出：

```
① 装饰阶段：定义时执行一次
--- 准备调用 ---
③ 调用阶段：每次调用都执行
② 原函数体
③ 调用阶段：每次调用都执行
② 原函数体
```

**关键认知**：装饰器的「装配」只发生一次；`wrapper` 里的代码才在每次调用时执行。

## 5. `functools.wraps`：为什么必须加

```python
def bad_deco(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper


@bad_deco
def login(user: str) -> bool:
    """用户登录。"""
    return True


print(login.__name__)     # wrapper   ❌ 名字丢了
print(login.__doc__)      # None      ❌ 文档丢了
print(login.__annotations__)   # {}    ❌ 注解丢了
```

加 `@functools.wraps`：

```python
import functools


def good_deco(func):
    @functools.wraps(func)          # 把元数据拷到 wrapper 上
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper


@good_deco
def login(user: str) -> bool:
    """用户登录。"""
    return True


print(login.__name__)          # login
print(login.__doc__)           # 用户登录。
print(login.__annotations__)   # {'user': <class 'str'>, 'return': <class 'bool'>}
```

### 5.1 不加会怎样（真实后果）

| 后果 | 说明 |
| --- | --- |
| 文档失效 | FastAPI 用它生成 OpenAPI 接口名/描述；Pydantic 也读注解 |
| 调试困难 | traceback 里全是 `wrapper` |
| 测试工具失效 | pytest 按函数名收集用例 |
| 签名反射失效 | `inspect.signature` 拿到 `(*args, **kwargs)` |
| 依赖注入失效 | FastAPI 靠签名解析参数，签名被吃掉就解析不出 |

> **结论：装饰器一律加 `@functools.wraps(func)`，没有例外。**

## 6. 带参装饰器（三层结构，首次教学）

### 6.1 需求：`@retry(times=3)`

`@retry` 只能固定参数；要传参就得**再包一层**：

```python
import functools
import time


def retry(times: int = 3, delay: float = 0.1):
    """带参装饰器：出错时重试 times 次。"""

    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as exc:
                    last_exc = exc
                    print(f"[retry] 第 {attempt} 次失败: {exc}")
                    time.sleep(delay)
            raise last_exc

        return wrapper

    return decorator


@retry(times=3)
def flaky():
    raise ConnectionError("网络抖动")
```

### 6.2 三层各自的作用

```
retry(times=3)        →  返回 decorator（闭包，记住 times）
decorator(func)       →  返回 wrapper（闭包，记住 func 与 times）
wrapper(*a, **k)      →  真正运行时执行
```

对照展开写法：

```python
flaky = retry(times=3)(flaky)
```

### 6.3 归纳模板

```python
def deco_with_args(arg1, arg2=...):          # 第 1 层：接收参数
    def decorator(func):                      # 第 2 层：接收函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):         # 第 3 层：接收调用参数
            # 前置
            result = func(*args, **kwargs)
            # 后置
            return result
        return wrapper
    return decorator
```

| 装饰器形式 | 层数 | 示例 |
| --- | --- | --- |
| 无参 | 2 层（`deco(func)` → `wrapper`） | `@timer` |
| 带参 | 3 层（`deco(**kw)` → `decorator(func)` → `wrapper`） | `@retry(times=3)` |

> 记不住就记「**多一层，多一个闭包**」。

## 7. 装饰器叠加：执行顺序

```python
def A(func):
    @functools.wraps(func)
    def wrapper(*a, **k):
        print("A 进入")
        r = func(*a, **k)
        print("A 退出")
        return r
    return wrapper


def B(func):
    @functools.wraps(func)
    def wrapper(*a, **k):
        print("B 进入")
        r = func(*a, **k)
        print("B 退出")
        return r
    return wrapper


@A
@B
def work():
    print("work")


work()
```

输出：

```
A 进入
B 进入
work
B 退出
A 退出
```

规则：

| 阶段 | 顺序 |
| --- | --- |
| **装饰（定义时）** | 自下而上：先 `B(work)`，再 `A(B_wrapper)` |
| **调用（运行时）** | 自上而下进入，自下而上退出（像洋葱） |

等价展开：

```python
work = A(B(work))
```

> 记住「**洋葱模型**」：最外层装饰器离函数最远，最后被包上，最先执行。

## 8. 常用装饰器清单

### 8.1 计时

```python
import functools
import time


def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            cost = (time.perf_counter() - start) * 1000
            print(f"[timed] {func.__name__} 耗时 {cost:.2f} ms")
    return wrapper
```

> 用 `try/finally` 保证异常时也打日志（呼应 [00-Python基础/05](../00-Python基础/05-异常与文件IO.md)）。

### 8.2 缓存

```python
from functools import cache, lru_cache

@cache
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(50))     # 秒出（无缓存会指数级卡死）
```

| 装饰器 | 特点 |
| --- | --- |
| `@cache` | 无容量上限（3.9+），等价 `lru_cache(maxsize=None)` |
| `@lru_cache(maxsize=128)` | 有容量上限，超出按 LRU 淘汰 |

前提：**参数必须可哈希**（`list`/`dict` 不能直接当参数）。

```python
fib.cache_info()      # hits, misses, maxsize, currsize
fib.cache_clear()
```

### 8.3 日志（打印调用）

```python
def logged(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"→ {func.__name__}(args={args}, kwargs={kwargs})")
        try:
            result = func(*args, **kwargs)
            print(f"← {func.__name__} = {result!r}")
            return result
        except Exception as exc:
            print(f"✗ {func.__name__} 抛出 {type(exc).__name__}: {exc}")
            raise
    return wrapper
```

> 生产环境应写 `logging`，而不是 `print`（阶段 3/02）。

### 8.4 单例

```python
import functools


def singleton(cls):
    instances = {}

    @functools.wraps(cls)
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]

    return get_instance
```

> 注意：这会改变 `cls` 的类型（变成函数），不便继承。Python 更常见的单例做法是**模块级实例**（[00-Python基础/04](../00-Python基础/04-模块、包与导入.md) 的 `settings = Settings()`）。

### 8.5 权限/参数校验

```python
def require_admin(func):
    @functools.wraps(func)
    def wrapper(user, *args, **kwargs):
        if not getattr(user, "is_admin", False):
            raise PermissionError("需要管理员权限")
        return func(user, *args, **kwargs)
    return wrapper
```

> FastAPI 里这类逻辑一般用 **`Depends`** 实现，而不是手写装饰器（阶段 5/02）——装饰器适合与框架无关的横切逻辑。

## 9. 类装饰器与「装饰器类」

### 9.1 装饰器类（用 `__call__`）

```python
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"第 {self.count} 次调用 {self.func.__name__}")
        return self.func(*args, **kwargs)


@CountCalls
def ping():
    print("pong")


ping(); ping()
print(ping.count)      # 2
```

适用：装饰器需要**保存状态**且提供额外方法（`ping.count`）时。

> `functools.update_wrapper(self, func)` 是类版本的 `@wraps`。

### 9.2 装饰一个类

```python
def add_repr(cls):
    cls.__repr__ = lambda self: f"{cls.__name__}(id={getattr(self, 'node_id', '?')})"
    return cls


@add_repr
class Node:
    def __init__(self, node_id):
        self.node_id = node_id


print(Node("n1"))      # Node(id=n1)
```

> `@dataclass` 就是「装饰类」的重型版本：读类属性注解，自动生成 `__init__`/`__repr__`/`__eq__`。下一篇细讲。

## 10. 项目实战：框架里的装饰器在做什么

### 10.1 `@app.exception_handler(StarletteHTTPException)`

完整文件路径：`apps/api-py/app/errors.py`（节选）

```python
def register_error_handlers(app: FastAPI) -> None:
    @app.exception_handler(StarletteHTTPException)
    async def _http_exception_handler(_request: Request, exc: StarletteHTTPException) -> JSONResponse:
        ...

    @app.exception_handler(RequestValidationError)
    async def _validation_exception_handler(_request: Request, exc: RequestValidationError) -> JSONResponse:
        ...
```

拆解：

| 现象 | 解释 |
| --- | --- |
| `@app.exception_handler(X)` 带参数 | 它是**带参装饰器**（三层结构） |
| 被装饰的是 `async def` | 装饰器对函数是否异步无要求，`wrapper` 只需原样返回协程 |
| 装饰后**没有变量接收** | 装饰器把函数**登记进 `app` 内部表**，不靠返回值 |
| 两个函数都叫 `_..._handler` | 名字不重要，因为它们是「注册进表」而不是「被外部调用」 |

关键洞察：**装饰器除了「包裹」，还能「注册」**。

```python
def register(func):
    ROUTES[func.__name__] = func      # 只要副作用，不包装
    return func                        # 原样返回
```

`@app.get("/health")` 同理：**装饰器把「路径 → 处理函数」写进路由表**，而不是改变函数行为。

### 10.2 `@router.get(...)`

完整文件路径：`apps/api-py/app/api/health.py` 之类的路由文件（结构）：

```python
router = APIRouter()


@router.get("/health")
async def health() -> dict:
    return {"ok": True}
```

这里的 `@router.get("/health")` 等价于：

```python
def health() -> dict: ...
health = router.get("/health")(health)
```

`router.get(...)` 返回一个装饰器，它把 `health` 注册到 router 的路由表，并**原样返回函数**（所以 `health` 仍可直接调用）。

> 这也解释了 [00-Python基础/04](../00-Python基础/04-模块、包与导入.md) 里 `main.py` 为什么能用 `include_router(apps_router)` 一次性挂载：路由表在装饰时已经攒好了。

### 10.3 其他框架装饰器速查

| 装饰器 | 类型 | 作用 |
| --- | --- | --- |
| `@app.get/post/put/delete(path)` | 带参，注册型 | 注册路由 |
| `@app.exception_handler(Exc)` | 带参，注册型 | 注册异常处理器 |
| `@app.middleware("http")` | 带参，包装型 | 注册中间件（阶段 5/04） |
| `@app.on_event("startup")` | 带参，注册型 | 生命周期钩子 |
| `@pytest.fixture` | 注册型 | 注册测试夹具（阶段 9） |
| `@property` / `@staticmethod` / `@classmethod` | 内建 | 改变方法语义 |
| `@functools.cache` | 包装型 | 记忆化 |

## 11. 与 TypeScript 对照

| Python | TypeScript | 说明 |
| --- | --- | --- |
| 闭包 | 闭包 | 语义一致 |
| `nonlocal` | 直接改外部 `let` | JS 无此限制 |
| `@deco` | `@deco`（TS 装饰器） | 语法相似，机制不同 |
| 装饰器 = 函数替换 | 装饰器 = 描述符 + 元数据 | TS 装饰器不改写实现 |
| `@functools.wraps` | 反射元数据需手写 | Python 更便利 |
| 高阶函数 `(f) => (...a) => f(...a)` | 同 | 装饰器的函数式本质 |
| NestJS `@Get('/health')` | — | 与 `@router.get` 同为注册型装饰器 |
| NestJS `@Injectable()` | — | 依赖注入元数据（对应 FastAPI `Depends`） |

> 心智迁移：**TS 装饰器主要用于「贴元数据」给框架读；Python 装饰器是「真替换函数」**——所以要加 `wraps`，也要考虑性能开销。

## 12. 验收自测

### 12.1 预测输出

```python
def make(tag):
    def deco(func):
        @functools.wraps(func)
        def wrapper(*a, **k):
            print(f"{tag} 前")
            r = func(*a, **k)
            print(f"{tag} 后")
            return r
        return wrapper
    return deco


@make("A")
@make("B")
def work():
    print("work")


work()
```

<details>
<summary>答案</summary>

```
A 前
B 前
work
B 后
A 后
```
装饰自下而上（`B` 先包），调用自上而下（`A` 先进入）。

</details>

### 12.2 找错

```python
def deco(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper


@deco
def add(a: int, b: int) -> int:
    """两数相加"""
    return a + b

print(add.__name__)      # wrapper
```

问题：丢了元数据。修复：加 `@functools.wraps(func)`。

### 12.3 动手题

写 `@retry(times=3, exceptions=(ConnectionError,))`：只对指定异常重试，其他异常直接抛出。

参考实现：

```python
import functools
import time


def retry(times: int = 3, delay: float = 0.1, exceptions: tuple[type[Exception], ...] = (Exception,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as exc:
                    if attempt == times:
                        raise
                    print(f"[retry] 第 {attempt} 次失败: {exc}")
                    time.sleep(delay)
        return wrapper
    return decorator
```

> 注意：`except exceptions` 之外的异常会**自然向上冒泡**，不会被重试——这正是期望行为。

## 13. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `add.__name__` 变成 `wrapper` | 没加 `wraps` | `@functools.wraps(func)` |
| FastAPI 接口文档里全是 `wrapper` | 同上（框架读元数据） | 同上 |
| `@retry` 加括号后不生效 | 带参与无参混用 | `@retry(times=3)` vs `@retry` 分清层数 |
| 装饰器在导入时就执行了重逻辑 | 装配阶段执行 | 装配只做注册，重逻辑放 `wrapper` |
| 多个装饰器顺序搞反 | 洋葱模型记错 | 调用「自上而下」，包装「自下而上」 |
| 循环里创建的装饰器共享变量 | 闭包捕获变量而非值 | 默认参数或工厂函数 |
| `@cache` 报 `unhashable type` | 参数是 `list`/`dict` | 转 `tuple` 或改用自定义缓存 |
| 装饰器把异步函数变成同步函数 | `wrapper` 用了普通 `def` 且内部阻塞 | 异步函数用 `async def wrapper` 并在内部 `await` |
| 类装饰器丢失实例方法 | 返回了函数而非类 | 装饰类要返回类 |
| 用装饰器做权限但绕过 FastAPI 依赖注入 | 与框架机制冲突 | 优先用 `Depends` |

## 14. 本篇小结

- **闭包 = 内层函数 + 被带走的外层变量**；值存在 `cell` 里（`__closure__[0].cell_contents` 可验证）。
- **改外层变量要 `nonlocal`**；读不用声明。
- **装饰器本质是一次调用 + 重新绑定**：`@deco` ≡ `f = deco(f)`，发生在**定义/导入时**，不是每次调用时。
- **三层结构**：带参装饰器 = `接收参数 → 接收函数 → 接收调用参数`，多一层多一个闭包。
- **`@functools.wraps(func)` 必须加**：否则名字/文档/注解全丢，框架与调试工具都会失效。
- **叠加是洋葱**：包装自下而上，执行自上而下（进入 A→B，退出 B→A）。
- **常用套路**：计时（`try/finally`）、重试、缓存（`@cache`）、日志、单例、权限。
- **类装饰器**用 `__call__` 保存状态；**装饰类**返回类（`@dataclass` 的原理）。
- **框架装饰器多为「注册型」**：`@app.exception_handler(...)`、`@router.get(...)` 只把函数登记进表，原样返回——装饰器不只能「包裹」，还能「注册」。

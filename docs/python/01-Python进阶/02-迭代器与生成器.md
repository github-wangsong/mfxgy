## 3. 两个容易混的概念

| 概念 | 定义 | 例子 | 能否 `for` |
| --- | --- | --- | --- |
| **可迭代对象**（Iterable） | 实现了 `__iter__`，能**产出**迭代器 | `list`、`dict`、`str`、文件对象、生成器 | ✅ |
| **迭代器**（Iterator） | 实现了 `__iter__` + `__next__`，**自己就是**游标 | 生成器、`iter(list)`、`enumerate(...)` | ✅ |

关系：**迭代器一定是可迭代对象，可迭代对象不一定是迭代器。**

```python
nums = [1, 2, 3]           # 可迭代对象
it = iter(nums)            # 迭代器

print(next(it))            # 1
print(next(it))            # 2
print(next(it))            # 3
print(next(it))            # ❌ StopIteration

print(iter(nums) is nums)  # False ← list 不是迭代器
```

生成器则是「自己就是迭代器」：

```python
def gen():
    yield 1

g = gen()
print(iter(g) is g)        # True
```

## 4. `for` 循环的真实展开（首次教学）

```python
for x in [1, 2, 3]:
    print(x)
```

等价于：

```python
_it = iter([1, 2, 3])          # ① 取迭代器
while True:
    try:
        x = next(_it)          # ② 取下一个
    except StopIteration:      # ③ 迭代器耗尽 → 正常退出
        break
    print(x)
```

这解释了三件事：

1. **`for` 不依赖下标**，所以 `set`/`dict`/文件/生成器都能 `for`。
2. **`StopIteration` 是「正常结束」信号**，不是错误。
3. **不要在生成器里手动 `raise StopIteration`**（PEP 479 起会被转成 `RuntimeError`）：想提前结束就 `return`。

## 5. 手写迭代器类

```python
class Countdown:
    """从 start 倒数到 1 的迭代器。"""

    def __init__(self, start: int):
        self.current = start

    def __iter__(self):
        return self                  # 迭代器返回自己

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration          # 结束信号
        value = self.current
        self.current -= 1
        return value


for n in Countdown(3):
    print(n)          # 3 2 1
```

对比：`__iter__` 返回**新的**迭代器（可重复遍历） vs 返回 `self`（一次性遍历）。

```python
class Reusable:
    def __init__(self, data):
        self.data = data

    def __iter__(self):
        return iter(self.data)       # 每次 for 都拿到新迭代器 → 可重复
```

> 这就是为什么 `list` 可以遍历多次，而**生成器只能遍历一次**——生成器 `__iter__` 返回的就是它自己。

## 6. 生成器函数：`yield`（首次教学）

### 6.1 最小示例

```python
def count_up(n: int):
    print("开始")
    for i in range(1, n + 1):
        print(f"准备产出 {i}")
        yield i
    print("结束")


g = count_up(3)          # ① 调用不执行函数体！只创建生成器对象
print(type(g))           # <class 'generator'>

print(next(g))           # 开始 / 准备产出 1 / 1
print(next(g))           # 准备产出 2 / 2
print(next(g))           # 准备产出 3 / 3
print(next(g))           # 结束 / StopIteration
```

输出顺序：

```
<class 'generator'>
开始
准备产出 1
1
准备产出 2
2
准备产出 3
3
结束
Traceback ... StopIteration
```

三个关键认知：

| 认知 | 说明 |
| --- | --- |
| **调用生成器函数不执行函数体** | 只返回生成器对象 |
| **每次 `next()` 执行到下一个 `yield` 就暂停** | 局部变量、执行位置全部保留 |
| **`yield` 既「产出值」又「交出控制权」** | 下次 `next()` 从暂停处继续 |

### 6.2 执行模型（图示）

```
next(g) ──→ 运行 ──→ yield 1 ──→ 暂停（保存栈帧、局部变量 i=1）
next(g) ──→ 恢复 ──→ 循环 ──→ yield 2 ──→ 暂停（i=2）
...
函数 return（或结束）──→ 抛 StopIteration
```

> 生成器本质是**可暂停的函数**（协程的前身）。`async def` + `await` 的协程就是这套机制的异步版（阶段 2/02）。

### 6.3 生成器的三种收尾

```python
def echo():
    try:
        while True:
            value = yield
            print("收到:", value)
    finally:
        print("清理资源")          # 生成器被关闭时执行


g = echo()
next(g)             # 启动，停在第一个 yield
g.send("a")         # 收到: a
g.send("b")         # 收到: b
g.close()           # 清理资源
```

| 方法 | 作用 |
| --- | --- |
| `next(g)` | 恢复并跑到下一个 `yield`（等价 `g.send(None)`） |
| `g.send(v)` | 恢复并把 `v` 作为 `yield` 表达式的值 |
| `g.throw(exc)` | 在暂停处抛出异常（生成器内部可用 `try/except` 处理） |
| `g.close()` | 抛 `GeneratorExit`，触发 `finally` 清理 |

> `send` 是「生成器变协程」的入口。日常业务 **90% 只用 `for`**，不需要手写 `send`；但理解它才能理解 `await`。

### 6.4 `yield` 在 `try/finally` 中

```python
def safe_gen():
    try:
        yield 1
        yield 2
    finally:
        print("一定执行")
```

无论正常耗尽、`break` 提前退出（`for` 结束时会 close）、还是 `close()`，`finally` 都会执行——资源清理可以放在这里（下一篇的上下文管理器会把这套逻辑标准化）。

## 7. 惰性求值：为什么要用生成器

### 7.1 内存对比

```python
import sys

squares_list = [i * i for i in range(1_000_000)]
squares_gen = (i * i for i in range(1_000_000))

print(sys.getsizeof(squares_list))     # 约 8 MB（800 万+ 字节）
print(sys.getsizeof(squares_gen))      # 约 200 字节（固定）
```

| 维度 | 列表 | 生成器 |
| --- | --- | --- |
| 求值时机 | 立即全部计算 | 用到才算 |
| 内存 | 与元素数成正比 | 常数级 |
| 可遍历次数 | 无限次 | **只能一次** |
| 可否索引/切片 | ✅ | ❌ |
| 适用 | 需要反复访问、随机访问 | 流式处理、大数据、一次性消费 |

### 7.2 什么时候必须用生成器

- 数据量大于内存（日志、CSV、数据库游标）；
- 只想消费一次（`sum`/`max`/`any`/写文件）；
- 上游生产慢、下游消费慢，希望**边产边消**（流式响应、SSE）；
- 提前退出能省掉剩余计算（`any(...)` 命中即停）。

### 7.3 什么时候别用

- 需要 `len()`、索引、多次遍历 → 用 `list`；
- 需要把结果传出去后被多处消费 → 用 `list`；
- 逻辑很短且数据很小 → 直接用推导式，别为「省内存」牺牲可读性。

## 8. 生成器表达式（首次教学）

```python
# 列表推导：立即算完
lst = [x * 2 for x in range(5)]

# 生成器表达式：惰性
gen = (x * 2 for x in range(5))
```

语法差别仅在括号：`[...]` vs `(...)`。

### 8.1 作为函数唯一参数时省略括号

```python
total = sum(x * x for x in range(1000))     # ✅ 推荐
total = sum([x * x for x in range(1000)])   # ❌ 多造一个 list
```

### 8.2 与 `any`/`all` 组合的短路优势

```python
logs = ["ok", "ok", "ERROR: disk full", "ok"]

has_error = any("ERROR" in line for line in logs)   # 命中即停，后面的不看
```

> 对比 `any(["ERROR" in l for l in logs])`：后者会**先算完全部**再判断。数据大时差距明显。

### 8.3 嵌套与条件

```python
rows = [[1, 2], [3], []]

flat = (n for row in rows for n in row)          # 双层展开
even = (n for n in range(20) if n % 2 == 0)      # 带过滤
```

> 超过两层嵌套就该考虑拆成生成器函数，可读性会更好。

## 9. 「只能用一次」的陷阱（必踩）

```python
gen = (x for x in range(3))

print(list(gen))      # [0, 1, 2]
print(list(gen))      # []  ← 已经耗尽
```

三个真实场景：

```python
# ❌ 场景 1：先 count 再遍历
gen = load_rows()
print("共", len(list(gen)), "行")     # 消费掉了
for row in gen: ...                   # 一行都没有

# ❌ 场景 2：函数参数是生成器，函数内遍历了两次
def summarize(items):
    total = sum(items)
    count = len(list(items))          # 第二次是空的
    return total, count

# ❌ 场景 3：把生成器存到对象属性，多处消费
self.rows = (parse(l) for l in lines)
```

修复策略：

| 场景 | 方案 |
| --- | --- |
| 需要多次遍历 | 一开始就 `list(...)` 落盘 |
| 需要长度 + 内容 | 先 `rows = list(gen)` 再算 |
| 大数据不能落盘 | 用 `itertools.tee(gen, 2)`（会缓存，谨慎） |
| 接口对外 | 返回 `list` 或让调用方自己缓存 |

> **接口设计原则**：如果你返回的是生成器，就要在文档里明确「一次性」，否则调用方一定会踩坑。

## 10. `yield from` 与流水线

### 10.1 `yield from`：委托给子生成器

```python
def inner():
    yield 1
    yield 2
    return "done"           # 子生成器的返回值


def outer():
    result = yield from inner()      # 把产出全部转发出去
    print("inner 返回:", result)
    yield 3


print(list(outer()))       # 打印 "inner 返回: done"，返回 [1, 2, 3]
```

`yield from` 做三件事：

1. 把子生成器的每个值**原样转发**；
2. 转发 `send`/`throw`/`close`；
3. 表达式结果是子生成器的 `return` 值。

用途：把一个「多层遍历」拍平成单层（比 `for x in inner(): yield x` 更高效、语义更准）。

### 10.2 流水线（pipeline）模式

```python
from collections.abc import Iterator


def read_lines(path: str) -> Iterator[str]:
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")


def only_errors(lines: Iterator[str]) -> Iterator[str]:
    for line in lines:
        if "ERROR" in line:
            yield line


def parse(lines: Iterator[str]) -> Iterator[dict]:
    for line in lines:
        level, _, message = line.partition(" ")
        yield {"level": level, "message": message}


def run(path: str) -> None:
    for row in parse(only_errors(read_lines(path))):
        print(row)


# 或者拆开写，便于单独测试
lines = read_lines("app.log")
errors = only_errors(lines)
for row in parse(errors):
    print(row)
```

好处：

| 特性 | 说明 |
| --- | --- |
| 常数内存 | 每级只持有「一个元素」 |
| 可组合 | 每级都是 `Iterator[X] -> Iterator[Y]` |
| 可单测 | 每级能独立测，不需要真文件 |
| 惰性 | 下游不取，上游不算 |

> 这正是 [00-Python基础/05](../00-Python基础/05-异常与文件IO.md) 里 `for line in f` 的扩展版：**文件 → 过滤 → 解析 → 消费**，全链路零全量加载。

### 10.3 `itertools` 速览（了解）

| 函数 | 作用 |
| --- | --- |
| `islice(it, n)` | 取前 n 个（生成器切片） |
| `chain(a, b)` | 串联多个可迭代对象 |
| `groupby(it, key)` | 分组（需先排序） |
| `count(start, step)` | 无限计数 |
| `cycle(it)` | 循环重复 |
| `takewhile` / `dropwhile` | 按条件截取/跳过 |
| `zip_longest` | 拉链补齐 |
| `tee(it, n)` | 复制 n 份（有缓存成本） |

```python
from itertools import islice

def naturals():
    n = 1
    while True:
        yield n
        n += 1

print(list(islice(naturals(), 5)))     # [1, 2, 3, 4, 5]
```

> 无限生成器 + `islice` 是「用多少算多少」的经典组合。

## 11. 项目实战：RAG 与 SSE 里的迭代思想

### 11.1 切分→向量化：天然的分批处理

完整文件路径：`apps/api-py/app/rag/splitter.py`（节选）

```python
def split_text(text: str) -> list[str]:
    """按 `SPLITTER_CONFIG` 把文本切成若干块（保持原顺序）。"""
    splitter = RecursiveCharacterTextSplitter(**SPLITTER_CONFIG)
    return splitter.split_text(text)
```

这里返回的是 `list`，因为块数有限、后续要多次使用（入库 + 记录数量）。但**消费侧**是按块循环处理：

```python
chunks = split_text(document)
for chunk in chunks:
    embedding = embed(chunk)          # 逐块向量化
    save_chunk(chunk, embedding)
```

教学点：**「产出一批、逐个消费」的结构，就可以改造成生成器**。如果文档极大（比如解析出的 PDF 有几十万字符），把 `split_text` 改成 `yield` 逐块返回，就能把内存从「全部块」降到「一块」。

对比两种写法：

```python
# 一次性：内存 O(块数)
def split_all(text: str) -> list[str]:
    return splitter.split_text(text)

# 流式：内存 O(1)
def split_iter(text: str):
    for chunk in splitter.split_text(text):
        yield chunk
```

> 判据不是「生成器更高级」，而是**「下游是否只消费一次」**。RAG 入库正是只消费一次，所以适合流式。

### 11.2 SSE：为什么必须流式

`apps/api-py/app/api/run.py` 提供 `/api/apps/{id}/run` 的 SSE 接口。SSE 的本质是**服务端一条一条推事件**：

```
data: {"event":"start", ...}

data: {"event":"token","data":{"delta":"你"}}

data: {"event":"end", ...}
```

如果用「先算完、再一次性返回」的写法，用户会盯着空白等十几秒——流式的价值就是**边算边推**。

Python 侧这种「逐条产出、逐条发送」的实现就是**异步生成器**：

```python
async def stream_events():
    yield "start"
    yield "token"
    yield "end"
```

> 本篇只建立「生成器 = 可暂停的产出器」这个心智；`async def` + `yield` 的完整用法、以及它如何与 ASGI 的 `StreamingResponse` 结合，在阶段 8/01 讲。**先有同步生成器，才谈得上异步生成器**。

## 12. 与 TypeScript 对照

| Python | TypeScript | 说明 |
| --- | --- | --- |
| `for x in list` | `for (const x of list)` | 都是迭代协议 |
| `iter(obj)` / `next(it)` | `obj[Symbol.iterator]()` / `.next()` | 协议名不同，结构一致 |
| `StopIteration` | `{value, done: true}` | JS 用 done 标记，Python 用异常 |
| `yield` 生成器 | `function*` 生成器 | 语义几乎一致 |
| `g.send(v)` | `it.next(v)` | JS 的 next 支持传值 |
| 生成器表达式 `(f(x) for x in xs)` | 无直接对应（需 `function*`） | Python 更简洁 |
| `yield from inner()` | `yield* inner()` | 一致 |
| `itertools` | 手写 / lodash / iter-tools | Python 标准库更全 |
| `async def` + `yield` | `async function*` | 阶段 8 |

> 心智迁移：**JS 的 `for...of` 与 Python 的 `for...in` 都走迭代协议**；JS 用 `{done:true}` 表示结束，Python 抛 `StopIteration`。

### 13.3 动手题

写一个生成器 `read_errors(path)`：

- 流式读文件，不 `readlines`；
- 只产出含 `ERROR` 的行（去掉行尾换行）；
- 文件不存在时产出 0 项（不抛异常）。

参考实现：

```python
from collections.abc import Iterator


def read_errors(path: str) -> Iterator[str]:
    try:
        with open(path, encoding="utf-8") as f:
            for line in f:
                if "ERROR" in line:
                    yield line.rstrip("\n")
    except FileNotFoundError:
        return          # 生成器里 return = 直接结束，产出 0 项
```

> 注意：`return` 在生成器里表示「正常结束」，**不要** `raise StopIteration`。

## 14. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 第二次遍历得到空 | 生成器一次性耗尽 | 落成 `list`，或每次重新调用生成器函数 |
| 调用生成器函数没执行 | 只有 `next`/`for` 才驱动 | 记住「调用 ≠ 执行」 |
| `RuntimeError: generator raised StopIteration` | 生成器内手动 `raise StopIteration` | 用 `return` 结束 |
| 生成器表达式传给多个消费者 | 共享同一个生成器 | 各自创建，或先转 `list` |
| 在生成器里改外部列表却不生效 | 惰性：没被消费就不会执行 | 确保有消费者；或改为立即执行 |
| `len(gen)` 报错 | 生成器没有 `__len__` | 转 `list` 或用计数器 |
| 生成器里的 `try/except` 抓不到异常 | 异常发生在暂停之前/之后 | 理解「暂停点」；必要时用 `throw` |
| 递归生成器爆栈 | 深度递归 + `yield` | 改迭代/显式栈，或 `yield from` 配合深度限制 |
| 大量数据用 `list(...)` 包装 | 丢失惰性优势 | 只在确实需要时物化 |

---

## 15. 本篇小结

- **可迭代对象**有 `__iter__`；**迭代器**还有 `__next__`，且 `iter(it) is it`。
- **`for` 的展开**：`iter` → 反复 `next` → 捕获 `StopIteration` 结束；所以不需要下标。
- **生成器函数调用不执行**，只有 `next`/`for` 驱动；每次 `yield` 暂停并**保留局部状态**。
- **`yield` 既能产出又能接收**（`send`），这是协程的雏形；日常只用 `for`，但概念要懂。
- **惰性与内存**：生成器常数内存、一次性消费；需要多次遍历/索引时用列表。
- **生成器表达式**在函数唯一参数时可省括号；与 `any`/`all` 组合能短路，比列表推导更快更省。
- **`yield from`** 转发产出与 `send`/`throw`/`close`，并返回子生成器的 `return` 值。
- **流水线模式**：`read → filter → parse → consume`，每级都是 `Iterator[X] -> Iterator[Y]`，可单测、常数内存。
- **接口返回生成器要在文档里标注「一次性」**，否则调用方必然踩坑。
- **下一步**：装饰器与闭包——闭包捕获、`functools.wraps`、带参装饰器、类装饰器。

## 3. 三类问题，三件工具

| 类别 | 例子 | 工具 | 能否自动修 |
| --- | --- | --- | --- |
| **格式**（排版） | 缩进、引号、换行、行尾空格 | `ruff format` | ✅ 全自动 |
| **风格/缺陷**（lint） | 未使用导入、可变默认参数、`== None` | `ruff check` | ✅ 大部分 `--fix` |
| **类型**（语义） | 把 `str` 传给要 `int` 的函数 | `mypy` | ❌ 需人改 |

> 前两类是「机器说了算」，第三类需要人补注解。**三者都通过，才叫「静态干净」。**

### 3.1 为什么不只用一种

| 只做格式化 | 只做 lint | 只做类型检查 |
| --- | --- | --- |
| 代码好看但可能有 bug | 捕获不了类型错误 | 捕获不了未使用变量 |

## 4. `ruff`：一个工具干三件事

### 4.1 它替代了什么

| 历史工具 | 职责 | ruff 对应 |
| --- | --- | --- |
| `black` | 格式化 | `ruff format` |
| `isort` | import 排序 | `ruff check --select I --fix` |
| `flake8` | 风格检查 | `ruff check`（`E`/`F` 规则） |
| `pyupgrade` | 现代化语法 | `ruff check --select UP --fix` |
| `flake8-bugbear` | 常见缺陷 | `ruff check --select B` |
| `pylint`（部分） | 代码质量 | 部分规则 |

优势：

| 优势 | 说明 |
| --- | --- |
| 快 | Rust 实现，比 flake8 快几十倍 |
| 单工具 | 一套配置、一次运行、一个输出 |
| 规则码统一 | `E501`/`F401` 等一眼可查 |
| 与 black 兼容 | `ruff format` 输出接近 black |

### 4.2 两条命令，职责不同

```powershell
uv run ruff check . --fix        # ① 修「问题」（未用导入、写法改进）
uv run ruff format .             # ② 修「排版」（引号、换行、缩进）
```

**必须按这个顺序**：

| 顺序 | 结果 |
| --- | --- |
| `check --fix` → `format` | ✅ 先删掉多余代码，再统一排版 |
| `format` → `check --fix` | ⚠️ `--fix` 可能改动排版，导致格式回归 |

> 常见 CI 写法：

```powershell
uv run ruff check . --fix
uv run ruff format .
uv run ruff check .              # 再确认一次（防止 fix 后仍有残留）
```

### 4.3 只检查不修改（CI 用）

```powershell
uv run ruff check .
uv run ruff format --check .     # 有需要格式化的文件就退出非 0
```

| 命令 | 行为 |
| --- | --- |
| `ruff check .` | 报告问题，不修改 |
| `ruff check . --fix` | 自动修可修的 |
| `ruff format .` | 直接改文件 |
| `ruff format --check .` | 只检查格式是否已符合 |

> **CI 一律用 `--check` 版本**，不允许 CI 改代码。

### 4.4 规则码：怎么读

```
app/security.py:27:5: F401 [*] `os` imported but unused
app/config.py:25:5: E501 Line too long (121 > 120)
app/rag/splitter.py:12:1: I001 [*] Import block is un-sorted or un-formatted
app/utils.py:8:5: B006 Do not use mutable data structures for argument defaults
```

| 前缀 | 来源 | 含义 |
| --- | --- | --- |
| `E`/`W` | pycodestyle | 风格（缩进、行长、空白） |
| `F` | pyflakes | 逻辑缺陷（未用导入/变量、未定义名） |
| `I` | isort | import 顺序 |
| `B` | bugbear | 常见坑（可变默认参数、`assert` 滥用） |
| `UP` | pyupgrade | 可现代化的旧写法 |
| `SIM` | simplify | 可简化的冗余代码 |
| `C4` | comprehensions | 推导式改进 |
| `N` | pep8-naming | 命名规范 |
| `ANN` | annotations | 缺类型注解（严格项目用） |

`[*]` 表示**可自动修复**。

```powershell
uv run ruff check --select F401 .        # 只看某一类
uv run ruff rule B006                    # 查某条规则的详细说明
uv run ruff rule --all | Select-String "mutable"   # 搜索规则
```

### 4.5 基础配置

```toml
# pyproject.toml
[tool.ruff]
line-length = 120
target-version = "py312"
exclude = [".venv", "__pycache__", "build", "dist", "migrations"]

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "C4"]
ignore = [
    "E501",      # 行长交给 formatter（或按团队决定保留）
]

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["ANN", "S101"]      # 测试里允许 assert 与不打注解
"app/models/**" = ["N815"]        # ORM 模型可用驼峰列名（如需要）
```

| 配置项 | 说明 |
| --- | --- |
| `line-length` | 建议 100~120；与 formatter 共用 |
| `target-version` | 决定 `UP` 规则是否建议新语法（`py312` 才允许 `type X = ...`） |
| `exclude` | 排除生成代码（迁移、`build/`） |
| `select` | 启用哪些规则族（**先少后多**，逐族加） |
| `per-file-ignores` | 按路径豁免 |

> **不要一开始 `select = ["ALL"]`**：几百条规则会让老项目寸步难行。推荐顺序：`E,F` → `+I` → `+B` → `+UP,SIM,C4`。

### 4.6 格式化的可控选项

```toml
[tool.ruff.format]
quote-style = "double"            # 双引号（默认）
indent-style = "space"
skip-magic-trailing-comma = false # 尾逗号是否强制换行
docstring-code-format = true      # 也格式化 docstring 里的代码示例
```

> 与 prettier 类似：**格式无争议，团队不讨论**。定了就全项目一致。

### 4.7 忽略单行

```python
import os  # noqa: F401        # 明确说明原因：兼容旧导出
value = compute()  # noqa: B018

# 忽略整段
# ruff: noqa: E501
```

> `# noqa` 必带规则码。**裸 `# noqa` 会掩盖将来的新问题**。

## 5. `mypy`：类型检查

### 5.1 它与注解的关系

注解只是**元数据**，Python 运行期不校验（[01-Python进阶/01](../01-Python进阶/01-类型注解与typing.md) §3）。`mypy` 在**不运行代码**的前提下，检查注解是否自相矛盾。

```python
def add(a: int, b: int) -> int:
    return a + b


add("1", "2")       # ✅ 能跑（字符串拼接），但 mypy 报错
```

```
error: Argument 1 to "add" has incompatible type "str"; expected "int"
```

> 这正是静态检查的价值：**在运行前抓住类型错误**。

### 5.2 安装与运行

```powershell
uv add --dev mypy
uv run mypy app
```

### 5.3 配置与渐进变严

```toml
[tool.mypy]
python_version = "3.12"
warn_unused_configs = true
warn_redundant_casts = true
warn_unused_ignores = true          # 没起作用的 ignore 也报错
no_implicit_optional = true
check_untyped_defs = true           # 未注解函数体也检查
disallow_untyped_defs = false       # ← 先关，逐步打开
plugins = ["pydantic.mypy"]
```

```toml
[[tool.mypy.overrides]]
module = "langchain.*"
ignore_missing_imports = true       # 第三方库缺 py.typed 时
```

**三档严格度**（推荐按顺序推进）：

| 档位 | 关键开关 | 适合 |
| --- | --- | --- |
| 宽松 | `check_untyped_defs = true` | 老项目起步 |
| 中等 | `disallow_untyped_defs = true` | 新代码必须注解 |
| 严格 | `strict = true` | 全新项目 / 核心库 |

> `strict = true` 等价打开一堆开关（`disallow_unchecked_any`、`no_implicit_optional`、`warn_return_any`…）。**别一上手就开**，会淹在几百条错误里。

### 5.4 常见错误与修法

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `Missing return statement` | 有分支没 `return` | 补全所有分支 |
| `Item "None" has no attribute` | 可能是 `None` | 加 `if x is None: return` 收窄 |
| `Incompatible types in assignment` | 变量类型变了 | 换变量名或改注解 |
| `Need type annotation` | 空容器无法推断 | `items: list[str] = []` |
| `Cannot find implementation or library stub` | 库无 `py.typed` | 装 `types-xxx` 或 `ignore_missing_imports` |
| `Returning Any from function declared to return` | 返回 `Any` | 显式 `cast` 或窄化 |

### 5.5 `# type: ignore` 的规范

```python
result = client.request(...)  # type: ignore[call-arg]
```

| 写法 | 评价 |
| --- | --- |
| `# type: ignore` | ❌ 忽略一切错误，将来新问题也被吞 |
| `# type: ignore[call-arg]` | ✅ 只忽略指定错误码 |
| `# type: ignore[call-arg]  # 上游签名与实际不符` | ✅✅ 最好（带原因） |

配合 `warn_unused_ignores = true`：**当上游修好后，这个 ignore 会报错提醒你删掉**。

### 5.6 与运行时校验的分工

| 层 | 负责 | 例子 |
| --- | --- | --- |
| `mypy` | 静态类型一致性 | 传错类型 |
| Pydantic | 外部输入校验 | JSON 里 `age: "abc"` |
| 单元测试 | 行为正确性 | 令牌过期是否被拒 |

> 三者互补，谁也替代不了谁。**外部输入永远交给 Pydantic，不要指望 mypy 兜住用户输入。**

## 6. `pyright` / `basedpyright` 简述

| 特性 | `mypy` | `pyright` |
| --- | --- | --- |
| 实现 | Python | TypeScript（Node 运行） |
| 速度 | 中 | 快 |
| 编辑器集成 | 插件 | **Pylance 内置**（VS Code 默认） |
| 严格度 | 可精细分档 | 分级 `basic`/`strict` |
| 生态 | 老牌、插件多 | 微软维护、更新快 |

```powershell
uv add --dev basedpyright
uv run basedpyright app
```

> 实践建议：**编辑器里靠 Pylance（pyright），CI 里跑 mypy**——两者互补能抓到不同问题。只选一个也行，选团队更熟的那个。

## 7. `pre-commit`：提交前拦截

### 7.1 解决什么问题

| 不装 pre-commit | 装了 |
| --- | --- |
| 忘了格式化就提交 | 自动格式化后重提交 |
| CI 才报 lint 错，来回修 | 本地就拦住 |
| 每个人的编辑器配置不同 | 统一由仓库配置决定 |

### 7.2 安装

```powershell
uv add --dev pre-commit
uv run pre-commit install
```

`pre-commit install` 会写 `.git/hooks/pre-commit`，之后每次 `git commit` 自动执行。

### 7.3 配置

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-toml
      - id: check-added-large-files

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.11.2
    hooks:
      - id: mypy
        additional_dependencies: [pydantic, types-PyYAML]
```

| 字段 | 说明 |
| --- | --- |
| `repo` | 钩子来源仓库 |
| `rev` | **必须固定 tag**（别用 `main`，否则不可复现） |
| `id` | 钩子名 |
| `args` | 传给工具的额外参数 |
| `additional_dependencies` | 钩子运行环境需要的包（mypy 需要能 import 你的依赖） |

### 7.4 常用命令

| 命令 | 作用 |
| --- | --- |
| `pre-commit install` | 装 git hook |
| `pre-commit run --all-files` | 对全部文件跑一遍（**首次必做**） |
| `pre-commit run` | 只跑暂存区文件 |
| `pre-commit autoupdate` | 更新 `rev` 到最新 |
| `pre-commit clean` | 清缓存 |
| `git commit --no-verify` | 跳过检查（**仅应急**） |

### 7.5 首次全量失败是正常的

新装 pre-commit 后第一次 `git commit`，可能一次改了几十个文件。原因：**历史代码从未被格式化**。

正确做法：

```powershell
uv run pre-commit run --all-files
git add -A
git commit -m "chore: 统一代码格式（pre-commit 首次全量）"
```

> 把它当成**一次性的格式统一提交**，单独成一个 commit，方便 review 时跳过。

### 7.6 mypy 在 pre-commit 里的坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Cannot find implementation` | 钩子环境里没装你的依赖 | `additional_dependencies` 列出 |
| 本地通过、钩子里失败 | 钩子用独立 venv，版本不同 | 固定 `rev` + 补依赖 |
| 变慢很多 | mypy 全量检查 | 用 `files:` 限定范围，或改在 CI 跑 |

> 折中方案：**pre-commit 只跑 ruff（快），mypy 放 CI（全量）**。这是很多团队的实际选择。

## 8. CI 集成

```yaml
# .github/workflows/ci.yml（示意）
jobs:
  check:
    steps:
      - uses: actions/checkout@v4
      - run: uv sync --frozen --no-dev --group dev
      - run: uv run ruff check .
      - run: uv run ruff format --check .
      - run: uv run mypy app
      - run: uv run pytest -q --cov=app --cov-fail-under=70
```

| 原则 | 说明 |
| --- | --- |
| 同一套配置 | 本地与 CI 都读 `pyproject.toml`，不写两套参数 |
| 只检查不修改 | CI 用 `--check`，不 `--fix` |
| 顺序由快到慢 | ruff（秒级）→ mypy（十秒级）→ pytest（分钟级） |
| 锁文件冻结 | `uv sync --frozen`（[01 篇](./01-pyproject与依赖管理.md) §6.3） |

> 顺序的意义：**最快失败的最先跑**，开发者等待时间最短。

## 9. 项目实战：给 `apps/api-py` 补齐检查链

### 9.1 现状盘点（真实）

| 项 | 现状 | 评价 |
| --- | --- | --- |
| `ruff` 在 dev 组 | ✅ `ruff>=0.6.0` | 已装 |
| `[tool.ruff]` 配置 | ❌ 无 | 用默认（行长 88，规则 `E4,E7,E9,F`） |
| `mypy` | ❌ 无 | 类型检查只能靠编辑器 |
| `pyright`/Pylance | 取决于编辑器 | 不稳定 |
| `pre-commit` | ❌ 无 | 无提交前拦截 |
| `[tool.pytest.ini_options]` | ❌ 无 | `testpaths` 与 `asyncio_mode` 未设 |

### 9.2 建议的 `pyproject.toml` 追加段

```toml
[tool.ruff]
line-length = 120
target-version = "py312"
exclude = [".venv", "__pycache__", "build", "dist"]

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "SIM", "C4"]
ignore = ["E501"]

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]

[tool.ruff.format]
quote-style = "double"

[tool.mypy]
python_version = "3.12"
check_untyped_defs = true
warn_unused_ignores = true
no_implicit_optional = true
plugins = ["pydantic.mypy"]

[[tool.mypy.overrides]]
module = ["langchain.*", "langgraph.*", "pgvector.*"]
ignore_missing_imports = true

[tool.pytest.ini_options]
testpaths = ["tests"]
asyncio_mode = "auto"
addopts = "-q"
```

### 9.3 为什么这些参数适合这个项目

| 决策 | 理由 |
| --- | --- |
| `line-length = 120` | 已有代码多为此长度；88 会产生大量无意义 diff |
| `ignore = ["E501"]` | 行长交给 formatter 统一处理，避免与 lint 打架 |
| `select` 只到 `C4` | 渐进：先抓真问题（`F`/`B`），暂不上 `ANN`/`S` |
| `tests/**` 用 `S101` | pytest 就是靠 `assert`，不该被「禁止 assert」规则拦 |
| `check_untyped_defs = true` | 老代码不必立刻全注解，但函数体里的错要抓 |
| `plugins = ["pydantic.mypy"]` | 让 `BaseSettings` 字段类型被正确理解 |
| `ignore_missing_imports` 三族 | 这些库的 `py.typed` 不全 |

### 9.4 落地步骤（可照抄）

```powershell
cd apps\api-py

# 1. 加依赖
uv add --dev mypy pre-commit pytest-cov pytest-asyncio

# 2. 写入上面的配置段（pyproject.toml）

# 3. 首次格式化（会产生较大 diff，单独提交）
uv run ruff format .
uv run ruff check . --fix
uv run ruff check .

# 4. 装钩子并对全量跑一次
uv run pre-commit install
uv run pre-commit run --all-files

# 5. 看类型问题规模（先不修，评估工作量）
uv run mypy app | Select-Object -Last 5
```

> 第 5 步的输出决定了「一次修完」还是「先加白名单逐步推进」。**先量化再决策**。

### 9.5 与 TS 侧的一致性

| 检查 | TS 侧 | Python 侧 |
| --- | --- | --- |
| 格式化 | Prettier | `ruff format` |
| Lint | ESLint | `ruff check` |
| 类型 | `tsc --noEmit` | `mypy` |
| 提交前 | husky + lint-staged | `pre-commit` |

> 双栈项目最好让两侧的**行宽、缩进、引号**保持一致，减少跨语言切换的心智负担。

## 10. 与 TypeScript 对照

| Python | TS | 说明 |
| --- | --- | --- |
| `ruff format` | Prettier | 无争议格式化 |
| `ruff check` | ESLint（`eslint --fix`） | 规则化检查 |
| `mypy` | `tsc --noEmit` | 类型检查 |
| `# type: ignore[code]` | `// @ts-expect-error` | TS 的 `@ts-expect-error` 更严格（若无错会报错） |
| `pyright`/Pylance | `tsc`（编辑器内建） | 编辑器即时反馈 |
| `pre-commit` | husky + lint-staged | 提交前拦截 |
| `[tool.ruff]` | `.eslintrc` / `eslint.config.js` | 都集中配置 |
| `per-file-ignores` | `overrides` | 按路径豁免 |
| `noqa` | `// eslint-disable-line` | 行内豁免 |
| `strict = true` | `strict: true`（tsconfig） | 严格模式 |

> 关键差异：**TS 的类型是语言的一部分（编译期强制），Python 的类型是可选的（工具链强制）**。所以 Python 项目更需要显式把 `mypy` 放进 CI，否则注解只是注释。

## 11. 验收自测

### 11.1 判断对错

1. `ruff format` 能修掉未使用的 import。
2. `# noqa` 不带规则码也能安全使用。
3. `mypy` 会在运行时校验参数类型。

<details>
<summary>答案</summary>

1. ❌ —— 那是 `ruff check --fix`（`F401`）的职责。
2. ❌ —— 裸 `# noqa` 会掩盖所有规则，将来新增问题也被吞。
3. ❌ —— `mypy` 只在静态分析阶段工作；运行期校验靠 Pydantic 或手写检查。

</details>

### 11.2 找错

```toml
[tool.ruff]
select = ["ALL"]
ignore = ["E501"]
```

两个问题：

1. `select` 位置错了（应在 `[tool.ruff.lint]`）；旧版 `ruff` 允许写在顶层，新版会告警/迁移；
2. `ALL` 一次性打开几百条规则，老项目会产生海量告警，应逐族增加。

### 11.3 动手题

给一个已有 50 个文件的 Python 项目接入 pre-commit，要求「提交快、CI 严」。

<details>
<summary>参考</summary>

```yaml
# .pre-commit-config.yaml —— 只放快检查
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
```

```yaml
# CI 里补全量
- run: uv run ruff check .
- run: uv run ruff format --check .
- run: uv run mypy app
- run: uv run pytest -q
```

首次：

```powershell
uv run pre-commit run --all-files
```

</details>

## 12. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 格式化后又变乱 | 先 `format` 后 `check --fix` | 调整顺序 |
| CI 报格式错但本地通过 | 本地跑的是 `--fix`，CI 是 `--check` | 本地也跑一次 `--check` |
| `ruff` 改了不该改的文件 | 未 `exclude` 生成代码 | 加 `exclude` |
| 迁移文件被格式化 | 自动生成的 SQL/模型不该动 | 排除 `migrations/` |
| `mypy` 报几百个错 | 一上手就 `strict` | 分档推进 |
| `mypy` 找不到库 | 缺 `py.typed` | `ignore_missing_imports` 或装 `types-*` |
| `type: ignore` 越积越多 | 未强制带错误码 | `warn_unused_ignores` + 必须带码 |
| `pydantic` 类型推断异常 | 未启用插件 | `plugins = ["pydantic.mypy"]` |
| pre-commit 首次改了几十个文件 | 历史代码从未格式化 | 单独一个「格式统一」commit |
| pre-commit 报 `rev` 不存在 | tag 写错或已删除 | `pre-commit autoupdate` |
| mypy 钩子缺依赖 | 独立 venv | `additional_dependencies` |
| Windows 下钩子乱码/失败 | 编码或路径 | 统一 UTF-8，用 `python -X utf8` |
| 有人用 `--no-verify` 绕过 | 习惯问题 | CI 兜底（CI 必须跑同样检查） |
| 双栈行宽不一致 | 两侧配置不同 | 统一 100 或 120 |
| 类型注解写了但没检查 | 没把 mypy 放 CI | CI 加 `mypy app` |

## 13. 本篇小结

- **三件事分开做**：`ruff format`（格式）、`ruff check`（lint）、`mypy`（类型）。
- **执行顺序固定**：`ruff check --fix` → `ruff format` → `ruff check`（确认）。
- **CI 只检查不修改**：`ruff check .` + `ruff format --check .`。
- **规则族逐步加**：`E,F` → `I` → `B` → `UP,SIM,C4`；别一上手 `ALL`。
- **`# noqa` 与 `# type: ignore` 必须带码**，并尽量带原因。
- **`mypy` 渐进变严**：宽松（`check_untyped_defs`）→ 中等（`disallow_untyped_defs`）→ `strict`。
- **`mypy` 不能替代运行期校验**：外部输入永远走 Pydantic。
- **`pre-commit` 用固定 `rev`**，首次 `run --all-files` 会产生一次大 diff，单独提交。
- **提交快、CI 严**：pre-commit 只跑 ruff，mypy 与全量测试放 CI。
- **同一套配置**：本地与 CI 都读 `pyproject.toml`，不写两套参数。
- **DRY 的反面**：`per-file-ignores` 用于「测试要 assert」「迁移是生成代码」这类**合理的例外**。
- **项目现状**：`ruff` 已装但零配置、`mypy` 与 `pre-commit` 缺失、pytest 无配置段——本篇给出的四段配置可直接落地。
- **阶段 3 收官**，下一步进入阶段 4：HTTP 与 ASGI/WSGI。

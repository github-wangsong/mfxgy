## 3. 路由匹配

### 3.1 路径参数

```python
@app.get("/apps/{id}")
async def get_app(id: str):
    return {"id": id}
```

| 规则 | 说明 |
| --- | --- |
| `{id}` 占位 | 匹配**一段**路径（不含 `/`） |
| 参数名必须一致 | 函数参数名 = 占位名 |
| 值永远是字符串 | 除非加类型注解/转换器 |

### 3.2 类型转换器

```python
@app.get("/items/{item_id:int}")
async def item(item_id: int): ...

@app.get("/files/{file_path:path}")
async def read_file(file_path: str): ...      # 可含 `/`
```

| 转换器 | 匹配 |
| --- | --- |
| `{x}` | 任意单段 |
| `{x:int}` | 整数（`/items/abc` → 404） |
| `{x:float}` | 浮点 |
| `{x:uuid}` | UUID |
| `{x:path}` | 贪婪匹配剩余路径 |

> 也可以直接写 `item_id: int`，FastAPI 会做转换并校验——**推荐用注解**，因为转换失败会返回 `422` 而不是 404，语义更清楚。

### 3.3 顺序敏感（真实事故点）

```python
@app.get("/apps/me")          # ① 固定路径
async def me(): ...

@app.get("/apps/{id}")        # ② 通配路径
async def get_app(id: str): ...
```

若把 ② 写在 ① 前面，`/apps/me` 会被当成 `id="me"` 命中 ②——**路由按注册顺序匹配，先到先得**。

| 原则 | 说明 |
| --- | --- |
| 固定路径写在前面 | `/apps/me` > `/apps/{id}` |
| 更具体的写在前面 | `/apps/{id}/graph` 与 `/apps/{id}` 不冲突（段数不同） |
| 用不同前缀彻底分开 | `/auth/me` + `/apps/{id}` |

### 3.4 尾部斜杠

| 请求 | 路由 | 结果 |
| --- | --- | --- |
| `/apps` | `@get("")`（prefix `/apps`） | ✅ 命中 |
| `/apps/` | 同上 | `307` 重定向到 `/apps` |
| `/apps/` | `@get("/")` | ✅ 命中 |

> FastAPI 默认 `redirect_slashes=True`。前后端联调时出现 `307`，通常就是这里。

## 4. 参数来源判定（本篇最重要的一节）

### 4.1 三条规则

```python
@app.get("/x/{id}")
async def f(
    id: str,                          # ① 出现在路径里 → Path
    q: str,                           # ② 标量且不在路径 → Query
    body: CreateReq,                  # ③ Pydantic 模型 → Body
    x_token: str | None = None,       # ④ 名字像 header？仍是 Query
): ...
```

| 规则 | 结论 |
| --- | --- |
| 名字出现在路径模板 `{}` 中 | **Path** |
| 是 `BaseModel` / `dict` / `list[Model]` | **Body** |
| 其余标量（`str`/`int`/`bool`/`float`/`Enum`/`datetime`…） | **Query** |
| `Header`/`Cookie`/`Form`/`File` 显式声明 | 对应位置 |

### 4.2 为什么这是最容易错的地方

```python
@app.post("/login")
async def login(username: str, password: str):      # ❌ 以为收 JSON body
    ...
```

实际收到的是 **query**：`POST /login?username=a&password=b`。前端按 JSON 发就会 `422`。

正确写法：

```python
class LoginRequest(BaseModel):
    username: str
    password: str

@app.post("/login")
async def login(body: LoginRequest):                # ✅ body
    ...
```

| 想收什么 | 写法 |
| --- | --- |
| 单个 JSON 对象 | `body: MyModel` |
| 多个 JSON 字段（不建模型） | `name: str = Body(...)`, `age: int = Body(...)` |
| 一个标量 JSON 值 | `value: int = Body(embed=True)` |
| 表单 | `username: str = Form(...)` |
| 文件 | `file: UploadFile = File(...)` |
| 请求头 | `token: str = Header(...)` |

### 4.3 判定速查表

| 参数位置 | 客户端怎么传 | 代码 |
| --- | --- | --- |
| 路径 | `/apps/a1` | `id: str` / `id: str = Path(...)` |
| 查询 | `/apps?limit=10` | `limit: int = 10` / `Query(...)` |
| 请求体 | JSON body | `body: Model` / `Body(...)` |
| 头 | `Authorization: ...` | `token: str = Header(...)`（`_` 自动转 `-`） |
| Cookie | `Cookie: sid=...` | `sid: str = Cookie(...)` |
| 表单 | `application/x-www-form-urlencoded` | `Form(...)` |
| 文件 | `multipart/form-data` | `File(...)` / `UploadFile` |

## 5. `Query` 与 `Path`

### 5.1 约束与文档

```python
from typing import Annotated
from fastapi import Query

@app.get("/apps")
async def list_apps(
    limit: Annotated[int, Query(ge=1, le=100, description="每页条数")] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
    keyword: Annotated[str | None, Query(max_length=64)] = None,
): ...
```

| 写法 | 评价 |
| --- | --- |
| `limit: int = Query(20, ge=1, le=100)` | 传统写法，可用 |
| `limit: Annotated[int, Query(ge=1, le=100)] = 20` | **推荐**（类型与约束分离更清晰） |

`Query` 常用参数：

| 参数 | 作用 |
| --- | --- |
| `ge`/`le`/`gt`/`lt` | 数值范围 |
| `min_length`/`max_length`/`pattern` | 字符串约束 |
| `description` | `/docs` 说明 |
| `alias` | 对外参数名 ≠ 变量名 |
| `deprecated=True` | 文档标记废弃 |
| `include_in_schema=False` | 隐藏参数 |

### 5.2 必填 query

```python
async def search(q: Annotated[str, Query(min_length=1)]):   # 无默认值 = 必填
```

缺了就是 `422`。

### 5.3 列表 query

```python
@app.get("/apps/filter")
async def filter_apps(
    tag: Annotated[list[str], Query()] = [],       # ?tag=a&tag=b
): ...
```

```powershell
curl.exe "http://127.0.0.1:8000/apps/filter?tag=a&tag=b"
```

| 写法 | 解析结果 |
| --- | --- |
| `?tag=a&tag=b` | `["a", "b"]` ✅ |
| `?tag=a,b` | `["a,b"]`（单元素，前端常见错误） |

> 若前端用逗号拼接，需要用 `field_validator` 手动 split。

### 5.4 `Path` 的约束

```python
from fastapi import Path

@app.get("/items/{item_id}")
async def item(
    item_id: Annotated[int, Path(ge=1, description="物品 ID")],
): ...
```

`Path` 的约束项与 `Query` 相同；区别是**必填**（路径参数不可能缺）。

## 6. `Body` 的三种形态

### 6.1 单模型（最常见）

```python
@app.post("/apps")
async def create(body: CreateAppRequest): ...
```

### 6.2 多字段不建模型

```python
@app.post("/calc")
async def calc(
    a: int = Body(...),
    b: int = Body(...),
):
    ...
```

请求：

```json
{"a": 1, "b": 2}
```

### 6.3 单标量必须 `embed`

```python
@app.post("/echo")
async def echo(value: int = Body(embed=True)): ...
```

请求体是 `{"value": 1}`；不加 `embed` 会期望裸 `1`（很多前端发不出来）。

| 形态 | 请求体 |
| --- | --- |
| `body: Model` | `{...}` |
| `a: int = Body(...), b: int = Body(...)` | `{"a":1,"b":2}` |
| `value: int = Body(embed=True)` | `{"value":1}` |
| `value: int = Body(...)` | `1`（裸值，易踩坑） |

### 6.4 `Body` 与 `response_model` 的对称性

```python
@router.post("", response_model=AppResponse, status_code=201)
def create_app(body: CreateAppRequest): ...
```

| 位置 | 模型 | 作用 |
| --- | --- | --- |
| 参数 `body` | 输入模型 | 校验 + 文档请求示例 |
| `response_model` | 输出模型 | 过滤 + 文档响应示例 |

> **输入输出模型要分开**（`CreateAppRequest` / `UpdateAppRequest` / `AppResponse`）——这是防止「密码哈希随响应泄露」的结构性保障。

## 7. `Header`、`Cookie`、`Form`、`File`

### 7.1 `Header`

```python
from fastapi import Header

@app.get("/whoami")
async def whoami(
    user_agent: Annotated[str | None, Header()] = None,        # User-Agent
    x_request_id: Annotated[str | None, Header()] = None,      # X-Request-Id
): ...
```

| 规则 | 说明 |
| --- | --- |
| `_` 自动转 `-` | `x_request_id` → `X-Request-Id` |
| 大小写不敏感 | HTTP 头本就如此 |
| `convert_underscores=False` | 关闭自动转换（头名真带下划线时） |

> 鉴权头一般不用 `Header` 直接取，而用 `HTTPBearer`/`Depends`（阶段 7）——因为要统一处理 401 与解析。

### 7.2 `Cookie`

```python
from fastapi import Cookie

@app.get("/prefs")
async def prefs(session_id: Annotated[str | None, Cookie()] = None): ...
```

### 7.3 `Form`

```python
from fastapi import Form

@app.post("/login/form")
async def login_form(
    username: Annotated[str, Form()],
    password: Annotated[str, Form()],
): ...
```

要求前端 `Content-Type: application/x-www-form-urlencoded`（或 `multipart/form-data`）。

### 7.4 `File` / `UploadFile`

```python
from fastapi import File, UploadFile

@app.post("/kb/{kb_id}/upload")
async def upload(
    kb_id: str,
    file: Annotated[UploadFile, File(description="支持 txt/md/pdf")],
): 
    content = await file.read()          # 异步读
    return {"filename": file.filename, "size": len(content)}
```

| 对比 | `bytes = File(...)` | `UploadFile` |
| --- | --- | --- |
| 读取 | 一次性进内存 | 支持 `await read(size)` 分块 |
| 大文件 | 内存风险 | ✅ 推荐 |
| 元数据 | 无 | `filename`/`content_type`/`size` |

> 上传依赖 `python-multipart`（项目 `pyproject.toml` 已装）。忘了装的报错是：

```
Form data requires "python-multipart" to be installed.
```

## 8. 响应

### 8.1 `status_code`

```python
from fastapi import status

@router.post("", status_code=status.HTTP_201_CREATED)
def create(): ...

@router.delete("/{id}", status_code=status.HTTP_204_NO_CONTENT)
def remove(id: str) -> None: ...
```

| 码 | 注意 |
| --- | --- |
| `200` | 默认 |
| `201` | 创建成功；可加 `headers={"Location": ...}` |
| `204` | **不能有响应体**；函数返回 `None`，且不要再写 `response_model` |
| `307` | 尾部斜杠重定向（框架行为） |

> 如果 `204` 还设了 `response_model`，FastAPI 会报 `Status code 204 must not have a response body`。

### 8.2 注入 `Response` 设置头与 Cookie

```python
from fastapi import Response

@app.post("/login")
async def login(body: LoginRequest, response: Response):
    response.headers["X-Token-Version"] = "1"
    response.set_cookie("sid", "abc", httponly=True, samesite="lax")
    return {"ok": True}
```

| 能做 | 说明 |
| --- | --- |
| 改状态码 | `response.status_code = 403` |
| 加头 | `response.headers[...]` |
| 设 Cookie | `response.set_cookie(...)`（`httponly`/`secure`/`samesite`） |
| 删 Cookie | `response.delete_cookie(...)` |

### 8.3 直接返回 `Response` 子类

```python
from fastapi.responses import FileResponse, JSONResponse, PlainTextResponse, StreamingResponse, RedirectResponse

@app.get("/json")
async def j():
    return JSONResponse({"a": 1}, status_code=201, headers={"X-A": "1"})

@app.get("/text")
async def t():
    return PlainTextResponse("hello", status_code=200)

@app.get("/old")
async def old():
    return RedirectResponse("/new", status_code=307)

@app.get("/download")
async def download():
    return FileResponse("report.csv", media_type="text/csv", filename="report.csv")

@app.get("/stream")
async def stream():
    async def gen():
        for i in range(5):
            yield f"chunk {i}\n"
            await asyncio.sleep(0.2)
    return StreamingResponse(gen(), media_type="text/plain")
```

| 类型 | 用途 |
| --- | --- |
| `JSONResponse` | 自定义状态码/头的 JSON |
| `PlainTextResponse` | 纯文本 |
| `RedirectResponse` | 重定向 |
| `FileResponse` | 下载（自动 `Content-Disposition`） |
| `StreamingResponse` | 流式（SSE/大文件） |

> `StreamingResponse` 与阶段 8 的 SSE 是同一机制：**多个 chunk 陆续 `send`**（[01 篇 §6.3](./01-HTTP与ASGI-WSGI.md)）。

### 8.4 `response_model` 与状态码冲突

| 组合 | 结果 |
| --- | --- |
| `status_code=201` + `response_model=X` | ✅ 201 带 X 的 body |
| `status_code=204` + `response_model=X` | ❌ 启动报错 |
| `status_code=204` + `-> None` | ✅ |

## 9. 项目实战：`apps.py` 的五个路由

### 9.1 路由声明

```python
router = APIRouter(prefix="/apps", tags=["apps"])

@router.get("", response_model=AppListResponse, operation_id="listApps")
@router.post("", response_model=AppResponse, status_code=201, operation_id="createApp")
@router.get("/{id}", response_model=AppResponse, operation_id="getApp")
@router.patch("/{id}", response_model=AppResponse, operation_id="updateApp")
@router.delete("/{id}", status_code=204, operation_id="deleteApp")
```

| 路由 | 最终路径 | 参数来源 |
| --- | --- | --- |
| `get("")` | `GET /apps` | 无（依赖注入见阶段 5） |
| `post("")` | `POST /apps` | `body: CreateAppRequest` → body |
| `get("/{id}")` | `GET /apps/{id}` | `id: str` → path |
| `patch("/{id}")` | `PATCH /apps/{id}` | `id` → path + `body` → body |
| `delete("/{id}")` | `DELETE /apps/{id}` | `id` → path，返回 `None` → 204 |

> 注意 `@router.get("")` 而不是 `"/"`：`prefix + ""` = `/apps`；若写 `"/"` 会得到 `/apps/` 并触发 307 重定向。

### 9.2 输入/输出三分

| 模型 | 用途 | 关键约束 |
| --- | --- | --- |
| `CreateAppRequest` | POST 输入 | `name` 必填 1~64；`extra="forbid"` |
| `UpdateAppRequest` | PATCH 输入 | 全可选（PATCH 语义） |
| `AppResponse` | 输出 | 只含契约字段（无 `owner_id` 泄露） |

> `AppResponse` 用的是 `ownerId`（驼峰），而 ORM 是 `owner_id`（下划线）——`_to_app_response` 做这层映射，**契约字段名与内部字段名解耦**。

### 9.3 PATCH 的正确实现

```python
for field, value in body.model_dump(exclude_unset=True).items():
    setattr(app, field, value)
```

| 技巧 | 作用 |
| --- | --- |
| `model_dump()` | 变 dict |
| `exclude_unset=True` | **只取客户端真正传了的字段** |
| `setattr` 循环 | 无需为每个字段写 `if` |

为什么必须 `exclude_unset`：

| 写法 | 问题 |
| --- | --- |
| `exclude_unset=False`（默认） | 未传的字段变成 `None`，会把 `description` 清空 |
| `exclude_unset=True` | 只更新显式传入的，`None` 也是显式传入（可清空字段） |

> 区分 `exclude_unset` 与 `exclude_none`：前者看「有没有传」，后者看「值是不是 None」。PATCH 要的是**前者**。

### 9.4 归属校验为什么返回 404 而不是 403

```python
def _find_owned(db, owner_id, app_id) -> App:
    app = db.get(App, app_id)
    if app is None or app.owner_id != owner_id:
        raise HTTPException(404, detail="App not found")
    return app
```

| 选码 | 信息泄露 |
| --- | --- |
| `403` | 「这个 id 存在，但不是你的」——**泄露资源存在性** |
| `404` | 「查不到」——不区分「不存在」与「无权」 |

> 这是安全实践里的标准做法：**对无权访问的资源统一回 404**（文件注释里写得很清楚）。

## 10. 与 NestJS 对照

| FastAPI | NestJS | 说明 |
| --- | --- | --- |
| `{id}` + `id: str` | `@Param('id')` | 路径参数 |
| `id: Annotated[int, Path(ge=1)]` | `ParseIntPipe` | 转换 + 校验 |
| `limit: int = 20` | `@Query('limit')` | 查询参数 |
| `body: Model` | `@Body()` + DTO | 请求体 |
| `Header()` | `@Headers('x-id')` | 请求头 |
| `Form()` | `@Body()` + `urlencoded` 解析 | 表单 |
| `UploadFile` | `FileInterceptor` | 文件 |
| `status_code=201` | `@HttpCode(201)` | 状态码 |
| `response: Response` | `@Res()` | 操作响应对象 |
| `StreamingResponse` | `res.write()` / `StreamableFile` | 流式 |
| 路由顺序敏感 | 同样（Express 也是先注册先匹配） | ⚠️ 两者都踩 |
| 参数来源自动判定 | **必须显式装饰器** | Python 更「约定」，Nest 更「显式」 |

> 关键差异：NestJS 每个参数都要写 `@Param`/`@Query`/`@Body`；FastAPI 靠**名字 + 类型**推断。**推断是便利，也是坑源**——不确定时用 `Annotated[..., Query()]` 显式写出来。

## 11. 验收自测

### 11.1 判断来源

```python
@app.post("/apps/{id}/items")
async def f(
    id: str,
    limit: int = 10,
    body: ItemCreate,
    x_trace: str | None = None,
): ...
```

四个参数各从哪来？

<details>
<summary>答案</summary>

`id` → path；`limit` → query；`body` → body（JSON）；`x_trace` → **query**（不是 header！名字像不代表是）。

要收头必须写 `x_trace: str | None = Header(default=None)`。

</details>

### 11.2 找错

```python
@router.delete("/{id}", response_model=AppResponse, status_code=204)
def delete(id: str): ...
```

两处问题：

1. `204` 不能带 body，与 `response_model` 冲突 → 启动报错；
2. 应去掉 `response_model` 并声明 `-> None`。

### 11.3 动手题

实现 `GET /apps/search?tag=a&tag=b&limit=10`：`tag` 为列表、`limit` 1~100，返回 `{"tags": [...], "limit": 10}`。

<details>
<summary>参考</summary>

```python
from typing import Annotated
from fastapi import Query

@router.get("/search")
async def search(
    tag: Annotated[list[str], Query()] = [],
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    return {"tags": tag, "limit": limit}
```

注意：`/apps/search` 必须注册在 `/apps/{id}` **之前**，否则会被当成 `id="search"`。

## 12. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| POST 的 JSON 收不到，参数是 `None` | 标量默认被当成 query | 用 Pydantic 模型或 `Body(...)` |
| 写操作返回 422 但字段都在 | 前端发了 query 而非 body | 检查 `Content-Type` 与写法 |
| `/apps/me` 命中 `{id}` | 路由顺序错 | 固定路径放前面 |
| 出现 307 重定向 | 尾部斜杠不匹配 | 统一「不以 `/` 结尾」 |
| `204` 启动报错 | 同时设了 `response_model` | 去掉 `response_model` |
| `204` 仍返回 body | 函数返回了值 | 返回 `None` |
| 列表 query 只有一个元素 | 前端用逗号拼接 | 用重复参数或后端 split |
| 单标量 body 收不到 | 没加 `embed=True` | 加 embed |
| 表单接口 422 | 缺 `python-multipart` | `uv add python-multipart` |
| 大文件上传内存爆 | 用了 `bytes = File(...)` | 改 `UploadFile` + 分块读 |
| PATCH 把字段清空了 | 没用 `exclude_unset` | `model_dump(exclude_unset=True)` |
| PATCH 无法清空字段 | 误用了 `exclude_none` | 两者语义不同 |
| 拿不到自定义头 | 头名带下划线 | 用 `-` 或 `convert_underscores=False` |
| 403 泄露资源存在性 | 权限失败返回 403 | 改 404（项目做法） |
| `int` 路径参数传字母报 422 | 注解转换 | 符合预期，前端应校验 |

## 13. 本篇小结

- **路由按注册顺序匹配**：固定路径写在通配路径之前。
- **参数来源三条规则**：在路径里 → Path；是模型 → Body；其余标量 → **Query**。
- **最容易踩的坑**：以为标量参数会收 JSON body，实际收的是 query。
- **显式优于推断**：不确定就用 `Annotated[T, Query()/Path()/Header()/Body()]`。
- **`Path`/`Query` 的约束**（`ge`/`le`/`min_length`/`pattern`）会同时进校验与 `/docs`。
- **列表 query 用重复参数**（`?tag=a&tag=b`），不要用逗号拼接。
- **输入输出模型必须分开**：`Create*` / `Update*` / `*Response`。
- **`201` 带 body、`204` 必须空体**；`204` 不能配 `response_model`。
- **PATCH 用 `exclude_unset=True`**：只改「客户端显式传了」的字段。
- **注入 `Response`** 可加头、设 Cookie、改状态码；返回 `Response` 子类可完全接管响应。
- **`StreamingResponse`/`FileResponse`** 分别对应流式与下载。
- **归属校验统一返回 404**，避免泄露资源是否存在。
- **项目范式**：`apps.py` 用一个 `APIRouter(prefix="/apps")` 覆盖 5 个路由，`""` 表示集合本身，`"/{id}"` 表示单个资源。

# 鸿蒙证书考试学习

## 1. 基础介绍

### 1-1 HarmonyOS设计理念
- 分布式架构: 设备无界协同
- 统一操作系统: 一次开发，多端部署
- 安全与隐私: 重构操作系统的安全体系与秩序，守护隐私与数据
- 流畅体验：确定性时延与资源优化
### 1-2 HarmonyOS的特征
在万物智联时代重要机遇期，HarmonyOS系统结合移动生态发展的趋势，提出了三大技术理念
- 一次开发 多端部署
- 可分可合 自由流转
- 统一生态 系统智能
### 1-3 HarmonyOS新体验
- 围绕人、终端、服务三方面创新体验
- 分布式能力多终端一拉即合
- 元服务创新、无缝流转
- AI使能、全场景服务分发
### 1-4 应用程序包核心概念总览
应用程序包是HarmonyOS 应用的标准封装单元，包含代码、资源、配置和元数据.
以下是核心组件:
- HAP ( Ha rm o n yOS A bilit y Pa c ka g e ) : 主应用包，包含A bilit y ，可独立安装运行。
- HAR ( Ha rm o n yOS A rc hive ) : 静态共享库，用于代码复用，编译时嵌入HA P。
- HSP ( Ha rm o n yOS Sha re d Pa c ka g e ) : 动态共享包，支持跨应用调用。
- Bundle : 一个应用中所有HA P和HSP的集合，由bun dle Na m e 唯一标识。
- App Pa c k ( .a pp) : Bun dle 的归档文件，是发布上架的基本单元
### 1-5 应用上架流程介绍
- AGC创建项目与应用
- 申请数字证书和Profile
  - 生成密钥: 格式为.p12，包含非对称加密中使用的公钥和私钥
  - 生成证书请求文件: 格式为.csr，包含开发者基本信息
  - 申请发布证书\调试证书: 格式为.cer，通过证书请求文件申请，有调试证书和发布证书两个类型
  - 生成Profile文件: 格式为.p7b，包含鸿蒙应用/元服务的包名、数字证书信息、描述鸿蒙应用/元服务允许申请
的证书权限列表等内容，每个鸿蒙应用/元服务包中均必须包含一个Profile文件
- 编译鸿蒙应用/元服务
  - 自动配置签名信息/在IDE中配置签名信息
  - 构建发布软件包
- 应用上架发布实践
  - AGC平台新建发布
  - 上传签名后的APP包
  - 生成应用发布所需协议
  - 测试鸿蒙应用/元服务
  - 测试用户管理
  - 创建应用测试版本
  - 提交审核并发布应用
  - 符合应用上架基础资质要求
  - 符合软著证书审核要求

### 2-4 ArkTS与TypeScript的区别
- 稳定性要求
  - 禁止any/unknown
  - 强制属性初始化
  - 严格的Null Safety: 在ArkTS中，null 和 undefined 不再是所有类型的合法值，必须显式地在类型中声明（如 string | null），否则相关代码无法通过编译
- 运行性能优化
  - 固定对象布局
  - 高效的字节码: 方舟字节码 
  - 内存管理优化
- ETS代码兼容性
  - 兼容模式: ets文件语法违规会以Warning（警告） 形式提示，工程仍可编译成功
  - 标准模式: .ets文件必须严格遵循ArkTS语法规则，任何违规都会导致编译失败

### 2-5 ArkTS基础类库

ArkTS基础类库主要提供了`XML生成解析与转换`、`二进制Buffer`、`JSON扩展库、多种容器类库`等功能模块，协助开发者简化开发工作，有效提升了开发效率
- XML: 一种用于存储和传输数据的标记语言, 核心目标是实现数据的结构化描述与跨平台/跨系统的交互
  - 元素（标签）（element）、属性（attribute）和内容（content）组成
- Buffer与FastBuffer: 这两个模块的核心设计理念在于将物理内存映射为可编程的逻辑单元——每个Buffer实例本质上是一个连续的字节序列容器，其内存布局严格遵循线性存储结构
- JSON扩展库场景介绍
  - parse： 解析JSON字符串,支持BigInt模式
  - stringify：将对象转换为JSON字符串，支持BigInt模式
  - has：检查对象是否包含指定的属性，确保传入的值是一个对象，并且属性键是有效的字符串
  - remove：从对象中删除指定的属性
### 2-6 ArkTS容器类库
- 线性容器: 实现能按顺序访问的数据结构，其底层主要通过数组实现
  - ArrayList: 动态数组，占用一片连续的内存空间。需要频繁读取元素时
推荐使用。
  - List: 单向链表，占用的空间可以不连续。推荐在需要频繁插入和
删除元素，且需要使用单向链表时使用。
  - LinkedList: 双向链表，占用的空间可以不连续。推荐在需要频繁插入和
删除元素，且需要使用双向链表时使用
  - Deque: 双端队列，支持从头尾两端进行元素的插入和删除操作，占
用连续的内存空间。推荐在需要频繁访问和操作头尾元素时
使用
  - Queue: 队列，是一种从尾部插入元素、从头部移除元素的数据结构，
占用连续的内存空间，适用于先进先出的场景
  - Stack: 栈，只能从一端进行插入和删除操作，占用连续的内存空间。
适用于先进后出的场景
  - Vector: 动态数组，占用连续的内存空间。已不再维护，推荐使用
ArrayList
- 非线性容器: 实现能快速查找的数据结构，其底层通过hash或者红黑树实现，包括HashMap、
HashSet、TreeMap、TreeSet、LightWeightMap、LightWeightSet、PlainArray七种。非线
性容器中的key及value的类型均满足ECMA标准
  - HashMap: 存储具有关联关系的键值对集合。键唯一，依据键的hash值确定存储位置。访问速度快，但不能自定义排序。推荐用于需要快速存取、插入删除键值对数据时使用
  - HashSet: 存储一系列值的集合。值唯一，依据值的hash确定存储位置。允许放入null值，但不能自定义排序。适用于不重复的集合或去重某个集合
  - TreeMap: 存储具有关联关系的键值对集合。键唯一，允许用户自定义排序方法。适用于按序存储键值对的场景
  - TreeSet: 存储一系列值的集合。值唯一，允许用户自定义排序方法，但不建议放入null值。适用于按序存储集合的场景
  - LightWeightMap: 存储具有关联关系的键值对集合。键唯一，底层采用轻量级结构，空间占用小。推荐用于存取键值对数据且内存不充足时
  - LightWeightSet: 存储一系列值的集合。值唯一，底层采用轻量级结构，空间占用小。适用于不重复的集合或去重某个集合
  - PlainArray: 存储具有关联关系的键值对集合。键唯一，底层与LightWeightMap一样采用轻量级结构，键固定为number类型。适用于存储键为number类型键值对的场景

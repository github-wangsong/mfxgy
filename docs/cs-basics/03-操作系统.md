# 03 · 操作系统

> 定位：Agent 服务端是典型的「高并发 + 大量 IO 等待」场景，进程/线程/协程、内存、IO 模型、锁是绕不开的底座。
> 面试权重：★★★★★
> 关联：[02 计算机网络](./02-计算机网络.md)（网络 IO）、[01 计算机基础](./01-计算机基础.md)（CPU/缓存）。

## 1. 一张图：进程 / 线程 / 协程

```
进程（资源隔离单位）
├── 独立虚拟地址空间
├── 打开的文件 / 网络连接
├── 信号处理 / 环境变量
└── 线程（CPU 调度单位）
    ├── 共享：代码段、堆、全局变量、文件描述符
    ├── 私有：栈、寄存器、程序计数器
    └── 协程（用户态调度）
        ├── 共享线程的栈/资源
        ├── 私有：协程栈帧、局部状态
        └── 协作式切换：await / yield
```

| 概念 | 一句话 | 开销 |
| --- | --- | --- |
| 进程 | 资源分配与隔离的单位 | 创建/切换最重 |
| 线程 | CPU 调度的基本单位 | 切换需内核参与 |
| 协程 | 用户态轻量执行单元 | 切换最轻，由运行时调度 |

## 2. 进程与线程

### 2.1 进程

- 由 PCB（进程控制块）描述：PID、状态、寄存器、页表、打开的文件、信号等。
- 进程间地址空间隔离，通信要靠 IPC：管道、消息队列、共享内存、Socket、信号。
- 进程状态：新建、就绪、运行、阻塞、终止。

### 2.2 线程

| 共享 | 私有 |
| --- | --- |
| 代码段、数据段、堆 | 栈 |
| 全局变量、静态变量 | 寄存器 |
| 文件描述符、当前目录 | 程序计数器 |
| 信号处理器 | 线程 ID、优先级 |

> 线程共享堆，所以多线程写同一对象要加锁；线程私有栈，所以递归深度/局部变量互不影响。

### 2.3 协程

| 点 | 说明 |
| --- | --- |
| 调度 | 用户态，协作式；只有 `await`/`yield` 才切换 |
| 优势 | 切换轻、单线程可承载大量并发 IO |
| 风险 | 一个协程阻塞（同步 IO/CPU 密集）会卡住整个事件循环 |
| 代表 | Python `async/await`、JS `async/await`、Go goroutine（M:N 调度） |

> Python 的 `async def` 协程由事件循环调度；遇到同步阻塞调用要用 `asyncio.to_thread` 或线程池兜底。

### 2.4 上下文切换

- 保存当前线程/进程的寄存器、PC、栈指针、页表等。
- 切换内核栈、刷新 TLB、影响 CPU 缓存。
- 线程切换比进程切换轻，因为不需要切换地址空间；协程切换最轻。

## 3. CPU 调度

| 算法 | 规则 | 优点 | 缺点 |
| --- | --- | --- | --- |
| FCFS | 先来先服务 | 简单 | 长任务拖住短任务 |
| SJF | 最短作业优先 | 平均等待短 | 长任务可能饥饿 |
| RR | 时间片轮转 | 公平、响应快 | 时间片太小切换多 |
| 优先级 | 高优先级先跑 | 重要任务优先 | 低优先级饥饿 |
| 多级反馈队列 | 多队列 + 动态降级 | 兼顾响应与吞吐 | 实现复杂 |

- **抢占式**：时间片到/更高优先级到达，可强制切换。
- **非抢占式**：运行到结束或主动让出。
- **优先级反转**：低优先级持锁，高优先级等待，中优先级抢跑；用优先级继承解决。

## 4. 内存管理

### 4.1 虚拟内存

| 作用 | 说明 |
| --- | --- |
| 隔离 | 每个进程看到独立地址空间 |
| 扩容 | 可用地址空间远大于物理内存 |
| 共享 | 只读代码段、动态库可共享 |
| 按需加载 | 缺页时才从磁盘换入 |

### 4.2 地址翻译与缺页

```
虚拟地址 → 页号 + 页内偏移
  → TLB 命中？→ 直接拿物理页
  → 未命中 → 查页表 → 页不在内存 → 缺页中断
  → 操作系统选一页换出（置换算法）→ 读入目标页 → 更新页表/TLB
```

| 概念 | 一句话 |
| --- | --- |
| 页表 | 虚拟页 → 物理页的映射 |
| TLB | 页表的缓存，减少查表次数 |
| 缺页中断 | 访问的页不在物理内存 |
| 页面置换 | FIFO / LRU / Clock / OPT |
| 抖动（Thrashing） | 频繁换页，CPU 大量时间在等 IO |

| 置换算法 | 特点 |
| --- | --- |
| FIFO | 简单，可能出现 Belady 异常 |
| LRU | 最近最少使用，效果好但实现成本高 |
| Clock | LRU 的近似，用访问位循环扫描 |
| OPT | 理论最优，无法实现，只能做基准 |

## 5. IO 模型

### 5.1 五种 IO 模型

| 模型 | 等待数据 | 拷贝数据 | 代表 |
| --- | --- | --- | --- |
| 阻塞 IO | 阻塞 | 阻塞 | 默认 socket |
| 非阻塞 IO | 轮询 | 阻塞 | `O_NONBLOCK` |
| IO 多路复用 | `select/poll/epoll` 等待 | 阻塞 | Nginx、Redis、uvloop |
| 信号驱动 | 信号通知 | 阻塞 | SIGIO |
| 异步 IO | 不阻塞 | 不阻塞 | io_uring、POSIX AIO |

> 前四种在「拷贝数据」阶段仍是同步的；只有异步 IO 是真正的「内核完成后通知」。

### 5.2 select / poll / epoll

| 维度 | select | poll | epoll |
| --- | --- | --- | --- |
| 数据结构 | `fd_set` 位图 | `pollfd` 数组 | 内核事件表 + 就绪链表 |
| fd 上限 | 通常 1024 | 无硬上限 | 无硬上限 |
| 每次调用 | 全量拷贝 fd 集合 | 全量拷贝 | 只在注册/修改时拷贝 |
| 时间复杂度 | O(n) | O(n) | O(就绪 fd 数) |
| 触发模式 | 水平触发 | 水平触发 | LT / ET |

> epoll 快在「只返回就绪的 fd」，不是「所有操作都 O(1)」。fd 很多但活跃很少时优势最明显。

### 5.3 LT 与 ET

| 模式 | 行为 | 注意 |
| --- | --- | --- |
| 水平触发（LT） | 只要缓冲区还有数据，就持续通知 | 默认，编程简单 |
| 边缘触发（ET） | 状态变化时只通知一次 | 必须一次读到 `EAGAIN`，否则丢事件 |

> ET 常配非阻塞 fd + 循环读；LT 可以用阻塞/非阻塞，但高并发下也要注意一次读多少。

### 5.4 Reactor 与 Proactor

| 模式 | 谁负责 IO | 代表 |
| --- | --- | --- |
| Reactor | 应用在「就绪」后自己 read/write | epoll + 事件循环 |
| Proactor | 内核完成 IO 后通知应用 | io_uring、Windows IOCP |

## 6. 并发与锁

### 6.1 锁的类型

| 锁 | 特点 | 适用 |
| --- | --- | --- |
| 互斥锁 | 拿不到就睡眠 | 临界区较长 |
| 自旋锁 | 忙等，不睡眠 | 临界区极短、多核 |
| 读写锁 | 读共享、写独占 | 读多写少 |
| 乐观锁 | 版本号/CAS，冲突重试 | 冲突少 |
| 悲观锁 | 先锁再操作 | 冲突多、强一致 |

### 6.2 死锁

**四个必要条件**：

1. 互斥：资源一次只能被一个线程占用。
2. 持有并等待：持有资源的同时等待其他资源。
3. 不可抢占：资源不能被强行夺走。
4. 循环等待：存在线程与资源的环形等待链。

| 策略 | 做法 |
| --- | --- |
| 预防 | 破坏任一条件：一次性申请、按固定顺序加锁、可抢占 |
| 避免 | 银行家算法：分配前判断是否安全 |
| 检测 | 资源分配图/等待图找环 |
| 恢复 | 回滚、杀进程、释放资源 |

> 工程上最常用：**固定锁顺序 + 缩小临界区 + `acquire(timeout=True)`**。

### 6.3 活锁与饥饿

- **活锁**：线程没阻塞，但一直重试失败（如两个线程互相让路）。
- **饥饿**：低优先级线程长期拿不到资源。
- 解决：公平锁、优先级老化、随机退避。

### 6.4 CAS 与 ABA

- CAS（Compare-And-Swap）：比较旧值再写入，原子操作。
- ABA：值从 A → B → A，CAS 以为没变；用版本号/时间戳解决。
- Python 的 GIL 让 `+=` 不是原子操作；多线程计数仍要锁。

## 7. 文件系统与 Linux

### 7.1 inode 与链接

| 概念 | 说明 |
| --- | --- |
| inode | 文件元数据：权限、大小、时间、数据块指针；不含文件名 |
| 硬链接 | 多个目录项指向同一 inode；不能跨文件系统；删一个不影响其他 |
| 软链接 | 独立文件，内容是目标路径；可跨文件系统；目标删了会断 |

### 7.2 page cache 与零拷贝

- page cache：内核缓存文件数据，读命中不走磁盘。
- `fsync`：把脏页刷盘，数据库提交常用。
- 零拷贝：`sendfile` / `mmap` 减少「内核态 ↔ 用户态」拷贝，Nginx/ Kafka 常用。

### 7.3 常用命令

| 命令 | 用途 |
| --- | --- |
| `top` / `htop` | CPU、内存、负载 |
| `ps -ef` | 进程列表 |
| `free -h` | 内存使用 |
| `vmstat 1` | 内存/IO/CPU 趋势 |
| `iostat -x 1` | 磁盘 IO |
| `ss -s` / `ss -tan` | 连接状态 |
| `lsof -p <pid>` | 进程打开的文件/连接 |
| `strace -p <pid>` | 系统调用跟踪 |
| `df -h` / `du -sh` | 磁盘容量 |
| `ulimit -n` | 文件描述符上限 |

> 命令里的 `<pid>` 是占位符，执行时替换为真实进程号。

## 9. 面试真题

### Q1. 进程、线程、协程的区别？

**结论**：进程是资源隔离单位；线程是 CPU 调度单位，共享进程资源；协程是用户态轻量执行单元，协作式切换。

**展开**：

- 进程有独立地址空间，切换要换页表，开销最大。
- 线程共享堆/文件描述符，私有栈/寄存器，切换需内核参与。
- 协程由运行时调度，`await` 才切换，适合大量 IO 并发。
- 协程不能解决 CPU 密集；阻塞调用会卡住事件循环。

### Q2. 上下文切换为什么贵？

**结论**：要保存/恢复寄存器与栈、切换内核栈、刷新 TLB/缓存，进程切换还要换地址空间。

**展开**：

- 线程切换比进程轻，但仍有内核开销。
- 协程切换在用户态，最轻。
- 高频切换会降低 CPU 有效利用率。

### Q3. 常见调度算法有哪些？

**结论**：FCFS、SJF、时间片轮转、优先级、多级反馈队列。

**展开**：

- SJF 平均等待最短，但长任务可能饥饿。
- RR 公平、响应快，时间片太小切换多。
- 多级反馈队列兼顾响应与吞吐。
- 优先级调度要处理优先级反转。

### Q4. 虚拟内存的作用？

**结论**：隔离进程、扩展地址空间、按需加载、共享内存、简化内存管理。

**展开**：

- 每个进程有独立页表。
- 缺页时才把页从磁盘换入。
- 物理内存不够时换出冷页。
- 过度换页会导致抖动。

### Q5. 缺页中断的流程？

**结论**：查页表发现页不在内存 → 触发缺页中断 → 选页置换 → 读入目标页 → 更新页表/TLB → 重新执行指令。

**展开**：

- 先判断是合法访问还是非法访问（非法则 SIGSEGV）。
- 置换算法选牺牲页；脏页要先写回。
- 页表更新后 TLB 可能失效。

### Q6. LRU 怎么实现？为什么页面置换不用完美 LRU？

**结论**：哈希表 + 双向链表，`get/put` O(1)；完美 LRU 需要每次访问都更新链表，硬件/内核成本高，常用 Clock 近似。

**展开**：

- 哈希表定位节点，双向链表维护新旧顺序。
- 访问移到头部，淘汰尾部。
- Clock 用访问位循环扫描，开销更低。

### Q7. select、poll、epoll 的区别？epoll 为什么快？

**结论**：select 有 1024 fd 上限且全量拷贝；poll 用数组去上限但仍 O(n)；epoll 用内核事件表，只返回就绪 fd，O(就绪数)。

**展开**：

- epoll 注册一次，后续只 `epoll_wait`。
- 适合 fd 多、活跃少的场景。
- fd 少且都很活跃时，优势不明显。
- epoll 是「就绪通知」，不是异步 IO。

### Q8. LT 和 ET 的区别？

**结论**：LT 只要还有数据就持续通知；ET 只在状态变化时通知一次，必须一次读到 `EAGAIN`。

**展开**：

- LT 编程简单，但可能反复触发。
- ET 性能更好，但漏读会丢事件。
- ET 通常要求非阻塞 fd + 循环读。

### Q9. 阻塞、非阻塞、同步、异步的区别？

**结论**：阻塞/非阻塞看「调用是否立即返回」；同步/异步看「数据拷贝由谁完成、是否等待结果」。

**展开**：

- 阻塞 IO：等待数据 + 拷贝都阻塞。
- 非阻塞 IO：没数据立即返回，拷贝仍阻塞。
- IO 多路复用：等就绪，拷贝仍由应用做。
- 异步 IO：内核完成数据拷贝后通知。

### Q10. 死锁的四个条件与解决方案？

**结论**：互斥、持有并等待、不可抢占、循环等待；破坏任一条件，或用银行家算法避免、检测恢复。

**展开**：

- 工程常用固定锁顺序、一次性申请、超时重试。
- 银行家算法需要预知最大需求，实际少用。
- 检测用等待图找环，恢复可回滚/杀进程。

### Q11. 自旋锁和互斥锁怎么选？

**结论**：临界区极短、多核用自旋锁；临界区长、可能睡眠用互斥锁。

**展开**：

- 自旋锁忙等，不释放 CPU，适合短临界区。
- 互斥锁拿不到会睡眠，避免浪费 CPU。
- 单核上自旋锁意义不大。

### Q12. 硬链接和软链接的区别？

**结论**：硬链接指向同一 inode，是同一文件的多个名字；软链接是独立文件，内容是目标路径。

**展开**：

- 硬链接不能跨文件系统，不能链接目录（通常）。
- 软链接可跨文件系统，目标删除会断。
- 删除硬链接只是减少 inode 链接计数。

### Q13. 什么是零拷贝？为什么快？

**结论**：减少内核态与用户态之间的数据拷贝（以及上下文切换），如 `sendfile`、`mmap`。

**展开**：

- 传统 read + write：磁盘 → 内核 → 用户 → 内核 → 网卡。
- `sendfile`：磁盘 → 内核 → 网卡，少两次拷贝。
- Nginx、Kafka 等大量使用。

### Q14. Linux 负载高，怎么排查？

**结论**：先区分 CPU、IO、内存、锁；再看是用户态还是内核态。

**展开**：

- `top` 看 load average、CPU 使用率、wa。
- `vmstat` 看 r/b、si/so、wa。
- `iostat` 看磁盘 util/await。
- `pidstat`、`perf`、`strace` 定位进程/系统调用。
- 负载高不一定是 CPU 高，也可能是大量不可中断 IO。

## 1. 一张图：怎么选结构

```
需要按索引随机访问？ → 数组
需要频繁头尾插入/删除？ → 链表 / 双端队列
需要 O(1) 查找？ → 哈希表
需要有序 + 范围查询？ → 平衡树 / B+ 树 / 跳表
需要每次取最大/最小？ → 堆
需要表达依赖/路径？ → 图
需要去重且能容忍误判？ → 布隆过滤器
需要缓存淘汰？ → 哈希 + 双向链表（LRU）
```

## 2. 复杂度速查

| 结构 | 查找 | 插入 | 删除 | 有序 |
| --- | --- | --- | --- | --- |
| 数组 | O(1) 按索引 / O(n) 按值 | O(n) | O(n) | ✅ |
| 链表 | O(n) | O(1)（已知位置） | O(1)（已知位置） | ✅（需排序） |
| 栈 / 队列 | O(n) | O(1) | O(1) | ❌ |
| 哈希表 | O(1) 平均 / O(n) 最坏 | O(1) 平均 | O(1) 平均 | ❌ |
| 平衡二叉搜索树 | O(log n) | O(log n) | O(log n) | ✅ |
| 堆 | O(1) 取顶 | O(log n) | O(log n) | 部分 |
| B+ 树 | O(log n) | O(log n) | O(log n) | ✅ |
| 跳表 | O(log n) 期望 | O(log n) 期望 | O(log n) 期望 | ✅ |
| 图（邻接表） | O(V+E) 遍历 | O(1) | O(1) | — |

> 面试先问「数据规模 + 操作频率」，再选结构；不要一上来就说「用 HashMap」。

## 3. 线性结构

### 3.1 数组 vs 链表

| 维度 | 数组 | 链表 |
| --- | --- | --- |
| 内存 | 连续 | 分散 + 指针 |
| 随机访问 | O(1) | O(n) |
| 插入/删除 | O(n) | O(1)（已知节点） |
| 缓存友好 | ✅ | ❌ |
| 扩容 | 重新分配/拷贝 | 无需连续空间 |

> 实际工程里数组/动态数组（Python `list`、TS `Array`）更常用；链表适合频繁中间插入、LRU、队列。

### 3.2 栈与队列

| 结构 | 规则 | 场景 |
| --- | --- | --- |
| 栈 | 后进先出（LIFO） | 括号匹配、DFS、函数调用、撤销 |
| 队列 | 先进先出（FIFO） | BFS、任务队列、生产者-消费者 |
| 双端队列 | 两端进出 | 滑动窗口最大值、工作窃取 |
| 环形缓冲区 | 固定容量循环覆盖 | 日志、音视频、流式缓冲 |

```python
from collections import deque

q = deque()
q.append(1)      # 入队尾
q.appendleft(0)  # 入队头
q.pop()          # 出队尾
q.popleft()      # 出队头
```

### 3.3 反转链表（高频手写）

```python
class ListNode:
    def __init__(self, val: int = 0, next: "ListNode | None" = None):
        self.val = val
        self.next = next


def reverse_list(head: ListNode | None) -> ListNode | None:
    prev = None
    cur = head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev = cur
        cur = nxt
    return prev
```

> 三指针：`prev`、`cur`、`nxt`；先保存 `next`，再改指向，最后整体后移。

## 4. 哈希表

### 4.1 核心机制

| 点 | 说明 |
| --- | --- |
| 哈希函数 | 把 key 映射到桶索引 |
| 冲突 | 不同 key 落到同一桶 |
| 拉链法 | 桶挂链表/红黑树 |
| 开放寻址 | 线性探测、二次探测、双哈希 |
| 负载因子 | 元素数 / 桶数；过高要扩容 |
| 扩容 | 重新哈希所有元素，O(n) |

> Python `dict` 用开放寻址；Java `HashMap` 用拉链法 + 红黑树（链表过长时）。

### 4.2 为什么 HashMap 容量常是 2 的幂

- 索引计算用 `(n - 1) & hash` 替代取模，速度快。
- 容量为 2 的幂时，`n - 1` 的低位全 1，分布更均匀。
- 扩容时元素要么留在原位置，要么移动 `oldCap`，减少重新计算。

### 4.3 哈希冲突的工程处理

| 方案 | 适用 |
| --- | --- |
| 拉链法 | 通用，Java HashMap |
| 开放寻址 | 负载低、缓存友好，Python dict |
| 再哈希 | 冲突严重时换第二个哈希函数 |
| 红黑树化 | 单桶链表过长，查询从 O(n) 降到 O(log n) |

## 5. 树

### 5.1 二叉树遍历

| 遍历 | 顺序 | 典型用途 |
| --- | --- | --- |
| 前序 | 根 → 左 → 右 | 复制树、序列化 |
| 中序 | 左 → 根 → 右 | BST 有序输出 |
| 后序 | 左 → 右 → 根 | 释放树、计算子树 |
| 层序 | 逐层 | BFS、最短层数 |

```python
from collections import deque


def level_order(root):
    if not root:
        return []
    q = deque([root])
    out = []
    while q:
        node = q.popleft()
        out.append(node.val)
        if node.left:
            q.append(node.left)
        if node.right:
            q.append(node.right)
    return out
```

### 5.2 BST / AVL / 红黑树

| 结构 | 平衡策略 | 查找/插入/删除 | 特点 |
| --- | --- | --- | --- |
| BST | 无 | 平均 O(log n)，最坏 O(n) | 有序，可能退化成链表 |
| AVL | 严格高度平衡 | O(log n) | 查询快，旋转多 |
| 红黑树 | 近似平衡 | O(log n) | 插入删除旋转少，工程常用 |
| B 树 | 多路平衡 | O(log n) | 磁盘/数据库 |
| B+ 树 | 多路 + 叶子链表 | O(log n) | 范围查询强，MySQL/PostgreSQL 索引 |

### 5.3 B+ 树为什么适合数据库索引

- **高扇出**：一个节点放很多 key，树高低，磁盘 IO 少。
- **数据都在叶子**：内部节点只存索引，缓存效率高。
- **叶子链表**：范围查询、排序扫描友好。
- **稳定**：所有查询都走到叶子，路径长度一致。

> 对比红黑树：红黑树是内存结构，B+ 树是为磁盘页设计的。

### 5.4 Trie

- 前缀树，按字符分层。
- 适合：词频统计、敏感词过滤、自动补全、路由匹配。
- 优点：前缀查询快；缺点：内存占用高。

## 6. 堆

### 6.1 堆的性质

| 类型 | 性质 |
| --- | --- |
| 最小堆 | 父节点 ≤ 子节点，堆顶最小 |
| 最大堆 | 父节点 ≥ 子节点，堆顶最大 |
| 存储 | 完全二叉树，用数组表示 |
| 插入 | 尾部插入 + 上浮 O(log n) |
| 删除堆顶 | 尾部元素换到顶 + 下沉 O(log n) |
| 建堆 | 自底向上 heapify，O(n) |

### 6.2 Top-K

- 求最大 K 个：维护大小为 K 的**最小堆**；新元素比堆顶大就替换。
- 时间复杂度：O(n log k)，空间 O(k)。
- 数据量小/一次性：快速选择（Quickselect）平均 O(n)。
- 数据流：堆更合适。

```python
import heapq


def top_k(nums: list[int], k: int) -> list[int]:
    heap: list[int] = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return sorted(heap, reverse=True)
```

### 6.3 中位数

- 两个堆：大顶堆存较小一半，小顶堆存较大一半。
- 插入 O(log n)，取中位数 O(1)。
- 保证两堆大小差不超过 1。

## 7. 图

### 7.1 表示方式

| 方式 | 空间 | 适合 |
| --- | --- | --- |
| 邻接矩阵 | O(V²) | 稠密图、快速判断边 |
| 邻接表 | O(V+E) | 稀疏图、遍历 |
| 边列表 | O(E) | Kruskal、批量处理 |

### 7.2 BFS / DFS

| 算法 | 数据结构 | 用途 |
| --- | --- | --- |
| BFS | 队列 | 无权图最短路径、层序遍历、连通块 |
| DFS | 栈/递归 | 连通性、拓扑、回溯、环检测 |

```python
from collections import deque


def bfs(graph: dict[str, list[str]], start: str) -> list[str]:
    q = deque([start])
    seen = {start}
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            if v not in seen:
                seen.add(v)
                q.append(v)
    return order
```

### 7.3 拓扑排序（DAG）

```python
from collections import deque


def topo_sort(graph: dict[str, list[str]]) -> list[str]:
    indeg = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] = indeg.get(v, 0) + 1

    q = deque([u for u, d in indeg.items() if d == 0])
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == len(indeg) else []  # 空表示有环
```

> Agent 工作流就是 DAG：节点是任务，边是依赖；拓扑排序决定执行顺序，有环则拒绝运行。

### 7.4 最短路径

| 算法 | 适用 | 复杂度 |
| --- | --- | --- |
| BFS | 无权图 | O(V+E) |
| Dijkstra | 非负权 | O((V+E) log V)（堆优化） |
| Bellman-Ford | 可有负权 | O(VE) |
| Floyd | 多源全对 | O(V³) |

### 7.5 并查集

- 两个操作：`find` 找根、`union` 合并。
- 优化：路径压缩 + 按秩合并，近似 O(1)。
- 场景：连通块、岛屿数量、Kruskal、账户合并。

## 8. 工程常用结构

### 8.1 LRU Cache

**要求**：`get` / `put` 均 O(1)。

| 组成 | 作用 |
| --- | --- |
| 哈希表 | key → 链表节点 |
| 双向链表 | 维护访问顺序，头新尾旧 |
| 淘汰 | 超容量删尾节点 |

```python
from collections import OrderedDict


class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.data: OrderedDict[int, int] = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

> `OrderedDict` 是工程捷径；面试要求手写时，用「哈希表 + 双向链表」实现同样的逻辑。

### 8.2 LFU

- 按访问频率淘汰；频率相同再按时间。
- 实现：频次桶 + 双向链表；O(1) 需要维护最小频次。
- 对比 LRU：LFU 抗突发扫描，但旧热点可能长期占坑。

### 8.3 布隆过滤器

| 点 | 说明 |
| --- | --- |
| 结构 | 位数组 + k 个哈希函数 |
| 插入 | 把 k 个位置置 1 |
| 查询 | k 个位置都为 1 才可能存在 |
| 误判 | 可能把不存在判成存在（false positive） |
| 漏判 | 不会把存在判成不存在 |
| 删除 | 标准布隆不支持；用计数布隆 |

> 场景：缓存穿透、爬虫去重、推荐去重；不能用来存真实数据。

### 8.4 跳表

- 多层链表，上层跳跃、下层全量。
- 查找/插入/删除期望 O(log n)。
- Redis ZSet 用它；实现比平衡树简单，范围查询友好。

### 8.5 一致性哈希

- 解决分布式缓存/分片扩容时「大量 key 重映射」。
- 把节点和 key 映射到哈希环，key 顺时针找第一个节点。
- 虚拟节点解决数据倾斜。
- 场景：Redis Cluster、负载均衡、分库分表。

## 9. 算法套路

| 套路 | 识别信号 | 典型题 |
| --- | --- | --- |
| 双指针 | 有序数组、去重、两数之和 | 两数之和 II、三数之和 |
| 滑动窗口 | 连续子数组/子串、最长/最短 | 无重复字符最长子串 |
| 二分查找 | 有序、边界、答案单调 | 搜索插入位置、旋转数组 |
| 回溯 | 排列/组合/子集/棋盘 | 全排列、N 皇后 |
| 动态规划 | 最优子结构、重叠子问题 | 背包、LIS、编辑距离 |
| 贪心 | 局部最优可推导全局 | 区间调度、跳跃游戏 |
| 分治 | 可拆成同类子问题 | 归并排序、快速排序 |

### 9.1 二分边界模板

```python
def lower_bound(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo  # 第一个 >= target 的位置
```

> 先确定区间是「左闭右闭」还是「左闭右开」，再写边界，能避免 90% 的二分死循环。

### 9.2 滑动窗口模板

```python
def longest_unique_substring(s: str) -> int:
    seen: dict[str, int] = {}
    left = 0
    ans = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1
        seen[ch] = right
        ans = max(ans, right - left + 1)
    return ans
```

## 10. 面试真题

### Q1. 数组和链表怎么选？

**结论**：随机访问多、缓存友好选数组；频繁插入删除、已知节点选链表。

**展开**：

- 数组 O(1) 索引，但插入删除要搬移。
- 链表插入删除 O(1)，但查找 O(n)、缓存不友好。
- 工程里动态数组更常用，链表用于 LRU、队列、频繁中间插入。

### Q2. 如何判断链表有环？

**结论**：快慢指针；相遇则有环，再从头与相遇点同步走，找到环入口。

**展开**：

- 快指针每次 2 步，慢指针 1 步。
- 有环必相遇；无环快指针先到 null。
- 哈希表也能做，但空间 O(n)。

### Q3. 有效括号怎么判断？

**结论**：栈；左括号入栈，右括号与栈顶匹配，最后栈空。

**展开**：

- 遇到右括号时栈空或不匹配 → false。
- 遍历结束栈非空 → false。
- 时间复杂度 O(n)，空间 O(n)。

### Q4. 哈希冲突怎么解决？

**结论**：拉链法或开放寻址；负载因子过高时扩容 rehash。

**展开**：

- 拉链法：桶挂链表，过长可转红黑树。
- 开放寻址：线性/二次探测、双哈希。
- 负载因子常见 0.75，平衡空间与冲突。

### Q5. 为什么 HashMap 容量常是 2 的幂？

**结论**：用 `(n-1) & hash` 代替取模，速度快且分布均匀；扩容时元素位置更稳定。

**展开**：

- 2 的幂让 `n-1` 低位全 1。
- 扩容时元素要么原位，要么 `原索引 + oldCap`。
- 需要 hash 扰动让高位参与运算。

### Q6. B+ 树为什么适合数据库索引？

**结论**：高扇出、树高低、叶子链表、范围查询友好，适合磁盘页。

**展开**：

- 内部节点只存 key，一个页能放更多索引。
- 数据都在叶子，查询路径稳定。
- 叶子链表支持范围扫描和排序。
- 对比红黑树：B+ 树为磁盘 IO 设计。

### Q7. 红黑树和 AVL 怎么选？

**结论**：查询多、要求严格平衡用 AVL；插入删除频繁、工程通用用红黑树。

**展开**：

- AVL 高度平衡，查询略快，旋转多。
- 红黑树近似平衡，插入删除旋转少。
- Java TreeMap、C++ map 多用红黑树。

### Q8. Top-K 怎么求？

**结论**：维护大小为 K 的最小堆，O(n log k)；数据量小可用快速选择平均 O(n)。

**展开**：

- 最大 K 个：最小堆，堆顶是当前第 K 大。
- 新元素大于堆顶才替换。
- 数据流场景堆更合适；一次性数据可用 Quickselect。

### Q9. 手写 LRU Cache

**结论**：哈希表 + 双向链表，`get/put` O(1)；工程可用 `OrderedDict`。

**展开**：

- 哈希表定位节点，双向链表维护顺序。
- 访问移到头部，淘汰尾部。
- 容量超限删尾节点并同步哈希表。

### Q10. 布隆过滤器的原理与误判？

**结论**：位数组 + 多个哈希；查询全 1 才可能存在，可能误判存在，但不会漏判。

**展开**：

- 插入把 k 个位置置 1。
- 误判率随元素增多而上升。
- 不支持删除；计数布隆可删除。
- 用于缓存穿透、去重，不存真实数据。

### Q11. 一致性哈希解决什么问题？

**结论**：分布式节点增减时，减少 key 的重新映射；虚拟节点解决倾斜。

**展开**：

- 节点和 key 映射到哈希环。
- key 顺时针找第一个节点。
- 加节点只影响相邻区间。
- 虚拟节点让数据分布更均匀。

### Q12. 拓扑排序怎么做？

**结论**：Kahn 算法：统计入度，入度为 0 入队，逐个删除并更新邻居入度；结果不足说明有环。

**展开**：

- 时间复杂度 O(V+E)。
- DFS 后序反转也可做拓扑排序。
- 工作流 DAG 执行顺序、依赖解析常用。

### Q13. 最短路径算法怎么选？

**结论**：无权 BFS；非负权 Dijkstra；有负权 Bellman-Ford；多源全对 Floyd。

**展开**：

- BFS O(V+E)。
- Dijkstra 堆优化 O((V+E) log V)。
- Bellman-Ford O(VE)，可检测负环。
- Floyd O(V³)，适合小图多源。

### Q14. 二分查找怎么写不容易错？

**结论**：先定区间语义（左闭右开/左闭右闭），再写循环条件与边界更新。

**展开**：

- 左闭右开：`lo < hi`，`hi = mid`。
- 左闭右闭：`lo <= hi`，`hi = mid - 1`。
- 找第一个/最后一个满足条件的位置，用 lower_bound/upper_bound 模板。

### Q15. 滑动窗口的适用条件？

**结论**：连续子数组/子串，且窗口扩张/收缩有单调性（满足条件后可收缩）。

**展开**：

- 维护 `left/right` 与窗口内状态。
- 右指针扩张，不满足时左指针收缩。
- 典型：最长无重复子串、最小覆盖子串、和 ≥ target 的最短子数组。

## 11. 速记卡

| 关键词 | 记住这一句 |
| --- | --- |
| 数组 | 随机访问 O(1)，插入删除 O(n) |
| 链表 | 插入删除 O(1)，查找 O(n) |
| 栈 | LIFO，括号/DFS/撤销 |
| 队列 | FIFO，BFS/任务队列 |
| 哈希 | 平均 O(1)，冲突用拉链/开放寻址 |
| 2 的幂 | `(n-1) & hash`，扩容稳定 |
| BST | 中序有序，可能退化 |
| 红黑树 | 近似平衡，工程常用 |
| B+ 树 | 高扇出、叶子链表、磁盘索引 |
| 堆 | 取顶 O(1)，插入/删除 O(log n) |
| Top-K | 大小为 K 的最小堆 |
| 图 | 邻接表 O(V+E) |
| BFS | 队列，无权最短路 |
| DFS | 栈/递归，连通/拓扑/回溯 |
| 拓扑排序 | 入度为 0 入队，结果不足有环 |
| 并查集 | 路径压缩 + 按秩合并 |
| LRU | 哈希 + 双向链表 |
| 布隆 | 可能误判存在，不会漏判 |
| 跳表 | 多层链表，Redis ZSet |
| 一致性哈希 | 哈希环 + 虚拟节点 |

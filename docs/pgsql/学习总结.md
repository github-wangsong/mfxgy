## 二、核心知识体系地图

### 2.1 类型系统（PG 的强项）

| 类别 | 关键类型 | MySQL 对照 |
| --- | --- | --- |
| 文本 | `text`（无长度上限，推荐）、`varchar(n)` | `varchar`/`text` |
| 整数 | `smallint`/`integer`/`bigint` + `GENERATED ... AS IDENTITY` | `AUTO_INCREMENT` |
| 时间 | `timestamp`/`timestamptz`、`date`、`interval` | `datetime`/`timestamp` |
| 布尔 | `boolean`（真/假/NULL） | `tinyint(1)` |
| JSON | `jsonb`（推荐，可索引）、`json` | `JSON`（较弱） |
| 数组 | `text[]`、`integer[]` | 无原生 |
| UUID | `uuid`（`gen_random_uuid()`） | 无原生（char(36)） |
| 向量 | `vector(n)`（pgvector 扩展） | 无原生 |

**要点**：PG 类型丰富且严格，`text` 优于 `varchar(n)`，`jsonb` 是半结构化首选。

### 2.2 DML 与方言差异

| 能力 | PostgreSQL | MySQL |
| --- | --- | --- |
| 自增 | `GENERATED ALWAYS AS IDENTITY`（推荐）/`SERIAL` | `AUTO_INCREMENT` |
| 返回插入行 | `INSERT ... RETURNING *` | 需再查 |
|  Upsert | `ON CONFLICT (col) DO UPDATE SET ...` | `ON DUPLICATE KEY UPDATE` |
| 引号 | 标识符用双引号 `"`，字符串用单引号 `'` | 反引号 `` ` `` 标识符 |
| 大小写 | 标识符默认转小写（除非双引号） | 默认不敏感 |
| 分页 | `LIMIT n OFFSET m`（同） | 同 |
| 布尔字面量 | `TRUE`/`FALSE` | `1`/`0` |

### 2.3 JSONB 速查（阶段 3）

```sql
-- 取字段
SELECT data->'name'          -- jsonb
SELECT data->>'name'         -- text
SELECT data#>>'{a,b}'        -- 路径取 text

-- 包含（走 GIN 索引）
WHERE data @> '{"role":"admin"}'

-- 存在键
WHERE data ? 'email'

-- 整体更新
UPDATE t SET data = data || '{"name":"x"}'::jsonb
-- 删除键
UPDATE t SET data = data - 'old_key'
```

**索引**：`CREATE INDEX idx ON t USING gin (data jsonb_path_ops);`（`@>` 走此索引）。

### 2.4 索引体系（阶段 6）

| 类型 | 适用场景 | MySQL 对照 |
| --- | --- | --- |
| B-tree | 等值、范围、排序（默认） | B-tree（默认） |
| GIN | jsonb、数组、全文检索 | 无原生 |
| GiST | 全文、范围、几何 | 无原生 |
| HASH | 等值（PG 10+ 持久化） | HASH |
| BRIN | 大表按物理顺序的范围（如时间） | 无原生 |

**EXPLAIN**：`EXPLAIN (ANALYZE, BUFFERS) ...` 看实际执行，关注 `Seq Scan` vs `Index Scan`、`rows` 估算偏差。

### 2.5 事务与并发（阶段 5）

| 概念 | PostgreSQL |
| --- | --- |
| MVCC | 多版本，读写不互斥（同 MySQL InnoDB） |
| 隔离级别 | `READ COMMITTED`（默认）、`REPEATABLE READ`、`SERIALIZABLE` |
| 锁 | `SELECT ... FOR UPDATE` 行锁；`LOCK TABLE` 表锁 |
| 死锁 | 自动检测并回滚一个事务 |
| 膨胀 | `VACUUM` 回收死元组；`VACUUM FULL` 重写表（锁表）；`autovacuum` 自动 |
| 监控 | `pg_stat_user_tables`（死元组数）、`pg_stat_activity`（活动连接） |

### 2.6 体系结构与权限（阶段 7）

**三层结构**：`Database` → `Schema` → `Table`；`Role` 是用户+组的统一概念。

```sql
CREATE ROLE app_user LOGIN PASSWORD '...';
GRANT USAGE ON SCHEMA public TO app_user;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO app_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO app_user;
```

**系统目录**：`pg_tables`/`pg_indexes`/`pg_stat_user_tables`/`pg_stat_activity`。

### 2.7 扩展与 pgvector（阶段 8）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 写入
INSERT INTO chunks(content, embedding)
VALUES ('...', '[0.1,0.2,...]'::vector(1536));

-- 余弦 Top-K
SELECT content, 1 - (embedding <=> $1::vector) AS score
FROM chunks
WHERE knowledge_base_id = $2
ORDER BY embedding <=> $1::vector
LIMIT 5;

-- HNSW 索引
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

### 2.8 表分区（阶段 11/02 新增）

```sql
CREATE TABLE events (...) PARTITION BY RANGE (created_at);

CREATE TABLE events_2026_10 PARTITION OF events
    FOR VALUES FROM ('2026-10-01') TO ('2026-11-01');

-- 秒级归档老数据
ALTER TABLE events DETACH PARTITION events_2026_10;
DROP TABLE events_2026_10;
```

## 四、学习路径建议

1. **入门（阶段 0）**：装好 PG，跑通类型、CRUD、JOIN、事务，建立「PG 类型更丰富、语法更严格」的直觉。
2. **差异适配（阶段 2）**：把 MySQL 习惯映射到 PG（引号、自增、Upsert、布尔）。
3. **半结构化（阶段 3）**：掌握 `jsonb` + GIN，这是 PG 相对 MySQL 的核心优势，也是项目画布的基石。
4. **查询进阶（阶段 4）**：窗口函数、CTE 解决复杂统计与图遍历。
5. **并发与性能（阶段 5、6）**：MVCC/锁/VACUUM 治理膨胀；EXPLAIN 读执行计划、选索引。
6. **架构与扩展（阶段 7、8）**：三层权限、扩展机制、pgvector 实现 RAG。
7. **运维（阶段 9、10，按需）**：全文检索、备份、WAL 复制。
8. **综合（阶段 11）**：ORM 映射 + 事件表 + 向量检索闭环，把所有能力串成项目真实数据层。

## 五、高频坑点速查

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| 大小写敏感 | 双引号标识符保留大小写，查询要加双引号 | 标识符一律小写，不用双引号 |
| jsonb 查不到 | `data->>'x' = 'y'` 不走索引 | 用 `data @> '{"x":"y"}'` + GIN |
| 表膨胀 | 频繁更新后表越来越大、查询慢 | `VACUUM`/调 `autovacuum`；大删改用 `TRUNCATE` 或分区 |
| 索引未命中 | `EXPLAIN` 显示 Seq Scan | 函数/表达式要建表达式索引；避免 `LIKE '%x'` 前缀模糊 |
| 向量维度不一致 | 插入报错 | 表/索引/插入三处维度必须相同（`vector(1536)`） |
| 分区裁剪失效 | 分区表查询扫了所有分区 | `WHERE` 必须带分区键范围；确认 `constraint_exclusion=partition` |
| ORM 默认值差异 | `@default(uuid())` 在应用层生成，DB 无 DEFAULT | 用 `server_default` 让 DB 层兜底；或触发器 |
| 时区混乱 | `timestamp` 无时区 vs `timestamptz` | 生产统一用 `timestamptz`，应用层处理显示 |
| 死锁 | 两个事务互相等待 | 固定加锁顺序；PG 自动检测回滚其一 |

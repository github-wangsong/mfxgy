## 4. CREATE TABLE 语法（首次完整教学）

### 4.1 语法骨架

```sql
CREATE TABLE 表名 (
    列名 数据类型 [列级约束],
    列名 数据类型 [列级约束],
    ...,
    [表级约束]
);
```

拆解：

| 组成 | 说明 | 例子 |
| --- | --- | --- |
| `CREATE TABLE 表名` | 建一张表，名字用小写 | `users` |
| `列名 数据类型` | 每一列都要声明**类型**（PG 强类型，无类型列不存在） | `name text` |
| **列级约束** | 紧跟在某列后，只约束这一列 | `age integer NOT NULL` |
| **表级约束** | 写在最后，可约束多列（如复合主键） | `PRIMARY KEY (a, b)` |

### 4.2 最小可运行示例

```sql
CREATE TABLE users (
    id          integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username    text    NOT NULL UNIQUE,
    created_at  timestamptz NOT NULL DEFAULT now()
);
```

> 这条语句里的三列，正好覆盖了「类型（integer/text/timestamptz）+ 六类约束里的四种（PRIMARY KEY / NOT NULL / UNIQUE / DEFAULT）」。下面逐项展开。

## 5. 数据类型（首次教学：核心一批）

PG 类型极其丰富，但日常选型集中在下面几类。先给一张总表，再逐类讲。

### 5.1 数值类型

| 类型 | 范围/精度 | 用在哪 | MySQL 对应 |
| --- | --- | --- | --- |
| `smallint` | 2 字节整数 | 极小计数 | `SMALLINT` |
| `integer` / `int` | 4 字节整数，最常用 | 主键、计数 | `INT` |
| `bigint` | 8 字节整数 | 大计数/时间戳毫秒 | `BIGINT` |
| `numeric(p, s)` / `decimal` | **精确**十进制，p 总位数、s 小数位 | 金额（**必须用这个，不能用浮点**） | `DECIMAL(p,s)` |
| `real` / `double precision` | 二进制浮点，有舍入误差 | 科学计算、不精确的场景 | `FLOAT` / `DOUBLE` |

> 关键取舍：**金额、精确计算用 `numeric`，不要用 `float`**，因为浮点是二进制近似（`0.1+0.2 != 0.3` 那类问题）。这条在两种数据库里通用。

### 5.2 文本类型

| 类型 | 说明 | 用在哪 | MySQL 对应 |
| --- | --- | --- | --- |
| `text` | **不限长**的可变长字符串（PG 首选） | 绝大多数字符串字段 | `TEXT` |
| `varchar(n)` | 可变长，**限制最大长度 n** | 需要业务上限时（如用户名 ≤ 64） | `VARCHAR(n)` |
| `char(n)` | 定长，不足自动补空格（**几乎不用**） | 极少 | `CHAR(n)` |

> PG 里 `text` 与 `varchar(n)` **存储性能几乎无差别**（不像 MySQL 早期 TEXT 独立存储），所以社区惯例是：**没事用 `text`，需要长度约束再用 `varchar(n)`**。

### 5.3 时间与日期类型

| 类型 | 说明 | 用在哪 | MySQL 对应 |
| --- | --- | --- | --- |
| `date` | 只有日期（年月日） | 生日、统计日 | `DATE` |
| `time` | 只有时间（时分秒） | 极少数 | `TIME` |
| `timestamp` | 日期+时间，**不含时区**（naive） | 明确「本地钟表时间」时 | `DATETIME` |
| `timestamptz` | 日期+时间，**含时区**（推荐） | 记录「某个瞬间」，跨时区正确 | `TIMESTAMP`（语义不同） |
| `interval` | 时间间隔 | 计算 `now() - t` | 无直接对应 |

> PG 的约定：**存「绝对时间点」一律用 `timestamptz`**。它内部以 UTC 存储、读取时按会话时区转换，跨时区不会错。`timestamp`（无时区）只在「墙钟时间就够、根本不关心时区」时用。
> MySQL 的 `TIMESTAMP` 有 2038 年上限、且会隐式做时区转换，`DATETIME` 则完全不感知时区——两者语义都相对绕，这也是很多人转 PG 后觉得 `timestamptz` 更清晰的原因。

### 5.4 布尔类型

```sql
is_active boolean NOT NULL DEFAULT true
```

PG 原生 `boolean`，值就是 `true` / `false`（也接受 `'t'`/`'f'`、`1`/`0` 等写法）。

> MySQL 没有原生布尔，惯例用 `TINYINT(1)` 顶替，`0`/`1` 当假/真。PG 直接 `boolean` 更自文档化。

### 5.5 特色类型：uuid / 枚举 / 数组 / jsonb

这四类是 PG「对象-关系型」扩展能力的直观体现，MySQL 要么没有、要么要绕（部分详情进对应阶段）：

| 类型 | 说明 | 本系列展开 |
| --- | --- | --- |
| `uuid` | 原生 UUID 类型，配 `gen_random_uuid()` 生成 | 本篇会用；生成函数见阶段 8 |
| 枚举 | `CREATE TYPE 状态 AS ENUM ('a','b');` 自定义有限集合 | 本篇教学 |
| 数组 | `text[]`、`integer[]` 原生数组列 | 本篇教学基础用法 |
| `jsonb` | 二进制 JSON，可索引 | 阶段 3 完整教学 |

## 6. 建表实战：一张含多类型的 users 表

**完整文件路径：`docs/pgsql/00-认识PostgreSQL与环境上手/03-数据类型与建表语法.md`（本篇示例 SQL，直接粘贴）**

```sql
-- 建一个自定义枚举类型：用户状态只有三种取值
CREATE TYPE user_status AS ENUM ('active', 'disabled', 'deleted');

-- 主表：混合多类型 + 多约束
CREATE TABLE users (
    id          integer     GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username    varchar(64) NOT NULL UNIQUE,
    email       text        NOT NULL UNIQUE,
    age         integer     CHECK (age >= 0),
    balance     numeric(12, 2) NOT NULL DEFAULT 0,
    tags        text[]      NOT NULL DEFAULT '{}',          -- 数组，默认空数组
    status      user_status NOT NULL DEFAULT 'active',      -- 枚举
    profile     jsonb,                                       -- 半结构化，可空
    is_active   boolean     NOT NULL DEFAULT true,
    created_at  timestamptz NOT NULL DEFAULT now()
);
```

### 6.1 逐列解释

| 列 | 类型 | 约束 | 为什么这样设计 |
| --- | --- | --- | --- |
| `id` | `integer` | `IDENTITY` + `PRIMARY KEY` | 自增主键（第 7 节详解） |
| `username` | `varchar(64)` | `NOT NULL` + `UNIQUE` | 需要长度上限 + 全局唯一 |
| `email` | `text` | `NOT NULL` + `UNIQUE` | 邮箱长度无上限要求，用 `text` |
| `age` | `integer` | `CHECK (age >= 0)` | 用检查约束挡住负年龄 |
| `balance` | `numeric(12,2)` | `NOT NULL` + `DEFAULT 0` | 金额必须精确 decimal |
| `tags` | `text[]` | `NOT NULL` + `DEFAULT '{}'` | 打标签，原生数组 |
| `status` | 枚举 `user_status` | `NOT NULL` + `DEFAULT 'active'` | 有限状态机，防脏值 |
| `profile` | `jsonb` | 无 | 扩展字段，可空（阶段 3 详解） |
| `is_active` | `boolean` | `NOT NULL` + `DEFAULT true` | 布尔开关 |
| `created_at` | `timestamptz` | `NOT NULL` + `DEFAULT now()` | 记录创建瞬间，含时区 |

### 6.2 验证建表结果

```sql
\dt          -- 应看到 users 表
\d users     -- 应看到每列的类型、约束、索引
```

**预期输出**（`\d users` 关键部分）：

```
                            Table "public.users"
   Column    |           Type           | ... |                     Default
-------------+--------------------------+-----+-------------------------------------------------
 id          | integer                  |     | generated always as identity
 username    | character varying(64)    |     |
 ...
```

> 注意 `varchar(64)` 在 `\d` 里显示为 `character varying(64)`，`text[]` 显示为 `text[]`——它是同一样东西的「规范写法」，别慌。

## 7. IDENTITY 自增主键（首次教学）

### 7.1 推荐写法

```sql
id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

- `GENERATED ALWAYS AS IDENTITY`：让 PG 自动生成自增值，你**手动插入 id 会被拒绝**（除非加 `OVERRIDING SYSTEM VALUE`）。
- 另有 `GENERATED BY DEFAULT AS IDENTITY`：允许手动插入覆盖，更灵活。

### 7.2 旧写法 SERIAL（知道即可）

```sql
id SERIAL PRIMARY KEY
```

`SERIAL` 是历史语法，等价于「`integer` + 一个 sequence 序列 + `DEFAULT nextval(...)`」。新项目推荐 `IDENTITY`（语义更标准、更清晰）。

### 7.3 与 MySQL 对照

| 维度 | MySQL | PostgreSQL |
| --- | --- | --- |
| 自增主键 | `id INT AUTO_INCREMENT` | `id integer GENERATED ALWAYS AS IDENTITY` |
| 底层实现 | 表级自增计数器 | 独立的**序列（sequence）对象** (见 `\d` 里的 `implicit sequence`) |
| 手动插 id | 允许 | `ALWAYS` 默认拒绝；`BY DEFAULT` 允许 |
| 拿到「刚插入的 id」 | `LAST_INSERT_ID()` | `INSERT ... RETURNING id`（下一篇教） |

## 8. 六类约束速查

| 约束 | 写法（列级） | 作用 |
| --- | --- | --- |
| **非空** | `列 类型 NOT NULL` | 该列不能为 `NULL` |
| **默认值** | `列 类型 DEFAULT 值` | 不填时用该默认值 |
| **主键** | `列 类型 PRIMARY KEY`（或表级 `PRIMARY KEY(a,b)`） | 唯一 + 非空，一张表一个 |
| **唯一** | `列 类型 UNIQUE` | 该列取值不能重复（允许多个 `NULL`） |
| **检查** | `列 类型 CHECK (条件)` | 自定义校验，如 `age >= 0` |
| **外键** | `列 类型 REFERENCES 表(列)` | 引用另一张表的行，保证引用完整性 |

> 外键涉及「关系建模」，会在后续「关系与 JOIN」相关篇完整教学，这里先记住语法与语义即可。

## 9. 与 MySQL 类型速查对照

| 场景 | MySQL | PostgreSQL | 备注 |
| --- | --- | --- | --- |
| 长文本 | `TEXT`（独立存储） | `text`（首选） | PG 无独立存储顾虑 |
| 变长字符串 | `VARCHAR(n)` | `varchar(n)` | 同 |
| 时间点 | `DATETIME` / `TIMESTAMP` | `timestamptz`（推荐） | 语义差异大，见 5.3 |
| 布尔 | `TINYINT(1)` | `boolean` | PG 原生 |
| 自增主键 | `AUTO_INCREMENT` | `IDENTITY` | 见第 7 节 |
| 无符号数 | `INT UNSIGNED` | **无 UNSIGNED** | PG 无此概念，用数值范围更大的类型 |
| 枚举 | `ENUM('a','b')`（表级） | `CREATE TYPE ... AS ENUM`（独立类型对象） | PG 更结构化，可复用 |

-- 然后插一条合法的最小数据，验证 IDENTITY 自增与默认值都生效

## 11. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `\d users` 显示 `character varying(64)` | `varchar` 是 `character varying` 的别名，PG 内部显示规范名 | 正常，二者等价 |
| 插入 `age=-5` 被拒后，想换另一条 `id` 仍从 1 开始吗 | 序列**不会**因失败回退，可能产生空洞 | 正常现象，自增主键允许空洞 |
| 建表时表名用大写 `USERS`，之后 `\dt` 查不到 | 未加引号的标识符折叠成小写（见阶段 2） | 用小写表名，或规范加双引号 |
| 想把 `varchar(64)` 改成不限长 | `ALTER TABLE users ALTER COLUMN username TYPE text;` | 记住 `ALTER TABLE ... ALTER COLUMN ... TYPE` 这条 |
| 金额算出来有小数误差 | 用了 `float`/`double` 存钱 | 金额用 `numeric(p,s)` |

## 12. 本篇小结

- `CREATE TABLE` = 列名 + 类型 + 约束；PG 强类型，每列必有类型。
- 核心类型：数值 `integer/bigint/numeric`、文本 `text/varchar`、时间 `timestamptz`（首选）、`boolean`、`uuid`/枚举/数组/`jsonb`。
- 自增主键用 `GENERATED ALWAYS AS IDENTITY`（对照 MySQL `AUTO_INCREMENT`）。
- 六类约束：`NOT NULL` / `DEFAULT` / `PRIMARY KEY` / `UNIQUE` / `CHECK` / `FOREIGN KEY`。
- 已建好实战表 `users`，下一篇用它讲 INSERT/SELECT/UPDATE/DELETE（增删改查）。

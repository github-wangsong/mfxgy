## 4. INSERT：插入数据（首次教学）

### 4.1 语法骨架

```sql
INSERT INTO 表名 (列1, 列2, ...)
VALUES (值1, 值2, ...);
```

- 列清单里的列，与 VALUES 里的值**一一对应**。
- **未列出的列**：有 `DEFAULT` 用默认值，否则 `NULL`；`IDENTITY` 主键列**不要手填**（`GENERATED ALWAYS` 会拒绝）。

### 4.2 插入一行（省略自增 id 与有默认值的列）

```sql
INSERT INTO users (username, email)
VALUES ('alice', 'alice@example.com');
```

> 这里只给了 `username`、`email` 两个必填列；`id` 自增、`balance`/`tags`/`status`/`is_active`/`created_at` 都吃默认值，`age`/`profile` 允许 `NULL`。

### 4.3 一次插入多行

```sql
INSERT INTO users (username, email, age)
VALUES
    ('bob',   'bob@example.com',   25),
    ('carol', 'carol@example.com', 30),
    ('dave',  'dave@example.com',  40);
```

> 多行 = 一条语句里写多个 `(值)`，逗号分隔。比循环单插**一次一条**高效得多。

### 4.4 RETURNING：插入后立刻拿回结果（PG 特色）

```sql
INSERT INTO users (username, email)
VALUES ('eve', 'eve@example.com')
RETURNING id, username, created_at;
```

**预期输出**：

```
 id | username |          created_at
----+----------+-------------------------------
  5 | eve      | 2026-10-21 12:34:56.789+08
```

> `RETURNING` 是 PG 的标志性能力：`INSERT` 后不用再查一遍，一次拿回 `id`（或任意列）。对照 MySQL：那里要 `SELECT LAST_INSERT_ID();`（且只能拿回一个自增 id，拿不回整行）。这条在第 8 节对照表再总结。

## 5. SELECT：查询数据（首次教学）

### 5.1 语法骨架与执行顺序

```sql
SELECT 列... FROM 表
WHERE 条件
ORDER BY 列 [ASC|DESC]
LIMIT 数量 OFFSET 偏移;
```

> 逻辑执行顺序（重要心智模型）：`FROM`（找表）→ `WHERE`（过滤行）→ `SELECT`（挑列）→ `ORDER BY`（排序）→ `LIMIT/OFFSET`（截取）。**先过滤再排序再截取**。

### 5.2 查所有行 + 挑列

```sql
SELECT * FROM users;                 -- 所有列（生产慎用，学习 OK）
SELECT username, email FROM users;   -- 只挑需要的两列
```

### 5.3 WHERE 条件（首次教学：一组运算符）

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `=` / `<>`（或 `!=`） | 等于 / 不等于 | `age = 30` |
| `>` `<` `>=` `<=` | 比较 | `age >= 30` |
| `AND` / `OR` / `NOT` | 逻辑组合 | `age > 20 AND age < 35` |
| `IN (...)` | 命中集合 | `username IN ('alice','bob')` |
| `BETWEEN a AND b` | 闭区间 | `age BETWEEN 20 AND 30` |
| `LIKE` / `ILIKE` | 模糊匹配（`ILIKE` 忽略大小写） | `email LIKE '%@example.com'` |
| `IS NULL` / `IS NOT NULL` | 判空（**不能用 `= NULL`**） | `profile IS NULL` |

示例：

```sql
-- 年龄 >= 30 的用户
SELECT username, age FROM users WHERE age >= 30;

-- 用户名是 alice 或 bob，且邮箱以 @example.com 结尾
SELECT username, email
FROM users
WHERE username IN ('alice','bob') AND email ILIKE '%@example.com';

-- profile 还没填的用户（判空要用 IS NULL）
SELECT username FROM users WHERE profile IS NULL;
```

### 5.4 ORDER BY 排序

```sql
SELECT username, age
FROM users
ORDER BY age DESC;          -- 按年龄降序

SELECT username, age
FROM users
ORDER BY age DESC, username ASC;   -- 多重排序：年龄降序，同龄按用户名升序
```

### 5.5 LIMIT / OFFSET 分页

```sql
SELECT id, username FROM users ORDER BY id LIMIT 2;           -- 前 2 条
SELECT id, username FROM users ORDER BY id LIMIT 2 OFFSET 2;  -- 跳过前 2 条，再取 2 条（第 2 页）
```

> `LIMIT 条数 OFFSET 偏移` 就是最朴素的分页语法。这条与 MySQL 完全一致（MySQL 也支持 `LIMIT n OFFSET m`）。生产大数据量分页有更优写法，阶段 6 会涉及，这里掌握基础。

## 6. UPDATE：更新数据（首次教学）

### 6.1 语法骨架与「必须带 WHERE」的铁律

```sql
UPDATE 表
SET 列1 = 值1, 列2 = 值2
WHERE 条件
RETURNING 列...;   -- 可选
```

### 6.2 安全示例

```sql
UPDATE users
SET age = 26, status = 'active'
WHERE username = 'bob'
RETURNING username, age, status;
```

**预期输出**：返回被更新的行，`age` 已是 26。

### 6.3 危险示范（不要真跑，理解即可）

```sql
-- ⚠️ 没有 WHERE 会更新【整张表】每一行！
-- UPDATE users SET status = 'disabled';   -- 危险，切勿执行
```

> 铁律：**写 UPDATE/DELETE 前，先写 `WHERE`**。可先跑对应的 `SELECT ... WHERE` 确认选中的行，再改成 UPDATE。

## 7. DELETE：删除数据（首次教学）

### 7.1 语法骨架

```sql
DELETE FROM 表
WHERE 条件
RETURNING 列...;   -- 可选
```

### 7.2 安全示例

```sql
DELETE FROM users
WHERE username = 'dave'
RETURNING id, username;
```

**预期输出**：返回被删的行，之后该行不存在。

### 7.3 清空整表：TRUNCATE（比 DELETE 快）

```sql
-- 删光所有行；RESTART IDENTITY 顺带把自增 id 计数器重置回 1
TRUNCATE users RESTART IDENTITY;
```

| 方式 | 逐行删除，可带 WHERE | 一个表只能全删 | 自增 id 是否重置 |
| --- | --- | --- | --- |
| `DELETE FROM t` | ✅ 可带 `WHERE` | — | 不重置 |
| `TRUNCATE t` | ❌ 不能带 `WHERE` | ✅ 整表 | 默认不重置；加 `RESTART IDENTITY` 重置 |

> 学习时想「一键清空重练」，`TRUNCATE users RESTART IDENTITY;` 最方便。

## 8. 与 MySQL 对照

| 操作 | MySQL | PostgreSQL | 差异点 |
| --- | --- | --- | --- |
| 插入后拿 id | `SELECT LAST_INSERT_ID();` | `INSERT ... RETURNING id;` | PG 能一次拿回整行/多列 |
| 模糊匹配不分大小写 | `LIKE`（依赖 collation，默认不区分） | `LIKE` 区分大小写，另需 `ILIKE` | 见阶段 2 |
| 判空 | `IS NULL` | `IS NULL` | 相同（都不能用 `= NULL`） |
| 分页 | `LIMIT n OFFSET m` | `LIMIT n OFFSET m` | 完全一致 |
| 清空整表 | `TRUNCATE t` | `TRUNCATE t [RESTART IDENTITY]` | 基本一致，PG 多了重置序列参数 |
| UPDATE/DELETE 语法 | 同 | 同 | 基本一致 |

> 一句话：**增删改查的「骨架」两种库几乎一样**，PG 的增量优势在 `RETURNING`、`ILIKE`、`DISTINCT ON` 这类细节上（阶段 2、4 逐个展开）。

## 9. 验收自测

> 建议从头跑一遍，把「清空 → 插入 → 查询 → 更新 → 删除」串成一个闭环。

### 9.1 清空并重建起始数据

```sql
TRUNCATE users RESTART IDENTITY;

INSERT INTO users (username, email, age) VALUES
    ('alice', 'alice@example.com', 28),
    ('bob',   'bob@example.com',   35),
    ('carol', 'carol@example.com', 22)
RETURNING id, username, age;
-- 预期：返回 3 行，id 从 1 开始
```

### 9.2 条件查询 + 排序 + 分页

```sql
SELECT username, age FROM users
WHERE age >= 25
ORDER BY age DESC
LIMIT 2;
-- 预期：bob(35)、alice(28)
```

### 9.3 更新 + 删除，均用 RETURNING 验证

```sql
UPDATE users SET age = 36
WHERE username = 'bob'
RETURNING username, age;
-- 预期：bob 的 age 变成 36

DELETE FROM users
WHERE username = 'carol'
RETURNING id, username;
-- 预期：返回被删的 carol 那一行
```

跑完后 `SELECT * FROM users;` 应只剩 alice、bob 两行。

## 10. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 字符串写成双引号报错 | SQL 里字符串用**单引号** `'abc'`；双引号是标识符（表/列名） | 值用单引号 |
| `WHERE profile = NULL` 查不到 | 与 `NULL` 比较永远不是「真」，必须 `IS NULL` | 判空用 `IS NULL` / `IS NOT NULL` |
| UPDATE/DELETE 误改/误删全表 | 忘了 `WHERE` | 先 `SELECT ... WHERE` 验证，再改写成 UPDATE/DELETE |
| `INSERT` 报 `null value in column "username"` | 必填列没给值（`NOT NULL` 且无默认） | 检查列清单是否漏了必填列 |
| `INSERT` 报违反 `users_username_key` | 插入了重复的唯一键（username/email 重复） | 换唯一值；或按唯一键做 `ON CONFLICT`（阶段 2） |
| `RETURNING` 在 MySQL 里报错 | `RETURNING` 是 PG 特性 | MySQL 用 `LAST_INSERT_ID()` |

## 11. 本篇小结

- 四大操作骨架：`INSERT INTO ... VALUES` / `SELECT ... FROM` / `UPDATE ... SET` / `DELETE FROM`。
- `WHERE` 是一组运算符（比较/逻辑/`IN`/`BETWEEN`/`LIKE/ILIKE`/`IS NULL`）。
- 执行顺序：`FROM → WHERE → SELECT → ORDER BY → LIMIT/OFFSET`。
- PG 特色 `RETURNING` 让增/改/删一次拿回结果；`TRUNCATE ... RESTART IDENTITY` 一键清空重练。
- 安全铁律：UPDATE/DELETE 前先写 `WHERE`。

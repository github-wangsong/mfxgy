## 3. 先确认连接三要素

连任何数据库都要有「三要素 + 一把钥匙」：

| 要素 | 项目取值（以 compose 为准） | 说明 |
| --- | --- | --- |
| **host** | `localhost`（web 端口映射时）/ 容器名（容器内互连时） | 连到哪台机器 |
| **port** | `5432`（PG 默认；映射到宿主机可能是别的宿主端口） | 连到哪个端口 |
| **database** | 默认 `postgres`（或 compose `.env` 里 `POSTGRES_DB` 指定） | 连哪个库 |
| **user + password** | 默认超级用户 `postgres` + compose `.env` 里 `POSTGRES_PASSWORD` | 谁、凭什么进去 |

> PG 默认端口是 **5432**（见 `01` 篇常见坑），默认超级用户是 **postgres**。准确值以 `docs/tutorial/00-项目初始化/02-本地中间件Docker.md` 里的 `.env` 为准。

先确认容器名与端口映射，用于下面第 4、5 节的命令：

```powershell
# 在 PowerShell 执行；目的：拿到容器 NAMES 与「宿主端口→容器 5432」的映射关系
docker ps --format "table {{.Names}}\t{{.Ports}}"
```

**预期输出解读**：`PORTS` 列若是 `0.0.0.0:15432->5432/tcp`，说明「宿主机 15432」映射到「容器内 5432」。下面凡用端口映射连库，就填那个**宿主端口**（本例 15432）。

## 4. psql 是什么（首次教学）

### 4.1 一句话

`psql` 是 PostgreSQL **官方自带的命令行客户端**，用来连库、执行 SQL、管理库对象。它是每个 PG 使用者的「最小必备工具」。

### 4.2 两种使用方式

| 方式 | 命令形态 | 适用 |
| --- | --- | --- |
| **交互式** | `psql [-参数]` 回车后进入 REPL，逐条敲命令 | 日常探索、学习（本篇主力） |
| **单条执行** | `psql ... -c "SQL"` 跑完即退，不进入 REPL | 脚本、自检（`01` 篇验收就用的这个） |

### 4.3 连接参数（常用 4 个）

```text
psql -h 主机 -p 端口 -U 用户名 -d 数据库名
```

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `-h` | host，要连的主机 | 本地 socket |
| `-p` | port，端口 | 5432 |
| `-U` | 用户名（**注意大写 U**） | 当前系统用户 |
| `-d` | 数据库名 | 与用户名同名 |

> 密码：psql 通常**交互式提示输入**，或用环境变量 `PGPASSWORD`、用户目录 `~/.pgpass` 提供。教程里为了演示方便，容器内连本地往往直接以超级用户进入（compose 里常配了 `POSTGRES_HOST_AUTH_METHOD=trust` 或已知密码）。

## 5. 环境搭建：建一个独立练习库（首次教学 `CREATE DATABASE`）

> 目的：本系列后续练习**绝不污染** mini-dify 的应用库。建一个 `pg_tutorial`，可随时 `DROP` 重建。

### 5.1 先看现在有哪些库

**完整命令**（进入容器内执行 psql，`<容器名>` 换成实际名）：

```powershell
docker exec -it <容器名> psql -U postgres
```

进入 psql 交互界面后（提示符形如 `postgres=#`），执行元命令列出所有库：

```sql
\l
```

**预期输出**：至少能看到 `postgres`、`template0`、`template1`（PG 自带的模板/默认库），以及项目应用的库（如 compose 里 `POSTGRES_DB` 指定的那个）。

### 5.2 两种建库写法

**方式 A：SQL 命令（在 psql 里）**

```sql
CREATE DATABASE pg_tutorial;
```

**方式 B：命令行工具 `createdb`（容器内 shell）**

```powershell
docker exec -it <容器名> createdb -U postgres pg_tutorial
```

> 两种等价。`createdb` 是 PG 自带命令行工具，内部就是发一条 `CREATE DATABASE`。
> `CREATE DATABASE` 的完整语义（模板、编码、属主、连接限制）在阶段 7「体系结构」再展开，这里**最小用法**够用。

### 5.3 切到练习库

```sql
\c pg_tutorial
```

**预期输出**：

```
You are now connected to database "pg_tutorial" as user "postgres".
```

提示符会变成 `pg_tutorial=#`。**从这里开始，之后所有练习都在 `pg_tutorial` 里做。**

## 6. psql 元命令大全（首次教学）

> 元命令 = 以反斜杠 `\` 开头的命令，**不是 SQL**，由 psql 客户端本地解释，不发到服务器。它俩要分清：`SELECT ...` 是 SQL（发服务器），`\dt` 是元命令（psql 客户端替你查系统表）。

按用途分类如下（全部在 psql 交互界面里敲）：

### 6.1 信息与浏览

| 元命令 | 作用 | 对应 MySQL |
| --- | --- | --- |
| `\l` / `\l+` | 列出所有数据库（`+` 带大小等详情） | `SHOW DATABASES;` |
| `\c 库名` | 切换连接到的数据库 | `USE 库名;` |
| `\conninfo` | 显示当前连接信息（谁、哪、库、编码） | 无直接对应 |
| `\dt` / `\dt+` | 列出**当前 schema** 下的表（`+` 带存储） | `SHOW TABLES;` |
| `\d 表名` / `\d+ 表名` | 查看表的结构（字段/类型/约束/索引） | `DESC 表名;` |
| `\dn` / `\dn+` | 列出 schema（命名空间，阶段 7 详讲） | 无直接对应 |
| `\du` / `\du+` | 列出数据库角色/用户 | `SELECT user FROM mysql.user;` |
| `\df` | 列出函数 | 无直接对应 |

### 6.2 显示控制

| 元命令 | 作用 |
| --- | --- |
| `\x` | **切换**「竖排显示」（每条字段一行，宽表更易读）；再敲一次切回 |
| `\timing` | **切换**「显示每条 SQL 耗时」；再敲一次关闭 |
| `\pset pager off` | 关闭分页（让输出一次性全打出来，适合复制） |
| `\encoding` | 显示/设置客户端编码（中文环境留意，见常见坑） |

### 6.3 输入与执行

| 元命令 | 作用 |
| --- | --- |
| `\i 文件.sql` | 执行某个 SQL 文件里的语句 |
| `\e` | 用系统编辑器打开上一条 SQL 编辑 |
| `\! 命令` | 临时跳出执行一条 shell 命令（如 `\! ls`） |
| `\q` | 退出 psql |
| `\?` | 查看**全部**元命令帮助（忘了就查它） |
| `\h SQL命令` | 查看某条 SQL 的语法帮助（如 `\h CREATE TABLE`） |

> 记忆：**信息用 `\l`/`\dt`/`\d`，显示用 `\x`/`\timing`，忘了用 `\?`**。其余用到再查。

## 7. 图形客户端入门（DBeaver / pgAdmin）

命令行适合学原理、跑脚本；**看图、改数据、导数据**还是图形客户端舒服。二选一即可：

| 客户端 | 定位 | 特点 |
| --- | --- | --- |
| **DBeaver** | 通用数据库桌面工具（社区版免费） | 同时支持 MySQL/PG/几十种库，界面现代 |
| **pgAdmin** | PG 官方 Web 图形界面 | 只服务 PG，随 compose 常带一个容器 |

**连接参数对照**（与 psql 完全一致，只是填到表单里）：

| psql 参数 | 图形界面字段 |
| --- | --- |
| `-h` | Host |
| `-p` | Port（填**宿主映射端口**或 5432，取决于你从哪连） |
| `-U` | Username |
| `-d` | Database |
| 密码 | Password |

> 若你从**宿主机**连（DBeaver 装在 Windows 上），Host 填 `localhost`、Port 填**宿主映射端口**（第 3 节的 `0.0.0.0:15432->5432` 里那个 `15432`），不是 5432——这是图形客户端最常见的连不上原因（见常见坑）。

连上后：左侧树展开 → `Databases` → `pg_tutorial` → `Schemas` → `public` → `Tables`，就能看到库结构（当前 `pg_tutorial` 还是空库，切到 `postgres` 库能看到系统表）。

## 8. 与 MySQL 对照：客户端与「看库看表」的差异

| 操作 | MySQL 客户端 | PostgreSQL（psql） |
| --- | --- | --- |
| 命令行客户端 | `mysql` | `psql` |
| 看所有库 | `SHOW DATABASES;` | `\l` |
| 切换库 | `USE db;` | `\c db` |
| 看所有表 | `SHOW TABLES;` | `\dt` |
| 看表结构 | `DESC 表名;` | `\d 表名` |
| 修改表结构 | `ALTER TABLE` | `ALTER TABLE`（语法同期阶段 1） |

> 一句话：MySQL 用 `SHOW`/`DESC` 这些**SQL** 查元信息，PG 用 `\` 开头的**客户端元命令**（背后也是查系统表，只是 psql 帮你封装了）。这也是「MySQL 的信息命令是标准 SQL，PG 的信息命令是 psql 方言」的直观体现。

## 10. 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 图形客户端连不上 `localhost:5432` | 端口映射到宿主机的不是 5432（如 15432）；或宿主 5432 被占用 | 用 `docker ps` 看 `PORTS` 列，填**宿主映射端口** |
| psql 里 `\` 命令没反应 / 报语法错 | 把元命令当成 SQL、多打了分号，或不小心在 `-c` 里用 | 元命令在交互界面里直接用，**不加分号**；`-c` 里用 SQL 而非元命令 |
| 中文乱码 | 客户端编码与服务端编码不一致（Windows 默认 GBK） | `\encoding` 看编码；`set client_encoding = 'UTF8';` 或 `psql` 加 `PGCLIENTENCODING=UTF8` |
| `\dt` 看不到项目表 | `\dt` 只列**当前 `search_path`**（默认 `public`）下的表；表可能在别的 schema（阶段 7） | 先 `\dn` 看 schema，用 `\dt 模式名.*` 或 `\d 模式名.表名` |
| 忘记退出 / 括号没闭合一直提示 | psql 里 SQL 以 `;` 结束；没加分号会一直等输入 | 补 `;`，或按 `Ctrl+C` 中断当前输入，`\q` 退出 |

## 11. 本篇小结

- 连库三要素 + 一把钥匙：host / port / database / user+password；PG 默认 5432 + postgres。
- psql 是最小必备客户端：参数 `-h -p -U -d`；元命令 `\l` `\c` `\dt` `\d` `\dn` `\x` `\timing` `\?` `\q`。
- 已建独立练习库 `pg_tutorial`，后续练习都在这里，不碰项目库。
- 元命令是「psql 方言、查询系统表」，与 MySQL 的 `SHOW`/`DESC`（标准 SQL）形成对照。
- 图形客户端连接关键：宿主机连接要填**映射后的宿主端口**。
